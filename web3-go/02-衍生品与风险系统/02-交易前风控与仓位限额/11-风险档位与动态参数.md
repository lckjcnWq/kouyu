# 大问题 11：档位、限额收紧与配置回滚怎样生效？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 线性永续、单向逐仓 | 用 USDC 计算 ETH 合约价格差，一个净仓由专用现金支持。 | 不交割 ETH，本文变更档位也不切成跨市场全仓。 |
| q、C、B、E | 净持仓、剩余入场成本、已记账现金、现金加浮盈亏的权益。 | 初始多 2、成本 4,000、B=E=1,000；C 不是四千现金付款。 |
| IM、MM、r/h | IM 是初始保证金要求，MM 是维持保证金要求，r/h 是对应比例。 | 教学 V1 为 10%/5%；保证金不是手续费，两种门槛也不互换。 |
| O1、Mark | O1 为买 1.5@2,000；Mark 是风险估值参考价。 | 主例 Mark=2,000 不保证成交价，档位例中同价使额外价差缓冲为零。 |
| 不可变配置、摘要 | 参数内容保存后不原地改，摘要用于核对内容是否还是那一份。 | 只有版本号却无法还原规则，不足以复算历史决定。 |
| V1/V2/V3、activeConfigId | 前者是规则版本身份，后者指当前正式生效的一版。 | V3 可以采用 V1 的内容，但它是新的激活决定，不是删除 V2 历史。 |
| 激活命令、生效序号 | 把参数正式切换作为市场有序事件，而不是各进程自行读文件切换。 | 激活若在 101，100 和 102 两侧的命令用各自应生效的规则。 |
| 受理事务 A、业务事务 T | A 保存请求身份与顺序；T 决定并共同保存实际业务结果。 | 已受理不承诺沿用旧配置，更不承诺通过或成交。 |
| 毛数量 G、毛名义 X | G 将持仓绝对量和普通余单相加，X 用 Mark 将它折成金额。 | O1 挂单时 G=3.5、X=7,000，不能先用相反买卖相抵。 |
| 单一费率变体 | 全部基数使用同一个保证金比例。 | 第 1 层的 12% 独立变体得到 R=840，不与后面分段 V2 叠加。 |
| 分段费率 | 不同区间各算自己的比例，再加总，像分段电价。 | 教学 V2 前 6,000 用 10%、多出的 1,000 用 15%，合计 750。 |
| 整档费率 | 一旦跨档，整个基数都改用对应档的比例。 | 7,000 全乘 15% 是 1,050，不是本文采用的分段语义。 |
| L、R、可用空间 | L 覆盖普通限价单不利差价；R 是分段基础需求加 L；可用风险空间为 E−R。 | IM、总需求和可用空间不同；R 不是已经扣掉的现金。 |
| 定点、费率分母、向上取整 | 用确定整数单位和比例计算，最后按约定保守取整。 | 跨 6,000 边界不应忽然把整段都改率，也不能靠显示小数判断。 |
| Q*、Qmax、Nmax | 最坏绝对仓位、数量上限、名义敞口上限。 | 保证金档位不代替硬限额，收紧到 3 和 6,000 会使原 O1 不再获支持。 |
| 存量重裁、被动超限 | 旧单按新规则重判；旧仓可能因规则收紧而超过新上限。 | 撤未成交余量，不回滚已经成交的 0.5，也不改判旧成交失败。 |
| 激活屏障、有界批次 | 先使未重裁资格不可执行，再分成受控大小的任务处理。 | 后台慢扫期间，不能靠 V1 的通过标记继续成交。 |
| RO、H 不减门禁 | RO 不得反手；H 是权益减持仓 MM，成交后不能更低。 | 有效价格下评估减险，不能把普通反向单当 RO 或省去健康检查。 |
| 配置回滚、经济冲正 | 回滚配置是以后采用修正参数；经济冲正是另有依据的账务纠正。 | 参数退回不删除成交、不复活撤单、不自动返还现金。 |
| 新意图身份、终态 | 新申请要有新的业务身份；已撤终态不会自动变回活动单。 | V3 放宽规则后，用户想重新挂 O1 必须明确重新申请。 |
| M2 与 V3 的交错顺序 | 价格、规则都是有身份的输入，由共同事件顺序决定组合。 | 先激活 M2、再 V3、再裁决订单，就使用 M2/V3。 |
| 影子计算、参考模型 | 影子计算只旁路比较，参考模型用独立算法核对预期。 | 不能让比较任务产生第二份成交或预占；本文给出方法，未声称实测通过。 |

## 把整篇文章压缩成一个故事

甲持有两个 ETH 永续多仓，又挂买一点五；Mark 两千，按 V1 的百分之十，毛名义七千对应需求七百。管理端改规则，不能让哪台机器先读到文件就先切换，而要排进市场顺序：激活前用旧版，激活后用新版，旧挂单也必须重评。

本文有两个独立变体。单一费率改百分之十二，需求是八百四十；分段 V2 则是前六千百分之十、超过部分百分之十五，所以七千只需六百加一百五十，共七百五十，不是整档的一千零五十。部分成交零点五后，持仓二点五加余单一，毛量没变，V2 需求仍七百五十；撤余才降到五百，现金没有退款。

若接着收紧数量与名义限额，先关闭旧资格再撤失效余单，不能回滚已成交。订单太多就先立屏障、分批重评；参数填错则以 V3 新事件修正，旧成交保留，旧撤单不复活。所有费率和阈值都是本文教学规则，关键是语义、精度和生效点可还原，而非背一个通用档位表。

**流程位置与核心机制：** 本题处理风险配置从提出到激活、存量重裁和回滚的过程，重点是分段规则、生效屏障及审计；价格和经济输入失效的通用保护见第 10 题。

**范围前提：** 固定 ETH-USDC 线性永续、单向逐仓，初始 `q=2、C=4,000、B=1,000、Mark=2,000`；V1 为 `r=10%、h=5%、Qmax=4、Nmax=8,000`。O1 买 `1.5@2,000`，部分成交 `0.5` 后 `q=2.5、remaining=1、R=700`，撤后 `R=500、B=1,000`。受理事务 A 与同库业务事务 T、单市场共同顺序保持不变。以下分段费率是明确扩展 V1 单一 IM 率的独立配置变体，主例不因此改成跨市场全仓或组合保证金。

## 第 1 层：参数修改怎样获得确定生效点

**面试官：** 档位、限额收紧与配置回滚怎样生效？如果管理端把 IM 率从 10% 调成 12%，正在排队的订单用哪一版？

**面试者：** 我不会让各进程读到新配置就自行切换，而是先持久保存不可变配置内容和摘要，再提交激活命令进入市场共同顺序。假设激活在序号一百零一，业务事务一百按 V1 判断，一百零二按新版本判断，与请求到达某台机器的时间无关。O1 挂单时毛名义七千，单一费率改成百分之十二，总需求就从七百变为八百四十，必须重评存量资格。配置文件可提前加载，但只有事务 T 提交 activeConfigId 和相应资格处理后才算生效；已经受理的命令不保证仍按受理时的旧参数获准。

## 第 2 层：分档费率必须先说明整档还是分段

**面试官：** 既然费率按版本裁决，如果 V2 改成“六千以内 10%，超过部分 15%”，O1 的需求应是 750 还是 1,050？

**面试者：** 先明确这是另一个独立变体，不接着上一层百分之十二的方案。我选择按毛名义 X=Mark×G 逐段累加：前六千按百分之十，超过六千的部分按百分之十五，因此 O1 的 X 为七千，基础需求是六百加一百五十，即七百五十；同价订单的不利价差缓冲为零。它不是整档把七千全部乘百分之十五，也不是把买卖单净额当基数。配置必须保存阈值、分段语义、费率分母及舍入规则，R 仍要加普通订单 L，限额仍单独检查 Q* 和 Mark×Q*，不能用分档保证金取代数量和名义上限。

## 第 3 层：边界与部分成交怎样保持同一算法

**面试官：** 你选逐段累加，跨过六千边界以及 O1 部分成交时，怎样避免舍入跳档或重复释放保证金？

**面试者：** 下面继续第 2 层的分段 V2，后续未另声明也沿用它，不回到第 1 层的单一百分之十二方案。我用定点原始乘积逐段累计，再把基础需求统一向上取整，不先把名义或每段随意截断。Mark 为二千时，G 从三变成三点零零零零零一，X 从六千到六千点零零二，需求从六百变成六百点零零零三，不会整档跳成九百多。O1 成交零点五后，仓位二点五加余量一，G 仍三点五，V2 需求仍七百五十；撤余量后 G 为二点五，才降到五百。若买限价改为二千一百，还须另加一百五十的 L。档位变化不是扣款分录，不能部分成交时把原预占全部退成现金。

## 第 4 层：限额收紧怎样处理旧挂单和旧仓位

**面试官：** 分档算清了，如果接着把 Qmax 收紧到 3、Nmax 收紧到 6,000，原来合法的 O1 要怎样处理？

**面试者：** 仍以尚未成交的 O1 为起点，原 Q* 是三点五、名义七千，新限额不支持，所以我在激活点先关闭旧资格，再按确定策略撤销失效普通单。不能只拒绝新单，却让旧单继续扩到三点五。如果改从已部分成交的状态开始，则撤掉余量一后保留真实仓位二点五，R 回到五百、现金仍一千；不能回滚已经共同提交的零点五成交。若新限额再收紧到二，连存量仓位也超限，就维持普通增险关闭，并允许有效价格下通过方向、可平量和 H 不减门禁的 RO，是否进入处置还要另看 MM。

## 第 5 层：订单太多时怎样建立激活屏障

**面试官：** 你要求激活时处理旧资格，如果有大量订单不能放进一个事务，能不能先切版本、后台慢慢扫？

**面试者：** 可以分批，但不能先切版本后继续相信旧通过标记。我会先在激活事务提交新版本和增险关闭屏障，使未重裁资格不可执行，再把重评拆成有界顺序命令，每批各自通过事务 T 提交订单、风险和进度。撤单、补保证金等仍按共同顺序应用，重评结果必须核对账户当前版本，不能覆盖期间的新状态。最后以屏障目标及受影响状态均已覆盖为条件，提交开放事件；尚不符合新规则的账户继续保护。若中途崩溃，就从已提交模式和进度恢复，而不是按已扫描百分比推断市场已经安全。

## 第 6 层：回滚是新决定，不是删除历史

**面试官：** 分批后发现 V2 参数填错，需要恢复 V1，已经撤掉的订单和已经发生的成交怎样办？

**面试者：** 回滚应提交一个新的激活事件，例如 V3 引用经确认的 V1 参数内容，排在当前已提交结果之后，而不是把数据库恢复到旧快照。V2 期间的成交、费用和双方账本都保留，已撤的 O1 也不自动复活，否则用户可能在不知情时重新获得交易义务。新参数只能影响后续重评和新请求；若用户要重新挂单，应使用新的意图身份。V3 仍须经历屏障、重算和开放，不能因为内容曾经合法就跳过当前仓位检查。审计上保留 V2、V3 的原因与生效序号，才能区分配置修正和经济冲正。

## 第 7 层：价格与配置交错怎样保证回放一致

**面试官：** 回滚也是新事件，如果恰好夹着价格更新，怎样保证另一台机器重放时不会算出另一套风险结果？

**面试者：** 假设价格 M2 在二百零一激活、V3 在二百零二激活、订单在二百零三裁决，它必须使用 M2 和 V3，而不是按机器加载文件的先后决定。决策还要保存状态版本、原始配置摘要、数值规则以及价格质量证据，回放读取对应内容，不拿当前墙钟重新判定历史价格年龄。缺失配置正文或遇到不支持的计算版本时应保护停处理，不能猜成默认百分之十。工程版本也要能解释旧事件语义；单有一个 configId 而无法还原阈值、舍入和门禁，并不足以证明历史决策可复算。

## 第 8 层：上线前怎样验证，不靠生产灰度赌结果

**面试官：** 既然历史必须可复算，你会怎样证明新档位和激活流程正确，又不虚构一组“上线后没问题”的结论？

**面试者：** 我会先为 V2 写独立参考计算，检查六千边界、最大数量、舍入与溢出，并用 O1 的七百五十、部分成交后仍七百五十、撤后五百作为手推预期。再构造激活前后各一笔命令、分批中崩溃和回滚事件，核对未重评订单不能成交、旧成交不可撤销、同序重放一致。影子计算只能比较结果，不能发出第二份成交或预占；同一市场不能让不同机器各用一版权威参数所谓灰度。只有实际运行并记录输入、版本和差异后才能报告验证结果，这里给的是方法与预期，不宣称测试或性能已经通过。

## 收束：机制、易错边界与反例

- **讲透的机制：** 配置内容不可变，激活事件确定生效序号；分档语义、精度和保守预算一起版本化。大规模重评靠先失效的屏障保障，而非后台扫描速度保障。
- **最易答错：** 分段费率不是整档费率；保证金基数不等于可达净敞口；配置回滚是新事件，不回滚成交、不复活撤单，也不改变专用现金桶的账务含义。
- **反例检验：** V2 下 O1 的 `X=7,000、L=0、R=750`。限额收紧后若它还能凭 V1 标记成交，或 V3 回滚后自动重新挂出已经撤销的一 ETH，就违反执行资格或身份终态约束。分批重评中断后应保持保护，不能仅恢复 activeConfigId 就开放。

以上为手工推演和待执行的验证方法；不新增单题工程，专题唯一 MVP 保留在总览。
