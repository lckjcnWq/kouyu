# 大问题 3：初始保证金和开仓空间怎样精确计算？

<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| ETH-USDC 线性永续 | 用 USDC 计算 ETH 合约价格变化产生的盈亏，不交割 ETH。 | 名义价值不是本次必须从钱包支付的现货本金。 |
| 逐仓、专用现金 | 一个仓位风险单元有自己的资金范围。 | 本文的 B 只认该逐仓现金桶，其他钱包资金不会自动支持开仓。 |
| q、abs(q)、sign(q) | q 带方向；abs 取不带正负的大小；sign 取方向，多为正、空为负。 | 多仓 q=2，所以绝对数量为 2；同一公式也能表达空头持仓的盈亏。 |
| C、均价 | C 是剩余持仓入场成本，均价是每单位平均成本。 | 两个 ETH 均价 2,000，对应 C=4,000，不代表从现金扣掉四千。 |
| B、已实现损益 | B 是已记账现金；平仓等已确认盈亏记入 B 后叫已实现损益。 | 历史已入账盈利不能再加一次，否则凭空增加权益。 |
| U、未实现盈亏 | 当前估值与持仓成本相比的账面盈亏，还没因平仓全部变成现金。 | Mark 2,000 与均价相同，所以主例 U=0。 |
| Mark | 为风险和盈亏估值使用的参考价格。 | 它不是用户一定能成交的价格；限价与它不同时还要留价差缓冲。 |
| Equity / E、权益 | 现金加当前未实现盈亏，衡量账户在该估值下的净值。 | 主例 E=1,000；持仓浮盈可能改变 E，却不等于现金同步到账。 |
| IM / r、初始保证金 | IM 是建立风险所需保证金要求，r 是本例计算它的比例。 | 本文教学 r=10%，原持仓 IM=400；保证金不是手续费。 |
| MM / h、维持保证金 | MM 是维持持仓的最低要求，h 是相应比例。 | 本例 h=5%、MM=200；它不等于 IM，也不是可用额度。 |
| 杠杆 | 用相对少的保证金承担当量更大的合约风险。 | 同一数量的盈亏由数量和价格差决定，不能算完后再乘一次杠杆。 |
| b、s、G | b、s 是普通买卖单剩余量合计；G 把持仓绝对数量与两侧普通余单全部相加。 | 本文刻意保守地预算资金，不先抵消相反方向的普通订单。 |
| p、L、不利价差缓冲 | p 是限价；L 为可能按不利于 Mark 的价格成交预留损失空间。 | 买 1.5 的限价改到 2,100 时，较 Mark 多出的 100 对应 L=150。 |
| R、总需求与增量 | R 是持仓加活动订单的总风险预算；增量只是接纳某单前后的差。 | O1 同价时 R=700、增量 300，不能在扣 700 后再扣一次 300。 |
| Available / E−R | 本文定义的剩余风险准入空间，不是钱包余额或可提现金额。 | 主例挂 O1 后为 300；不能把可用空间和权益都叫“余额”。 |
| Q*、Qmax | Q* 是订单可能造成的最大绝对仓位，Qmax 是允许上限。 | 加 O1、O2 后 Q*=4.5，超过教学上限 4，即使资金够也拒绝。 |
| Nmax、名义敞口 | 名义敞口用参考价格把风险数量折成 USDC，Nmax 是其上限。 | 拟 4.5 ETH 对应 9,000，超过本例 8,000；它不是需要支付的本金。 |
| POSITION_LIMIT | “仓位限额失败”的原因码。 | O2 不是保证金不足，补钱也不能自动越过硬限额。 |
| Reduce-Only / RO、可平量 | RO 只能减少现有仓位；可平量是最多还能关闭多少仓。 | 单独分配额度并逐笔防止反手，不给普通单预先抵扣 R。 |
| NORMAL、REDUCE_ONLY、CANCEL_ONLY | 分别为普通交易、受约束只减仓、禁止新成交的保护模式。 | 有效价格下的减仓与价格无效后的停成交不是一回事。 |
| scale、定点整数 | 先约定小数位，把金额和数量变为整数保存与运算。 | 不能靠 float64 显示出来“差不多相等”决定临界通过。 |
| ceil、floor、溢出 | ceil 向上取整，floor 向下取整；溢出是数超过类型容量后失真。 | 需求向上、可认权益向下，中间乘法也要足够宽。 |

## 把整篇文章压缩成一个故事

甲有一千 USDC 逐仓现金，持多仓两个 ETH，均价和 Mark 都是两千，所以没有浮盈亏，权益也是一千。按本文教学比例，持仓初始保证金要求四百、维持保证金二百。它们是不同风险门槛，不是两笔手续费，更不是一千现金里已经发生的损失。

甲想买一点五个，限价两千。系统把现仓和余单一起算，总需求七百，可用风险空间三百。若把限价单独改成两千一百，就还要预留一百五十的不利价差，总需求八百五十。后来再申请买一个，即使拟总需求九百有权益覆盖，最坏仓位四点五仍超过四个的限额，必须拒绝。

第一单同价成交零点五后，持仓需求五百、余单需求二百，总量仍七百；撤掉余单才降到五百。这里只因同价零费用而现金不变，不能推广成所有成交都不影响权益。算式还必须固定精度与舍入，且不能把总需求和订单增量再扣两次，更不能把未成交 RO 当作保证会减险的信用。

**流程位置与核心机制：** 本题深入交易前的权益与资金准入计算。它不替代保证金模型专题，不将简化教学公式说成所有交易所的规则，也不重复仓位限额算法。

沿用 README 基线。起点 q=2 ETH、C=4,000 USDC、B=1,000、Mark 2,000，r=10%、h=5%；不把历史毛损益重复加进 B。

## 第 1 层：权益、保证金和现金怎样区分

**面试官：** 下单前要计算 Equity、IM 和 available，你会怎样定义它们？

**面试者：** 本教学逐仓账户的账本现金是 B，已经包含已入账实现损益、手续费和资金费；未实现盈亏为 `U=sign(q)×(abs(q)×Mark−C)`，因此 `E=B+U`。持仓初始保证金为 `ceil(r×Mark×abs(q))`，维持保证金用 h 单独计算。这里的可用风险空间是 `E−R`，R 包含持仓和活动订单保守风险需求，不等于账面现金，也不等于提现额度。主例 U=0、E=1,000、IM=400、MM=200。若拿现金 B 再加已入账的历史已实现盈亏，或把未实现盈亏当可立即转出的现金，就会重复计入或错误放大可用额度。

## 第 2 层：开仓订单为什么不能只加剩余量 IM

**面试官：** O1 买 1.5 ETH @2,000，按 10% 算不是增加 300 IM 吗？

**面试者：** 在固定 Mark、成交价不劣于限价、无费用的主例里，R 从 400 增到 700，差额确实是 300。一般限价单要考虑实际成交价相对 Mark 的不利差异。买单最差合法成交价按限价 p，新增损失缓冲 `qty×max(p−Mark,0)`；卖单是 `qty×max(Mark−p,0)`。本专题保守需求 `R=ceil(r×Mark×G)+ceil(L)`，G 是当前仓位与普通订单毛数量上界，L 是各活动限价单的不利价差之和。它不是所有产品的普遍公式，但比只算当前仓位 IM 明确多覆盖一项。O1 与 Mark 同价，L=0；若只把它的数量变成 1.5，限价提高到 2,100，L=150，R 就是 850，不是 700。

## 第 3 层：资金准入和数量限额如何分别裁决

**面试官：** O2 申请 1 ETH 后，E=1,000 仍大于计算出的 900，为什么还要拒绝？

**面试者：** 因为预算和限额是不同约束。加入 O1 与拟 O2 后，最坏数量 `Q*=2+1.5+1=4.5 ETH`，高于 `Qmax=4`；按 Mark 计名义金额是 9,000，也超过 `Nmax=8,000`。资金公式给出拟 R=900，保证金这道门是通过，但产品限制的数量和名义额两道门失败。只有所有相关门槛都通过才接纳。理由应具体报告，例如 `POSITION_LIMIT`，而不是笼统回一个“保证金不足”。这也意味着扩大仓位的产品风险可以先于资金不足发生，不能用加钱来绕过明确的仓位上限。

## 第 4 层：成交和浮盈变化后 E、R 如何更新

**面试官：** O1 成交 0.5 后，剩余订单和仓位同时变化，怎么算新需求？

**面试者：** 成交后 q=2.5，O1 剩余 1 ETH。固定 Mark 与成交价均为 2,000，现金仍为 1,000，U=0。持仓 IM 是 500，剩余普通买单占用 200，总 R=700；原总风险没有因订单字段减少而在中间凭空释放。若 Mark 上涨到 2,100，且成本均价仍 2,000，仓位 U 会增加 250，使 E=1,250；但名义限额与保证金计量也需要按新 Mark 重算。能否允许组合内未实现盈利全部支持新开仓是产品政策，本文选择纳入逐仓权益但保留数量和名义硬限额。计算必须使用同一个新 Mark 版本，不能只更新 E 而沿用旧的 R。

## 第 5 层：动态限额和存量超限会怎样

**面试官：** 市场价格变化导致现有 2.5 ETH 名义价值从 5,000 升到 5,500，或者配置把 Qmax 从 4 调到 2，怎么处理？

**面试者：** 价格上涨带来的名义敞口被动变化不能抹去历史成交，也不意味着账户已违反当初规则；但后续普通开仓必须按新 Mark 检查，并可能拒绝。参数 V2 收紧 Qmax 则要定义生效点与存量策略：本教学在配置激活后暂停相关开仓，按确定订单序列重评挂单，撤掉不能继续支持的普通订单；现有仓位处于 `REDUCE_ONLY` 或处置评估状态，强平不在本母题执行。配置不能回写历史结果。新增保证金可能改善资金 R 的可承受性，却不能解决硬数量限额。产品应单列“被动超限”和“主动新风险”状态，避免拿一个布尔值使存量仓突然失去解释。

## 第 6 层：为什么活动订单预算会重复扣 IM

**面试官：** 你用 G 把未成交订单和仓位相加，然后又给每张订单保留一份 IM，会不会双重占用？

**面试者：** 会，所以数据模型要区分总需求和增量占用。R 已经由仓位加全部未决订单计算出来；账户风险可用空间判定为 E−R，不再额外减一次独立 `orderIM`。展示层可拆 `Rpos` 和 `Rorder`，但要满足它们和 R 的定义一致，且成交转换时总量连续。举例 O1 前 Rpos=400，接纳后 R=700、订单增量为 300；若再算 `E−700−300`，就错误把可用说成 0。对于价格变化造成的 L，也要清楚它是否包含在 R，而不能既计入 R 又单独再扣一遍。

## 第 7 层：RO 为什么不能进入普通的资金门槛

**面试官：** Reduce-Only 能减仓，为什么不把它也简单按候选剩余量增加 R？

**面试者：** RO 的约束目标是只允许风险不扩大的成交，不是开仓预算。若对当前多仓发卖出 RO，单纯把卖单数量加进 `s` 会把它当成可能反向开仓的普通单，既过度拒绝，也混淆语义；反过来若完全相信它“只减仓”，多个 RO 共享可平量就可能超卖。方案是 RO 独立占用 `abs(q)` 可平量额度，不给普通订单抵扣保证金；每笔执行再检查方向、余量和当前仓位不穿零。实际成交还须通过价差健康门禁。权益或价格无效时进入 CANCEL_ONLY，不拿 RO 标签绕开无效风险输入。

## 第 8 层：数值和舍入怎样确保临界判断稳定

**面试官：** 上述公式在 Go 里直接 float64 计算，接近阈值可能只差很小，有什么风险？

**面试者：** 金额和数量用带 scale 的整数，费率用定分母有理数；乘法前检查范围，或以宽整数计算中间乘积。保证金需求向上取整，认可权益向下取整，方向是不给账户虚增风险空间。还要固定先乘后除、金额最小单位与负数规则，避免 Go 与离线审计版本得出不同边界。超限时用精确的不等式，而不是比较展示格式化后的两位小数。测试重点是 Qmax 恰好 4 与 4 加一个最小数量单位、E 恰等 R 与差一个最小金额单位、极值乘法溢出；发现溢出或未知精度必须拒绝裁决，而非 wraparound。

## 收束：IM 计算不是风险准入的全部

- **讲透的机制：** 权益、持仓 IM、活动订单保守需求、硬限额分别定义并只计一次。
- **易错边界：** 已实现损益已在 B；RO 可平额度不是普通订单保证金；足够权益不覆盖 Qmax/Nmax。
- **反例：** 对 O1+O2 只检查 `1,000 >= 900` 会放行一个 4.5 ETH 的最坏仓位，违反 4 ETH 硬限额。验证时应让每个门槛独立给出结果和原因。
