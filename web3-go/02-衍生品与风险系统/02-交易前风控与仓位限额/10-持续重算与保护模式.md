# 大问题 10：价格和经济事件怎样触发持续重算与保护？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| ETH-USDC 永续、单向逐仓 | 按 ETH 价格差计算 USDC 盈亏，一个净仓使用专用资金承担风险。 | 不交割 ETH，不支付现货本金，外部资金不会自动支持本仓。 |
| q、C、B | q 是带方向的持仓，C 是剩余入场成本，B 是已记账现金。 | 原始分支为多 2、成本 4,000、现金 1,000，别与部分成交后的分支混用。 |
| U、E、Available | U 是未实现盈亏，E 是现金加 U；本文 Available 指 E 减总需求后的风险空间。 | 现金仍 1,000 时，浮亏可以使 E 只剩 600，可用空间更不是现金余额。 |
| IM / r、MM / h | IM 是初始保证金要求，MM 是维持保证金要求，r/h 是其比例。 | 本文教学比例为 10%/5%，保证金不是手续费；低于 IM 不自动等于强平。 |
| Mark、价格版本 | Mark 是风险估值参考价，版本标识选用的那份价格。 | Mark 跌到 1,800 要重算，但它不承诺订单按 1,800 成交。 |
| G、L、R | G 是持仓与普通余单毛数量，L 是不利限价差缓冲，R 是两项构成的总需求。 | 原 O1 未成交时跌到 1,800，基础需求 630 加缓冲 300，共 930。 |
| O1、remaining | O1 是买 1.5@2,000 的订单，remaining 是还能执行的剩余数量。 | 已成交 0.5 的分支 q=2.5、余 1，不能与未成交分支 q=2 混算。 |
| 存量重评、事件触发 | 已有仓位或挂单在价格、资金、规则变化后重新判断。 | 不是首次通过后就不再检查，也不能只等定时扫描。 |
| 资格失效、执行门禁 | 旧批准已不能支持当前成交；门禁负责在实际执行前阻断。 | 先让旧订单不可执行，再重评，避免慢扫描期间继续增险。 |
| Qmax、Nmax、被动超限 | Qmax 限数量，Nmax 限按 Mark 算的金额；价格变化也会让存量跨限。 | 2 ETH 在 Mark 5,000 时名义 10,000，尽管盈利仍超过教学上限 8,000。 |
| NORMAL | 输入和规则支持时允许普通交易的状态。 | 不是进程一重启或网络一恢复就默认回到此模式。 |
| REDUCE_ONLY、RO | 前者是只允许受约束减仓的模式，后者是不能反手的减仓订单。 | 反向普通卖单不等于 RO；有可信价格时仍须检查方向、数量和健康缓冲。 |
| CANCEL_ONLY | 禁止一切新成交，只保留关闭与安全管理动作。 | 价格无效或无法证明经济状态时，不能让 RO 借“减仓”标签绕过。 |
| H、H'≥H | H 是权益减持仓 MM 的健康缓冲；撇号表示候选成交后，要求缓冲不下降。 | E=1,000、MM=200 时 H=800；不是可用开仓额度。 |
| 可平量、不穿零 | 已分配给 RO 的减仓数量，执行不能超过现仓而反手。 | 数量通过还不够，差价格可能让 H 下降，仍须拒绝。 |
| 资金费、经济输入缺口 | 资金费是永续持仓按规则发生的支付；缺口表示应记经济事实还不完整。 | 缺失应扣 900 的输入不能假设为零，保护停机也不能抹去这笔义务。 |
| 补保证金、账务身份 | 将额外资金真实转入逐仓现金桶，并用唯一身份防止重复入账。 | 用户声称已补或别处余额足够，都不能先改善本仓 E。 |
| 共同顺序、appliedSeq | 所有相关命令统一定序，appliedSeq 记录已处理位置。 | 经济输入缺口不能跳过；后到撤单可先受理，不能假称已越序执行。 |
| 事务 T、价格激活 | T 共同保存相关业务变化；激活让新价格正式成为裁决依据。 | 输入变化、风险重算和订单资格处理要有确定生效点。 |
| 保护屏障、有界批次 | 先提交关闭执行的屏障，再分成大小受控的任务重评。 | 大市场可分批，但尚未覆盖的旧单不能继续成交。 |
| 处置请求、强平 | 处置请求是带证据交给负责方评估；强平是另有权限的实际执行流程。 | E=100、MM=200 需要处置评估，不等于已经强平成交。 |
| 重放、价格质量证据 | 按原顺序及原时间、质量结论恢复历史状态。 | 不拿当前机器时钟重判历史价格，也不把恢复旧事实当新成交许可。 |

## 把整篇文章压缩成一个故事

甲有两个 ETH 永续多仓、成本四千、现金一千，另挂买一点五，初始总需求七百。这张单还没成交，Mark 就从两千跌到一千八百：现仓浮亏四百使权益只剩六百，挂单又可能按两千买入，基础需求六百三十加价差缓冲三百，总计九百三十，旧批准已经撑不住。

系统先关闭旧执行资格，再按新价格撤掉挂单，需求降为三百六十，现金仍一千，不是退回现金。另一个后续分支里，价格涨到五千，甲虽然权益升到七千，两个 ETH 的名义额却到一万，仍超过八千上限，只能保护并限制新风险。可见盈利也不保证准入。

如果来源价格失效，就连 RO 新成交也暂停。价格恢复后，RO 还要比较真实成交后的健康缓冲，不能只看数量下降；缺失的资金费同样要补齐，不能当作零。低于维持保证金只触发处置评估，不宣称已强平。分批重评或重启期间都先保留屏障，确认覆盖当前状态后才开放，不能恢复网络就盲目交易。

**范围前提：** 沿用总览的 ETH-USDC 线性永续、单向逐仓、零费用与资金费主例。初始 `q=2、C=4,000、B=1,000、Mark=2,000`，`r=10%、h=5%、Qmax=4、Nmax=8,000`。O1 买入 `1.5@2,000`，部分成交 `0.5` 后 `q=2.5、remaining=1、R=700`，撤余量后 `R=500、B=1,000`。单市场共同权威顺序及同库业务事务 T 不变；价格变体明确标出起点。完整公式、RO 分配和精度以 README 为准。

## 第 1 层：已有准入结果为什么还要重算

**面试官：** 价格和经济事件怎样触发持续重算与保护，订单既然已经通过风控，为什么不能一直按原资格成交？

**面试者：** 准入只证明当时那组输入支持订单，不是永久担保。O1 挂单时权益一千、需求七百；成交零点五后，仓位增至二点五、余量减至一，总需求仍是七百，并没有释放掉原来全部订单占用。价格、现金或参数随后改变，旧预算就可能失效。我会把这些变化放入市场共同顺序，在事务 T 中更新输入、重算风险并撤销失效普通订单，相关成交仍共同更新双方仓位和账本。定时扫描只负责发现遗漏，不能替代事件触发和逐笔执行门禁，否则两次扫描之间，旧挂单仍能绕过新约束。

## 第 2 层：价格下跌怎样吃掉旧订单预算

**面试官：** 你说旧预算可能失效，回到 O1 刚挂单、尚未成交时，Mark 从 2,000 跌到 1,800，具体怎么算、先做什么？

**面试者：** 这个分支仍是仓位二、成本四千、现金一千。新价格下未实现亏损四百，权益只剩六百；毛数量三点五的保证金是六百三十，买单限价高于 Mark 的不利价差缓冲另有三百，所以总需求九百三十，不能继续信任原来的七百。我会先使旧资格不可执行，再在价格激活的事务中确定撤销 O1；撤后只剩仓位需求三百六十，权益仍六百、现金仍一千。价格激活与后续撮合按顺序裁决，不允许先用新价格展示亏损，却继续凭旧预占成交，也不能把撤单解释成退回三百现金。

## 第 3 层：权益增加也可能被动超限

**面试官：** 上一步撤单后已经没有挂单，如果 Mark 接着涨到 5,000，权益改善了，为什么还可能需要保护？

**面试者：** 此时仍持有二个 ETH，未实现盈利六千、权益七千，但仓位名义敞口已是一万，超过八千上限，说明资金充足与限额通过是两道检查。这属于价格变化造成的存量被动超限，不是把过去合法成交改判为失败。我会关闭普通增险资格，进入只减险的保护状态，并记录价格版本和超限原因；不能因为权益上涨就恢复普通单。有效价格下，可以评估不扩大绝对仓位的 RO，但仍须满足可平量和健康缓冲门禁。若有存量普通订单，则按确定策略撤掉，不能靠一笔未来可能成交的反向单承诺风险一定下降。

## 第 4 层：没有可信价格时为什么连 RO 也不能盲放

**面试官：** 你允许有效价格下减险，如果随后价格源失效，但用户急着提交 RO 平仓，为什么不先成交再补价格？

**面试者：** 因为只减数量不等于只减风险，没有可信 Mark 就无法可靠判断成交损失和健康缓冲。我会进入 CANCEL_ONLY，阻断普通单和 RO 的一切新成交，允许权威关闭及安全管理动作；不能拿最后一个价格版本号冒充价格仍新鲜。价格接收年龄、处理积压和源质量都要参与门禁，裁决保存 decisionTime、priceTime、质量与原因。若新价格已排队而激活落后，也先失效关闭，不能继续消费旧资格。恢复必须等有效价格命令按顺序生效并完成必要重评，不是网络恢复或收到一条行情推送就立即开放。

## 第 5 层：价格恢复后 RO 怎样证明没有越平越危险

**面试官：** 假设有效 Mark 恢复为 2,000，仍是原来二个多仓和一千现金，怎样判定一笔 RO 卖单真的可以成交？

**面试者：** 我先检查方向是卖、获分配可平量足够且实际成交不穿零，再比较实际价格下的健康缓冲。当前权益一千、维持保证金二百，H 是八百。若卖出零点五、成交价一千九百，权益减少五十到九百五十，剩余仓位一点五的 MM 是一百五十，成交后 H 仍八百，可以通过；若价格是一千八百九十，权益变九百四十五，H 只有七百九十五，就不能放行。该检查看实际执行顺序和双方最新状态，不复用上一笔 H。RO 不需要满足普通开仓的 E≥R，但价格无效、方向错误或可平量不足时仍不能成交。

## 第 6 层：资金费输入缺口不能当作没有扣款

**面试官：** H 依赖权益，如果应扣资金费的输入缺了一段，账面暂时仍有一千，能不能先按现有余额支持 RO 或跳过这笔事件？

**面试者：** 不能把未知经济义务当成零。独立看扣款前的二个多仓，若缺失资金费实际要扣九百，真实现金和权益就只有一百，和当前显示的一千完全不同。我会标记经济输入不完整并保护停成交，补齐来源序号、金额与唯一账务身份后再应用。如果缺口就在下一条经济命令，appliedSeq 不能跨过去；后续撤单可以先持久受理，却不能伪称已经越序完成。恢复输入后，扣款、分录及风险状态同事务提交，再评估是否开放减险。保护可以先阻断执行，但不能用删除事件、跳序或撤单把已存在的经济义务抹掉。

## 第 7 层：低于维持保证金怎样交给处置方

**面试官：** 补齐后果然只剩权益 100、MM 200，持续重算模块要不要立即标记“已强平”，RO 又会不会挡住清算？

**面试者：** 我只把它判为需要风险处置评估，不凭一条告警宣称已经强平。请求应带市场序号、仓位二、现金一百、价格和配置身份，以及 E=100、MM=200 的证据，处置方执行前还要复核，因为补保证金或先前减仓可能已改变状态。有效价格下，普通 RO 若卖出零点五且成交于 Mark，权益仍一百、MM 降到一百五十，H 从负一百改善为负五十，仍可按规则评估。协议清算则是独立授权路径，有自己的价格保护和破产规则，不能拿用户 RO 的门禁替代它，也不能把提交处置请求当作处置完成。

## 第 8 层：大市场分批重评与重启怎样不留下窗口

**面试官：** 你要求恢复前完成重评，如果活动订单太多必须分批，途中又崩溃，怎样避免尚未扫描的旧订单继续成交？

**面试者：** 我先提交保护屏障，使旧版本资格全部不可执行，再以有界批次形成顺序命令，每批各自用事务 T 保存重评结果与进度；不能跳过未完成命令推进处理位置。批次根据账户状态版本计算，期间发生补保证金或减仓，就重新裁决受影响项，而非照搬扫描开始时的结果。只有追平目标版本并确认没有未覆盖变化，才提交重新开放事件。崩溃后从数据库恢复模式、进度与已提交结果，提交未知则先查清，绝不默认 NORMAL。回放使用原裁决证据，不重新读取当前墙钟，否则同一历史可能重放出另一种保护结论。

## 收束：机制、易错边界与反例

- **讲透的机制：** 持续重算改变的是存量订单的执行资格；输入生效、资格失效、重评及重新开放都有确定顺序。风险占用不是现金扣款，经济事件也不会因保护停机而消失。
- **最易答错：** 权益上涨仍可能名义超限；低于 IM 不自动等于强平；价格无效必须 CANCEL_ONLY；有效价格下 RO 还要检查方向、可平量及 `H'=E'−MM'≥H`。
- **反例检验：** O1 尚未成交时激活 Mark 1,800，预期 `E=600、R=930`，旧单不可继续成交；撤后 `R=360、B=1,000`。另把价格变为无效，即使卖单标记 RO 也不应新增成交。若分批重评崩溃后未扫描订单仍能匹配，说明保护屏障没有覆盖执行端。
