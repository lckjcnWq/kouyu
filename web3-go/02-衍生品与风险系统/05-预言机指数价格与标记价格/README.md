## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
| --- | --- | --- |
| 保证金、杠杆、逐仓 | 保证金是抵押现金；用较少现金承受较大仓位叫杠杆；逐仓限定这一风险单元。 | 价格影响这笔仓位的权益，不把全仓、多抵押或反向合约公式混进来。 |
| U、E、维持保证金、强平 | U 是浮盈浮亏；E 是现金加 U；维持保证金是继续持仓的最低要求。 | 主例 U=12、E=512，维持要求 200.6 USDC；权益低于要求才进入强平复核。 |
| ETH-USDC-PERP、线性永续 | 以 ETH 为标的、USDC 计盈亏、没有固定到期日的合约。 | 数量按 ETH、价格按 USDC/ETH，合约乘数 1；案例不代表真实平台规则。 |
| Last／Index／Mark、I／M | 最近成交事实／外部参考／风险估值；I、M 分别指指数与标记价。 | 主例 I=2,000、M=2,006，Mark 不保证实际成交，也不直接写账本现金。 |
| Oracle、预言机、信任边界 | 把外部事实送入系统的机制，以及系统相信哪些主体和证据。 | 不是预测未来；主线相信受控链下配置采集，不默认拥有链上去中心化保证。 |
| 源、独立组、共同上游 | 源是配置的数据主体；组近似描述共同依赖；多个入口可能背后同源。 | 多源不等于独立，至少三源三组也不是抗任意多数串谋的证明。 |
| 中位数、离群、等权 | 居中参考、偏离过大的输入、每个合格源同等权重。 | R1 先筛时间，再一次中位数筛 1% 离群，筛后查三源三组，最后平均。 |
| bps、ppb、S=10^6 | 基点、十亿分之一比例、价格存成整数的倍率。 | 100 bps 是 1%，3,000,000 ppb 是 0.3%；价格最小单位为 0.000001。 |
| bid／ask、mid、盘口深度 | 买卖一、两者中间价、挂着多少买卖量。 | 本例年龄最多 500 ms、每侧至少 10 ETH，只证明采样资格，不保证未来成交。 |
| 相对基差、B_t、C_t | 合约相对指数的比例偏离、窗口均值、均值限幅后结果。 | 连续 30 个一秒点先平均再限在 ±0.5%，不平滑指数的真实急跌。 |
| floor、trunc_zero、宽整数 | 向下取整、向零截断、避免中间乘积溢出的整数计算。 | 价格与有符号基差舍入不同，不用浮点近似替代边界规则。 |
| sample_valid、完整窗口、TWAP | 单点证据合格、连续样本齐全，以及通常按时间加权的价格概念。 | 单点可在受限期积累；本例是 30 点离散均值，不冒充连续积分型 TWAP。 |
| source_time、received_at、T | 源报价时间、本地接收时间、固定采样时刻。 | 刚收到不等于新鲜，源年龄按 T 检查 0—2,000 ms，截止位置另证是否已接纳。 |
| usable_until、committed_at | 原包授权截止，以及持久提交时间。 | 期限固定 T 后 1,500 ms，不随晚提交延长；末端最老源可能已有 3,500 ms。 |
| price_id、round_seq、流身份 | 稳定价格身份、市场连续轮次、所属价格流。 | 重发或切主不换业务身份，版本变新也不意味着源数据变新。 |
| quality、FULL／DEGRADED_BASIS／INVALID_INDEX | 数据证据完整、基差条件不足、指数无效三种质量。 | 基差不足可有候选 M=I；指数无效则两价为空，旧好价不补位。 |
| mode、ACTIVE／LIMITED／HALTED／RECOVERING | 正常、受限、风险价停用、恢复观察四种权限状态。 | 质量好不等于权限已恢复；非 ACTIVE 暂停自动强平，并承认坏账代价。 |
| Reduce-Only、撤单、实到账补款 | 只减已有仓位、撤未执行订单、以真实入账增加抵押。 | 非 ACTIVE 可按各自规则处理，减仓须执行裁剪、不反开仓、不顺带划出。 |
| owner、goroutine、背压、原子快照 | 市场负责人、Go 并发任务、过载限流、一次读取完整状态。 | 本地单写和完整可见不代替持久化；中间输入合并须有明确等价契约。 |
| 事务、checkpoint、Outbox／Inbox | 共同提交、处理进度、生产待发／消费应用记录。 | 价格窗口模式进度共同生效，至少一次交付靠幂等收敛，不等于全链只执行一次。 |
| 消费水位、在途敞口、最终复核 | 已处理位置、未完成经济义务、产生效果前再查资格。 | 组合可解释的仓位现金版本，已知限制立即门控，不拿旧通过回执执行。 |
| 恢复迟滞、任期围栏、RPO | 连续好轮次后再开放、拒绝旧主写入、故障可能丢失的已确认数据边界。 | 完整恢复连过三轮 FULL；任期不重置轮次，本机 ACK 不等于跨机零损失。 |
| R1／R2、影子计算、应急审计 | 规则版本、新规则旁路试算、临时能力的受控证据。 | 新规则从明确位置生效并重建窗口，人工无无限改价权，回滚不删除历史。 |
| 链上报告、EVM、确认／最终性、MVP | 报价证据、合约执行环境、链状态稳定阶段、最小计算演示。 | 第 11 题另换链上边界，提交不等于最终；本页唯一 MVP 仅计算候选，不提供生产风控授权。 |

## 把整篇文章压缩成一个故事

小林拿 500 USDC 保证金持有 2 ETH 多仓。价格下跌会让浮亏侵蚀权益，低于维持要求才进入强平复核，所以风险价不是普通行情数字。主例按 Mark 2,006 算出浮盈 12、权益 512、维持要求 200.6，本轮不强平；现金仍为 500，Mark 也不承诺平仓成交。

系统通过预言机引入外部事实，先核身份、单位、源时间和截止位置，再排陈旧及离群源、检查独立组，得到指数 2,000。每个点用自己的指数和盘口算基差，连续 30 点先平均再限幅，形成 Mark；平滑不能洗掉真实急跌。

Go 的市场 owner 按序处理，窗口、完整价格包、模式和待发记录共同提交，风险端去重追赶，结合仓位现金及在途义务复核。不可用就明确收紧，不沿用旧价；期限固定，版本新也不能给旧数据续命。

故障恢复靠真实样本、连续完整轮次与主备围栏，规则升级靠版本、审批和审计，人工不能无限改价。链上分支另查签名域、执行顺序和重组依据，提交、确认、最终性分开。最后用独立算例与故障方案验证；本页 MVP 只算候选，不冒充可运行的生产风险系统。

## 一、文字全流程：外部报价怎样成为可执行的风险输入

### 1.1 讨论基线与适用范围

本专题采用**链下托管、链下订单簿撮合与记账的线性 USDC 永续合约**，市场为 `ETH-USDC-PERP`。价格系统由 Go 服务实现；这是教学设计，不是任何平台的实际协议规则。

- 数量单位为 ETH，价格单位为 USDC/ETH，合约乘数为 1。盈亏案例采用单向净持仓、逐仓风险单元，不混用现货交割、反向合约、全仓或多抵押品公式。
- **最新成交价**来自本市场已经确定的成交，用于成交行情等场景；**指数价格**来自多个独立外部现货市场的合格报价；**标记价格**由指数与受限、平滑的本地基差构造，用于本例未实现盈亏及保证金风险计算。
- **预言机是外部事实进入受信任计算域的机制，不是一条特定的价格公式。** 主基线采用经过鉴权的链下行情适配器，信任运营方的源配置、采集与计算；没有链上签名门槛、交易确认或最终性承诺。
- 主基线不依赖某个命名预言机协议。链上推送／拉取预言机、签名报告、交易链状态机和链重组属于明确改变执行与信任条件后的分支，由第 11 个母题深入。
- 每个市场每秒形成一轮价格裁决。一个市场的轮次、配置变更、模式切换和已提交结果按唯一顺序处理；不同市场可以并行，但共享源和共享抵押品不能因此自动获得账户级一致性。
- 价格变化只更新估值及风险输入，**不改持仓数量、入场成本、历史成交或账本现金**。减仓成交、资金费、手续费和保证金划转仍由各自的权威经济事件驱动。
- 本批只交付一个计算型 MVP，不创建可运行工程，不执行工程测试，不声称验证了生产可用性或性能。

### 1.2 贯穿案例：排除异常源，生成 2,006 的标记价格

所有数值均为教学数据，不是实时市场报价。`T` 是本轮预定采样时刻，时间差均以毫秒表示；接收截止点决定本轮能看到哪些记录，不把源时间戳当作到达证明。

系统已经完成启动验证，前一轮处于 `ACTIVE`，使用规则 `R1`。本轮外部源的报价已经完成身份、资产、计价币和精度标准化：

| 源 | 报价（USDC/ETH） | 相对 T 的报价年龄 | 本轮判断 |
|---|---:|---:|---|
| A | 1,998 | 100 ms | 新鲜，进入初筛 |
| B | 2,000 | 120 ms | 新鲜，进入初筛 |
| C | 2,002 | 80 ms | 新鲜，进入初筛 |
| D | 2,400 | 100 ms | 新鲜，但后续作为离群源排除 |
| E | 2,001 | 5,000 ms | 超过 2,000 ms，按陈旧排除 |

本例五个源属于五个不同的独立性分组。独立性分组与源列表由配置固定，不因收到更多连接或更多消息而增加票数。

1. 初筛保留 A、B、C、D，中位数为 `(2,000 + 2,002) / 2 = 2,001`。
2. 相对该中位数偏离超过 1% 的报价排除。D 偏离约 19.94%，不进入最终指数；A、B、C 均保留。
3. 合格源与独立分组均不少于 3，按剩余源等权平均，指数 `I = (1,998 + 2,000 + 2,002) / 3 = 2,000`。
4. 本地买一／卖一为 2,005／2,007，两侧挂量各 20 ETH，盘口年龄为 100 ms，满足本例盘口资格；中间价为 2,006。当前样本的相对基差为 `2,006 / 2,000 − 1 = 0.003`。
5. 本轮及此前 29 个一秒采样点的相对基差都为 0.003，完整窗口均值为 0.003。按 ±0.005 限幅后不变，得到标记价格 `M = 2,000 × 1.003 = 2,006`。

这里是**固定一秒采样、30 个完整样本的离散时间均值**，不是逐笔消息均值，也不冒充连续时间积分型 TWAP。各采样点用当时自己的指数计算相对基差，不能用今天的指数重新解释历史盘口。

### 1.3 价格如何影响一笔持仓业务

假设某逐仓风险单元已经持有 2 ETH 多仓，入场均价为 2,000 USDC/ETH，保证金现金为 500 USDC。本例没有手续费、资金费、订单预留及其他现金变化。

```text
未实现盈亏 U = 2 × (2,006 − 2,000) = 12 USDC
逐仓权益 E   = 500 + 12 = 512 USDC
当前名义价值 = 2 × 2,006 = 4,012 USDC
维持保证金   = 4,012 × 5% = 200.6 USDC
```

本例规则为权益低于维持保证金时进入强平复核，因此本轮不触发。保证金现金仍为 500 USDC，仓位仍为 2 ETH，入场均价仍为 2,000。

5% 只是本例固定维持保证金率，不代表真实产品的阶梯、费用或强平公式。标记价格也不保证用户能按 2,006 平仓；真实平仓成交价决定已实现盈亏，并通过清算与账本结转。

### 1.4 主流程与完成点

```text
用户持有 ETH-USDC 永续仓位，需要持续估值与风险检查
    ↓
外部源适配器接收报价〔源身份、资产、报价、源时间、流序号〕
    ├─ 校验连接／消息身份与允许的交易对
    └─ 标准化计价币、价格单位、精度，记录本地接收时间
    ↓
接入日志可靠接纳输入，并交给该市场的唯一 owner
    ├─ 同源去重、载荷冲突检查、顺序与流重启处理
    └─ 维护每个源截至确定接入位置的最新候选，不按消息条数投票
    ↓
本轮 Tick 进入市场权威序列，固定采样 T、输入截止位置和规则 R1
    ↓
指数计算
    ├─ 按源身份、正值、时间和配置过滤
    ├─ 以中位数筛离群，检查剩余源数及独立分组
    └─ 生成有效指数，或生成明确的“指数不可用”裁决
    ↓
本地盘口与基差处理
    ├─ 检查盘口新鲜度、买卖顺序及本例最小挂量
    ├─ 将当前样本追加到同规则的一秒采样窗口
    └─ 完整窗口：平滑并限幅；不完整：候选标记价格退化为指数
    ↓
质量和市场模式裁决
    ├─ ACTIVE／LIMITED／HALTED／RECOVERING
    └─ 固定价格、质量、模式、证据、规则与有效期限
    ↓
共同提交〔价格快照 + 窗口／源状态 + 模式 + 检查点 + Outbox〕
    ├─ 提交后才作为权威价格结果发布
    └─ 提交前崩溃则不宣称该轮已经生效
    ↓
风险单元接收完整价格包，记录市场价格进度并触发重算
    ├─ 组合权威仓位、现金、在途义务及风险参数版本
    ├─ 在决策与最终执行处校验价格模式、期限和状态版本
    └─ 有效时形成准入／限制／强平复核结果，不直接修改成交事实
    ↓
本例产出 U=12、E=512、“本轮不触发强平”的版本化风险结果
    └─ 查询／推送更新；账本与仓位事实保持不变
```

价格包已提交、风险单元已应用、业务动作已执行和页面已显示是不同完成点。价格服务不遍历并同步锁住全平台所有账户后才确认本轮；风险执行端必须拒绝超期或落后于规定水位的决策，防止传播暂态变成无限期旧价授权。

### 1.5 主要异常分支

```text
源身份、资产或单位错误
    → 接入拒绝并审计；不能先把错误报价混入指数再靠平滑掩盖

输入重复／乱序／同身份不同内容
    → 相同身份与内容不重复更新；旧序号不能覆盖新值；冲突隔离

离群源被排除，但剩余源数和独立性仍达标
    → 继续计算有效指数，记录排除原因；不必因单源失败全市场停机

剩余合格源或独立分组少于 3
    → 本轮指数与标记价格均不可用，进入 HALTED
    → 历史末次好价只供带陈旧标签展示，不刷新时间、不允许据其强平

指数有效，但本地盘口或 30 点基差窗口不合格
    → 候选 M=I，质量 DEGRADED_BASIS，进入 LIMITED
    → 不把“有一个数”当成可以继续一切业务

失效后又出现合格价格
    → 进入 RECOVERING，连续 3 个全条件合格轮次后才恢复 ACTIVE
    → 期间再次失效则中断恢复，不能靠旧包重放累计轮次

价格提交成功，但风险消费者或推送中断
    → 从 Outbox／已提交日志补发；消费者按版本处理
    → 旧包到期后就地收紧权限，不等待消息恢复才停止使用旧授权
```

上述为独立异常变体，不与主案例叠加。对于全市场真实急跌，本模型可能因价格缺失暂停自动强平并增加坏账风险；这是明确的安全取舍，不是声称“停强平就没有风险”。必须告警并进入有权限、有限时、可审计的应急流程。

## 二、核心板块：谁拥有价格，谁有权动资金

| 核心板块 | 决定什么与为什么核心 | 权威状态或产物 | 上下游契约 |
|---|---|---|---|
| 源适配与标准化 | 输入是否是正确资产与单位，时间与身份能否解释 | 原始证据、本地接收时间、标准化记录 | 不把不同计价币天然视为等价，不伪造缺失时间 |
| 指数聚合 | 外部市场参考是否有足够质量与独立性 | 各源候选、剔除原因、有效源集合与指数 | 公开固定阈值与最小集合，失去条件时输出不可用 |
| 基差与标记价格 | 把本地偏离纳入风险估值且限制影响 | 盘口样本、30 点窗口、未限幅／已限幅基差 | 不保证可成交，不靠滤波解决所有操纵问题 |
| 模式与配置 | 数据异常时哪些业务仍有执行资格 | 市场模式、恢复计数、配置生效位置及审计 | 价格、质量和模式一同提交；动作分类由风险规则落实 |
| 交付与恢复 | 已提交版本能否完整恢复并可追溯 | 价格快照、输入位置、规则版本、Outbox、owner 任期 | 不发布未提交结果；旧主受持久写围栏约束 |
| 风险及业务执行 | 哪个价格和经济状态有资格决定动作 | 消费水位、风险快照、执行裁决 | 价格服务不写现金；执行端复核时效、模式及状态版本 |

“一个源失效”与“指数失效”不同；“标记价格存在”与“该价格允许强平”不同；“价格被收到”与“账户已经按它完成风险裁决”也不同。

## 三、核心 20%：决定正确性的机制

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| 三类价格与信任边界 | 规则定义 | 先决定输入可以支持什么结论 | 用成交价强平、把签名当成真实市场证明 | 最新价／指数／Mark、链下与链上权威 |
| 身份、单位与时效 | 采集和初筛 | 数值正确不等于数据可用 | USD 当 USDC、旧价被重贴新时间 | source／receive／sample／expiry 时间、scale、流身份 |
| 独立性与鲁棒聚合 | 指数计算 | 多连接不等于多独立证据 | 共同上游失效、少数源控制全部权重 | 最小源数、独立分组、中位数、阈值、重归一化 |
| 同步样本与受限基差 | 标记价格 | 给本地市场影响明确边界 | 消息洪泛增加权重、错配历史指数 | 等间隔采样、完整窗口、限幅和舍入顺序 |
| 数值、质量和权限原子绑定 | 发布及消费 | 杜绝半新半旧授权 | 收到新数值却继续沿用旧的 ACTIVE 标志 | 完整快照、版本、期限、缺口与本地失效 |
| 单写、可靠提交与确定性恢复 | 全价格链路 | 相同已提交输入应得到相同价格史 | 双主发布、重放结果漂移、已确认轮次丢失 | Tick 日志、源状态、窗口、规则、围栏 |
| 端到端决策证据 | 风险到执行 | 正确价格不能弥补错误状态组合 | 对已补仓账户执行旧强平、追不出用价 | 价格与经济版本、在途敞口、执行复核 |
| 降级、恢复与审计 | 异常闭环 | 防止失效继续放大风险，也避免永久停摆 | 旧价无限授权、恢复抖动、人工作弊无痕 | 动作矩阵、迟滞、应急权限、独立重算 |

不在这里完整重写撮合算法、保证金档位或强平接管；但价格如何影响这些模块的资格，必须有明确接口，不能只写“交给风控处理”。

## 四、共用设计与规则

### 4.1 价格输入与指数规则 R1

1. 每个配置源每轮至多一个有效候选，来源必须在允许列表；本例五源等权。源的经济独立分组由配置提供，至少 3 个合格源且至少 3 个独立分组。
2. 候选必须在本轮输入截止位置前接收，价格为正、单位匹配，且 `0 ≤ T − source_time ≤ 2,000 ms`。本模型拒绝未来时间戳，不隐含容忍负年龄；生产若需时钟误差容忍，应显式改变规则。
3. 本地接收时间不替代源时间：刚收到的旧消息仍然陈旧。源时间本身也依赖源的时钟和诚实性；需监测接收延迟与时间漂移，不能只凭时间字段证明实时性。
4. 对通过初筛的价格排序，奇数取中项，偶数取中间两项均值并按价格最小单位向下取整。相对中位数偏离不超过 100 bps（1%）的源保留；比较采用宽整数交叉相乘，不先做浮点近似。
5. 仅做这一轮确定性离群筛选，不迭代删除直到“碰巧足够一致”。再检查剩余源数与独立分组；不达标则本轮无指数。
6. 达标则对剩余源等权平均，价格向下取整到六位小数。五源模型不能泛化为抵抗任意串谋的安全证明；超过 1/2 的独立源同向作恶，中位数也可能受控。

用中位数筛异常、再等权平均是本教学规则，不是行业唯一算法。加权中位数、截尾均值、流动性权重或置信区间法都需要重新定义权重来源、最小有效集合与失败条件。

### 4.2 基差与标记价格规则 R1

每秒在同一轮固定采样本地盘口。有效盘口要求：来源与市场匹配，采样时年龄在 0—500 ms，`0 < bid ≤ ask`，买一和卖一各至少 10 ETH。这个挂量门槛只用于教学筛选，不能证明报价一定可成交，也不排除挂撤操纵。

```text
当前中间价 mid_t = floor_to_price_unit((bid_t + ask_t) / 2)
当前相对基差 b_t = trunc_zero((mid_t − I_t) × 10^9 / I_t) 〔单位 ppb〕

窗口 = t−29 秒至 t，每秒恰好一个已确认样本，均绑定 R1
完整窗口均值 B_t = trunc_zero(sum(b_j) / 30)
受限基差 C_t     = clamp(B_t, −5,000,000, +5,000,000)       〔±0.5%〕
标记价格 M_t     = floor_to_price_unit(I_t × (10^9 + C_t) / 10^9)
```

- 历史样本保存当时的指数、盘口及证据；本地盘口和指数有最大允许年龄，但并非物理意义上的绝对同时。更严格的跨源同步需要额外延迟预算与规则。
- 单个采样点的 `sample_valid=true` 只要求该点自己的指数、盘口、时间与规则证据完整，不要求当时已经拥有 30 点窗口，也不要求市场已经 ACTIVE。整轮价格包的 `quality=FULL` 则要求完整窗口成立，两者不能混用，否则启动和恢复会形成循环依赖。
- 窗口任何一点缺失、无效或跨规则版本，就视为不完整；不补零、不复制旧样本、不让高频源占据更多时间权重。当前点无效时也不能借前 30 点继续伪装成完整窗口。
- 指数有效、窗口不完整时，候选标记价格取指数，质量为 `DEGRADED_BASIS`，模式收紧；指数无效时，标记价格也无效，不能拿缓存基差“救活”它。
- 本模型没有增加“指数每秒只能变化 x%”的硬限幅。全市场真实急跌时，这类限速可能阻止价格反映真实风险；异常诊断、暂停和应急定价应是独立、可审计的规则。
- 改用资金费调整、冲击买卖价、多个候选价中位数或其他 Mark 公式时，必须明确是另一套产品规则，不在追问中悄悄更换。

### 4.3 质量、模式与动作矩阵

`quality` 描述本轮证据：`FULL`、`DEGRADED_BASIS`、`INVALID_INDEX`。`mode` 描述当前业务权限，可以因恢复流程而比本轮质量更严格。

| 模式 | 进入条件 | 新增风险／增仓 | 保证金划出／依赖风险估值的提现 | 撤单、已确认补充保证金 | 用户主动 Reduce-Only | 自动强平 |
|---|---|---|---|---|---|---|
| ACTIVE | 完整价格正常，且恢复已完成 | 按最新风险检查 | 按最新风险检查，不等于直接可提未实现盈利 | 允许 | 按执行约束 | 允许触发复核，执行仍需检查当前状态 |
| LIMITED | 指数有效，基差条件不完整 | 禁止 | 禁止 | 允许，仍检查身份与幂等 | 有条件允许 | 本模型暂停 |
| HALTED | 指数不可用 | 禁止 | 禁止 | 允许，补保证金按资金到账事实 | 有条件允许，不依赖旧 Mark 授权 | 暂停 |
| RECOVERING | 从受限状态返回完整质量，尚未达到连续恢复门槛 | 禁止 | 禁止 | 允许 | 有条件允许 | 暂停 |

**Reduce-Only 的“有条件允许”**：订单必须在最终撮合／执行处按权威当前仓位裁剪并裁决，不得反向开仓；不得顺带划出抵押、发放估值信用或绕过其他在途义务；用户须有有效执行价格保护和可用对手方。本例主动减仓的准入不依赖 Mark，但真实成交仍需原子结转损益及费用，可能暴露负现金与剩余债务；不能把它叫作保证偿付的方案。无法满足这些约束的订单不执行。

模式迁移由市场 owner 顺序裁决：任意模式遇到无效指数立即 `HALTED`，遇到有效指数但基差缺失立即 `LIMITED`。从任一受限模式返回 `FULL` 时，第一轮进入 `RECOVERING`，计数为 1；连续第 3 个完整轮次提交时进入 `ACTIVE`。中间出现任一不合格轮次即清零。已经 `ACTIVE` 且持续 `FULL` 时不反复恢复。

重复投递同一轮不增加计数。消费者即使没有收到下一轮，也必须按已知期限就地使旧授权失效；`ACTIVE` 不是永久租约。等待期间增加的市场风险必须监测和升级，恢复条件不应被人为删除来掩盖服务不可用。

### 4.4 精度、时间与版本

- 价格存为 `price_u = price × 10^6` 的整数；数量以 ETH 六位小数为本例表示；基差用有符号 ppb 整数。所有阈值和舍入顺序在规则中固定。
- 中间乘积必须证明位宽足够，或使用经检查的宽整数／Go `math/big`。不能因为输入能装进 `int64` 就认为阈值交叉乘法也安全；不使用 `float64` 决定边界。
- 每轮声明预定采样时刻 `sample_time=T`，源记录保留 `source_time`、`received_at`。快照另有 `committed_at` 和固定 `usable_until=T+1,500 ms`。
- 用价要求消费时 `sample_time ≤ now ≤ usable_until`，所需证据在采样时已满足年龄要求，而且模式与消费者进度满足动作规则。1,500 ms 是本例输出授权期，不会重置源年龄；它意味着最老合格源在最后用价时可能已接近 3,500 ms，应按产品风险预算决定是否接受。
- 本例通过输入日志记录每轮采用的时间值，重放时不重新调用当前墙钟；运行期另用可靠时钟监测期限。跨机器时钟漂移必须有预算与监控；预算失控就收紧动作，不能用未校准墙钟继续授权。
- `round_seq` 在单市场、固定价格流身份内连续；`price_id=(market, price_stream_id, round_seq)` 唯一。owner 任期用于围栏，不因切主重置业务序号。
- 规则变化成为已提交事件，绑定 `rule_version` 和生效轮次。主模型不混用不同规则的基差样本，从新规则生效位置起重新积累完整窗口并走恢复流程；影子样本与影子恢复计数只用于评估，不导入生产。另设样本迁移规则时属于改变前提的变体。

### 4.5 权威状态、数据对象与提交边界

```text
源适配器 → 接入日志 → 市场 owner〔同市场单写、输入／Tick／配置统一排序〕
                            ├─ 各源最新输入与身份检查状态
                            ├─ 指数计算与历史基差窗口
                            ├─ 模式与恢复计数
                            └─ 价格裁决事务
                                  ↓
                    持久库：状态 + 价格包 + 检查点 + Outbox
                                  ↓
                    风险消费者／行情查询各自维护投影与水位
                                  ↓
                    业务执行处复核资格，不接受页面缓存作授权
```

| 对象 | 必要字段 | 用途与权威 |
|---|---|---|
| 标准化报价 | `source_id、source_group、source_stream_id、seq、asset、quote_asset、price_u、source_time、received_at、digest、ingress_offset` | 接入身份和时序证据；本地配置核验 group，不能接受源自行声明的独立性 |
| 盘口样本 | `market、book_seq、bid_u、ask_u、bid_qty_u、ask_qty_u、book_time、sample_time` | 本地撮合行情派生，需检查水位与年龄，不以订单意图代替权威盘口 |
| 价格包 | `price_id、round_seq、index_u?、mark_u?、quality、mode、rule_version、sample_time、usable_until、input_cutoff、evidence_digest` | 单轮不可拆分权威结果；失效时数值为空，历史末次好价另存且带旧时间 |
| 样本与裁决证据 | 源值及筛选原因、指数源集合、盘口身份、基差窗口、未限幅值、恢复计数 | 可从价格追到实际输入，避免只存一个无法解释的最终数字 |
| 恢复状态 | 源候选、源序号／摘要、窗口、模式、连续轮数、检查点、owner 任期 | 快照必须在一致输入位置生成；所有会影响下一轮的状态都要恢复 |
| 风险决策 | `risk_unit_id、price_id、position_version、ledger_version、pending_exposure_version、risk_rule_version、decision_seq` | 风险 owner 维护，解释为何允许或禁止；不是价格服务直接扣款的命令 |

教学实现选一个关系数据库作为价格状态、检查点与 Outbox 的共同事务域。进程内按市场分片 owner 串行计算，事务再校验 owner 任期和前一版本，防止双写；消息至少一次交付，消费者幂等。

发布 ACK 只承诺本轮已达到所声明的数据库持久提交边界，不承诺所有风险单元都已应用。若要承诺跨机器故障不丢已确认轮次，还必须给出同步复制／多数提交及切主条件，不能仅凭“写了数据库”默认 RPO 为零。

风险消费者接收价格、持仓和现金流，并不自动获得一个全平台全局快照。风险单元负责组合可解释版本，把未结转成交纳入在途敞口；新增风险与划出资格需在该风险单元权威执行处重新检查。

### 4.6 必须成立的不变量

1. 同一价格身份只有一个已提交载荷；重复返回同一结果，同身份异内容隔离。
2. 数值、质量、模式、规则、证据与期限一起发布，不能分别从多个缓存拼接。
3. 无足够有效指数证据，不产生可用于业务授权的 Mark；旧好价不能重贴时间变新价。
4. 每个源每轮至多贡献一次；每秒最多一个基差采样点，输入频率不改变时间权重。
5. 同样的已提交输入位置、Tick、配置、历史状态与算法版本，应重建相同裁决；恢复不重采历史网络行情。
6. 价格事件不改经济历史。已完成成交也不能因后来发现源错误直接删掉；纠错与资金修复另走有权限的业务流程。
7. 期限或质量不满足时，最终执行不能仅凭旧风险通过回执继续增仓、划出或强平。

## 七、工程实践：唯一的简洁 MVP

### 7.1 目标与范围

只验证一个小闭环：**本轮多源报价过滤 → 指数 → 30 点相对基差均值与限幅 → 带质量的候选标记价格**。

输入已由适配层完成身份、交易对和六位精度标准化，且每源只有本轮截止点前的最新一条；源分组由固定配置取得。传入此前 29 点已验证历史样本及当前盘口，历史点均绑定 R1、相邻一秒，带 `sample_valid=true` 并保留当时指数与盘口有效性的证据。MVP 不实现这些历史证据的采集与持久化。

**不覆盖生产鉴权、可靠交付、持久事务、去重状态、模式恢复、风险授权、主备和链上验证。** 输出中的质量不是执行许可；不能把下列计算函数直接接成自动强平接口。

### 7.2 核心伪代码

`S=10^6` 为价格整数倍率，`B=10^9` 为基差倍率，`t` 用毫秒；所有乘法使用足够位宽。`floor_div` 为正数向下取整，`trunc_zero` 为有符号向零截断，两者均只表示明确的整数运算，不隐含事务或可靠性能力。

```text
candidate(T, quotes, previous_29, current_book):
    fresh = []
    对每条标准化报价 x：
        若 x.source 在 R1 允许列表，x.price > 0，且 0 <= T-x.source_time <= 2000：
            fresh.append(x)                         # 每源已由输入约束限制为一条
    若 fresh 少于 3：返回 {index: null, mark: null, quality: INVALID_INDEX}
    prices = sort(fresh.price)
    median = 中间项，偶数时 floor_div(中间两项之和, 2)
    good = [x for x in fresh if abs(x.price-median)*10000 <= median*100]
    若 len(good) < 3 或 R1 中 good 对应独立分组少于 3：
        返回 {index: null, mark: null, quality: INVALID_INDEX}
    I = floor_div(sum(good.price), len(good))
    book_ok = current_book.market == ETH-USDC-PERP
              且 0 <= T-current_book.time <= 500
              且 0 < current_book.bid <= current_book.ask
              且 current_book.bid_qty >= 10*S 且 current_book.ask_qty >= 10*S
    history_ok = len(previous_29) == 29
    若 history_ok：
        对 j 从 0 到 28：
            h = previous_29[j]
            若 h.time != T-(29-j)*1000 或 h.rule != R1 或非 h.sample_valid：
                history_ok = false
    若非 book_ok 或非 history_ok：
        返回 {index: I, mark: I, quality: DEGRADED_BASIS}
    mid = floor_div(current_book.bid + current_book.ask, 2)
    b = trunc_zero((mid-I)*B / I)
    mean = trunc_zero((sum(previous_29.basis_ppb) + b) / 30)
    clipped = min(5000000, max(-5000000, mean))
    M = floor_div(I*(B+clipped), B)
    返回 {index: I, mark: M, quality: FULL,
          sample_time: T, usable_until: T+1500,
          selected_sources: good.source, raw_basis: mean, clipped_basis: clipped}
```

展示时将 `I、M` 除以 S。历史中的 `sample_valid` 是单点证据资格，与整轮价格包的 `quality` 和市场 `mode` 分开。当前指数与盘口合格时，即使窗口尚未完整，也可以将当前真实基差作为后续样本；但不能把 `M=I` 的降级输出倒推成零基差。当前指数或盘口无效时则不产生有效样本。这样既不会补造数据，也不会形成“没有完整窗口就不能积累窗口”的循环依赖。

### 7.3 输入与预期结果

下面均为手工推演预期，不是实际工程测试。各变体从同一主案例独立出发，不连续叠加。

| 输入 | 预期结果 | 要验证的边界 |
|---|---|---|
| 主案例 A—E、有效盘口 2,005／2,007、历史 29 点各为 3,000,000 ppb | 排除 D、E；`I=2,000，M=2,006，quality=FULL` | 离群与陈旧不同，完整窗口形成 Mark |
| 将历史 29 点各改为 10,000,000 ppb，当前盘口改为 2,019／2,021 | 均值为 1%，限幅为 0.5%；`I=2,000，M=2,010` | 先平均再限幅，Mark 不跟随全部本地溢价 |
| C 也陈旧，其余条件不变 | A、B、D 初筛后中位数 2,000，D 排除，仅剩 2 源；指数和 Mark 均为空 | 不能把最低源数检查只做在剔除之前 |
| 保留 A、B、C，但配置中三者都属于同一独立分组 | 指数和 Mark 均为空 | 三个地址／连接不等于三份独立证据 |
| 主案例中当前盘口已陈旧 600 ms | `I=2,000，M=2,000，quality=DEGRADED_BASIS` | 候选价存在不代表仍有 FULL 权限 |
| 主案例历史只有 28 点，或其中一点评为 R0 | 同上，退化为指数，不补样本 | 缺失与跨规则窗口不得隐式混合 |
| 所有源年龄均超过 2,000 ms | 指数和 Mark 均为空；历史末次 2,006 不变成新价格 | 收到 Tick／心跳不等于源数据更新 |

生产模式的手工序列可另按同一规则检查：`HALTED → FULL第1轮/RECOVERING → FULL第2轮/RECOVERING → FULL第3轮/ACTIVE`；重复第 2 轮不计第 3 轮。这只是模式规则的推演，不声称 MVP 已实现恢复状态机。
