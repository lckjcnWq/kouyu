# 大问题 8：资金费扣完保证金不足怎么办？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 资金费／手续费／借款利息 | 资金费用多空持仓间的周期收付调节持仓激励，不是成交服务费或借款利息。 | 发生欠款也不把原资金费改成另一笔借贷收费。 |
| q、M、f／应付符号 | 带符号数量乘参考价和周期费率得到有符号应付 D，现金变化为 -D。 | 本文多正空负，正费率多付空收；5×2,000×0.0001 应付 1 USDC。 |
| 逐仓风险单元 | 一份单独计算仓位、抵押和风险的小账本。 | 允许记负逐仓现金是本文明确模型，不代表其他资金池自动补足。 |
| 主例／独立变体 | 主例是共同基线；变体只为一个问题明确改条件。 | 主例甲现金 1,000，欠款例才改成 0.4，不能把二者混成同一初态。 |
| 现金 B／权益 E | 现金是账面资金；权益还要结合未实现盈亏等项目。 | 甲由 1,000 变 999 不自动代表保证金不足，更不代表 999 全能提走。 |
| 维持保证金／可提现余额 | 前者是维持仓位所需的风险要求，后者是满足全部限制后能划出的部分。 | 要看同版本仓位、价格、订单与未决义务，不能只看现金余额。 |
| SEALED／APPLIED | 前者固定费率、参考价与快照证据，后者表示资金事务已共同提交。 | 费用归属和金额不能因现金不足重写，风险确认则发生在账务提交之后。 |
| funding_due／完整应付 | 保存按原规则已经确定的全部费用义务。 | 应付 1 就仍记 1，不能因为只剩 0.4 而把效果截成 0.4。 |
| 负现金／debt_receivable | 负现金表示用户欠款，debt_receivable 表示平台待收债权。 | 0.4-1=-0.6，其中 0.6 不是平台已经收到的现金。 |
| 实收／债权 | 实收是已取得的真实资金，债权是以后有权追收的钱。 | 原费用 1 中用户实扣 0.4、剩余债权 0.6，不能把债权当可花现金。 |
| 平台信用／损失缓冲 | 经授权、预先落实且可控制的承接资金。 | 完整付给收款方需占用真实同币种缓冲，配置里写“额度足够”不算。 |
| 缓冲可用额／承诺额 | 可用额尚未被占用，承诺额已经分配给待履行责任。 | 事务内占用 0.6 防止并发重复承诺，实际划付时再记录现金流出。 |
| 收款资格／抵押价值 | 账面有一笔应收，不等于立刻能提走或拿它开仓。 | 真实缓冲落实后还需按收款方版本确认风险；平台缓冲不是甲的逐仓权益。 |
| 行锁／同库原子提交 | 用数据库排队并将相关修改一次性提交。 | 用户分录、缓冲占用、欠款、去重、风险待办与 Outbox 一起成立。 |
| READY + PAUSED | 计划已验好，但因原因暂停应用，原阶段仍保留。 | 缓冲不足时整批无人入账，不允许只停甲却先付乙丙。 |
| risk_pending／risk_generation | 前者记录风险待办，后者是区分新旧待办的代次编号。 | 新变化会产生更新代次，旧计算不能清掉后来的门禁。 |
| ledger／position／price／rule version | 分别标明账本、仓位、价格和规则的状态版本。 | 风险结果必须匹配当前要求的同组输入，不能拿旧余额确认新风险。 |
| compare-and-clear／owner | owner 是权威负责人；compare-and-clear 是核对目标没变后才原子清除待办。 | 风险重算成功还须在提交边界比对代次与版本，才解除对应限制。 |
| collection_id／追偿 | 追偿是后续收到现金后冲减已有债权，collection_id 给到账事件固定身份。 | 充值 0.6 是还欠款，不是把 F0800 的资金费再扣一遍。 |
| debt_adjustment_id／减免 | 减免是批准减少债务，用独立调整身份留记录。 | 不改原计划、不抹历史，先锁债权版本并最多处理当前未偿金额。 |

## 把整篇文章压缩成一个故事

1. 甲多仓 5 ETH，按本文正费率多付空收、应付等于数量乘参考价乘周期费率的约定，5×2,000×0.0001 应付 1 USDC。这是资金费，不是手续费或借款利息。主例现金 1,000 变 999，没有据此证明风险不足；风险还得看仓位、价格和其他义务。

2. 独立变体才把甲现金改成 0.4。原费率和屏障仓位已固定，应付仍是 1，不能只扣到零。若平台有真实授权缓冲，就同时记录甲实付 0.4、欠款 0.6、缓冲占用 0.6，并承接乙丙合计 1 的收款；没有能力则整批暂停，不能凭负数制造可提现资产。

3. 全部账务共同提交才是 APPLIED，风险确认另做且必须匹配新代次和版本，之前不放开增险或划出。甲以后补资是归还债权，不重收原费用；平仓归零也不消灭旧欠款。资金费只改变现金和费用归属，不改成交价，债务减免也要追加记录而不是删除历史。

**必要前提：** 沿用[总览的讨论基线与贯穿案例](README.md#一文字全流程)：单一 USDC 逐仓风险单元、F0800 周期费率 `f=0.0001`，资金费在屏障快照后按完整计划结转。主例中甲应付 1 USDC、结转前现金 1,000，乙和丙分别应收 0.6 与 0.4；主例没有余额不足。仅在明确标记的独立变体中，甲现金改为 0.4。该专题允许负逐仓现金表示债权，但不等于实际收款已发生，也不自动成为可提现余额。

**流程位置与核心机制：** 本题负责资金费完整义务与保证金、债权及风险资格的衔接；04 题规定金额和舍入，05 题规定账务原子提交。本题不改变费率、快照或金额，不把欠款追偿当第二次资金费扣款。

## 第 1 层：先看主例，怎样区分“资金费后现金减少”和“保证金不足”？

**面试官：** 资金费扣款会降低权益，但并非每次扣费都意味着违约。用总览主例解释你先看哪些数，避免把现金、权益和可提现余额说成一回事。

**面试者：** 甲的屏障仓位为 +5 ETH，结算价 2,000，周期费率 0.0001，所以应付 `5×2,000×0.0001=1 USDC`。主例现金从 1,000 变为 999；在其他输入为零时权益随现金少 1，但这不表示保证金不足，更不表示 999 全部可提现。风险判断还需同版本的仓位、Mark、维持保证金、挂单和未决义务。总览明确主例现金充足；不能为讲欠款而悄悄把主例初始余额改小。

## 第 2 层：独立变体中，甲只有 0.4 却应付 1，能否只扣到零？

**面试官：** 现在单独改变甲的结转前现金为 0.4，应付金额仍为 1。若系统只扣现有 0.4、把其余 0.6 忽略，会有什么问题？

**面试者：** 那会把已冻结的经济义务改成“尽力扣款”，资金费不再守恒。按本专题欠款模型，应付仍为 1，甲的逐仓账面现金在记账后为 `0.4-1=-0.6 USDC`，其中 0.6 是甲对平台的欠款，不是已收到的 0.6 现金。原计划和 `effect_key` 仍记完整应付 1；不能把 effect 改为仅扣 0.4，也不能将周期余额不足当作改费率或重算快照的理由。此独立变体不叠加其他资金异常。

## 第 3 层：负现金作为欠款入账时，账本要区分哪些事实？

**面试官：** 你说甲余额为 -0.6。这个负数既像账户余额又像平台应收，如何设计字段，防止报表把债权误当成可支用现金？

**面试者：** 账务保留原始 `funding_due=1`、已收自甲现金 `0.4`、剩余 `debt_receivable=0.6`，同时记录资金费效果键、币种、计划摘要、前后 `cash_version` 和债权状态。用户子账显示负现金可以表达偿付义务，但可用余额、抵押价值和提现额度要把未收债权排除；它不是托管账户里多出来的 0.6 USDC。总账应按资产、负债和费用科目定借贷，避免把同一欠款既当现金又当一笔可再次扣取的独立支出。

## 第 4 层：乙、丙的应收如何全额成立，平台缓冲必须具备什么？

**面试官：** 乙应收 0.6、丙应收 0.4。若只从甲实际收到 0.4，其余 0.6 没有现金来源，能否仍无条件给两位收款方记成可提余额？

**面试者：** 不能无担保地宣称两笔全额已实收。若协议允许平台信用垫付，必须存在真实、已预置且币种一致的缓冲资金；账务事务里要同时验证并占用 0.6 缓冲、记录甲的 0.6 欠款、将完整 1 分配给乙和丙，并设置收款可用资格。这样甲的 0.4 是实际扣收，另 0.6 是平台垫付，待追偿债权归平台；不是凭空创造收款，也不是让收款方承担甲的违约。若缓冲只是一项配置值、额度已被占用或没有可控资金权限，就不能让乙、丙无条件提现。

## 第 5 层：怎样在同一提交域控制缓冲余额与整批暂停？

**面试官：** 缓冲检查若在事务外完成，两个周期可能同时看到可用 0.6 并重复承诺。你会把哪些条件放进提交边界？

**面试者：** 在 F0800 APPLIED 事务内按稳定顺序锁定或条件更新甲、乙、丙及缓冲账户，校验缓冲 `available>=0.6`、预期余额版本、周期状态、计划摘要、欠款额度与权限策略；同事务写用户分录、缓冲占用／转出、债权记录、效果去重、`risk_pending` 和 Outbox。若实际托管转账不能纳入该数据库事务，就只能使用预先入账且可由该账务域控制的缓冲余额，不得把 RPC 成功想象成原子事实。校验失败时保持 `READY + PAUSED`，整批无人 APPLIED，维持屏障与划出门禁等待处理，不能只暂停甲却先付乙、丙。

## 第 6 层：资金费提交后，风险服务怎样重新计算而不放大欠款风险？

**面试官：** 账务事务已提交，甲的现金为 -0.6，但风险计算是异步的。能因周期已 APPLIED 立即恢复开仓和提现吗？

**面试者：** 不能。APPLIED 只承诺资金效果、债权、缓冲和待办共同落账，不承诺风险投影已追上。待办保存单调递增的 `risk_generation` 及目标 `ledger_version、position_version、price_version、rule_version`。风险 owner 按这些输入和当前未结费用、债权资格重算；仅在提交时仍匹配同一 generation 和所有版本，且权威账户 owner 以 compare-and-clear 原子清除该待办，才解除对应门禁。若期间有新成交、新价格版本或下一笔费用，旧计算必须失败并重算，不能清掉更新的 pending。未确认前持续阻止增险和划出。负债权通常不能当抵押；平台缓冲是平台资产，不是甲的逐仓权益。减仓或撤单仍按账户 owner 的顺序执行。若收款方的入账已经由真实缓冲支持，其风险可按自己的新账务版本计算；缓冲不足时前述整批不应提交，不能靠风险异步来补救资金缺口。

## 第 7 层：后续追偿、补资或债务减免怎样避免对甲重复扣款？

**面试官：** 甲之后充值 0.6，或者平台批准减免一部分欠款。你会再执行一次 F0800，还是修改原资金费记录？

**面试者：** 都不应重跑原资金费。原 `FundingEffect` 保持应付 1、已结算及剩余债权证据不可变；充值是有独立 `collection_id` 的现金到账事件，按当时未偿债权抵销 0.6，并单独更新债权余额和账本版本。若债务减免，也用审批后的 `debt_adjustment_id` 追加调整，记录原因、金额与审批人，不改历史计划。每次追偿先锁定债权版本，最多收取未偿额；充值超出欠款部分再按明确规则成为账户现金。由此不会让同一个 0.6 既被资金费扣一次、又在充值时作为新的资金费重复扣。

## 第 8 层：怎样验证完整应付、平台承接与风险门禁闭合？

**面试官：** 给出一个审计与故障反例，检验既没有漏记应收，也没有把未收现金包装成可提余额。

**面试者：** 对独立变体核对 `甲应付1=甲现金实扣0.4+平台缓冲承诺0.6`，乙收0.6、丙收0.4，周期内用户资金效果总和为零；平台账同时保留对甲0.6债权，并将真实缓冲可用额减少、承诺额增加0.6，实际划付时才记录现金流出。提交前若缓冲不足，周期应整体停在 READY/PAUSED，不能出现收款方已可提而付款来源未落实。反例是并发两个批次都读到同一笔0.6缓冲并各自 APPLIED，或者先给乙、丙合计记 1 USDC 可提现资金、稍后再找甲收款；前者说明缓冲无原子占用，后者把垫付风险错误转给收款用户。本文是手工账务推演，不是生产账务验证。

## 本题收束

**讲透的机制：** 资金费义务不因余额不足而截断；负现金明确代表欠款而非实收；收款端全额入账必须由真实、可控缓冲承接，并与债权及风险门禁共同提交。

**易错边界：** 把负余额当可提现现金、把债权当抵押、把配置额度当真实资金、只给付款方记欠款却让收款方无条件提款，或追偿时重复扣原资金费。

**反例检验：** 令甲只有 0.4、缓冲无可用余额而仍提交乙 0.6 与丙 0.4 的可提现余额；若系统允许，完整应付已变成无来源信用扩张。基线允许负现金欠款，但不豁免真实垫资能力与权限检查。
