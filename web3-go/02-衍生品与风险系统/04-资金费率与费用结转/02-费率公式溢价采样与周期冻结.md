# 大问题 2：最终费率怎样由溢价样本和周期规则产生？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 资金费／成交手续费／借款利息 | 资金费用持仓双方的周期收付调节持仓激励，不是成交服务收费或借款计息。 | 本题只决定本周期的计费比例，还没有对用户扣款。 |
| 多空／q 与支付符号 | 多空是相反持仓方向，q 带符号表示数量。 | 本文 q 多正空负、D=q×M×f、现金变化为 -D，故正费率多付空收，负费率反向。 |
| 周期费率 f | 一轮资金费按名义价值收付的比例。 | 0.0001=0.01%，是本 8 小时周期值，不是年化值，不再乘 8/24。 |
| Pᵢ／双边报价中点 | Pᵢ 是第 i 个槽的永续参考价，中点取买卖两侧报价的中间值。 | 使用经校验的报价，不拿最后一笔成交替代。 |
| Iᵢ／指数价格 | 独立价格管道提供的参考市场价格。 | 必须大于零，与同槽报价按规则时间可比；不是累计资金费指数。 |
| πᵢ／溢价样本 | 某一槽永续相对指数贵或便宜的比例。 | πᵢ=(Pᵢ-Iᵢ)/Iᵢ，无货币单位，也不是利息收入。 |
| P̄／时间平均溢价 | 横线表示对一整窗样本求平均。 | 480 个同长槽等权，不能只看临近结算的一次报价。 |
| UTC／[00:00,08:00) | UTC 是统一时区；左闭右开表示含起点、不含终点。 | 00:00 可进入首槽，08:00 报价不进入 F0800。 |
| 计划槽／480 槽 | 预先约定每分钟检查一次，共覆盖八小时。 | 每槽都要有有效证据，缺一槽不能把分母改成 479。 |
| 报价陈旧度／60 秒 | 报价距离采样槽起点有多旧。 | 只选不晚于槽起点且最多早 60 秒的最近有效值，不偷看未来。 |
| r、d、c | r 是规则中的基准项，d 限制修正幅度，c 限制最终费率幅度。 | 本文教学参数分别为 0.0001、0.0005、0.003，不代表行业统一参数。 |
| clamp／cap | clamp 把数夹在上下限内；cap 指上限约束。 | 先限制 r-P̄，再加回 P̄，最后限制总结果，不能合并乱序。 |
| M／Mark Price | Mark 是用于结算和风险判断的标记参考价。 | 屏障处独立冻结的 M 用于算钱；溢价样本决定 f，两者职责不同。 |
| 固定点／scale | 把小数乘固定倍数后存整数，以固定精度计算。 | 槽值和费率按 10¹² 缩放，不能重放时改用浮点数或新精度。 |
| trunc₀／向零截断 | 丢弃不能表示的小数部分，正负数都朝零靠。 | 每槽先截断一次，平均后再截断一次，位置改变就可能改变结果。 |
| 完整性水位／WAIT_INPUT | 水位证明规定范围的数据已齐；WAIT_INPUT 表示还在等输入。 | 缺槽不是零溢价，不能靠沉默或超时当作数据完整。 |
| SEALED／APPLIED／CLOSED | 分别是证据封存、资金提交、核对关闭。 | 费率在 SEALED 固定，费用归属还依赖仓位证据，实际入账要等 APPLIED。 |
| 规则版本／证据哈希 | 版本说明使用哪套算法，哈希是输入内容的校验指纹。 | 保存样本来源、时间、序号及摘要，才能说明旧费率为何算成这个数。 |
| 重放／追加调整 | 重放按原证据恢复同一结果；调整是保留旧记录后另记纠错差额。 | 已封存周期不能因行情或配置更新而偷偷重定价。 |

## 把整篇文章压缩成一个故事

1. 系统要为 F0800 确定资金费率。这种费用是持仓双方的周期转移，用来影响持仓激励，不是手续费或借款利息。它先看永续报价相对指数价的偏离，把八小时切成 480 个一分钟槽，逐槽留证，再按原定权重求平均。

2. 主例平均溢价为 0.0004，教学规则先算修正 0.0001-0.0004=-0.0003，未触及内限，再相加得到最终费率 0.0001。它就是本周期万分之一，不能再折算八小时。缺槽就等齐，不能删槽、填零或引用 08:00 的未来边界数据。

3. 完整证据在 SEALED 固定；谁承担费用要看另行封存的屏障仓位，入账更要等完整计划共同提交。这些阶段不能为了赶进度而跳过。按本文多正空负、现金变化取应付负数的约定，甲 +5 ETH、参考价 2,000 时付 1 USDC，空方收款。之后平仓不改已归属义务，旧费率也不能因重试改写；费用结转不会修改成交价。

**流程位置与核心机制：** 本题覆盖价格/报价样本进入费率计算，直到周期规则与输入被冻结为 `SEALED`；重点是单位、480 个槽的窗口边界、缺口处理、clamp 顺序和重放证据。公式、参数及数值只采用本专题 README 的教学规则，不宣称行业通用。下一题处理 S5000 仓位资格；结算参考 Mark 是费率之外的独立输入。

## 第 1 层：先按总览规则算出主例最终费率

**面试官：** 主例中每分钟溢价样本都是 `0.0004`。最终费率从什么公式得到，周期结束时应冻结哪个数？

**面试者：** 本专题教学规则是 `πᵢ=(Pᵢ-Iᵢ)/Iᵢ`，480 个一分钟槽等权求 `P̄`，再算 `f=clamp(P̄+clamp(r-P̄,-d,d),-c,c)`。参数为 `r=0.0001、d=0.0005、c=0.003`；主例 `P̄=0.0004`，内层 `r-P̄=-0.0003` 未触及限幅，故 `f=0.0004-0.0003=0.0001`。这个 `0.0001` 是本 8 小时周期费率；观察窗口结束、480 槽完整性水位达标并完成校验时，在 `SEALED` 阶段冻结，之后才生成计划、APPLIED 并核对到 CLOSED。不能把 CLOSED 说成费率冻结时点。

## 第 2 层：这个数的单位是什么，为什么不再乘 8/24

**面试官：** `0.0001` 看起来很小，是否要把它解释成年化利率，再乘本周期 8 小时占一天的比例？

**面试者：** 不要。总览把 `r、πᵢ、P̄、d、c、f` 全部定义在本 8 小时计费约定下，`πᵢ` 是同一时点价格差相对指数的无量纲比值，`f` 直接乘结算名义价值。`0.0001` 等于该周期名义价值的万分之一，不是年化值，也没有“先年化再折算”的步骤。若再乘 `8/24`，甲的 `5×2,000×f` 会从应付 1 USDC 错成约 0.3333；把百分数 `0.01%` 当成 `0.01` 又会放大百倍。

## 第 3 层：溢价样本使用哪两个价格，窗口如何平均

**面试官：** 既然 `πᵢ` 是价格差比例，`Pᵢ` 和 `Iᵢ` 分别从哪来，是否可以用最后一笔成交或 Mark 代替？

**面试者：** 本专题取经校验的永续双边报价中点作 `Pᵢ`，指数价格管道提供独立的 `Iᵢ`；只有 `Iᵢ>0` 且两路输入按同一槽规则时间可比时，才计算 `(Pᵢ-Iᵢ)/Iᵢ`。窗口平均为 `Σ(πᵢ×60秒)/(480×60秒)`，每槽同长，因此完整窗口等权。实现采用固定点：先算 `πᵢ,u=trunc₀((Pᵢ-Iᵢ)×10¹²/Iᵢ)`，即每槽先按 `10¹²` scale 向零截断；再算 `P̄ᵤ=trunc₀(Σ(πᵢ,u×60)/(480×60))`，均值再截断一次。这与总览 `f` 的 `10¹²` scale 对齐，重放不得换精度或改变截断位置。最后一笔成交受单笔冲击，不替代双边中点；结算 Mark 是 S5000 处另行冻结的 `M`，不能反过来用资金费调整后的 Mark 计算溢价。`M` 进入金额计算，`P̄` 进入费率规则，两者职责不同。

## 第 4 层：观察窗口的边界槽怎样取样

**面试官：** 主窗口是 `[00:00,08:00)`。若样本或报价恰好落在 00:00、08:00，或者某槽没有正好整分钟报价，怎么避免边界歧义？

**面试者：** 把 `[00:00,08:00)` 切成 480 个 60 秒计划槽，槽起点为 00:00 至 07:59 UTC。每槽选报价时间戳 `t_quote` 满足 `t_quote <= t_slot` 且 `0 <= t_slot-t_quote <= 60秒` 的最近有效报价；所以时间恰好等于 00:00 的报价允许用于首槽，恰好早 60 秒也在有效边界内，而 08:00 数据不属于 F0800。报价与指数输入还必须按同一槽规则时间可比。每个样本保存来源、时间和序号；不得使用槽起点之后的未来报价，也不得跨越超过 60 秒的缺口续值。精确边界由版本化采样器执行，避免 worker 各自解释。

## 第 5 层：一个槽无有效报价，能否用剩余样本继续算

**面试官：** 某分钟报价陈旧超过 60 秒，或者指数输入缺了一槽。去掉该槽后除以 479，似乎仍然有一个平均值，能否继续？

**面试者：** 不能。每槽都有来源、时间、序号和有效性证据；不满足固定取样条件的槽就是数据缺口，不是零溢价，也不允许缩短分母给其余样本更大权重。周期保持 `WAIT_INPUT`，等数据补齐并达到窗口完整性水位；按规则确认无法补齐时则阻断该周期并走明确运营处置，不能默默生成费率。行情故障期间是否允许减仓或撤单由风险规则另定，费用冻结与交易放行不能靠把缺失样本当正常值来折中。

## 第 6 层：内外两层 clamp 的顺序怎样影响结果

**面试官：** 公式有两次 clamp。若 `P̄` 极高或极低，能否合并成“把溢价限制在一个范围”来算？

**面试者：** 不能跳过次序：先把 `r-P̄` 限制到 `[-d,d]`，加回 `P̄` 后，再把结果限制到 `[-c,c]`。例如 `P̄=0.001` 时，`r-P̄=-0.0009` 被内层截为 `-0.0005`，内层合成 `0.0005`；`P̄=0.004` 时合成为 `0.0035`，再被外层 cap 到 `0.003`。负向样本同理受下限限制。此处参数和样本只演示总览定义的教学规则，不能据此断言某交易平台也使用这些 cap 或同一方向约定。

## 第 7 层：最终费率冻结时还必须冻结哪些证据

**面试官：** 得到 `f` 后只存一个小数是否足够？以后追问“为什么这周期是这个费率”，怎样复算？

**面试者：** 不足够。`SEALED` 的费率证据要绑定市场、周期窗口、规则版本、480 槽清单及摘要、样本来源/时间/序号/有效性、完整性水位、固定点算法与除法/向零截断版本、`P̄`、最终 `f` 和证据哈希。结算参考 Mark `M` 也保存独立的价格来源与屏障位置，不能把它并入溢价样本摘要。后续 `FundingPlan` 引用这些冻结摘要；同一周期若传来不同费率或样本摘要，就应报告载荷冲突而不是覆盖旧证据。

## 第 8 层：采样 worker 重放或规则升级时如何保持原结果

**面试官：** 采样 worker 在冻结前后崩溃接管，规则代码也可能升级。怎样保证重放不会把已生成周期悄悄改价？

**面试者：** 冻结前，接管者从持久样本槽与完整性水位继续处理，必须使用周期已绑定的规则版本；同一输入、算法版本和整数运算顺序应产生相同证据摘要。冻结后只读取 `SEALED` 记录，不再查询实时行情，也不因当前配置升级重算原周期。若发现历史报价错误，保留原证据和原账，通过经批准的追加调整纠正差额。一个可推翻方案的反例是重放 F0800 时少一槽却仍生成相同 `plan_hash`；这说明完整性或摘要没有覆盖样本。并发接管和账务提交细节由第 5、6 题展开。

## 本题收束

讲透的是本教学窗口的无量纲周期费率、槽权重与边界、先内后外 clamp、缺口阻断和冻结证据。最易错的是年化折算、用 Mark/最后成交替代中点，或对 479 槽重新归一。验证反例是移除一个槽或将 08:00 报价放入 F0800；系统应拒绝不完整证据或维持原窗口摘要，而非静默改价。本文没有声称运行过采样测试。
