## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| ETH-USDC 线性永续／PERP | PERP 指永续合约；这里没有固定到期日，按 ETH 数量和 USDC 价格线性算金额。 | 合约乘数为 1，名义价值是计费规模，不是实际支付的买币本金。 |
| 资金费／成交手续费／借款利息 | 资金费通过持仓双方的周期收付调节持仓激励，帮助永续价格贴近参考市场；另两者对应成交服务和借贷。 | 本专题资金费是多空间转移，不能当平台按成交收费或借款计息。 |
| 多仓／空仓／单向净仓 q | 多空是相反价格方向的仓位，净仓是相抵后的数量。 | 本文多正空负；甲 +5、乙 -3、丙 -2 ETH，合计为零。 |
| 周期费率 f／有符号应付 D | f 是一轮计费比例，D 为带正负的应付金额。 | D=q×M×f、ΔB=-D；按本文符号，正费率多付空收，负费率反向，不宣称各平台符号相同。 |
| M／Mark Price／指数价格 | M 是结算时固定的标记参考价，指数价格是计算市场偏离的独立参考输入。 | M 用来算钱；永续报价与指数的偏离用来算费率，不能混用。 |
| 结算名义价值／ΔB | 名义价值是仓位换算的计费规模，ΔB 是本次现金增加或减少。 | 甲 5×2,000=10,000 USDC，乘 0.0001 应付 1，现金变化 -1。 |
| B、U、E／可划出金额 | B 是现金，U 是未实现盈亏，E 是权益；能划出多少还取决于风险限制。 | 主例 U=0、E=B+U，现金变化不等于可提现额度变化后就能立即提款。 |
| UTC／F0800／cycle_id | UTC 是统一时区，F0800 是截至 08:00 的周期简称，cycle_id 是稳定编号。 | 每 8 小时一轮，0.0001=0.01% 已是本周期费率，不是年化，不再乘 8/24。 |
| 逐仓风险单元／链下托管 | 逐仓单独计算一份仓位风险；链下托管由内部账本管理账户资金。 | 共同基线不包含全仓多抵押或链上履约，不默认保险基金或 ADL（自动减仓）已实现。 |
| S5000／时点快照／消费水位 | S5000 是逻辑截止线，快照保存该处仓位，水位证明前序已连续结转。 | 屏障不是成交；不按持有分钟数收费，后序平仓不免掉已归属费用。 |
| 溢价 πᵢ／P̄／480 槽 | 溢价是永续报价相对指数的偏离比例，P̄ 是完整窗口平均值。 | 每分钟一槽，缺槽就阻断；不能填零、缩小分母或把 08:00 数据放进前一窗口。 |
| clamp／r、d、c | clamp 把数限制在上下界，r 是基准项，d 限修正幅度，c 限最终费率。 | 先内层、再加溢价、再外层限幅；教学公式和参数不代表行业统一规则。 |
| SEALED／READY | 分别表示输入证据封存和完整收付计划通过校验。 | 冻结费率、固定仓位归属与实际扣款不是同一阶段，这两步还未改变现金。 |
| FundingPlan／plan_hash | FundingPlan 是完整收付清单，plan_hash 是规范内容的校验指纹。 | 保存每行依据、金额和尾差；重试不读新仓位、新费率或新配置覆盖原计划。 |
| 定点／宽整数／向零截断 | 固定精度整数计算，足够宽的类型承接乘积，丢弃不足最小单位的小数时朝零靠。 | 数量价格各乘 10⁶、费率乘 10¹²；现金按微 USDC，每单元每周期只舍入一次。 |
| Σq=0／尾差账户 | Σ 是求和，数量须全市场相抵；尾差只承接合法舍入残差。 | 先核验含自营仓的完整清单，再使用户加尾差金额为零，不掩盖漏仓、不凭空造钱。 |
| 分录／同库事务／APPLIED | 分录保留资金来去；同库事务让相关修改共同成败；APPLIED 表示资金已生效。 | 全周期收付、余额、去重、风险待办和 Outbox 一起提交，不支持逐页先扣，也不冒充跨库原子性。 |
| effect_key／幂等／owner_epoch | 效果键标识同一笔经济变化，幂等防重，任期号阻止旧负责人写入。 | 超时先查原周期；同键不同摘要隔离，新 worker 不能另造费用或换快照。 |
| Outbox／risk_pending／CLOSED | 分别是通知待发箱、风险待确认标记、完成规定核对的关闭状态。 | 资金可先于页面和风险投影完成；门禁等版本匹配确认才解，关闭不保证页面绝无延迟。 |
| 负现金／债权／真实缓冲 | 负现金表示用户欠款，债权不是已收现金，完整收款需要真实授权资金承接。 | 完整方案须共同登记欠款、缓冲和限制；简化 MVP 只接受足额余额，不足则整批拒绝。 |
| Maker／Taker／渠道返佣 | Maker 提供挂单流动性，Taker 主动吃单，渠道返佣是另一项收入分配。 | 成交费、Maker 补贴、渠道分配与资金费各有触发事实和身份，净额不替代明细。 |
| 补做／追加调整／同水位 W | 未提交义务按原身份补做；已提交错误另记差额；W 固定对账截止位置。 | 保留原价、原账和审批链，比较恰好同一水位的分录、调整及余额，不拿新余额硬比旧快照。 |
| 累计资金费指数 K／检查点 | K 是每单位仓位累计应付刻度，检查点记该仓位已结到哪里。 | 第 12 题才比较替代模型；K 不是价格指数，连续计费与周期快照惰性实现也不是一回事。 |
| 链上 tx／上链／最终性 | tx 是交易；广播提交、进入当前区块执行、满足目标链稳定性规则是不同阶段。 | 第 12 题才改变链上边界；执行成功不等于足额收齐，重组需回滚投影并重放核对。 |

## 把整篇文章压缩成一个故事

1. 甲多仓 5 ETH，乙丙空仓 3 和 2 ETH。永续不固定到期，资金费用周期收付调节持仓激励，不是手续费或借款利息。按本文多正空负、正费率多付空收的约定，参考价 2,000、八小时费率 0.0001，甲付 1 USDC，乙丙收 0.6、0.4；现金由 1,000/800/600 变为 999/800.6/600.4，总额仍是 2,400。

2. 先收齐 480 槽报价证据，执行域停在 S5000，账户结转完前序成交，再封存费率与仓位归属。完整计划验好后，同库事务共同提交全部分录、余额、去重和风险待办才算入账；风险确认及同水位核对后关闭。重试查原身份，快照后平仓不免旧费，结转不改成交价或抹历史，尾差只补精度残差。

3. 后半专题检查平仓强平顺序、欠款真实承接、手续费归因、追加纠错和并发容量；简化 MVP 余额不足就整批拒绝。最后才另设累计指数与链上模型：K 不是价格指数，连续计费不等于快照；tx 提交、上链和最终性不同，成功也不证明足额清偿。

## 一、文字全流程

### 1.1 讨论基线

采用**链下托管、链下订单簿撮合与内部账本结转的 ETH-USDC 线性永续合约**。单向净持仓、逐仓风险单元；数量以 ETH、价格以 USDC/ETH、现金以 USDC 表示，合约乘数为 1。正数量是多仓，负数量是空仓。

- 正资金费率表示多方向空方支付，负费率反向。资金费是持仓双方的周期性转移，不是平台按成交收取的交易手续费，也不是买入名义本金。
- 每 8 小时一个资金费周期，使用 UTC。主例观察窗口为 `2026-10-18 [00:00, 08:00)`，周期身份为 `ETH-USDC-PERP/20261018T080000Z`，记作 F0800。
- **采用结算时点快照，不按持有时长累计。** 08:00 的逻辑结算屏障决定该周期仓位。窗口内曾经持仓但屏障前已经平仓，不参与；屏障后才平仓，仍承担本周期费用。
- 本教学规模下，参与账户、仓位、资金费计划、账本、幂等记录和风险门禁位于同一个支持事务的关系数据库。一个周期的全部收付在一个数据库事务内提交。后文讨论分片时明确改变这个条件，不拿单库事务冒充跨库原子提交。
- 市场经济事件具有可恢复的权威顺序。屏障 S5000 前的成交必须先完成账户结转；屏障后的成交结转、受影响风险单元的划出等操作等待资金费账务提交。撮合在屏障处短暂停止继续执行，不能只有资金费程序自己停下来。
- 账务提交后，风险重算异步完成；待重算期间，增加风险和划出资金仍由持久门禁阻止。减仓、撤单按账户 owner 的既定顺序处理；旧强平命令执行前必须复核当前状态。
- 基线不包含链上履约、多抵押品、全仓交叉抵押、保险基金实际赔付或 ADL。第 12 题在改变状态归属后比较累计指数及链上结算。

这是一套容易解释原子边界的小规模基线，不是生产吞吐最优解。暂停、长事务和跨账户锁竞争是必须正面承认的代价。

### 1.2 贯穿案例

屏障 S5000 表示资金费截止位置，不是成交。S5000 之前的全部成交已经结转，S5000 之后的经济事件尚未执行。本例三个风险单元没有其他市场、挂单占用、充提或待处理经济义务；入场价和本次结算参考 Mark Price 均为 2,000，因此本步未实现盈亏为 0。

| 风险单元 | 屏障快照数量 q | 结转前现金 B | 结算名义价值 | 本周期现金变化 ΔB | 结转后现金 |
|---|---:|---:|---:|---:|---:|
| 甲 | +5 ETH | 1,000 USDC | 10,000 USDC | -1 USDC | 999 USDC |
| 乙 | -3 ETH | 800 USDC | 6,000 USDC | +0.6 USDC | 800.6 USDC |
| 丙 | -2 ETH | 600 USDC | 4,000 USDC | +0.4 USDC | 600.4 USDC |

教学费率规则计算出**本 8 小时周期最终费率 `f = 0.01% = 0.0001`**。它不是年化利率，也不再乘一次 `8/24`。

```text
有符号应付 D = q × 结算参考价 M × f
账户现金变化 ΔB = -D

甲：D = 5 × 2,000 × 0.0001 = 1 USDC，应付 1
乙：D = -3 × 2,000 × 0.0001 = -0.6 USDC，应收 0.6
丙：D = -2 × 2,000 × 0.0001 = -0.4 USDC，应收 0.4

Σq = 0；ΣΔB = 0；现金总和仍为 2,400 USDC。
```

资金费只改变现金与资金费归因，不改变仓位数量、入场成本或毛交易已实现盈亏。在价格不变且其他事件为零时，权益 `E = B + U` 随本次资金费等额变化。现金不是可提现余额，可划出金额仍受保证金、在途义务和风险门禁约束。

### 1.3 主流程：从持仓形成到周期关闭

```text
用户下单并形成确定成交
    ↓
成交清算与账户结转
    └─ 持仓、现金、手续费按成交身份可靠提交

观察窗口内采集指数价与永续参考报价
    ↓
费率计算器维护带来源证据的溢价样本
    ↓
UTC 08:00 到达：调度器提交稳定周期身份及逻辑屏障 S5000
    ↓
市场执行域停在屏障；账户域消费完全部前序经济事件
    ├─ 风险单元划出等并发操作也进入屏障协议
    └─ 不用墙钟时间替代已提交顺序与消费水位
    ↓
校验窗口数据、价格有效性、规则版本和完整持仓清单
    ├─ 冻结最终费率、结算参考价与仓位快照
    └─ 生成 SEALED 周期证据，后续重试不得读取新仓位
    ↓
计算器生成不可变 FundingPlan
    ├─ 每个风险单元的原始应付、实际入账和精度规则
    ├─ 舍入尾差账户的平衡项
    └─ 数量、清单数量、摘要和金额守恒校验 → READY
    ↓
账务应用器开启同库事务
    ├─ 校验周期身份、计划摘要、屏障门禁与状态版本
    ├─ 登记全部分录并更新现金及资金费累计
    ├─ 同时写 APPLIED、幂等记录、risk_pending 和结果 Outbox
    └─ 共同提交：此后不能因通知失败取消已结转资金费
    ↓
解除市场结转屏障，可靠发布账务与风险事件
    ├─ 风险 owner 按当前版本重算，合格后解除对应风险门禁
    ├─ 查询投影按账务版本更新，允许暂时落后
    └─ 对账核对清单、分录、尾差与必要风险确认 → CLOSED
```

资金费没有逐次由用户发起的扣款请求。用户的持仓事实产生结算资格，周期调度器只发起确定性处理，不能自己创造或更改用户仓位。

### 1.4 主要异常分支

```text
重复调度 F0800 → 查询相同周期；复用原记录，不生成第二笔费用
前序成交存在缺口 → 留在 WAIT_INPUT；补缺，禁止直接快照当前缓存
报价缺失、陈旧或窗口不完整 → 阻断该周期；不默认为零费率
快照后甲平仓 → 先结转 F0800，再执行屏障后的平仓；仍支付 1 USDC
同周期不同 rate/price/snapshot 摘要 → 隔离冲突，不把“重试”变成改价
计划生成失败 → 尚未入账；由冻结输入重建相同计划
账务事务未提交就崩溃 → 全部回滚，按原周期重试
提交成功但回执丢失 → 查询 APPLIED 与 plan_hash，返回原结果
账务完成但风险事件未到 → risk_pending 保留；Outbox 补发，不先放开划出
已关闭周期发现历史数据错误 → 新调整事件与审批，不覆盖原计划
```

报价故障期间的交易、撤单和减仓策略由风险规则明确决定；本例暂停该资金费周期的结转及受影响市场新增风险，不能一边无限延迟费用、一边允许全部抵押资金退出。

### 1.5 不同“完成”的承诺

| 阶段 | 已成立的事实 | 尚未承诺 |
|---|---|---|
| WAIT_INPUT | 周期身份与屏障意图已持久接管 | 数据、前序水位和快照已经齐备 |
| SEALED | 最终费率、价格、规则和快照证据被冻结 | 已经扣款 |
| READY | 完整可复算计划通过校验 | 全部余额已经更新 |
| APPLIED | 同周期全部分录、余额、幂等与风险待办共同提交 | 风险、查询已追上，或链上已经转账 |
| CLOSED | 同水位核对通过，必要风险确认完成 | 页面绝不延迟，或后续永不产生调整 |

暂停时保留原阶段及原因，例如 `READY + PAUSED(reason)`，不是清空记录回到一个新周期。没有任何账务效果时，取消屏障也必须由执行域有序确认；不能删掉任务记录后任由迟到 worker 扣款。

## 二、核心板块

| 板块 | 决定什么／为什么核心 | 权威状态与交互 |
|---|---|---|
| 费率规则与数据证据 | 本周期用哪个费率，避免单位、窗口和数据污染 | 规则版本、样本清单、最终费率；向结转交付不可变输入 |
| 屏障与持仓快照 | 哪些持仓承担费用，避免边界套利或漏收 | 已提交顺序、消费水位、全量快照；由执行域与账户 owner 共同落实 |
| 金额计算与计划 | 谁付谁收、金额和尾差怎样闭合 | 原始金额、入账额、清单摘要；计算器没有修改余额的权限 |
| 账本与风险门禁 | 资金效果是否唯一且可安全使用 | 分录、余额、处理记录、risk_pending、Outbox 共同提交 |
| 恢复、补算与核对 | 重复、崩溃和纠错后还能否解释账 | 稳定效果身份、提交水位、调整链、可审计证据 |

## 三、核心 20%

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| 周期与费率单位 | 观察到冻结 | 决定经济口径 | 把百分数、年化和周期费率混算 | UTC、窗口边界、clamp、cap、版本 |
| 屏障与完整快照 | 到期结算 | 决定付费资格 | 用当前仓位补扣旧周期、漏掉迟到成交 | 前序水位、单写权限、完整清单 |
| 有符号金额与整数舍入 | 计划计算 | 决定钱的方向与守恒 | 负费率方向错、微量资金长期漂移 | 单位、乘法位宽、向零截断、尾差账户 |
| 周期原子提交 | 账务应用 | 禁止半批资金生效 | 已扣未加、重复支付 | 事务、唯一约束、锁顺序、风险待办 |
| 身份与冻结证据 | 交付及恢复 | 定义“同一笔费用” | 重试生成新身份或读取新配置 | cycle_id、effect_key、payload_hash |
| 经济顺序与风险资格 | 屏障到风控 | 费用改变抵押能力 | 先提现后扣款、过期强平 | cash_version、risk_pending、执行前复核 |
| 同水位对账与追加调整 | 关闭和纠错 | 错误可解释而非被抹平 | 最新余额直接比旧快照、覆盖原账 | 清单完整性、首个差异、审批、差额事件 |

“20%”是优先级，不是删掉关键依赖的理由。撮合算法、全套保证金梯度、保险基金和链合约各自不在此重写，但资金义务、结算资格、亏空和最终性必须有明确契约。

## 四、共同设计与规则

### 4.1 教学费率公式与窗口

以下仅是本专题选择的规则，不宣称行业通用：

```text
每分钟一个计划样本槽，共 480 槽，每槽覆盖 60 秒。
πᵢ = (永续参考报价 Pᵢ − 指数价格 Iᵢ) / Iᵢ
P̄ = Σ(πᵢ × 60秒) / (480 × 60秒)
f = clamp(P̄ + clamp(r − P̄, -d, d), -c, c)

r = 0.0001；d = 0.0005；c = 0.003
主例每槽 πᵢ = 0.0004，因此 P̄ = 0.0004，f = 0.0001。
```

`r、P̄、d、c、f` 都按本 8 小时计费约定解释，不能把一个未经定义的“溢价”直接当成年化收益率。报价参考取经校验的双边报价中点，指数为独立价格输入；不是取最后一笔成交或反过来用资金费调整后的 Mark 计算溢价。

每槽必须有来源、时间、序号与有效性证据；报价和指数各自选取满足 `t_price ≤ t_slot` 且 `0 ≤ t_slot−t_price ≤ 60 秒` 的最近有效值，故两个价格源的时间差也不超过 60 秒；不跨越更长缺口续值。00:00 的同刻样本可进入第一个槽；08:00 样本位于窗口右边界，不进入 F0800。每个指数价格必须大于零。最终冻结前，等数据管道达到约定窗口完整性水位。缺槽阻断，不能缩短分母悄悄提高剩余样本权重。槽值 π 以 `10⁻¹²` 定点表示，每槽按宽整数除法向零截断；480 个定长槽求和后再除以 480 并向零截断得到 P̄。采样与平均的定点误差由该规则版本确定，不记入账户现金尾差账户；重放使用同一算法版本。

最终 `f` 与结算参考价 `M` 是不同输入：前者来自观察窗口，后者是屏障上固定的有效 Mark Price。只有确认数据规则允许，才可以对缺失历史槽补齐；已 SEALED 的周期发现错误时走调整，不重新解释原记录。

### 4.2 金额单位与不变量

数量 `q_u = q × 10⁶`，价格 `M_u = M × 10⁶`，费率 `f_u = f × 10¹²`，现金最小单位为 `10⁻⁶ USDC`。

```text
raw_num = -q_u × M_u × f_u           〔有符号、宽整数〕
ΔB_u = trunc_toward_zero(raw_num / 10¹⁸)
尾差账户变化 round_u = -Σ用户 ΔB_u
```

资金费每个风险单元、每个周期只舍入一次，不按分页或线程批次额外舍入。本基线不把资金费小数尾数跨周期累积；逐笔原始值及本次尾差必须留证。它与相邻持仓专题的“交易盈亏结算余数”是不同费用类型的规则，不能混用。

1. 同市场全量净数量 `Σq = 0`；若存在平台或做市商自营仓，也必须纳入同一清单。快照不平衡先排查完整性，不用尾差账户吞掉大额敞口。
2. 使用同一参考价与最终费率时，原始资金费零和；舍入后用户加尾差账户变化之和仍为 0。不得跨币种相加抵平。
3. 同一效果身份最多提交一次；同身份不同载荷必须冲突，不能返回一个含糊的“处理成功”。
4. 资金费不改数量、入场成本与毛交易盈亏；它独立影响现金和资金费累计。
5. 账务、幂等、APPLIED、risk_pending 与 Outbox 要共同提交。页面刷新不在这笔事务里。
6. 主例现金充足。余额不足变体允许逐仓账面现金记负并明确形成用户欠款，不截断既定费用；完整应收不是无条件可提现的承诺，必须有真实平台信用／损失缓冲及划出限制。没有授权承接能力时在入账前暂停整批，不能给收款方凭空制造无担保可用资金。
7. 欠款识别、缓冲占用及门禁变化与相应账务在同一提交域决定；后续追偿、补资或损失承担另记事件，不能重复把欠款再扣一次。

有符号资金桶变化用于表达经济平衡，正式总账仍需按资产、负债、费用等科目性质定义借贷。负用户现金必须按欠款表达，不能把负负债和真实托管资产混成“所有钱都在库里”。

### 4.3 架构与权威边界

```text
价格／报价管道 → 费率计算与证据冻结 ─┐
                                  ├→ FundingPlan 计算与校验
执行日志 → 屏障 → 持仓快照清单 ────┘           ↓
                                         账务应用器
                                             ↓
     同库事务：周期 + 用户/尾差分录 + 余额 + 效果去重
               + 风险门禁/欠款约束 + 结果 Outbox
                                             ↓
                  风险 owner / 查询投影 / 对账 / 审计
```

计算器只能提出计划，账本才有入账权限。Go worker 和 Redis 锁不能替代数据库唯一约束；任期／围栏用于禁止旧执行者在接管后继续提交，最终仍需数据库校验有效任期、预期状态和计划身份。

### 4.4 核心对象与提交契约

| 对象 | 必要字段与约束 |
|---|---|
| FundingCycle | `market、cycle_id、window_start/end、barrier_seq、status、owner_epoch、rule_version`；市场和结束时刻唯一 |
| RateEvidence | 样本清单摘要、完整性水位、最终费率、参考价、价格证据、计算／舍入版本 |
| PositionSnapshot | 风险单元、数量、仓位版本、账本版本、屏障位置；完整清单数量、数量和、摘要 |
| FundingPlan | `cycle_id、evidence_hash、snapshot_hash、plan_hash`，逐单元金额和尾差；READY 后不可变 |
| FundingEffect | 稳定键 `cycle_id/risk_unit/USDC/FUNDING`；不把 rate、worker、重试次数或规则版本放入身份以绕过去重 |
| Ledger / Balance | 业务效果键、分录组、金额、前后版本；金额与对应平衡项同事务提交 |
| Outbox / RiskGate | 结果事件 ID、账务版本、风险待办目标；消费者按事件身份去重并校验状态版本 |
| FundingAdjustment | 新调整 ID、原周期／原效果、批准依据、目标金额、已调整累计、差额与审批记录 |

`SEALED` 的快照与证据可以先持久提交；计划也可以先提交 READY。**真正改变用户资金的是 APPLIED 事务。** 若采用分页生成计划，必须先完整物化并核对清单，再标 READY；不能第一页算好就开始扣款。

## 七、工程实践——唯一简洁 MVP

### 7.1 目标与范围

验证**冻结周期输入 → 整数金额计划 → 同库全体入账 → 重复调用不产生第二次经济效果**。输入是已验证的完整快照；不实现真实行情、市场屏障、数据库驱动、完整风控、Go 工程、跨分片或链上结算。

### 7.2 核心伪代码

```text
apply(cycle, frozenSnapshot, balances):
    # 前提：屏障已由执行域落实，原始快照及费率证据已冻结。
    require cycle.status in {READY, APPLIED}
    require frozenSnapshot.hash == cycle.snapshot_hash
    require sum(frozenSnapshot.q_u) == 0
    plan = []
    for row in frozenSnapshot.rows_sorted_by_risk_unit:
        num = -WideInt(row.q_u) * cycle.mark_u * cycle.rate_u
        delta = trunc_toward_zero(num / 10^18)
        plan.append(effect_key(cycle.id, row.id, "USDC", "FUNDING"), delta)
    plan.append(rounding_key(cycle.id), -sum(plan.delta))
    require hash(plan) == cycle.plan_hash

    BEGIN TRANSACTION
        lock cycle row; require owner_epoch == expected_epoch
        if cycle.status == APPLIED:
            require stored_plan_hash == hash(plan)
            COMMIT; return original_result
        require status == READY and barrier_is_active(cycle.barrier_seq)
        lock affected balance/version/gate rows in stable key order
        require all expected snapshot versions still match
        # 本 MVP 只接受余额足够的输入；不足时整笔中止，不声称已实现欠款。
        require every user(balance + delta >= 0)
        require no effect_key in plan already exists
        for (key, delta) in plan:
            insert immutable ledger entry(key, delta, cycle.id)
            update balance += delta, balance_version += 1
        require sum(plan.delta) == 0
        insert all effect records; set cycle.status = APPLIED
        set affected user risk_pending(target_balance_version) = true
        insert outbox(cycle.id + "/APPLIED", cycle.plan_hash, affected_versions)
    COMMIT
    return committed_result
```

`barrier_is_active` 只检查已有持久屏障凭据，不假装实现跨模块屏障；快照完整性与资金效果身份均需要真实上游证据。数据库崩溃窗口由事务承诺覆盖，伪代码本身不等于已经验证数据库配置与故障恢复。Outbox 后续交付与风险解禁也明确不在本 MVP 内。

### 7.3 输入与预期结果

| 输入／变体 | 手工推演的预期结果 |
|---|---|
| 主例：q 为 +5/-3/-2，M=2,000，f=0.0001 | 甲 999、乙 800.6、丙 600.4；尾差为 0，总额 2,400 |
| 原 F0800、原 hash 再调用 | 返回第一次结果；余额、版本、分录和 Outbox 不新增 |
| 同 F0800 改 rate 或快照 | 与冻结摘要或 plan_hash 冲突，拒绝；不能解释为新费用 |

| 独立尾差变体：q 为 +0.000008/-0.000004/-0.000004，M=2,000，f=0.0001 | 原始变化 -0.0000016/+0.0000008/+0.0000008；入账 -0.000001/0/0，尾差账户 +0.000001 |
