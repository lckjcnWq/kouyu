# 大问题 9：成交手续费、Maker 返利和资金费怎样分别记账？

<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 资金费／手续费／借款利息 | 资金费调节多空持仓激励，手续费对应成交服务，借款利息对应借贷占用。 | 三者触发原因不同，不能因为都改现金就合并成无法解释的一个净额。 |
| q、M、f／资金费符号 | 资金费应付 D=q×M×f，账户现金变化为 -D。 | 本文多正空负、正费率多付空收；主例 +5×2,000×0.0001 付 1 USDC。 |
| S5000／独立新成交 | S5000 是本轮资格截止屏障；本题另设屏障后的丁戊成交。 | 新成交不塞回 F0800 原快照，先完成 F0800 APPLIED，再按序执行。 |
| Taker／吃单方 | 主动与已有报价成交、取走流动性的一方。 | 本题丁是 Taker，实际费率 +0.02%，不是由客户端自行声明角色。 |
| Maker／挂单方 | 原本挂在订单簿上提供报价、后来被成交的一方。 | 本题戊是 Maker，费率 -0.01%，负号表示平台给予成交补贴。 |
| fill／fill_id／账户腿 | fill 是一笔实际成交，fill_id 是它的编号，账户腿是同笔成交中某一方的效果。 | 同一订单可有多笔 fill、不同角色，逐笔按确定事实计费。 |
| 成交名义额／合约乘数 | 实际数量乘成交价格再乘合约单位倍数，得到手续费基数。 | 0.5×2,000×1=1,000 USDC；未成交的委托量不产生这笔费用。 |
| fee_signed／现金变化 | 有符号手续费为正表示收费，为负表示返利；现金变化取其负数。 | 丁手续费 +0.2、现金 -0.2；戊手续费 -0.1、现金 +0.1。 |
| fee_schedule_version | 固定本笔成交所用的费率表版本。 | 角色、资格、数量、价格和舍入证据一起保留，后来升级等级不改旧 fill。 |
| 渠道返佣／受益人 | 按合同把合格收入的一部分分给渠道，不等于 Maker 补贴。 | 本题从丁已收 0.2 的 20% 分配 0.04，不从负 Maker 费或资金费取基数。 |
| rebate_id／源费用效果 | 返佣固定身份引用哪笔手续费、哪位受益人和哪项分配约定。 | 规则版本属于校验载荷，不用来把同一次分配变成多次付款。 |
| 应付／实际划入 | 应付是平台承担的待付责任，划入是责任落实到受益人子账。 | 异步两阶段合计只确认一份返佣，不能应付记一次、到账又多付一次。 |
| 平台费用对手科目 | 与用户费用变化相对应的平台账务分类。 | 丁扣费、戊补贴、渠道分配各有来源，最终平台净留 0.06 USDC。 |
| 同库事务／Outbox | 数据库事务共同提交经济效果，Outbox 同时保留待发通知。 | 成交双方仓位、成本、现金、费用、去重和风险待办不能半途生效。 |
| 定点／向零截断／资金费尾差 | 定点固定整数精度，向零截断决定不足最小单位的处理方式，尾差账户有专门用途。 | 成交每个账户腿截到微 USDC，平台项按实际额平衡，不借资金费尾差支付补贴。 |
| 毛交易盈亏／净已实现收益 | 毛交易盈亏只看交易价差，净收益还要按报表口径计入相关费用。 | 开仓毛交易盈亏为零也会发生费用；不能在成本和净额里重复扣同一笔。 |
| 费用归因／净额展示 | 归因保留每笔钱的原因，净额只是汇总显示结果。 | 资金费、成交费、渠道收益独立展示，入场成本不偷偷掺入手续费。 |
| 效果键／幂等／摘要冲突 | 效果键识别同一变化，幂等防止重试多记，摘要检查内容是否一致。 | 同 fill 新费率是冲突，不是新增费用；重复渠道通知也不能多分 0.04。 |
| risk_pending／可用资格 | 账务变化后需重新确认风险，入账不等于无条件可提或可作抵押。 | 旧风险结果不能解开新现金版本门禁，未兑现渠道应付也不能先当抵押。 |
| 平台资金承接 | 补贴和返佣必须有真实资金来源与授权。 | 已确定 fill 不能事后把负 Maker 费改成零，更不能挪资金费付款填补平台支出。 |

## 把整篇文章压缩成一个故事

1. 先分清两本账：资金费是持仓间周期转移，不是手续费或借款利息。按本文多正空负的约定，正费率多付空收，甲 +5 ETH、参考价 2,000、周期费率 0.0001 付 1 USDC。费率封存、快照归属、完整账务提交分别完成后，才轮到屏障后的新成交，不能把新仓塞回旧周期。

2. 丁吃单、戊挂单，实际成交 0.5 ETH@2,000，手续费基数为 1,000 USDC。丁按 0.02% 付 0.2，戊按 -0.01% 收平台补贴 0.1；渠道另分丁已收费用的 20%，得到 0.04，平台净留 0.06，四方合计为零。这些不是负资金费，也不借资金费尾差来补贴。

3. 成交经济效果与费用共同入账，渠道异步分配另有稳定身份，重复消息不能多付。毛交易盈亏为零不代表没有费用，净收益也不能重复扣；账面应付不直接变抵押。已归属旧费不因后来平仓消失，结转不改成交价，历史纠错另留记录。

[返回专题总览](README.md)

**必要前提：** 沿用总览的 ETH-USDC 线性永续、单向净持仓、USDC 现金及单库事务。为说明成交费用，明确另设 S5000 **之后的独立新成交**：丁为 Taker、戊为 Maker，双方无初仓且有足够现金，成交 0.5 ETH@2,000，合约乘数 1。本题费用版本约定 Taker 费率 +0.02%、Maker 费率 -0.01%；另按合格 Taker 已收费用的 20% 给一个渠道受益人返佣。它们不是总览预设费率，也不叠加回 F0800 的冻结计划。

**流程位置与相邻题边界：** 04 题计算周期资金费，05—06 题规定资金费账务与恢复，08 题处理付款不足。本题讨论成交费、Maker 补贴、渠道分配的身份、提交和损益归因，不把成交费混进资金费尾差，不另建工程或单题 MVP。

## 第 1 层：按经济事件划分费用身份与金额来源

**面试官：** 成交手续费、Maker 返利和资金费怎样分别记账？既然最终都改变现金，为什么不能只保存一个费用净额？

**面试者：** 净额可以展示，不能代替原始效果。资金费稳定键是 `cycle_id/risk_unit/USDC/FUNDING`，金额来自屏障仓位、结算 Mark 和周期费率；成交费使用 `fill_id/account_leg/USDC/TRADE_FEE`，金额来自实际成交及适用规则；渠道返佣又有源费用、受益人与分配身份。费率、规则版本和载荷摘要是校验内容，不放进身份给重试另开一笔。这样同一 fill 重放不再扣手续费，同一周期重调不再收资金费，渠道消息重投也不能重复分配；若只记净额，就无法解释谁因哪一事实付钱，也无法定位冲突。

## 第 2 层：成交手续费只按实际成交基数产生

**面试官：** 既然手续费引用实际 fill，丁申报 1 ETH 但只成交 0.5 ETH@2,000 后撤单，你会按哪个数扣费，和资金费基数差在哪里？

**面试者：** 成交名义额是 `abs(q_fill)×P_fill×乘数=0.5×2,000×1=1,000 USDC`，丁费率 0.02%，因此手续费为 0.2。未成交的 0.5 不产生这笔手续费，撤单确认只释放剩余预留；后续另一 fill 按自己的数量和成交价计费。资金费则看 F0800 屏障净仓，不使用该成交额；本例新仓在 S5000 之后形成，不承担已封存周期的费用。金额用定点宽整数按冻结精度计算，本题约定每个成交账户腿向零截断到 10⁻⁶ USDC 一次；平台对应项按实际入账金额平衡，不借用资金费尾差账户。

## 第 3 层：每笔成交冻结角色与费率而非信任订单标签

**面试官：** 你按丁的 Taker 费率算了 0.2。若客户端声明自己是 Maker，或者同一订单先吃单、后挂单，重试时又升级费率等级，旧 fill 怎么办？

**面试者：** 以撮合对每个 fill 确认的流动性角色为准，客户端标签不产生优惠权。订单可以先有 Taker fill，再有作为挂单成交的 Maker fill，两笔各自绑定 `fee_schedule_version`、账户优惠资格证据、角色、数量、价格及舍入规则。后续升级等级只能依生效协议影响未来成交，不能在重放旧 fill 时读取最新配置。对同一费用效果键，原角色、费率或金额摘要不一致必须冲突隔离，而非新增效果或覆盖历史。准入时可预留估计费，但最终金额仍须依据已确定成交，估计与实收的差额不能留下重复占资。

## 第 4 层：成交经济效果与费用对手科目共同提交

**面试官：** 费率已冻结，账务若先更新仓位，再扣丁手续费，中途崩溃会怎样？怎样防止仓位已成、费用却永远漏记？

**面试者：** 在本题同库条件下，同一成交的双方仓位、成本、毛交易盈亏、现金、费用对手科目、效果去重及 Outbox 共同提交，并更新 `position_version、cash_version` 和持久风险待办。事务失败全回滚，权威 fill 仍保留为待结转义务，以原身份重试；提交成功但回执丢失则查询原效果，不能撤销成交。不能只扣用户而忘记平台收入，或先宣告新现金可提再补费用。本例在 S5000 之后，成交执行和结转都排在 F0800 APPLIED 后；屏障解除也不代表风险门禁解除，新增仓位仍需满足当前准入资格。

## 第 5 层：负 Maker 费是成交补贴而非负资金费

**面试官：** 你提到平台费用对手科目。戊的 Maker 费率 -0.01%，本笔算出 -0.1；谁承担这笔信用，资金不足能否临时把它改成零？

**面试者：** 仍按成交手续费类型记录 `fee_signed=-0.1`，用户现金变化是 `-fee_signed=+0.1`，平台记 Maker 补贴支出，不是向 F0800 的付款方再收 0.1，也不是渠道返佣。资金能力和授权应在允许这类费率成交前落实，不能靠科目名称制造可支用现金。若准入前发现额度不足，应限制未来交易或按明确版本切换未来费率；已经确定的 fill 不能追溯改成零，也不能只完成丁扣费而漏付戊。结转遇阻时保留完整成交义务和风险门禁，受控补足后按原身份恢复，不能谎称双方已结清。

## 第 6 层：渠道返佣引用源费用且与 Maker 补贴分开

**面试官：** 戊的 0.1 已归成交补贴。渠道也要求拿钱时，如何定义基数、稳定身份和总预算，避免同一笔收入被无限分发？

**面试者：** 本题渠道分配的是丁已确认实收手续费 0.2 的 20%，为 0.04，不是戊负手续费的 20%，更不是资金费。稳定 `rebate_id` 绑定源手续费效果、受益人和合同分配项；规则版本放载荷，重试不另造身份。渠道归属及资格在约定时点冻结，单个分配项只入账一次，所有项合计受可分配收入和预算上限约束。异步处理时先记平台渠道应付，再将应付转为受益人余额，两个阶段不是再付两次；本笔的最终平衡是丁 -0.2、戊 +0.1、渠道 +0.04、平台净留 +0.06，总和零。

## 第 7 层：区分毛损益、净损益与风险可用资格

**面试官：** 钱的平衡明确了。丁、戊本次都是开仓，毛交易盈亏为零，页面能否说没有损益？渠道应付还没到账，又能否先用来开仓？

**面试者：** 毛交易已实现盈亏为零，不代表费用没发生。报表可定义净已实现收益为“毛交易盈亏－有符号成交费＋资金费现金变化＋本账户已确认渠道收益”，但各分项独立展示；费用不能既塞入入场成本，又在净额中再扣一次。渠道应付未转入受益人可用子账前，不当其抵押。成交或返佣入账时都同事务提升现金版本并写风险待办；owner 用当前仓位、订单、Mark 和规则重算，版本匹配才解除对应 pending，旧结果不得放开新门禁。平台资金承接、债务和处置限制还要独立满足，现金入账不是无条件可提承诺。

## 第 8 层：按原身份重放并核对跨类别资金归因

**面试官：** 渠道分配异步、风险也异步。若手续费消息和返佣消息都重复，且期间费率升级，怎样手工推演是否重复付钱或提前放行？

**面试者：** 固定原 fill、费率和渠道资格重放：丁仍只扣 0.2，戊仍只加 0.1，渠道应付与实际划入总共只确认一份 0.04，平台净收入仍为 0.06。同身份新费率应冲突而不是再扣一笔；每笔费用有源事实、对应平台科目和版本，F0800 的资金费效果完全独立。令返佣入账先于旧风险结果返回，旧结果不得解除新现金版本的限制。再检查开仓成本未掺入手续费、净收益只归属本账户、托管资产与实际付款来源能覆盖责任。若两次 Outbox 令渠道多收 0.04，或用资金费尾差补 Maker 支出，就直接推翻防重和归因设计。

## 本题收束

- **机制：** 成交基数决定手续费，负 Maker 费由平台承担，渠道返佣另立来源与身份；费用与风险资格分别提交、确认。
- **易错边界：** 按委托量扣费、将费率放进去重键、把 Maker 返利当渠道返佣或负资金费、用毛盈亏冒充净收益，以及应付未兑现就开放抵押。
- **反例检验：** 同一 fill 重放不得改变 `-0.2/+0.1/+0.04/+0.06=0` 的最终分配；若净额能平却找不到各方来源，仍不能证明账正确。以上金额为手工推演，不是生产经历或工程测试结果。
