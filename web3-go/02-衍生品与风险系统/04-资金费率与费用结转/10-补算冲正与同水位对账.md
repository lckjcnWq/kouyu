# 大问题 10：漏算、错算怎样补记、冲正和对账？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 资金费／手续费／借款利息 | 资金费是多空持仓间的周期转移，用于影响持仓激励；不是成交服务费或借款计息。 | 补记和冲正修的是原资金费事实，不能混成一次新成交的费用。 |
| q、M、f／收付符号 | 带方向数量乘参考价、周期费率得到应付 D，现金变化为 -D。 | 本文多正空负、正费率多付空收；+5×2,000×0.0001 应付 1 USDC。 |
| F0800／S5000 | F0800 是原资金费周期，S5000 是该周期的逻辑资格截止线。 | 不是用发现错误当天的仓位，平仓后零仓也不能抹掉历史义务。 |
| SEALED／READY／APPLIED | 分别是输入封存、计划验好、资金事务提交。 | 冻结费率、确定仓位归属、实际入账是不同事实，纠错先查最后一项是否成立。 |
| 补做／冲正／追加调整 | 未提交的原义务按原身份补做；已入账错误以新分录抵销或更正。 | 冲正不等于删原账，基线也不允许把半批提交当普通漏几行处理。 |
| 提交未知／权威库行锁 | 网络超时不证明失败，权威库的周期锁让恢复者等原事务定局。 | 普通查询一时没看到效果不等于能再扣，要查原状态、摘要与提交版本。 |
| 历史检查点／事件回放 | 检查点保存可信历史起点，回放按原序列还原后来变化。 | 重建到 S5000，补齐前序并排除后序，不拿当前仓位补历史缺页。 |
| PAUSED／顺序事故 | PAUSED 是保留原阶段并注明暂停；顺序事故是后序越过未完成的前序义务。 | 历史证据不足就阻断，不能靠直接扣当前余额掩盖屏障失效。 |
| plan_hash／原效果键 | plan_hash 校验原完整计划，效果键确定周期内单项经济变化。 | 原周期补做只能用原冻结证据和身份，不改价、不换摘要。 |
| adjustment_id／审批依据 | 调整有独立编号，记录谁批准、为什么改、引用哪条原效果。 | 相同 ID 同载荷重试返回原结果，不同载荷拒绝。 |
| 目标总效果／目标调整累计 | 目标总效果是最后应有多少；目标调整累计是相对原账一共应改多少。 | 原效果 O、应有额 C，则目标调整累计 T=C-O，不能把两种目标混用。 |
| 已调整累计 A／本次差额 | A 是此前已经提交的修正总和，本次只补到目标所需的差额。 | 本次为 T-A；已调 +0.20，目标调到 -0.60，新增 -0.80 USDC。 |
| adjustment_version／比较并交换 | 版本标记累计调整进度，比较并交换只在预期版本未变时更新。 | 并发审核先锁定并重读累计，旧目标需重审，不能两方重复补同一差额。 |
| 双边分录／整组守恒 | 每项变化都要有对应资金去向，整组金额合计相抵。 | 不只修某用户一行，要计算完整相关清单及对应项后共同提交。 |
| 尾差／逐单元舍入 | 尾差只承接合法量化残差，舍入按每个风险单元应有额执行。 | 尾差也按新旧目标和已调累计算差，不能吞掉缺失交易对手或凭空造钱。 |
| 同库事务／Outbox／risk_pending | 同一数据库共同提交账务、通知待发箱和风险待办。 | 调整余额、累计版本、审批引用与门禁一起生效，旧风险确认不能放开新门禁。 |
| 欠款／真实缓冲 | 扣款不足产生债权，收款的可用性需要真实授权资金承接。 | 无承接能力就暂停整组调整，不能无来源增加可划出资金。 |
| 水位 W／一致性快照 | W 是固定账本截止位置，一致性快照让比较对象处在同一历史截面。 | 只比较截至 W 已提交的效果，审批中目标不混入已实现结果。 |
| 查询投影／恰好 W | 投影是派生查询视图；追过 W 不等于还能读出 W 时的值。 | 要能读取恰好 W 的状态，否则等待或重建，不能误报时间差为账差。 |
| 审计链／全事件重放 | 审计链串起发现、证据、审批和新分录；余额重建要覆盖全部经济事件。 | 不只重放旧资金费，还包括截至 W 的后续成交及其他费用；不改成交价或覆盖原账。 |

## 把整篇文章压缩成一个故事

1. 页面像是少了一笔 F0800，先别重扣。资金费是持仓间的周期转移，不是手续费或借款利息；按本文多正空负、正费率多付空收的约定，甲 +5 ETH、参考价 2,000、周期费率 0.0001 原应付 1 USDC。费率封存、仓位归属都不证明已经入账，先到权威库查原事务结果。

2. 确认没提交，才按原屏障证据、原计划和原效果键补做；历史缺页要回放，不看今天零仓。若已 APPLIED，就保留原账，审批后追加调整。例中此前调整累计 +0.20，目标调整累计 -0.60，本次只加 -0.80；这个目标是“累计修多少”，不是“原费用最终是多少”，并发请求也不能各补一次。

3. 调整双方、尾差、余额和风险待办共同提交，有欠款还需真实缓冲。最后固定水位 W，比较同一截止处的原账、历次调整和完整事件重放结果。不能拿最新余额硬比旧快照，也不能改成交价、删分录或把未审批目标当作已生效资金。

[返回专题总览](README.md)

**必要前提与边界：** 沿用总览的 ETH-USDC 线性永续、UTC 8 小时周期、结算屏障与冻结快照；周期资金费、尾差账户、效果幂等及风险门禁位于同一个支持事务的关系数据库。此题区分“周期尚未 APPLIED，旧周期补做原效果”和“已经 APPLIED，追加纠错效果”，不以当前仓位代替历史快照，也不覆盖原账。链上履约和跨库纠错不在此基线内。

**流程位置与核心机制：** 对应周期关闭后的恢复与核对。核心是先判定原资金效果是否提交，再以稳定身份补做或以新调整身份追加目标差额，最后在相同事件水位比较完整清单与账本。

## 第 1 层：先区分漏做与已入账错误

**面试官：** 发现 F0800 可能有错，你怎样判断应补算还是冲正？

**面试者：** 先查主库的周期状态、原 `plan_hash`、效果记录及账本提交版本，不能只看页面余额。确认原事务已结束且未提交、没有资金效果，才按原周期补做；提交结果未知时先锁定周期行查明，不能因一次未查到就重扣。若已 APPLIED，即便回执或投影缺失，资金效果也已成立，纠错必须追加新调整并关联原效果，不得覆盖旧分录。基线不允许同周期部分效果提交；真发现这种状态应隔离为一致性事故，而非把漏掉的几行直接补进账。

## 第 2 层：旧周期缺少快照时怎样还原

**面试官：** 如果查到 F0800 从未入账，但历史持仓快照文件缺了一页，能否用现在的仓位补齐？

**面试者：** 不能。应从有校验的历史检查点按权威事件序号回放到 S5000，确认全部前序事件已结转、后序事件未混入，重建完整风险单元清单、数量、版本和摘要，并匹配冻结的费率、价格及规则。历史不足以证明完整性就阻断：尚未封存留 WAIT_INPUT；已 SEALED／READY 则保留阶段并标 PAUSED，不能倒退或覆盖证据。原屏障和资金门禁仍有效；若发现后序交易已经越过未入账周期，应隔离为顺序事故，不能只凭重建快照直接补扣当前余额。

## 第 3 层：尚未入账的原周期如何补做

**面试官：** 重建了完整历史快照，但补算 worker 在计划生成后、账务提交前崩溃，怎样重试才不会改出另一笔费用？

**面试者：** 查明原事务未提交，再按 SEALED 证据、快照摘要及算法版本重建；排序、整数舍入和尾差规则固定，已有 READY 的 `plan_hash` 必须相同，尚无 READY 则全量校验后封存。应用器校验屏障、任期和周期状态，以 `cycle_id/risk_unit/USDC/FUNDING` 等原效果键在单事务补做，唯一约束防重。摘要冲突就隔离，不能重定价。若 SEALED 输入本身有错，保留原证据与暂停状态，交审批明确原效果及追加调整的处理；不能改写原摘要后宣称是相同计划重试。

## 第 4 层：已入账错误怎样计算追加差额

**面试官：** 若 F0800 某个效果此前已累计调整 +0.20 USDC，复核后确认该效果总计应调整到 -0.60 USDC，本次应该再记多少？

**面试者：** 以原效果为锚点保存复核后的目标调整累计 `target_adjusted_cumulative`，汇总该原效果此前所有已提交调整 `adjusted_cumulative`，本次新调整为 `target_adjusted_cumulative - adjusted_cumulative`。本例应再记 -0.80 USDC，使历次调整合计达到 -0.60；这不同于把原始效果也计入后的目标总效果。每次创建全新的 `adjustment_id`，记录原 `effect_key`、原周期、目标累计、调整前累计、计算所得差额、依据与审批。相同 ID 同载荷重试返回原结果，同 ID 不同载荷必须拒绝。

## 第 5 层：两个纠错请求并发怎样防止超调

**面试官：** 两个审核员几乎同时针对同一原效果提交新的目标金额，怎样避免它们都按旧累计值计算差额？

**面试者：** 在同一数据库事务中锁定原效果的调整汇总行或使用可比较并交换的 `adjustment_version`，重新读取已提交的累计调整，再算目标差额；同时对 `adjustment_id` 建唯一约束，对原效果的目标版本／审批请求建立明确的并发裁决规则。若两个不同请求基于不同依据，后提交者必须在锁内发现目标版本已变化并重新审核或拒绝，不能仅因 ID 不同就都通过。周期、原效果、账户和尾差账户按稳定键顺序加锁，防止死锁；事务失败后从新版本重算，不复用过期差额。

## 第 6 层：双边分录、尾差与风险状态怎样共同提交

**面试官：** 纠错只改变了一个用户的金额，怎样保证不会形成无对应收款方的资金？

**面试者：** 先对完整历史清单按批准的修正规则计算应有入账额 C，原效果为 O，则目标调整累计 T=C-O，本次差额为 T-A，A 是已提交调整累计。按固定规则只对各单元应有额舍入，不对分页再舍入；尾差也以新旧目标之差扣除已调累计，整组变化必须为零，不能拿尾差账户吞掉缺失的交易对手。收付双方、尾差、全部调整 ID／原效果引用、累计版本、审批、余额、risk_pending 与 Outbox 在同一事务提交。扣款方欠款须同步识别并占用真实授权缓冲；无承接能力就入账前暂停整组，禁止凭空增加可划出资金。

## 第 7 层：为什么必须在同一水位对账

**面试官：** 纠错提交后，用户又成交、平仓并发生下一周期资金费；你怎么确认 F0800 已经对平？

**面试者：** 固定账本提交水位 W，按 S5000 快照和截至 W 已生效的批准版本复算目标，对照 F0800 原效果、截至 W 的全部调整及用户、尾差分录，逐项核对清单、金额和摘要；尚未提交的审批目标另列待处理义务，不混进已实现效果。核对余额时，从已核对起点重放截至 W 的所有经济事件，包含后续成交和其他费用，不能只重放 F0800。账本使用一致性快照；投影既要追到 W，也要能读到恰好 W，否则等待或重建。先定位首个缺页、重复键或金额差异，不能把水位差当欠款。

## 第 8 层：如何关闭纠错并验证边界

**面试官：** 最后怎样让这条修复链可审计、可关闭，并证明没有把旧周期错误地算到新仓位上？

**面试者：** 将发现、分类、原证据、差异清单、审批、新 `adjustment_id`、目标减累计公式、事务版本、风险确认和同水位摘要串成追加审计链。未入账周期等原效果完整提交并核对后关闭；已入账纠错保留原 APPLIED，调整提交后按当前账户版本重算，旧风险结果不能解开新门禁。易错边界是回执丢失不等于未提交、当前仓位不是历史仓位、重试不是新调整。反例推演：已入账后甲平仓，纠错仍按 S5000 的 +5 ETH 算目标；两个请求并发把累计 +0.20 调到 -0.60，应合计只新增 -0.80，而非各记 -0.80。
