# 保证金、杠杆与逐仓全仓：专题总览

<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

> 先记三句话：保证金是承担交易风险的钱；杠杆描述仓位相对保证金有多大；逐仓和全仓决定哪些钱一起扛。下列数字只沿用本文教学模型，不是实际行情或所有平台的统一规则。

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| ETH / USDC | ETH 是交易标的；USDC 是目标锚定美元的稳定币，不是无风险现金。 | 数量用 ETH，保证金和盈亏用 USDC。 |
| 现货 / 永续合约 | 现货是买到资产；永续是没有固定到期日、按价格变化结算盈亏的合约。 | 开 1 ETH 合约仓位，不等于钱包收到 1 ETH。 |
| 线性合约 / 乘数 | 固定数量下，价格每变化一单位，盈亏按固定比例变化；乘数负责换算一份合约代表多少标的。 | 本例乘数为 1，1 ETH 多仓遇到价格跌 16，就亏 16 USDC。 |
| 链下托管 | 资金由平台托管，主要交易与记账在平台内部完成。 | 不能把数据库提交直接说成链上最终结算。 |
| 开仓 / 平仓 / 多空 | 开仓是建立交易，平仓是减少或结束交易；多仓涨价赚，空仓跌价赚。 | 主例在 100 开 1 ETH 多仓。 |
| 单向净持仓 | 同一市场按一个净方向计算仓位。 | 卖出可能先平多，超过原多仓后再开出空仓。 |
| 保证金 / 抵押品 | 拿来支撑交易、承担损失的资金或资产，不是交了就没了的手续费。 | 本例只用 USDC，不混入其他币的价格折扣。 |
| 杠杆 / 名义敞口 N | 敞口是承担的价格风险规模；杠杆是这个规模与相应保证金或权益的比例。 | 开仓价值 100、所需保证金 20，对应 5 倍；亏损不再乘 5。 |
| 逐仓 Isolated / 隔离桶 | 给某个仓位圈出专用风险资金，桶外资金不自动参与。 | 只分配 20，外侧另 20 没有划入就不能拿来算该仓权益。 |
| 全仓 Cross / 风险池 | 约定范围内的资金与仓位一起算风险、一起承担损失。 | 同池 40 共同支撑，不等于所有子账户或全平台互保。 |
| Entry / Mark | Entry 是入场价；Mark 是风险估值使用的标记价格。 | 按 84 算风险，不代表一定能按 84 平仓。 |
| 未实现盈亏 U / PnL | 没平仓时按当前价格算的浮盈浮亏；PnL 是盈亏的英文简称。 | 从 100 跌到 84，U 为 −16，不是已经又发生一笔现金扣款。 |
| 已实现盈亏 / 账本余额 | 已按规则确认的损益进入正式资金流水；余额包含已经结算的结果。 | 已结算亏损不能再当作浮亏扣第二遍。 |
| Equity / E / 权益 | 把池内余额与浮盈浮亏合起来，看现在按估值还剩多少。 | 逐仓为 20−16=4；全仓为 40−16=24。 |
| IM / IMR | IM 是扩大风险所需的初始保证金金额；IMR 是对应比例。 | 本例 IMR 为 20%，Mark 为 84 时现仓 IM 为 16.8。 |
| MM / MMR | MM 是现有仓位的维持保证金要求；MMR 是对应比例。 | 本例 MMR 为 5%，Mark 为 84 时 MM 为 4.2。 |
| Available / 可提现额 | 前者是按规则还能用于新增风险的额度；后者是实际允许转走的钱。 | 本文可用额为权益减 IM、额外挂单预留和其他锁定，不能直接当提现余额。 |
| 挂单 / 撮合 / 部分成交 | 挂单是未全部成交的订单；撮合是买卖配对；部分成交是只执行了一部分。 | 请求买 1 ETH，不代表已经持有 1 ETH。 |
| 预留 reservation / R | 订单未成交前，先占住可能需要的额度，防止重复使用。 | 成交后转换成仓位风险占用，不再保留同一部分的完整订单预留。 |
| Reduce-Only / 只减仓 | 订单只能减少已有仓位，不能越过零后反手开新仓。 | 两张卖单共享同一份可减数量，不能各自都声称能卖掉全部原仓。 |
| 划转 / 模式迁移 | 划转改变钱属于哪个资金范围；模式迁移改变哪些钱和仓位共同承担风险。 | 需要正式记录，不能只改一个逐仓／全仓显示字段。 |
| 风险处置 / 强平 / 穿仓 | 处置是风险流程；强平是强制减仓或平仓；穿仓是损失超过可承担资金出现缺口。 | 权益不大于 MM 仅表示触发，不代表已经成交，也不承诺逐仓永不穿仓。 |
| owner / 原子预留 / TOCTOU | owner 是状态负责人；原子预留把检查和占额做成整体；TOCTOU 是查完到使用之间被插队。 | 剩 20 时两笔各需 15，不能都依据旧余额放行。 |
| 版本 / 水位 / 快照 | 标明每份数据处理到哪一步，并组成一份有因果依据的状态。 | 最新余额与旧仓位不能随便拼成“最新风险”。 |
| 定点数 / 舍入 / 档位 | 按固定精度算钱，明确小数取整方向，以及不同规模用哪组要求。 | 临界值的一分钱或更小单位，都可能改变风险结论。 |
| 幂等 / Inbox / Outbox | 同一请求反复来只生效一次，并可靠记录收件与待发送结果。 | 响应丢了按原编号查询，不再预留或结算一次。 |
| owner epoch / fencing / 重放 | 负责人代次、阻止旧负责人写入的围栏，以及按历史事件恢复状态。 | 换主后旧节点复活，也不能再次花掉同一额度。 |
| MVP / 不变量 | MVP 是只演示核心的最小例子；不变量是任何操作都不能破坏的规则。 | 本文只给简化估值例子；“同一额度不能用两次”等还需独立验证。 |

## 把整篇文章压缩成一个故事

小林有 40 USDC，想在 ETH 价格为 100 时开 1 ETH 多仓。这里买的是合约风险，不是真的借钱买到一枚 ETH。按本文 20% 的初始保证金率，这笔交易需要 20 USDC，开仓名义规模相对所需保证金是 5 倍。系统先把订单可能用到的额度占住，成交后再更新正式仓位；占额度不是扣手续费，受理订单也不是已经成交。

小林可以选两个独立方案：逐仓只给这笔仓位分配 20，剩余 20 留在外面；全仓则让共享池里的 40 一起支撑。同样从 100 跌到标记价 84，两种方案的仓位都浮亏 16，逐仓权益剩 4，全仓剩 24。此时维持保证金要求是 4.2，所以逐仓触发本文的处置条件，全仓没有；这不是逐仓多亏了，而是可参与承担风险的钱不同。

故事后半段都在防程序把这些钱算错：并发订单不能重复占用，逐仓外的钱必须正式划入才可使用，成交和撤单不能把同一额度退两次，风险计算不能拼接新旧数据。系统故障后也要按原编号和连续记录恢复。即使判断要强平，实际成交价和最终缺口仍要等真实执行确认，不能把标记价当成交保证。

## 一、文字全流程：保证金风险如何从下单走到可解释的账户结果

### 1.1 讨论基线

采用**链下托管、线性 USDC 永续、单向净持仓、单一 USDC 抵押品**作为教学基线。交易撮合、账本和风险计算由链下系统负责；这不代表目标公司或所有 DEX 的实际架构。订单簿还是池式成交不改变本文的保证金计算边界；链上合约权威、反向合约、多抵押品和组合保证金不混入主例。

- 合约为 `ETH-USDC-PERP`，数量单位 ETH，价格单位 USDC/ETH，乘数为 1；正数量是多仓，负数量是空仓。
- 账户初始有 40 USDC。主例买入 1 ETH，成交价 100 USDC；比较两种独立账户模式：逐仓只向该仓划入 20 USDC，剩余 20 USDC 留在账户外侧、不参与这笔逐仓风险；全仓的 40 USDC 都属于同一个 Cross 风险池。
- 教学初始保证金率 `IMR=20%`，对应最大名义杠杆 5 倍；维持保证金率 `MMR=5%`。无风险档位，仓位和订单均不触发额外费用。真实协议的档位、费率、手续费预留和舍入必须按版本化规则定义，这两个费率不是行业通用值。
- 资金费和交易费用取 0；不存在其他仓位、挂单、未结算成交、抵押品折扣、未结费用或外部资金变化。Mark Price 有效且新鲜。
- 已实现盈亏、费用和资金费一旦结算，已包含在各自权威账本余额中；计算权益时不重复加一次已结算项目。Mark 产生的未实现盈亏只用于估值与风险，不直接成为现金。
- 本例约定当风险权益 `E <= MM` 时进入“需风险处置”状态。该状态是风险裁决，不表示强平已成交；强平工作流由相邻专题负责。

### 1.2 贯穿案例与数值口径

线性合约本例的未实现盈亏为 `U = q × (Mark − Entry) × multiplier`。名义价值 `N = |q| × Mark × multiplier`，初始保证金需求 `IM = N × IMR`，维持保证金需求 `MM = N × MMR`。由于只用 USDC 抵押且无折扣，权益是权威抵押余额加未实现盈亏。

| 阶段 | 逐仓：仓位 / 保证金桶 | 逐仓权益 / MM | 全仓：仓位 / 共享抵押余额 | 全仓权益 / MM |
|---|---|---:|---|---:|
| 开仓成交，Mark=100 | 多 1 ETH，划入 20 USDC | 20 / 5 | 多 1 ETH，池内 40 USDC | 40 / 5 |
| Mark=90 | 多 1 ETH，未实现盈亏 -10 | 10 / 4.5 | 同一仓位，未实现盈亏 -10 | 30 / 4.5 |
| Mark=84 | 多 1 ETH，未实现盈亏 -16 | 4 / 4.2，触发风险处置 | 同一仓位，未实现盈亏 -16 | 24 / 4.2，未触发 |

开仓时名义价值为 100，初始保证金需求为 20，故开仓名义杠杆为 `100 / 20 = 5`。价格到 84 时，逐仓权益 4 已低于维持保证金 4.2；全仓还有共享池里的额外 20 USDC，权益为 24。该对比只说明风险池边界不同，不说明全仓没有风险：若共享池内其他仓位也亏损，损失会共同消耗这 40 USDC。

杠杆不是盈亏乘数。价格从 100 跌到 84，两个模式的这笔仓位均亏 16 USDC；5 倍只描述开仓名义敞口相对初始保证金的比例。它影响准入和风险缓冲，不把线性合约的盈亏公式改成 `16 × 5`。Mark=84 时逐仓的当前权益杠杆为 `84 / 4 = 21`，这描述权益变薄后的风险，不代表用户又修改了开仓杠杆档位。

按此简化公式，逐仓风险边界满足 `20 + (P−100) = 0.05P`，交点约为 `P=84.210526`。这只是忽略费用、档位、资金费、价格跳跃和执行滑点的连续估算；不能宣称该价格一定成交或等于生产系统显示的强平价。

### 1.3 主流程：从开仓意图到风险状态更新

```text
用户提交开仓／加仓／减仓意图
    ↓
接入校验〔账户模式、合约、方向、价格数量精度、权限〕
    ├─ 参数或权限不合法 → 拒绝，不创建风险预留
    └─ 合法 → 进入所属风险池的有序裁决
                    ↓
读取同一风险版本的账本、仓位、挂单预留、有效价格与参数
                    ↓
检查操作后的 IM、杠杆上限与仓位限额
    ├─ 扩大风险且额度不足 → 拒绝或缩量，不进入撮合
    ├─ 风险输入不可信／版本缺口 → 禁止扩大敞口，转入保护策略
    └─ 满足规则 → 原子建立带身份、额度和版本的风险预留
                    ↓
订单进入撮合；部分成交按成交量消耗预留，剩余量继续占用
    ├─ 撤单／过期得到权威确认 → 仅释放未成交剩余预留
    └─ 成交确定 → 持仓与账本按成交身份结转，更新风险输入版本
                    ↓
风险引擎按所属风险池重算 Equity、IM、MM、Available 与状态
                    ↓
版本化风险结果交付；查询视图可随后追上
```

逐仓风险池以一个被隔离的仓位／产品风险单元为边界；全仓以账户或产品定义的共享 Cross 池为边界。本例假设逐仓是一仓一池、全仓是一子账户内单一 USDC 资产的共享池。订单、账本、持仓、风险服务可以物理部署在一起或分开，但必须对风险池身份、事件顺序、预留和提交语义达成一致。

### 1.4 主要拒绝与失败分支

```text
校验拒绝 → 不撮合，不预留；返回明确原因

风险预留已提交但响应超时 → 用原命令身份查询／重试；不得当作未预留后再花一次额度

预留成功但撮合受理结果不确定 → 查询原订单和受理状态；不能仅因超时释放预留

部分成交后撤单 → 先按权威顺序裁决成交与撤单；结转已成交量，只释放确认撤销的余量

成交确定但账本／持仓结果未送达风险引擎 → 保留未结转义务或保守风险占用；重放同一成交身份并核对版本

风险结果已提交但通知丢失 → 不重做风险状态；按同一结果身份继续交付，投影按版本追赶
```

Mark 陈旧、价格来源冲突或风险参数版本不一致时，禁止扩大风险并转入事先定义的保护策略。预留不等于扣掉经济资产，风险需求不等于账本流水，订单受理也不等于成交。已确定成交是履约事实；不能因风险重算失败就把成交或持仓改回去。相反，客户端超时也不能作为释放保证金的证据。

### 1.5 完成含义不能混用

| 阶段 | 已经承诺什么 | 还没有承诺什么 |
|---|---|---|
| 订单受理 | 订单意图进入确定的处理流程 | 不保证成交，更不保证有仓位 |
| 风险预留提交 | 指定额度已被风险池占用 | 不代表撮合成交或账本扣款 |
| 成交提交 | 成交事实及其结转义务已经确定 | 持仓、账本、风险视图不一定已追上 |
| 风险状态更新 | 风险计算到指定输入和参数版本 | 页面不一定可见，执行也不保证能按 Mark 成交 |
| 查询更新 | 投影到达指定风险结果版本 | 不能代替权威风险准入或强平执行 |

## 二、核心板块：决定共享风险边界与可交易额度

| 核心板块 | 决定什么／为什么核心 | 权威状态或产物 | 上下游契约 |
|---|---|---|---|
| 风险池与保证金模式 | 哪些抵押物和仓位共同承担损失 | `risk_pool_id`、保证金模式、成员关系与模式版本 | 逐仓隔离或全仓共享必须在预留、估值、划转和处置上保持同一边界 |
| 账户权益与保证金需求 | 仓位及订单能否承受损失、还能否扩大敞口 | 权威账本余额、仓位、挂单预留及版本化 `RiskResult` | 输入来自账本、持仓、订单、价格和风险参数；输出带完整版本和原因码 |
| 杠杆与订单预留 | 将名义敞口限制在已批准的初始保证金额度内 | 杠杆上限、风险额度、reservation 身份和剩余额度 | 下单检查与额度占用须在同一排序边界；成交消耗、撤单释放不得重复 |
| 价格与参数证据 | 确保风险判定使用有效、可复现的输入 | Mark 身份／时间／质量、IM/MM 档位和参数版本 | 价格失真或配置半更新时不能静默用“最新值”拼接风险快照 |
| 风险状态交付与恢复 | 重复、乱序、超时或切主后不重复用额度、不漏处理成交 | 事件序号、Inbox／Outbox、检查点、owner epoch | 风险结论可重算；强平状态机只消费确定的触发结果，不由扫描器旁路改账 |

## 三、核心 20%：优先掌握的机制

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| 保证金术语与单位 | 风险计算 | Equity、IM、MM、Available 各回答不同问题 | 把余额、权益和可用额混为一谈 | 资产余额、未实现盈亏、挂单预留、单位与计算口径 |
| 杠杆与名义敞口 | 下单准入 | 决定最大可开的仓位和缓冲，不改变合约盈亏公式 | 误把杠杆当作 PnL 乘数或借款本金 | `notional / initial margin`、限额、档位与风险增量 |
| 逐仓／全仓风险池 | 风险聚合 | 决定损失传播和一致性／并发边界 | 逐仓越界动用他仓资金，或 Cross 漏聚合共享仓位 | 风险池成员、共享抵押、隔离承诺、划转与切换 |
| 风险预留及成交转换 | 下单至结转 | 防止同一额度被并发重复使用 | TOCTOU 超开、成交和预留重复计入 | 原子准入、部分成交消耗、撤单余量释放 |
| 同版本风险快照 | 持续风险判定 | 各自最新的余额、仓位、价格可能从未同时存在 | 错误拒单、漏平或误触发 | 输入版本、水位、参数版本、快照摘要 |
| 精度、档位与阈值 | 数值裁决 | 临界值一单位误差即可改变交易资格 | IM 低估、available 虚增、风险判定跨语言不一致 | 定点数、方向性舍入、溢出、档位边界 |
| 模式迁移与资金划转 | 账户操作 | 改变资金归属和潜在损失承担者 | 资金重复计入、迁移中仍能开仓或强平错对象 | 显式账务分录、冻结条件、迁移版本与回滚 |
| 故障与恢复 | 持续运行 | 内存锁和消息 offset 不能证明额度只消费一次 | 双主、迟到成交或重试后风险状态漂移 | 权威日志、去重、提交点、fencing 与重放 |

“20%”表示正确性机制集中，不是章节配额。Mark Price 异常与系统降级在本专题只覆盖它们如何影响保证金裁决；价格聚合算法和强平执行流程分别由行情／强平专题完整展开。

## 四、共同设计与规则

### 4.1 公式与业务约束

本例金额与价格用 USDC 和 USDC/ETH 表示；实际实现应固定各字段 scale、合约乘数、档位选择和舍入顺序。

```text
线性合约未实现盈亏 U_i = q_i × (Mark_i − Entry_i) × multiplier_i
名义价值 N_i           = |q_i| × Mark_i × multiplier_i
初始保证金 IM_i        = N_i × IMR_i(position_tier)
维持保证金 MM_i        = N_i × MMR_i(position_tier) + 明确约定的附加项

Cross Equity = 池内账本确认的折后抵押／现金净值 + Σ U_i
               〔余额已包含结算后的 PnL、费用、资金费和划转〕
Isolated Equity_i = 该隔离桶账本确认余额 + U_i

Cross IM = 风险池内当前仓位的初始保证金需求
Cross MM = 风险池内当前仓位的维持保证金需求之和
Cross Available = Cross Equity − Cross IM − 未成交订单的增量风险预留 R − 其他锁定额

Isolated Available_i = Isolated Equity_i − 该仓 IM − 未成交订单的增量风险预留 R_i − 其他锁定额
本例处置条件：对应风险池 Equity <= MM
```

`R` 是按当前版本评估的未成交订单增量风险需求；主例无挂单，所以为 0。同价、固定 Mark 的同向加仓可以简化为增量 IM；若允许的成交价不利于 Mark，还要覆盖成交带来的权益损失，不能只用订单限价乘 IMR。多笔订单按产品允许的可达成交路径统一计算，具体教学包络见[母题02](02-杠杆额度与初始保证金.md)；新增订单不得提前兑现未成交减仓的收益或释放。

若订单预留已计入聚合 IM，就不能再次从 Available 扣一次；字段模型必须定义它是“已折入”还是“额外扣减”。成交时应把对应订单约束转换为已成交仓位及必要的结转义务，而非同时保留两份或在交接中漏掉风险。真实多资产账户还需明确抵押品折扣、汇率、集中度、风险档位、强平费用和信用负债；不得把这些在本例中默认为 0 后又在回答里悄悄加回来。

预留金额字段统一用 USDC 最小单位表达。对同一批准版本／额度分段，`approved_im = remaining_im + consumed_im + released_im` 记录额度的历史分配；其中 `consumed_im` 不是当前仓位 IM 的永久副本。Mark、仓位或参数变化后，需要按当前版本重算仓位及剩余订单的风险需求，补额或释放也必须有身份和版本。反向订单不能只按“全部成交后的净仓”评估：还要覆盖允许的部分成交路径、其他挂单的执行顺序与反手风险，或用可执行的 Reduce-Only 约束限制其资格。

必须成立的边界：

1. 任何扩大风险敞口的操作生效前，按目标风险池的一致状态满足初始保证金、杠杆和限额约束；Reduce-Only 等减险行为按产品语义单独判断。
2. 逐仓亏损只能消耗分配给该隔离风险单元的抵押和明确约定的风险支持；全仓可共享池内资产，也共同承担池内损失。逐仓不等于永远不会穿仓，全仓不等于所有子账户都互保。
3. 账户模式、仓位、余额、预留、价格和参数要有可比较的版本或水位；风险引擎不能以不同时间点的“最新数据”拼成假快照。
4. 同一订单的额度分段只能处于预留中、已消耗或已释放等互斥且可恢复的状态；订单可以同时含有这三类不同分段。数量满足原始量等于已成交量、已取消量与未决量之和；金额另按同一批准版本的预留守恒式核对，不能把数量和 USDC 金额直接相加。
5. 杠杆设置影响准入额度／保证金参数，不改变线性合约 PnL；权益、IM、MM、Available 和可提现额不得同名或互相替代。
6. 已确定成交不能因后续风险计算或通知故障而撤销；未确定的请求也不能因为超时就假定没有副作用。
7. 金额、价格、数量和费率用定点整数或有明确舍入语义的十进制计算；任何溢出、未知档位或精度超限均拒绝风险扩大并保留原因。

### 4.2 架构与状态所有权

```text
账本／抵押品域 ──余额版本、抵押归属、划转流水──┐
持仓／清算域 ───数量、成本、结转序号─────────┤
订单域 ───────挂单剩余量、预留身份─────────┤
行情域 ───────Mark、时间、质量、价格版本────┤
参数治理 ─────IM/MM 档位、限额、规则版本─────┤
                                                ↓
                                   风险池有序状态所有者
                                   ├─ 折叠风险事实／去重／校验版本
                                   ├─ 计算 Equity、IM、MM、Available
                                   ├─ 原子预留或拒绝风险扩张
                                   └─ 产生带证据的 RiskResult
                                                ↓
                      订单接入／用户查询／强平状态机／审计投影
```

领域职责可以分进程，但不要让多个服务各自写一个 `liquidatable` 布尔值。账本拥有现金事实，持仓拥有成交后仓位事实，订单拥有订单生命周期及其剩余量，行情域拥有带质量的价格事实，风险引擎拥有给定序列和规则版本上的派生风险状态与交易准入裁决。强平执行消费风险触发，不反向篡改触发输入。

逐仓的串行化键按风险池定义；本例是一仓一池。全仓的串行化键必须覆盖共享抵押和参与聚合的全部仓位／预留，不能仍按市场各算各的再相加后声称并发准入安全。若热门全仓账户计算成为瓶颈，需改变协调／额度设计并证明不变量，不能仅把 goroutine 数量调大。

### 4.3 核心对象与交互

| 对象 | 关键字段 | 权威与用途 |
|---|---|---|
| 风险池 | `risk_pool_id、mode、member_version、collateral_scope、policy_epoch` | 确定共担风险的账户／仓位集合及模式生效点 |
| 风险输入 | `account_seq、ledger_version、position_version、order_version、price_id、config_version` | 证明风险结果所使用的逻辑状态；序号缺口不允许越过 |
| 订单预留 | `reservation_id、order_id、risk_pool_id、approved_im、funded_remaining_im、required_remaining_im、consumed_im、released_im、decision_version` | 历史批准预算可对账；当前未成交风险需求按新版本重算，成交、撤单和过期竞争按身份裁决 |
| 风险结果 | `decision_id、equity、IM、MM、available、status、reason、input_digest` | 可审计、可复现的派生结果，不替代源事实 |
| 划转记录 | `transfer_id、from_pool、to_pool、amount、state、mode_version` | 显式改变抵押归属；不能仅改内存中的 pool id |

### 4.4 跨专题边界

- **持仓与账本：** 只用已经确定的成交、结算和划转更新权威事实。已实现 PnL 何时可用于风险额度，需要明确结转确认状态；不能从持仓投影猜现金。
- **交易前风控：** 负责订单风险预留、并发防超用和成交消耗契约；本专题的母题地图会覆盖接口边界，不重复完整订单状态机。
- **预言机与 Mark：** 风险输入必须包含新鲜度、质量、来源和版本。无效价格如何保护在本专题声明风险行为，不完整设计行情聚合。
- **强平与坏账：** `Equity <= MM` 表示触发风险处置条件，不等于已成交、已接管或债务已清偿；强平状态机和风险瀑布属于相邻专题。
- **链上合约权威：** 本基线为链下账本。若抵押和头寸以合约状态为权威，交易提交、区块确认、重组及最终性都要重新定义，数据库提交不能直接叫最终结算。

## 七、工程实践：唯一的简洁 MVP

### 7.1 目标与范围

用同一笔线性永续多仓，对照逐仓隔离桶和全仓共享池，在不同 Mark 下手算权益、IM、MM 和风险触发差异。示例不实现下单撮合、资金费、费用、档位、预言机、数据库或强平执行。

### 7.2 核心伪代码

```text
evaluate(mode, balance, qty, entry, mark, imr, mmr):
    若 qty == 0 或 entry <= 0 或 mark <= 0：返回输入错误
    若 imr <= 0 或 mmr < 0 或 mmr > imr：返回参数错误

    unrealized = qty * (mark - entry)       # 本例乘数为 1，线性 USDC
    notional = abs(qty) * mark
    initial_required = notional * imr
    maintenance_required = notional * mmr

    若 mode == ISOLATED：
        equity = balance + unrealized        # balance 仅为该仓隔离桶
    否则若 mode == CROSS：
        equity = balance + unrealized        # balance 为共享池已结算余额
    否则：返回未知模式

    available_for_new_risk = equity - initial_required
    status = NEEDS_RISK_ACTION 若 equity <= maintenance_required，
             否则 HEALTHY
    返回 {equity, initial_required, maintenance_required,
          available_for_new_risk, status}

iso = evaluate(ISOLATED, 20, 1, 100, 84, 0.20, 0.05)
cross = evaluate(CROSS, 40, 1, 100, 84, 0.20, 0.05)
```

伪代码中的 `balance` 必须在调用前由权威账本及池归属确定；它不是缓存余额、总资产估值或前端可提现数。这里 `HEALTHY` 只表示本次估值未触发 `Equity <= MM`，不表示允许加仓或提现；例如 Mark=90 时逐仓权益 10 高于 MM 4.5，但 Available 为 `10−18=−8`，仍不满足新增风险的 IM 门槛。生产级订单预留、抵押品折扣、档位、资金费和并发提交都明确不在这个 MVP 中。

### 7.3 输入与预期结果

| 输入 | 预期结果 |
|---|---|
| 逐仓余额 20、全仓余额 40；各自持有多 1 ETH，入场价 100，Mark=100 | 两者 `U=0，N=100，IM=20，MM=5`；逐仓权益 20，全仓权益 40，均未触发风险处置 |
| 相同状态，Mark=90 | `U=-10，N=90，IM=18，MM=4.5`；逐仓权益 10，全仓权益 30，均高于 MM |
| 相同仓位，Mark=84 | `U=-16，N=84，IM=16.8，MM=4.2`；逐仓权益 4，状态为 `NEEDS_RISK_ACTION`；全仓权益 24，状态为 `HEALTHY` |
| 逐仓余额仍为 20，但尝试把账户外侧 20 未划入资金直接加进风险计算 | 输入违反风险池归属，不得按余额 40 计算；必须先完成显式划转并产生新版本 |

这些是公式和预期值的手工推演，不声称伪代码已运行或性能验证通过。实际系统还要为阈值等值、风险档位切换、舍入方向、费用、资金费、并发预留及陈旧价格建立额外规则与验证。
