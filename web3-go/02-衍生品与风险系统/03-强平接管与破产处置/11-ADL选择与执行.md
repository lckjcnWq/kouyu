## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
| --- | --- | --- |
| 保证金、权益 E、MM | 保证金承担亏损；权益加上浮动盈亏；MM 是继续持仓的最低要求。 | 基线现金 20、Mark 84 时 E=4、MM=4.2，严格不足才触发复核，不代表亏光或成交。 |
| 多头、空头、反向敞口 | 多头跌价亏、空头跌价赚；反向敞口是同一合约相反方向的存续仓位。 | ADL 必须有仍待关闭的源多仓和合格空仓，不能凭空配对。 |
| 逐仓、线性 USDC 永续 | 按指定风险单元核算，盈亏线性计算并以 USDC 结算的永续合约。 | 只在此产品范围讨论，不承诺逐仓任何情形都没有额外缺口。 |
| Mark、close price | Mark 是风险估值；close price 是关闭仓位采用的价格。 | 本教学规则明确选有效 Mark 作配对关闭价，不是任何平台都按 Mark 成交。 |
| ADL、自动减仓 | 在协议规定条件下，按规则选中反向对手仓位进行被动减仓。 | 不是平台随意从盈利用户抢钱；额外损失承担还必须有事先规则和账务依据。 |
| 独立变体、基金可用额 | 独立变体是一条另行声明的案例路径；可用额是本路径真正能动用的基金。 | 此处基金为 0，先成交 0.5 ETH@78，不延续半仓@84 或覆盖 1.5 的案例。 |
| source、counterparty、basis | 分别是源账户、被选中的对手账户和每单位入场成本基础。 | 源余多仓 0.5、basis 100、现金 9；对手空仓 0.5、basis 90、现金 10。 |
| 浮盈、可实现利润、可分配利润 | 依次是估值盈利、按关闭计划预计实现的盈利、扣除其他义务后真正可承担损失的部分。 | 对手在 78 预计毛利 6，不等于现在就有 6 可随意扣走。 |
| 候选资格、可减数量 | 资格检查谁能参与；可减数量是仍能按方向关闭多少仓位。 | 先验方向、仓位、账户限制及利润约束，再排名和执行。 |
| score、Q_short、P_entry | score 是排序分数，Q_short 是合格空仓数量，P_entry 是其入场价。 | 教学分数为 max(0, Q_short×(P_entry−M_snapshot))，分数降序、稳定账户 ID 升序破同分。 |
| snapshot_id、冻结排名 | 给固定时点的候选输入和排序留证据。 | 冻结的是审计依据，不是永久许可；排序输入改变需按本文规则重新快照排名。 |
| 执行前复核、版本 | 执行前确认当前仓位、价格及资金仍符合原计划。 | 对手已自行减仓时不能仍用旧数量，失去资格要留下跳过原因。 |
| 数量预留、利润预留 | 先占住将用于配对的仓位数量及承诺承担的可用利润。 | 两个 ADL 案例不能重复消耗同一份仓位或利润；不确定时不能提前释放。 |
| adl_pair_id、close_qty、leg | 配对身份、配对数量和双方各自的经济腿。 | 双方各关 0.5，配对量是 0.5；两腿绝对值相加为 1 不代表成交量为 1。 |
| PnL、清算对边 | PnL 是普通盈亏；清算对边是完整账本中与这些损益对应的记录。 | 源实现 -11、对手实现 +6，不能把两个成本不同的账户误当封闭现金池。 |
| loss_id、allocation_id | 前者标识核定短缺，后者标识依约承担的一笔金额。 | 关闭仓位与承担缺口分开记身份及科目，不能把普通盈亏再记一遍。 |
| 复合经济提交、journal | 将配对关闭、普通盈亏和事先约定的承担在同一权威记录下共同生效。 | 全量例先推导现金 -2 和 16，再在同一复合提交落实承担 2，最终为 0 和 14。 |
| 权益守恒、净利润 | 守恒要求内部处理不凭空造钱；净利润是毛利扣掉依约承担后的结果。 | 双方合计权益前后为 14，对手毛利 6、承担 2、净利 4。 |
| 破产价 82 | 源剩余仓位在本阶段现金条件下权益归零的理论价格。 | 为 100−9/0.5=82，不是初始仓位的 80，也不是市场成交承诺。 |
| 分批承诺、aᵢ、D、Q | aᵢ 是第 i 批承担额，D 是最终缺口，Q 是约定总配对量。 | 分批先关仓并预留；仅在计划按约完成、最终定损后，按比例且受承诺及可用利润上限兑现。 |
| UNKNOWN、累计关闭量 | UNKNOWN 是配对结果未知；累计关闭量是已确认的成对总进度。 | 任一腿未知先查原 pair，不换候选盲做原数量，也不能提前按暂态负权益收款。 |
| PENDING_UNCOVERED、尾部缺口 | 表示仍有未覆盖责任的待处理状态。 | 全部配对关闭后仍欠钱，不能再凭空找新仓配对；补资或独立分摊须另有明确规则。 |
| 最终定损、结案 | 核齐全部确定成交、费用和资金费等义务后确认缺口，并核实承担落实。 | 仓位归零与现金责任结清不同，ADL 执行成功不自动证明全案完成。 |

## 把整篇文章压缩成一个故事

小林拿保证金持有多头，权益包含现金和浮动盈亏，跌破维持要求后需要强平复核。此篇另走独立路径：基金可用额为零，普通强平只成交 0.5 ETH@78，现金剩 9、余多仓 0.5，Mark 78 下权益为 -2。旧余单已取消且成交查齐，但还有真实仓位未关闭，因此才有 ADL 的配对对象。

协议按公开的教学规则选中一名仍持有 0.5 空仓的对手，其入场价为 90、现金为 10。执行前复核资格、数量和可用利润，事先约定双方按有效 Mark 78 关闭，并由对手在利润及承诺上限内承担核定缺口 2。普通盈亏先推导出小林现金 -2、对手现金 16；同一复合提交再落实约定承担，最终为 0 和 14。对手毛利 6、净利 4，不是无损替人兜底。

排名不是永久许可，分批关闭时先记成交和利润预留，须等全平、确定义务核齐才按既定承诺分配。结果未知就查询原配对，不能换人再做一遍。Mark 作为关闭价仅是本文规则；若仓位已全部闭合仍有欠账，只能另按明确机制处理，不能事后任挑盈利用户扣钱并称为 ADL。

[返回专题总览](README.md)

**流程位置与核心机制：** 本题讨论协议定义的自动减仓（ADL）如何选中仍持有反向敞口的对手方，按明确价格关闭未平仓位，并在协议明示的分配规则下承担损失。ADL 不是已全平结算后随意向盈利账户扣现金的万能坏账工具；若没有仍可配对的敞口，就必须转入补资、追偿或其他独立损失分摊机制。

**共同前提：** 沿用[总览基线](README.md#11-讨论基线)：链下托管线性 USDC 逐仓多头，初始 `q=1、P₀=100、C=20、MMR=5%`，忽略费用、资金费，严格 `E < MM` 才触发。Mark 90 为 `E=10、MM=4.5`；Mark 84 为 `E=4、MM=4.2`。ADL 使用独立变体，不延续主例的 `0.5@84` 或基金覆盖1.5：该变体可用于此仓位的基金余额为0，Mark 下跌至 78，普通强平只完成 `0.5 ETH@78` 且原余单已权威取消、成交水位核清，所以源现金 `9`、剩余多仓 `0.5 ETH@100`，其 Mark 78 权益 `9−11=-2`、MM 为 `1.95`。另有合格对手方持有 `0.5 ETH` 空仓，basis 90、现金 10，Mark 78 时浮盈 6。教学 ADL 规则采用执行前有效 Mark 作为双方相同关闭价；本次计划在78配对关闭各0.5，同时根据执行前已明确的责任承诺，以独立科目的 loss allocation 将该计划核定短缺2从对手方转给源，且不超过本次平仓真正实现并扣除其他义务后可用的利润6。配对和分配分别留身份，在一个复合经济提交中生效，不是平仓后另找盈利账户扣款；规则、价格选择和排序都只用于教学，不是通用协议。

本题共 10 层，沿“是否仍能配对→协议定义→候选资格→排名版本→冻结后复核→配对数量与提交→价格与现金守恒→利润上限及尾部缺口→UNKNOWN与并发→结案边界”推进。

## 第 1 层：什么条件下 ADL 才有可执行对象？

**面试官：** 保险基金不够覆盖缺口，系统能否从所有盈利账户中挑一个，直接扣一笔现金？

**面试者：** 不能把 ADL 说成向盈利账户任意扣款。它首先是处置仍存在的风险敞口：要有待关闭的源仓位、可按协议匹配的反向对手方仓位、明确的关闭数量和价格裁定方式。对手方账户因被强制减仓而少掉仓位，之后也无法继续持有这段头寸；若协议还要让它承担损失，必须另有公开、可审计的分配规则。

如果源账户普通全平已完成，且执行款项和所有 close leg 已确认结清，它已没有可与对手方配对关闭的仓位。此时再称为“ADL 平仓”，实际只是现金损失分摊或追偿，应以独立协议机制描述。否则系统会谎称 ADL 消除了负现金，却找不到任何仍存续的仓位或真实过户事件。

## 第 2 层：本题采用什么明确的教学 ADL 规则？

**面试官：** 既然 ADL 规则由协议决定，请把本例的源敞口、对手方和处置规则具体化，避免只说“按规则执行”。

**面试者：** 本变体不是 78 全平、现金 -2 的基金例。源账户初始 1 ETH 多仓，在普通强平中只先成交 0.5 ETH@78，cash 从 20 到 9，剩余 0.5 ETH 的成本 100，Mark 78 下权益是 `9 + 0.5×(78−100) = -2`。教学协议选一名合格反向空仓账户：0.5 ETH、basis 90、cash 10；它在 78 有 6 USDC 浮盈。

该变体基金可用额为0，普通余单已关闭，但源仍有可配对多仓。规则要求在执行前就绑定源仓、候选空仓、价格证据、最大可减量和损失承担上限：双方各0.5在78关闭，源余仓实现亏损11、对手方实现盈利6，源最终短缺为2；对手方依这份计划承担其中2。配对腿与分配腿是不同身份/科目，但逻辑上共同提交，不能等全平结算后再随意决定扣谁。候选未必就是源的原始开仓对手方，因成本不同，其普通PnL通过系统既有清算科目完整结算，损失承担另记。这只是教学规则，真实协议可能采用不同关闭价格、排名或责任分配。

## 第 3 层：候选账户怎样才有 ADL 资格？

**面试官：** 当前只有一个盈利空仓账户的例子。生产系统怎样避免挑中仓位已平、保证金不足或法律上不能参与的账户？

**面试者：** 候选快照至少要有账户与风险单元身份、合约、方向、可减数量、持仓版本、当前可实现权益/利润、保证金和限制标志。先按协议检查账户是否允许被 ADL、是否存在相反方向的有效仓位、可减量是否大于零、执行是否会违反数量和账户规则，再计算排序值。资格计算必须读取权威版本或带水位的可信快照，不能依据行情 UI 上的浮盈排行榜。

教学对手方的0.5空仓与源剩余0.5多仓方向相反，按计划价格78关闭可实现利润6，超过计划承担额2，因此可进入候选；此时6还是预计可实现利润，不是已经到账的现金。若该账户已经自行平仓、仓位方向变了、数量降到 0.2 或利润已被提现/其他义务占用，冻结快照不再证明它可用，必须在真正执行时重验。

## 第 4 层：ADL 排序公式是通用的吗？

**面试官：** 常见系统会组合盈利率、杠杆或风险等级。可否把某个公开经验公式直接当作 ADL 通用排名？

**面试者：** 不可以。排序表达的是具体协议希望怎样分摊社会化风险，应由产品定义输入、归一化、取整、方向、层级和并列打破规则。本题教学排序分数为 `score=max(0, Q_short×(P_entry−M_snapshot))`，即在快照价格关闭合格空仓预计可实现的USDC利润，按分数降序、稳定账户ID升序打破并列。排序分数与最终可分配额不同：后者还要扣其他已承诺义务并受本次实际关闭量限制。它不宣称是行业通式，也不把冻结时的浮盈当成已经到账的可扣现金。

排序快照要固定 `snapshot_id、as_of_position_seq、price_id、rule_version、candidate inputs`，这样事后能解释为何某账户入选。但排序只生成候选顺序，不是永久执行许可：成交/提现、账户限制变化、Mark 更新或其他并发 ADL 都可能使其版本失效。不能为避免重排成本而在旧排名下超量执行。

## 第 5 层：冻结排名之后，怎样处理版本变化与并发？

**面试官：** 冻结的候选名单中第一名在执行前又减仓了。为了可重复，你能否仍按冻结数量强制对它执行？

**面试者：** 不能。先保留冻结排序作为审计证据，再在权威执行前按当前持仓/资金版本重新验证资格、方向、数量、利润和限制。本教学规则规定，数量、价格等排序输入改变就生成新快照重排；仅当候选已失去资格时，才保留跳过原因并继续到下一合格候选。两种决策都记录输入版本和规则版本，不能由worker任意选。快照过时或价格证据无效也必须重评，而非把旧快照悄悄当成最新事实。

同一对手方也可能被两个 ADL case 并发选中，所以要在账户/合约风险单元中原子预留其可减仓数量和可分配利润，分配身份关联对应 loss 与 case。预留不能超过实时可执行头寸；部分失效后释放未消耗部分也要先确认没有在途 close fill 或 loss journal。冻结快照给确定性，执行前版本复核给安全性，两者缺一不可。

## 第 6 层：配对数量和两个仓位腿怎样守恒？

**面试官：** 现在源剩余多仓 0.5、候选短仓 0.5。ADL 执行要怎样限制数量，如何处理只完成 0.3 的情况？

**面试者：** 一次配对动作的数量上限是源尚未关闭多仓、对手方仍存续空仓、协议允许额度三者的最小值，并以一个稳定 `adl_pair_id` 和 `close_qty` 记录。若只确认 0.3 成交，源多仓和对手方空仓都各减少 0.3；剩余双方 0.2 进入后续复核。任何一腿不能先全减、另一腿稍后想办法补齐，否则会出现经济仓位临时消失或重复承担。

本例把 `adl_pair_id` 关联到同一成交/关闭事实以及source与counterparty各自的leg ID；每条腿均为0.5，两个有向变化为 `-0.5/+0.5`，净和0，不能把两腿绝对值相加的1误当成成交量0.5。全量关闭且所有其他义务已核清时，在共同权威事务中复核双方仓位/资金版本、消耗预留，并提交关闭腿、PnL清算腿及预先约定的loss/allocation。若跨库，需双方预留/prepare确保不能独立花掉，最终由单一权威journal确认整体提交；未投影的一侧保留义务并补投影，不允许两边各自决定终态。损失承担资格与上限在配对前确定，不是事后挑人扣款。

分批是对全量复合提交的显式变体：每批只共同提交双边 close 及普通 PnL，记录预计责任并保留对手方利润预留，暂不核定最终 loss、不提交实际转款 allocation。`0.3@78` 后，源现金 `9+0.3×(78−100)=2.4`、剩余多仓 0.2，Mark 78 下 `E=2.4+0.2×(78−100)=-2`；对手方现金 `10+0.3×(90−78)=13.6`、剩余空仓 0.2，本批实现利润 3.6 可按承诺预留，但不能因此直接向源转款 2。

本分批变体约定计划总量 `Q=0.5` 最终全部由这些配对完成，且责任承诺在每批执行前锁定。源全平且全部义务核清后，才核定实际负现金缺口 `D`，各批按 `aᵢ=min(D×qᵢ/Q, 该批承诺上限, 该批实际实现且扣除其他义务的可用利润)` 分配；未覆盖额为 `D−Σaᵢ`，不将超过某批上限的份额临时加给其他候选。若余下 0.2 也在 78 配对，最终 `cash=-2、D=2`，各批上限足够时分配分别为 `2×0.3/0.5=1.2` 与 `2×0.2/0.5=0.8`；第一批关闭时实际划款为 0，待最终定损才兑现既定承诺。价格变化须重评余量并重算最终缺口，不突破旧承诺上限。若计划未完成或关闭方式改变，不套用该比例公式，保持预留与风险限制，按明示的终止／替代规则裁决。loss 及各 allocation 在权威账本共同提交，清算对边和预留消耗可审计，不能用暂态负权益冒充最终定损。

## 第 7 层：以 78 配对时，双方价格与现金如何变化？

**面试官：** 上一层确认双方各平掉 0.5。使用教学规则的 Mark 78 作为双方 close price，给出每边现金和剩余仓位，说明价格责任。

**面试者：** 对源多仓，损益是 `0.5×(78−100)=-11`，现金从 9 变成 -2，仓位从 +0.5 变成 0。对手方空仓以 `0.5×(90−78)=+6` 实现利润，现金从 10 变成 16，仓位从 -0.5 变成 0。数量上双方各关闭 0.5；这是在题设 mark-close 规则下的配对结算，不把 Mark 当任意产品都必须采用的 ADL 成交价。

这里 `9→-2、10→16` 是复合提交中普通PnL科目的中间推导，不是让源先全平、再临时决定扣款。配对前双方权益合计为 `(9−11)+(10+6)=14`，关闭后现金合计为 `-2+16=14`，权益守恒。由于入场basis不同，两边现金从19降至14的差额5，对应此前合约浮盈亏净额的实现；完整复式账还须有普通衍生品清算对边净增加5，不能把这两账户单独视为此前所有交易的封闭现金池。

同一复合journal内，预先约定的allocation贷记源2、扣减对手方2，使现金最终成为 `0/14`，双方分配前后现金总额仍14，源未覆盖额由2到0。原核定loss金额2保留，承担方和allocation单独记载，不把普通PnL的 `-11/+6` 再记一次。价格规则由本教学协议负责选用有效Mark，并绑定 `price_id/rule_version`；Mark若失效或版本变化，拒绝旧计划后重评，不由worker改价。在本例中对手方毛利润6、承担损失2，净利润只有4；这与双方直接按82关闭的净效果相同，因为源剩余仓位的简化破产价是 `100−9/0.5=82`。该82不同于初始1 ETH仓位的80，不能混用，也不是市场成交价承诺。若协议只定义close而没有这份分配承诺，源短缺2仍未解决。

## 第 8 层：对手方利润不足时怎样处理剩余短缺？

**面试官：** 假设同一规则下对手方的合格可分配利润只有 1.2，而源缺口是 2，能否把剩下 0.8 记到 ADL 已完成？

**面试者：** 不能。这是对主ADL例的独立上限变体：对手方本次可分配利润因其他已承诺义务只剩1.2，不是前述浮盈6自己变成1.2。计划按 `min(待分配损失、本次实际实现可用利润、单账户限额)` 最多承担1.2，以独立 `allocation_id` 入账；源现金从-2到-0.8，对手方减少1.2。原缺口2、已分摊1.2、未覆盖0.8必须同时保留。

如果该批只配对部分源仓位，仍有存续源敞口，下一批才可重新选合格对手仓继续ADL；如果本例各0.5已经全部关闭，则不许为剩余0.8再找新仓位谎称配对。只能履行此前已承诺的分摊义务，或进入补资/追偿/协议独立损失分摊。本例属于后者，源虽空仓仍欠0.8，不能结案。

候选没有足够敞口、达到协议单账户上限或排序名单耗尽时，必须显式进入 `PENDING_UNCOVERED` 一类状态，保留源负债及审计证据。产品可以选择暂停新风险、向保险基金申请、要求补资或按公开规则跨账户分摊；这属于 ADL 未覆盖尾部的协议决策，不可由服务把 `remaining_loss` 截成零。

## 第 9 层：执行超时或对手方取消时，如何避免双重配对？

**面试官：** 你说缺口不能因为空仓就消失，也不能随意另找人承担。若原 `adl_pair_id` 的一条 close fill 回报超时、是否已空仓尚未知，对手方又提交自行减仓，能否换一名候选并按原数量继续？

**面试者：** 先对原 pair 查询执行端成交序号、两腿 close 状态和 loss allocation 状态。对手方自减与 ADL 的先后由该风险单元的权威顺序决定；若自减先完成，旧 ADL 只能按新版本可减数量执行或终止。若 pair 结果未知，不应把整份 `0.5` 再给下一名，否则原对手方可能已关闭、造成总平仓超过源仓位。

两个close leg与后续损失分配分别拥有稳定身份。pair partial时只保存已确认的成对累计关闭量、普通PnL和责任/利润预留，实际loss allocation暂不转款；待源全平且所有义务核清，才按第6层事先定义的配对量比例及承诺上限共同核定并提交loss/allocation。执行端最终裁决累计关闭量不超过源剩余仓位，资金系统原子保护预留并对allocation身份幂等。任一腿未知就先按原pair查询，不因ACK慢忽略权威fill，也不凭暂态负权益提前收取最终亏损。

## 第 10 层：已全平且对手款项结清，ADL 还能做什么？

**面试官：** 回到另一种情况：账户已在普通市场全平于 78，现金 -2，相关成交款项已结清，所有反向对手仓也不存在。系统还能称下一步扣盈利用户 2 为 ADL 吗？

**面试者：** 不能。没有存续源敞口和可配对对手方仓位时，配对减仓没有对象；若此时向用户收款，那是独立损失分摊、追偿、补资或其他明示合同责任，必须给出该机制自己的资格、上限、争议处理和账务依据。否则只能将 2 保持为未覆盖负债，不能声称已经通过 ADL 消除。

本题独立变体在普通全平尚未完成时就选择和约束了对手方：双方各0.5在78关闭，普通PnL科目中间现金分别 `9→-2、10→16`，同一复合提交履行事先承诺的2损失承担，最终为 `0/14`。双方权益由配对前14变成现金14，普通PnL的清算对边与独立allocation都能追溯；这是履行已绑定仓位的旧计划，不是源仓位已清后新挑一个盈利账户。ADL完成仍须通过全case的审计与恢复门禁。

## 本题收束

- **讲透的机制：** ADL 必须有实际未平敞口与合格反向仓位；先固定协议价格/数量和配对腿，再明确区分正常 PnL 结转与损失分摊；排名快照可审计但执行前必须版本复核。
- **最容易答错的边界：** ADL 不是全平后对盈利账户随意扣款；冻结排序不等于执行许可；配对关闭能消除仓位，不一定消除负现金；未分配余额不能截零。
- **检验反例：** source 全平且 fill/结算水位已确认，系统仍生成 `0.5` 配对单并向盈利空仓扣款。该操作没有源仓位可关闭，必须拒绝 ADL，转向协议独立损失分摊或维持待补资状态。
