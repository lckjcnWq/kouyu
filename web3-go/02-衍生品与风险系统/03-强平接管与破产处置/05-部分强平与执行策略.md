## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
| --- | --- | --- |
| 保证金、逐仓现金 C | 为指定仓位承担亏损的资金。 | 本例起初为 20 USDC；逐仓是风险范围，不是任何情况下的绝对损失上限承诺。 |
| 多头、q、P₀ | 多头随价格下跌亏损；q 是数量，P₀ 是入场价。 | 起初 q=1 ETH、P₀=100，减仓就是减少这份多头。 |
| Mark、M | 用于风险估值的价格。 | M=84 是计算输入，不保证能按 84 卖出。 |
| U、E | U 是浮动盈亏；E 是现金加浮动盈亏后的权益。 | 忽略费用时 U=q×(M−P₀)，E=C+U。 |
| MM、MMR | MM 是维持持仓所需最低金额；MMR 是维持保证金率。 | 本例 MMR=5%，Mark 84 时 MM=4.2。 |
| 触发、恢复门槛 | 触发决定进入复核，恢复决定能否结束保护。 | 本文严格 E<MM 触发；教学恢复需 E>=MM 且余单、在途义务核清。 |
| 部分强平 | 不必一次清空，而是尝试减到风险符合规则。 | 强平不必然全平，也不意味着保证金已亏光。 |
| x、C'、q' | x 是计划减掉的数量；带撇号的是减仓后的现金和余仓。 | 仅假设按 84 成交且无费用时，C'=20−16x、q'=1−x。 |
| 1/21 ETH、数量步长 | 前者是本例理想化最低减仓量；步长是合约允许的最小数量间隔。 | 只在文中假设下成立，实盘需按步长向上取整并使用真实成交重算。 |
| buffer、生产变体 | buffer 是额外安全余量；生产变体是明确不同于教学基线的规则。 | 不偷偷把安全缓冲混入本文等值即可满足的数值门槛。 |
| 订单簿、流动性 | 订单簿是待成交买卖报价；流动性表示可在多大价格代价下成交多少。 | 风险上该减多少，不等于市场当下就能成交多少。 |
| 滑点、冲击成本 | 实际成交偏离预期的价格代价，以及订单推动市场造成的额外成本。 | 无限制扫单可能把可控风险变成更大亏损。 |
| 限价、市价、价格保护 | 限价约束可接受价格；市价优先寻找即时成交；保护规定最差可接受边界。 | 有价格保护也可能完全不成交，不能承诺又快又按理想价格成交。 |
| 分块、step、策略版本 | 把执行拆成多步，每步留下数量、价格、有效期和规则记录。 | 每批真实成交后重评，改保护参数要授权新步骤，不改写旧载荷。 |
| fill、结转 | fill 是真实成交；结转是正式应用仓位和资金变化。 | 目标不是成交量，只有实际 fill 才能改变权威仓位。 |
| Reduce-Only、可平数量 | 只减现仓，并按当时剩余仓位限制实际成交。 | 用户与强平并发减仓必须共享最终数量约束，不能卖过零。 |
| 在途量、已确定未结转量 | 尚可能执行的余量，以及已经成交但账务尚未处理的数量。 | 本地还显示旧仓位，也不能把这两类数量当作不存在。 |
| UNKNOWN、替代动作 | UNKNOWN 是旧动作结果未知；替代动作是另一个新意图。 | 先查原动作、关闭旧执行资格并对账，不能超时后盲发新单。 |
| Backstop、拍卖 | Backstop 是按协议承接风险的后备方；拍卖是组织参与者报价的处置方式。 | 都不是无条件备用成交保证，需明确对象、定价、容量和完成事实。 |
| 订单终态、风险解除 | 前者说明该单不再继续执行，后者说明产品恢复条件成立。 | 停止发送余单不等于取消已生效；空仓也不代表费用与损失责任全部结清。 |

## 把整篇文章压缩成一个故事

小林以 20 USDC 保证金持有入场价 100 的 1 ETH 多头。Mark 跌到 84，现金加浮亏后的权益为 4，低于 4.2 的维持要求，系统复核后准备强平。目标是把风险降回规则允许的范围，不是看到触发就无条件清仓，更不是保证金已经全部亏光。

执行器先计划减多少、最差接受什么价格、每批有效多久。在恰好按 84 成交且没有费用的假设下，减掉部分仓位不会凭空增加权益，却会降低剩余仓位的维持要求。若实际成交 0.5 ETH，现金为 12、余仓为 0.5，Mark 仍为 84 时权益为 4、维持要求为 2.1；它必须先结转这笔真实成交，再检查其他余单是否关闭，不能机械继续卖完。

如果限价单一直没成交，系统按既定边界暂停、重评或申请后备通道，不能无限追价。旧动作结果未知时先查原身份，不能另发一单；用户也在减仓时，最终执行点必须防止越零开空。Mark 不等于成交价，Backstop 也不是抹去亏损的开关，切换前后都要核清已有义务。

**流程位置与核心机制：** 本题讨论强平资格已复核、处置权已接管之后，如何把风险目标转成受限执行动作，以及如何根据真实成交和流动性决定继续、停止或切换。这里不展开接管权仲裁、UNKNOWN 恢复和坏账分配；重点是部分执行不能脱离成交事实和新的风险状态。

**必要前提：** 沿用总览的链下托管、线性 USDC 永续、单一逐仓多头，初始 `q=1 ETH、P₀=100、C=20、MMR=5%`，忽略费用与资金费。`U=q×(M−P₀)、E=C+U、MM=q×M×5%`，严格 `E<MM` 才触发，等值不触发。教学恢复门槛为 `E>=MM`，并且余单和在途义务已核清；生产安全缓冲是需要显式声明的产品变体。Mark 是风险估值，不是成交价格。

## 第 1 层：为什么强平不一定一次性平掉全部仓位？

**面试官：** Mark 为 84 时，主例已满足强平条件。为什么不能直接按 1 ETH 发一个不受限制的市价平仓单？

**面试者：** 强平的目标是把风险降到规则允许的范围，不是把“强平请求”误当成“已经全平”。在 `M=84` 时，`U=-16、E=4、MM=4.2`，因此 `E<MM`，进入复核；但 84 只用于风险估值，市场实际可成交数量和价格由订单簿决定。无保护地一次性扫单可能承受极端滑点，也可能在流动性差时把可控处置变成更大的损失。

我会先确定允许的减仓方向、最大数量、价格保护和风险目标，再由执行端按受限动作尝试。若流动性充足且协议要求立即退出，策略可以趋向快速全平；若冲击成本或价格恶化风险更大，则可小批执行并在每批后重评。选择依据必须是产品风险策略和当前市场状态，不是一个固定的“强平就全平”假设。

## 第 2 层：部分平仓的数量如何与风险恢复门槛关联？

**面试官：** 你说要按风险目标减仓。对 `q=1`、Mark 84 的主例，怎样判断一笔部分成交是否足够？

**面试者：** 数量计划可以用风险状态推导，但计划不是成交事实。若假设恰好按 Mark 84 卖出 `x` ETH，忽略费用，则结转后现金为 `C'=20−16x`，剩余数量 `q'=1−x`，剩余未实现亏损为 `−16(1−x)`，所以 Mark 84 下权益仍为 `E=4`，而 `MM=4.2(1−x)`。理想化计算中，恢复条件 `E>=MM` 等价于 `x>=1−4/4.2=1/21 ETH`，约 `0.047619 ETH`；精确等值满足本题教学门槛。若合约数量有步长，按步长向上取整，生产系统额外安全缓冲则另行明示。

这个计算只说明如何形成目标，不允许系统在成交前提前降低权威仓位。实际成交价若低于 84，已实现损失会更大；费用也会减少权益，且在途订单可能继续成交。因此每笔 fill 结转后都要用新仓位、真实现金、费用和未结义务重算。主例平 `0.5 ETH@84` 后，现金 12、剩余 `q=0.5`、成本 50，`E=4、MM=2.1`，此时才有新版本证据支持风险评估。

## 第 3 层：如何选择分块、订单类型和价格保护？

**面试官：** 目标数量算出来后，为什么不直接按这个数量挂一个限价单？分块策略怎样防止价格保护失效？

**面试者：** 策略要同时约束价格、数量和有效期。限价保护能限制最差成交价，但价格设得过于保守时可能完全无成交；市价或可成交限价可能更快降低风险，却要限制单笔数量、可接受滑点和累计数量。分块可以观察每批成交后的盘口和风险变化，但不能保证市场会按预期恢复流动性。

我会让每个 step 绑定明确的数量上限、价格边界、有效时间和策略版本，并由执行端在最终裁决时检查 Reduce-Only 与当前可平数量。每个已成交部分按 fill 结转并触发重评；未成交剩余量仍是待执行义务。若要放宽价格保护、提高紧迫度或改用另一执行通道，必须记录触发原因并生成经过授权的新 step，而不是悄悄修改旧动作载荷。

## 第 4 层：没有流动性或价格越过保护线时，是否应该继续追价？

**面试官：** 市场快速下跌，保护限价单挂出后没有成交，账户仍低于维持保证金。系统能否不断下调限价直到成交？

**面试者：** 不能把“持续成交”当成无条件目标。越过价格保护可能把执行风险转成不可控的价格风险。策略应规定最大可接受滑点、单次与累计暴露、重试间隔和升级路径；触及边界或流动性不足时，停止当前余单、保留处置保护，并明确进入暂停、重新评估、拍卖或协议指定后备通道等状态。

停止余单不代表风险解除，也不等于订单已取消。必须取得执行端对旧订单的权威终态，核清在途成交和剩余数量，再允许新 step 或替代通道取得执行资格。若外部市场不可执行且协议没有后备安排，应明确承认仍有未处置敞口并维持风险限制，不能将“请求成功”展示为强平完成。

## 第 5 层：每批成交后，怎样决定继续、暂停还是改变策略？

**面试官：** 第一批只成交 `0.5 ETH@84`，此后市场反弹或进一步下跌。系统是否按最初计划自动执行剩下的 0.5 ETH？

**面试者：** 不应机械执行旧计划。该 fill 先以真实数量和价格结转，然后重新读取风险单元的权威仓位、现金、费用、当前有效 Mark 和未完成义务。市场反弹可能使风险条件改善；市场继续下跌则可能需要更快或更深的减仓。新决策必须绑定新风险快照和规则版本。

沿主例按 84 成交 0.5 ETH 后，`q=0.5、C=12、E=4、MM=2.1`。即使该快照达到教学恢复门槛，也还要核对未成交余单、其他有效强平动作以及已经确定但未结转的成交。若恢复条件成立，且这些义务均已闭合，可以停止新的减仓；若价格、费用或执行价不同导致权益低于维持要求，则按新快照重新设定数量和执行保护。

## 第 6 层：如何避免部分成交与普通减仓把仓位卖过零？

**面试官：** 强平目标是卖出 0.5 ETH，但用户也提交了 Reduce-Only 卖单，两个命令并发到达。怎样避免合计卖出超过 1 ETH，甚至反手开空？

**面试者：** 本地协调器按旧仓位分别计算两个订单数量是不够的，最终数量限制必须在具有权威裁决权的执行端或撮合端实施。每个动作的累计成交量和当前可平数量共同决定剩余资格；所有有效订单的在途量也要计入风险约束，不能让两个独立命令各自消费同一份仓位。

具体而言，执行端按风险单元维护可平额度或等价的序列化裁决，在提交每个 fill 前重新检查方向和数量上限。Reduce-Only 的语义是只能减少当前同向仓位，仓位归零后余量必须取消或拒绝，不得反向开仓。强平服务还要确保旧 action 的剩余量已被终态关闭，才能发出替代动作；否则用户和强平两个执行通道可能共同超过目标。

## 第 7 层：为什么旧仓位不能用于再次发单？

**面试官：** 一笔强平成交已确定，但账户结转还在排队。协调器没有看到新的仓位版本，可以先按旧 `q=1` 再卖 0.5 ETH 吗？

**面试者：** 不可以。成交确定后，仓位变化已成为经济义务，即使本地持仓投影或账本尚未更新，也不能把旧 `q` 当作仍可出售的事实。该动作的成交量要纳入“已确定未结转数量”，并从后续可执行上限中扣除；否则迟到的结转会显示仓位已减少，而第二张按旧数量生成的订单可能造成过平。

系统应按账户风险单元串行推进经济版本，或采用能等价约束累计仓位的执行门禁。在途 fill 未结转时保留风险保护和待处理标记；结转完成后才以新仓位生成下一轮风险计划。若无法确认成交是否发生，则先走 UNKNOWN 查询恢复，不得把查询延迟当作成交未发生。

## 第 8 层：什么条件允许切换到后备通道或解除强平模式？

**面试官：** 当前市场没有可接受的流动性，主执行通道已经停止余单。何时可以转给 Backstop，或宣布强平完成并恢复普通交易？

**面试者：** 转入 Backstop 必须由协议定义其接管对象、定价方式、最大容量和责任转移的完成事实。仅仅发送接管请求或停止普通订单，并不表示仓位已经转移，也不表示原风险单元的经济义务消失。切换前要关闭旧通道的执行资格、确认其订单终态，并把已确定成交先行纳入结转。

恢复普通交易则要求以最新权威经济版本达到门槛。本教学基线使用 `E>=MM`，同时要求余单和在途义务核清；若产品要求高于维持保证金的安全缓冲，例如 `E>=MM+buffer` 或额外风险率，必须标为生产策略变体并定义缓冲来源、币种和版本。若仓位关闭后仍有待结转费用或负余额，不能因为 `q=0` 就把强平案例和损失处置都标成完成。

## 本题收束

- **机制：** 按风险目标计划数量，以价格／数量保护执行；每笔真实 fill 结转后重评，未结余单和在途义务始终参与执行上限与恢复判断。
- **易错边界：** 风险计算出的目标不是成交量；停止当前余单不是取消终态；未结转的已确定成交不能继续按旧仓位发单；教学门槛与生产缓冲不能混为一谈。
- **反例：** 1 ETH 多仓上，强平和用户 Reduce-Only 各自基于旧快照发出 0.6 ETH 卖单。若最终裁决点没有共享的可平数量约束，两单合计可卖 1.2 ETH 并反向开仓；正确做法是在权威执行边界按当前仓位、在途量和已确定成交共同限量。
