## 二、岗位准备主线

根据招聘要求，优先建立以下能力：

1. **交易核心链路**：订单接入、撮合、成交清算、结算、持仓与账户资产。
2. **衍生品风险系统**：保证金、杠杆、限额、持续风险重算、资金费率、强平与坏账处置。
3. **行情与风控输入**：多源数据、盘口、交易回报、指数价格、标记价格和预言机异常策略。
4. **Go 工程底座**：并发、数据结构、网络 IO、低延迟、数据库事务、Redis 边界、可测试性和可观测性。
5. **DEX 特有边界**：签名授权、链上执行、确认与最终性、重组、链上链下一致性。
6. **产品扩展**：结合实际架构学习 AMM、RFQ、聚合路由和预测市场，避免把所有机制都当成岗位硬要求。

Go、数据库和工程质量是任职要求，不应等业务学习结束后再补。预测市场来自公司产品介绍，AMM、RFQ 和具体成交／结算机制仍需确认，不能据此推断目标公司的真实架构。

## 三、先区分产品、成交机制和执行结算方式

| 维度 | 典型选择 | 影响 |
|---|---|---|
| 产品 | 现货、永续合约、预测市场 | 决定资产、持仓、费用、风险与最终兑付规则 |
| 成交机制 | 订单簿、AMM、RFQ、聚合路由 | 决定报价来源、对手方、成交约束与流动性组织方式 |
| 执行结算 | 全链上、链下排序／撮合与链上结算、专用交易链等 | 决定权威状态、履约保证、确认语义和故障边界 |
| 资产控制 | 用户钱包、合约托管、协议抵押账户等 | 决定授权、预占、充提、提现权和管理权限 |

**这几个维度相互组合，不是四种互斥架构。** 例如，预测市场可以采用订单簿，Perps 可以采用订单簿或池式机制，AMM 交易也可以经过聚合器。

后续流程文档分别采用明确的教学基线讲解，不把一种流程强加给所有 DEX。

## 四、全套专题必须共同遵守的边界

- **撮合不等于成交清算，成交清算不等于强平。** 前者决定成交，中者计算成交义务，强平根据风险规则减仓或接管，再进入适用的成交、清算和结算流程。
- **链下成交不等于链上结算完成。** 可靠受理、成交裁决、账户结转、链上确认和产品认可的最终性需要分别定义。
- **展示视图不等于权威状态。** 行情、索引和缓存通常是派生视图，不能未经架构约定就替代订单、资产或风险真相源。
- **可用余额不等于账户权益。** 冻结、在途、抵押、未实现盈亏等应按产品规则区分，不能把风险估值直接当成可提现资金。
- **一个模块恢复不等于整条链路恢复。** 撮合、成交交付、账本、持仓和链上投影需要核对各自进度与业务结果。
- **目录覆盖不等于内容完成，手工推演不等于测试通过。** 本模块给出准备范围和验收口径，不编造项目经历或性能数据。

## 五、推荐推进顺序

1. 阅读流程文档，确定本次讨论的产品、成交机制、状态归属和结算方式。
2. 按目录规划优先补齐 P0：工程底座、资金账本与对账、持续风控、预言机异常处理和充提闭环。
3. 以现有撮合专题为起点，逐步串起订单、成交、资产、持仓与风险，复用已有可靠交付和恢复讨论。
4. 推进 P1：补完整 AMM／LP、预测市场生命周期，以及适用的交易回报、链上失败恢复和路由执行边界。
5. 每篇专题交付时检查正常路径、主要异常、关键不变量、跨模块责任和验证方法，不以题数代替覆盖质量。
