# DEX 完整交易流程

## 一、流程适用范围

本文用于面试建立业务全貌，不描述某家公司的实际实现，也不是所有 DEX 必须遵守的统一协议。

先确定四件事：

1. **交易什么**：现货、永续合约还是预测市场头寸。
2. **怎样成交**：订单簿、AMM、RFQ，是否经过聚合器。
3. **谁拥有权威状态**：链上合约、交易链状态机、链下订单／账户系统分别负责什么。
4. **何时完成结算**：链下裁决、账户结转、链上执行、确认和最终性之间是什么关系。

下文四条流程分别强调订单簿、AMM、Perps 和预测市场，但它们不是互斥分类。Perps 和预测市场也可以采用订单簿或池式机制；聚合路由是组合执行方式，不替代底层成交与结算规则。

**完整流程至少包含正常路径、主要异常、状态与资金变化，以及恢复和对账责任。** 只画“下单 → 撮合 → 结算”不足以证明闭环。

## 二、通用职责与完成语义

### 2.1 核心模块分工

| 模块 | 主要职责 | 不应混淆的边界 |
|---|---|---|
| 接入与授权 | 身份、签名、权限、请求格式、精度、准入限流 | 通过校验不代表订单已接纳或已成交 |
| 订单管理 | 请求幂等、订单状态、撤单／改单语义、结果查询 | 客户端超时不是拒绝或撤单成功 |
| 撮合／执行 | 按规则确定价格、数量、对手方或池状态变化 | AMM 不必有中心化订单簿和价格时间队列 |
| 成交清算 | 根据成交计算资产交割、费用、持仓与保证金变化 | 不等同于风险触发的强平处置 |
| 账户与账本 | 维护适用的资产权威状态、预占、记账、冲正和审计 | 内部余额不能未经约定代表链上可支配资产 |
| 持仓与风险 | 成本、盈亏、保证金、限额、风险重算与强平触发 | 未实现盈亏不能直接当成可提现现金 |
| 链上结算 | 验证授权与履约条件、提交和执行资产／头寸变更 | 广播成功不代表执行成功，更不代表达到最终性 |
| 行情与回报 | 公共盘口／成交视图、私有订单／账户结果 | 派生视图落后不应反向改写成交或资产真相 |
| 对账与恢复 | 核对进度、识别差异、补交付、重放和业务修复 | 不能直接改余额掩盖差异，也不能任意撤销已确定的成交 |

### 2.2 一次业务有多个完成点

| 完成点 | 表示什么 | 不表示什么 |
|---|---|---|
| 接口收到请求 | 网络入口拿到内容 | 请求已可靠保存 |
| 可靠受理 | 在承诺的故障模型下可恢复请求 | 业务已接纳或成交 |
| 订单接纳／成交裁决 | 权威状态机给出订单或成交结果 | 账务、链上结算和页面均已同步 |
| 账户结转 | 适用账本中的资产／持仓变化已提交 | 必然达到链上最终性，具体取决于架构 |
| 链上执行成功 | 交易在某个链状态中成功执行 | 不会重组或已满足产品最终性要求 |
| 达到认可最终性 | 满足该链和产品明确的最终性策略 | 零风险；极端最终性故障仍需应急方案 |
| 展示完成 | 查询／推送视图已更新 | 展示系统就是权威状态 |

不同系统可以合并其中一些步骤，但接口与面试回答必须说明成功回执到底承诺了什么。链上原子交易可以把成交与结算合在一次执行中；混合架构则必须解释中间承诺及履约风险。

## 三、订单簿／混合 DEX：从订单到资产交割

### 3.1 教学基线

采用现货限价订单簿、价格时间优先、Maker 价格成交，撮合状态在链下。资产控制和结算再区分两种情况：

- **预存资产或抵押型**：账户／合约提供有效的预占或抵押承诺，撮合依据该承诺执行，按约定结转和结算。
- **钱包签名单型**：签名只是授权意图，用户余额或授权额度可能变化。必须说明何时检查可履约性、如何避免超额成交、是否有链上锁定或其他保证，不能把签名等同于资金冻结。

[撮合专题](../01-撮合交易与核心链路/01-撮合交易从0到1/README.md)采用独立账户模块提供预留凭据的教学模型。本节补充它与资金和链上边界的关系。

### 3.2 主流程

| 步骤 | 输入与处理 | 状态／资金变化 | 主要异常及责任 |
|---|---|---|---|
| 1. 规则与权限 | 交易对、资产、价格数量步长、费用、签名域和账户权限 | 确定本次订单采用的规则与授权范围 | 过期签名、错误链／合约、越权、精度错误由接入拒绝 |
| 2. 幂等与准入 | 按账户、操作、请求标识识别意图，校验规范化载荷 | 新请求进入处理，重试复用已有结果／进度 | 相同身份但载荷不同应冲突，不重复预占 |
| 3. 交易前检查 | 检查资金、授权、产品限额和适用风险，取得预占／履约承诺 | 适用模型中可用转预占；非锁定钱包模型只形成校验结果 | 并发花费、授权撤销不能靠一次静态检查解决 |
| 4. 排序与接纳 | 下单、撤单进入声明的权威序列并按约定可靠提交 | 形成接纳／拒绝及可恢复位置 | 超时查询原请求；拒绝或撤销结果驱动适用的资金释放 |
| 5. 撮合与撤单裁决 | 检查当前状态，按价格时间规则匹配 | 形成稳定成交身份，更新剩余量与队列 | 部分成交、撤单竞争、过期订单按唯一裁决处理 |
| 6. 成交清算 | 根据成交计算交割、费用及适用持仓变化 | 明确双方应收应付、消耗和剩余预占 | 整数／定点精度、舍入、费用归属必须一致 |
| 7. 账务与链上履约 | 按架构提交账务，必要时构造链上结算交易 | 资产／头寸按权威状态变更；待结算状态单独表示 | 业务原子范围、跨分片和链下链上部分成功须有专门协议 |
| 8. 确认与释放 | 确认结算结果，按明确业务终态释放不再需要的预占 | 用户获得可用资产或明确的待结算权利 | 广播不确定不能直接释放；失败先判断是否已执行 |
| 9. 回报与对账 | 交付订单／成交／账户私有回报，更新公共行情 | 视图追上权威状态，形成可核对进度 | 断线重连、缺口补齐；按共同截止点核对成交、账本和链上状态 |

第 7、8 步的先后与提交边界取决于架构：链上结算为权威时，链下账务可能只是待结算记录或链上投影；存在内部权威账本时，则必须说明它与合约资产和用户权利之间的对应关系。不能默认所有 DEX 都先内部扣款、后链上结算。

### 3.3 一笔现货交易的资金推演

教学数值，不代表市场价格。忽略手续费，价格步长为 0.01 USDT，数量步长为 0.001 BTC，账本支持本例需要的金额精度：

- 卖盘 A1：100.00 USDT/BTC × 0.004 BTC。
- 卖盘 A2：100.00 USDT/BTC × 0.003 BTC。
- 卖盘 A3：101.00 USDT/BTC × 0.005 BTC。
- 买单 B1：限价 101.00 USDT/BTC，买入 0.010 BTC，预占 1.010 USDT。

按 Maker 价依次成交 0.004、0.003、0.003 BTC，成交额为 `0.400 + 0.300 + 0.303 = 1.003 USDT`。完成结转后买方获得 0.010 BTC，支付 1.003 USDT，释放 0.007 USDT；A3 剩余 0.002 BTC。

必须同时核对：

- 订单原始数量 = 累计成交量 + 累计撤销量 + 剩余可成交量。
- 买卖双方成交数量与金额对应；无手续费时，本例 BTC、USDT 分别守恒。
- 一个成交只产生一次业务账务效果；成交重放不能再次扣款。
- 有手续费时加入费用账户，有舍入时加入明确的差额规则，不能靠二进制浮点近似“平账”。

### 3.4 异常闭环

- **请求超时**：凭原请求身份查询或幂等重试，不另建订单意图，不自行释放资金。
- **部分成交与撤单并发**：按权威顺序保留先发生的成交，只撤销尚可成交部分。
- **成交已确定、账务未完成**：保留可恢复事实，可靠重交付并幂等消费；不能因回报丢失就重新撮合。
- **链上履约失败**：区分暂时未确认、永久拒绝和原始成交承诺类型，按事先约定执行重试、失效或风险处置；若成交已是不可撤销义务，不能由服务单方面删成交解决。
- **撮合崩溃或切主**：从一致快照和已提交输入恢复、隔离旧主，再检查成交交付及账务进度。
- **链重组**：撤销受影响的链上投影并重扫，按协议处理待结算／已授信业务；链下权利和账务不一定能直接回滚。

## 四、AMM：从报价到 Swap 与 LP 生命周期

### 4.1 教学基线

以 EVM 上两个标准代币的恒定乘积池为例，Swap 在单笔交易内原子执行与结算。集中流动性作为扩展，不把单一 `x × y = k` 公式套用于所有 AMM。

### 4.2 Swap 主流程

| 步骤 | 处理与状态变化 | 必须讲清的边界 |
|---|---|---|
| 1. 获取报价 | 读取池状态，计入手续费、价格影响和路由成本 | 报价对应某个状态，不保证打包时仍有效；价格影响与滑点不是同一概念 |
| 2. 设置执行约束 | exact-input 设置最小接收量，exact-output 设置最大输入量，并设适用期限 | 用户约束由合约执行校验，不能只在前端检查 |
| 3. 授权与签名 | 检查余额和 allowance，必要时先 approve，或使用协议支持的签名授权 | 普通交易签名、Permit 和资产授权作用不同；单独 approve 成功不会因后续 Swap 失败自动撤销 |
| 4. 构造与模拟 | 指定链、目标合约、资产、金额、接收者、路由和 gas 条件，模拟适用交易 | 模拟降低错误但不承诺未来执行成功；检查恶意／异常代币行为的支持边界 |
| 5. 广播与追踪 | 发送签名交易，追踪待处理、替换、执行成功／回滚和确认 | RPC 超时不等于未发送；按交易身份和账户 nonce 等查询，避免业务重复 |
| 6. 链上执行 | 验证约束、转移资产、更新池状态、产生日志 | 本例同一交易内任一步失败，状态变化回滚，但执行失败通常仍有 gas 成本 |
| 7. 确认与核对 | 依据链最终性策略确认余额和池状态，索引事件 | 链重组可能撤销先前结果；索引应支持重扫与幂等，不能仅看返回的交易哈希 |

多跳同链路由只有被组合进同一原子交易时，才能使用本例的原子失败语义。跨多笔交易或跨链路径必须单独定义部分完成和失败恢复，不能直接套用。

### 4.3 无手续费的简化数值例子

池中有 100 个 X 和 10,000 个 Y，`k = 1,000,000`。用户输入 10 个 X，则新储备 `X' = 110`，理论输出：

`Y_out = 10,000 - 1,000,000 / 110 ≈ 909.0909 Y`。

初始边际价格为 100 Y/X，本次平均成交价格约为 90.9091 Y/X，差异来自有限流动性造成的价格影响。若用户设置最小接收量 900 Y，只有执行时实际结果满足约束才允许成功；若池状态变化使结果低于 900 Y，则回滚。

这是实数公式教学推演，不是合约整数执行结果。实际实现必须说明费用、代币小数位、整数除法和舍入方向，并使用相应模型的不变量。含手续费的恒定乘积池也不能机械断言每次交易后 `k` 严格不变。

### 4.4 LP 生命周期

1. 选择池和资产，理解价格、份额、费用和风险；集中流动性还需选择价格区间。
2. 授权并添加流动性，取得 LP 份额或仓位凭证，核对实际投入而非只看期望数值。
3. 交易改变池资产组成并积累费用；集中流动性在区间外可能停止提供活跃流动性。
4. 需要调整时减仓或换区间；费用领取与本金提取是否分开，按具体协议说明。
5. 退出并达到认可最终性，核对取回资产、费用和剩余仓位；分析无常损失、代币和合约风险。

钱包直连 AMM 通常没有交易所式内部充值、冻结余额和提现流程。若通过 Vault、托管或跨链入口接入，需要另外建模，不能因 AMM 本身原子执行就省略外层风险。

## 五、Perps：从抵押到平仓、强平和剩余风险处置

### 5.1 教学基线

采用 USDC 抵押、线性 USDC 结算永续合约，先讨论单一逐仓多头，忽略交易费与资金费率做简单盈亏推演。实际价格源、保证金档位、执行与结算方式必须另行声明。

这是一条产品流程，不限定订单簿或池式成交。全仓、多抵押品、反向合约不能直接复用本例公式。

### 5.2 主流程

| 步骤 | 处理与状态变化 | 关键约束 |
|---|---|---|
| 1. 抵押入账 | 抵押资产经适用确认后进入保证金账户 | 抵押余额、账户权益、可用保证金、可提现额分开；抵押折扣按产品定义 |
| 2. 交易前风控 | 检查订单、杠杆、初始保证金、仓位限额、挂单占用与权限 | 校验与接纳／执行之间的状态竞争要受控，不能重复使用同一保证金 |
| 3. 成交建仓 | 通过订单簿、池或其他机制成交，计算费用并更新仓位 | 说明净仓／双向持仓模式、平均成本、增减仓规则与精度 |
| 4. 持续估值 | 使用适用标记价格更新未实现盈亏，响应价格、持仓、抵押和参数事件 | 最新成交价、指数价格、标记价格用途不同；检查新鲜度和异常策略 |
| 5. 资金费率与费用结转 | 按协议时间窗口、仓位基准和支付方向结转 | 幂等批次、补算、舍入与资金平衡；结转后触发适用风险重算 |
| 6. 主动减仓／平仓 | 执行 reduce-only 等适用约束，计算已实现盈亏，释放不再需要的保证金 | 减仓不能意外反向开仓；释放要依据权威成交与结转结果 |
| 7. 强平触发与复核 | 比较适用权益和维持保证金，校验最新状态与接管权限 | 过期风险快照不能直接决定执行；充值、减仓、撤单可能改变结果 |
| 8. 强平执行 | 按协议撤销增险挂单、部分或全部减仓、拍卖或接管，持续反馈成交 | 触发不等于成功减仓；需要处理滑点、流动性不足、执行超时与重复指令 |
| 9. 剩余风险处置 | 结算盈亏、费用和负债，处置剩余坏账 | 保险基金、ADL、LP 承担或其他机制按协议定义，并非所有 Perps 都具备 |
| 10. 退出与对账 | 满足风险和提现规则后提取资金，核对账本、仓位、费用和链上资产 | 不允许把未确认抵押或不可提现盈亏直接提走；异常先隔离风险再修复 |

步骤 4、5 是持仓期间反复发生的事件，不是只能走一次的线性阶段。主动平仓和强平是不同分支；无触发条件时不进入强平。

### 5.3 保证金与强平数值推演

教学价格：多头持仓 1 个基础资产单位，开仓价 100 USDC，逐仓抵押 20 USDC，开仓名义杠杆为 5 倍。忽略所有费用、资金费率和其他余额变化，维持保证金比例固定为 5%，按当前标记价格计算名义价值：

- 未实现盈亏 = 持仓数量 ×（标记价格 − 开仓价格）。
- 逐仓权益 = 抵押余额 + 未实现盈亏。
- 本例维持保证金 = 当前名义价值 × 5%。

| 标记价格 | 未实现盈亏 | 逐仓权益 | 维持保证金 | 本例判断 |
|---|---:|---:|---:|---|
| 90 USDC | -10 USDC | 10 USDC | 4.5 USDC | 未触发 |
| 84 USDC | -16 USDC | 4 USDC | 4.2 USDC | 若规则为权益低于维持保证金则触发复核／强平 |

这不是通用强平价格公式。真实产品可能包含保证金档位、手续费预留、强平费用、资金费率、多抵押品和全仓其他仓位。标记价格用于风险判断，不保证强平能按该价格成交。

资金费率另行举例：若协议约定本期正费率为 0.01%、多头向空头支付，以 10,000 USDC 名义头寸结转，则本期支付 1 USDC；支付会影响账务和风险。该数字不与上表叠加，具体计费基准与收付平衡按协议确定，不能把资金费率固定当成平台收入。

### 5.4 重点异常

- **价格陈旧或源失效**：执行明确的风控限制、降级和恢复条件，不盲目沿用旧价强平，也不泛泛承诺所有功能继续运行。
- **过期强平指令**：在最终执行边界复核状态或版本，防止已经补足保证金仍被旧指令减仓。
- **强平没有流动性**：跟踪未消除的风险和资金缺口，按协议进入后备处置，不把“已发强平单”当作已恢复偿付能力。
- **资金费率批次部分成功**：用稳定批次与明细身份补算、去重、对账，不重扣已结转账户。
- **链上结算延迟**：限制新增风险，区分已承诺成交、待结算资产与可用抵押，不因页面显示盈利就允许提现。

## 六、预测市场：从市场定义到最终兑付

### 6.1 教学基线

采用完全抵押的二元结果市场，每份最终获胜头寸兑付 1 USDC。示例使用结果代币完整集模型，交易可采用订单簿或 AMM。其他模型可以不发行结果代币，也不一定具备拆分／合并操作。

### 6.2 主流程

| 步骤 | 处理与状态变化 | 关键异常与边界 |
|---|---|---|
| 1. 定义市场 | 明确问题、互斥结果、交易截止、观察时点、数据源、裁决和无效规则 | “发生了什么”必须可裁决，时区、延期和边界事件不能留到结算时再定 |
| 2. 抵押与头寸形成 | 示例中锁定抵押，铸造完整集；也可直接购买他人头寸 | 保证兑付义务有抵押支持；买入流通头寸不等于再次创造全部抵押 |
| 3. 交易与流动性 | 通过订单簿或 AMM 形成价格和头寸转移 | 采用对应成交／结算流程；价格受风险溢价与流动性影响，不是被保证准确的概率 |
| 4. 截止与事件观察 | 按规则停止或限制交易，等待适用事件与数据 | 交易截止、事件发生和裁决完成可能是不同时间，不能混成一个状态 |
| 5. 提议结果与争议 | 按机制提交结果，进入适用挑战、仲裁或争议窗口 | 数据源不可用、结果含糊、争议期间均需明确资金和交易规则 |
| 6. 最终裁决 | 结果达到协议认可的不可再普通挑战状态 | 普通市场裁决终局性和底层链最终性是两层条件；不把初次提议当最终结果 |
| 7. 兑付或合并 | 获胜头寸按规则兑付；完整集在协议允许时可合并取回抵押 | 明确销毁／已领取状态、批次、舍入与重复调用，防止重复兑付 |
| 8. 异常结案与对账 | 无效、取消、延期按预先约定处理，核对抵押、头寸和兑付 | 无效不必然是各退一半或按原买入价退款，必须依据该市场规则 |

### 6.3 完整集数值推演

以下为合成教学案例，忽略费用：

1. 用户 A 锁定 100 USDC，获得 100 份 YES 和 100 份 NO。每对 YES＋NO 代表一份完整集，最终合计对应 1 USDC 兑付义务；**不是铸造了可同时兑付 200 USDC 的资产**。
2. A 以 0.60 USDC/份把 40 份 YES 卖给 B，获得 24 USDC。合约抵押仍为 100 USDC，交易只转移了头寸所有权。
3. 最终 YES 获胜，A 持有的 60 份 YES 兑付 60 USDC，B 的 40 份 YES 兑付 40 USDC，NO 兑付为零。
4. 该批抵押总兑付 100 USDC；A 获得的交易款 24 USDC 来自 B，不是协议额外创造的收益。A 本例净损益为 -16 USDC，B 为 +16 USDC。

若改为无效市场，应使用预先定义的无效兑付向量重新计算，不能沿用 YES 获胜案例。完整集合并、争议保证金、创建激励等按具体协议另外说明。

## 七、贯穿所有适用模型的支撑链路

### 7.1 行情、预言机和风险价格

- **行情管道**：采集 → 清洗 → 标准化 → 聚合 → 构建快照／增量与指标 → 推送。保留源、时间、序号和有效性，缺口要补齐。
- **风险价格**：按产品规则把适用数据转换为指数／标记价格等风险输入，处理陈旧、离群、偏离、操纵和源失效。并非所有 AMM 都依赖外部预言机执行 Swap。
- **私有交易回报**：来源于订单、成交、账户权威事件，按用户权限推送并支持查询与重连；不能拿公共行情猜测自己的订单是否成交。
- **做市与 RFQ**：做市商根据行情、库存、限额和对冲成本报价；RFQ 还要明确报价身份、有效期、可成交数量、签名、履约和拒绝规则。

### 7.2 充值与提现

仅在存在协议存款、保证金账户、Vault 或其他资金入口时采用，不给钱包直连 Swap 强加平台内部余额模型。

**充值：** 识别资产与收款对象 → 观察链上执行 → 按确认策略记为待确认／可用 → 幂等入账 → 核对链与账。重组时撤销投影、重新识别有效交易，并按业务规则处理已授信部分。

**提现：** 鉴权与风险检查 → 预占可提现资金 → 适用审批和安全签名 → 广播与追踪 → 确认付款 → 结转在途资金。若业务是合约自助提款，则由合约验证和执行，不假设所有 DEX 都有平台审批或热钱包。

提现广播超时、替换交易或服务崩溃后，应查询既有付款意图和链上状态。只有能够确认不会再付款时，才能按规则释放预占；不能因为某个 RPC 返回失败就重新支付一笔。

### 7.3 Go、数据库与可靠性

每条业务链都应能回答：

- 谁拥有可变状态，串行化和并发范围是什么，跨交易对／账户共享资源怎样协调？
- 哪个提交点决定成功，日志、数据库、消息和链上执行之间有何部分成功窗口？
- 请求、命令、成交、记账、链上交易和事件各用什么身份，重放身份是否稳定？
- 事件积压、慢消费者、数据库锁等待、GC 或 RPC 抖动会影响哪段尾延迟，如何背压和止损？
- 崩溃后恢复什么，谁隔离旧主，重新开放接单／提现／强平之前需要哪些校验？

具体专题归属见[P0 与 P1 目录补齐规划](./01-P0与P1目录补齐规划.md)。

## 八、端到端对账与恢复验收

| 核对对象 | 核对内容 | 不一致时的处理原则 |
|---|---|---|
| 订单与成交 | 终态、剩余量、成交身份、序列缺口 | 找到权威裁决与可靠记录，不根据前端展示重新生成成交 |
| 成交与账本 | 应收应付、费用、预占消耗／释放、幂等身份 | 补交付、补处理或受控业务冲正，保留审计，不直接改余额 |
| 持仓与风险 | 成本、数量、已实现／未实现盈亏、保证金和风险版本 | 先限制不确定状态下的新增风险，再依据事实重建或纠错 |
| 链上资产与内部记录 | 抵押、充提、结算、事件与确认水位 | 区分正常在途、索引延迟、重组和真实缺失，处理相应业务权利 |
| AMM／LP 与预测市场 | 池状态、LP 权利、抵押、结果头寸和兑付 | 依据协议状态与规则验证模型不变量，不套用订单簿账务 |

对账必须选定可比较的时间、区块和事件水位。不能用一个模块最新状态与另一个模块滞后快照直接比较，也不能把不同币种的数量简单求和当成资金守恒。

恢复验收至少包括：已确认业务未丢失或损失符合明确承诺；重放不重复成交、扣款或兑付；旧执行者失去写权；积压可追平；关键资产、仓位和链上状态可核对；恢复接单与资金操作的条件明确。

## 九、面试复述与覆盖检查

讲一个 DEX 方案时，依次回答：

1. 我的产品、成交机制、资产控制和结算方式是什么？哪些只是教学假设？
2. 一笔业务从哪里开始，到哪个状态才算完成？主要拒绝、取消、失败分支在哪里？
3. 订单、资金、持仓和风险分别由谁维护，状态如何交接？
4. 数量、资产、费用、保证金和兑付遵守什么规则与不变量？
5. 并发、重试、超时、崩溃、部分成功或重组发生后，谁恢复、谁对账？
6. Go、数据库、网络和链上机制如何支持这些承诺，性能指标和验证方法是什么？
