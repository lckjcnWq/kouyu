# 大问题 2：做市系统怎样得到可用的公允价格，并在行情失真时阻止错误报价？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文中的含义与边界 |
|---|---|---|
| 公允价格 F | 策略认为当前大致值多少钱的参考 | 教学输入为 2000 USDT/ETH，不保证能在 B 按这个价卖出 |
| 最新成交价与盘口 | 一笔历史买卖的价格，与当前各价档愿意买卖的量 | 历史成交不等于现在的退出条件，盘口也要检查时效与完整性 |
| 可执行深度 | 按某方向交易指定数量时，需要吃到哪些价档 | 卖 0.6 ETH 要看 B 买盘，不只看中点或最优一小档 |
| 序号缺口与重建 | 更新记录缺了一段，要重新拼出可信盘口 | 重连或心跳正常不恢复交易资格；按各场所协议衔接快照与增量 |
| 事件时间、接收时间、单调时钟 | 源端发生时刻、本地收到时刻、衡量本机经过多久的时钟 | 未校准的两所时间不能直接用于证明精确领先关系 |
| 输入版本与质量状态 | 给整套价格依据贴上版本和可用性说明 | 同一次报价使用一致快照；旧好价可供诊断，不能假装仍可交易 |
| delta、r、k | 确认库存偏离、报价中心、每多一单位库存调多少价格 | r=F−k×delta；k 的单位保证结果为 USDT/ETH，不是资金金额 |
| tick、lot 与 Post-Only | 价格格子、数量格子、只挂不吃的执行条件 | 教学 tick=0.01、lot=0.001；被拒后重算，不放弃保护去追旧报价 |
| 熔断与 UNKNOWN | 停止新增不安全承诺，以及尚不能判定结果的请求 | 熔断仍需撤旧单、补成交；未知单继续占预算，不能在本地直接删掉 |

## 把整篇文章压缩成一个故事

小林看到参考价 2000，准备在 A 挂 1999 买、2001 卖，却发现 B 虽然心跳正常，盘口更新中间少了一段。系统不能继续拿旧买盘算退出成本：先把输入标为不可用，阻止扩险报价，按协议重建并衔接增量。接收年龄、有效深度和跨源偏离也要检查，不能靠重复旧消息给价格续命。

即使输入恢复，F 仍只是估值。沿正文独立主例，A 买入 0.6 ETH 花 1199.4 USDT，B 若只能在 1998 全卖出，就只收回 1198.8，零手续费也亏 0.6。B 尚未确认成交时，确认敞口仍是 +0.6，报价不能因已有对冲计划就恢复中性。每次候选还要绑定行情、库存和规则版本，发送前检查资格；已发出的旧单则只能通过撤单与证据管理。文章要讲的是把价格可信度一直传到真实订单，而不是选一个漂亮的平均价便宣告安全。

[返回专题总览](README.md)

**必要前提：** 沿用总览的 ETH/USDT 现货基线。A 是链下托管 CEX 做市场所，B 是独立 CEX 对冲场所，两所预先各有 10 ETH、100000 USDT；无杠杆、借贷、裸卖空和跨所原子成交。交易与账务以各所为权威，不靠逐笔链上转账对冲。以下 F=2000 USDT/ETH、半价差 s=1 USDT/ETH、tick=0.01 USDT/ETH、lot=0.001 ETH 都是教学参数，不代表最优策略。

**流程位置与核心机制：** 本题位于“接收行情 → 重建可用盘口 → 计算 F 与执行成本 → 放行报价输入”。它解决价格输入是否值得相信，不负责把公允价格误称为可保证成交的价格。

```text
A、B 行情输入
    ↓ 校验交易对、精度、序号、时效与盘口完整性
形成带版本和质量状态的价格输入
    ├─ 不合格 → 禁止新增风险，撤销不再安全的旧报价
    └─ 合格 → 计算 F，检查 B 的可执行成本
                  ↓
          交给库存偏斜、预算和报价生命周期
```

## 第 1 层：为什么不能直接拿最新成交价报价？

**面试官：** A 上做市、B 上对冲，你怎样确定公允价格？直接取最新成交价再上下加一块钱行不行？

**面试者：** 不行。最新成交价只是某一时刻的一笔历史结果，可能量很小、已经过时，或者来自我自己的报价，不能代表现在能以什么价格退出库存。我会先把公允价格 F 定义为策略使用的参考估值，再把实际对冲价格定义为 B 上相应方向、相应数量的可执行价格，两者分开保存。

在这个模型中，教学输入给定 F=2000，因此初始参考报价是 1999 和 2001。实际生产可以从经过质量检查的盘口中点、微价格或多源估值生成 F，但必须明确来源、权重和失效条件。特别是 A 自己的挂单会影响 A 的盘口，不能让策略不断把自己推高的价格当成新的外部价值。F 是决策输入，不是交易所担保，也不保证 B 能按 2000 成交。

## 第 2 层：参考价要可信，原始行情必须附带什么事实？

**面试官：** 你说 F 要附带来源和失效条件。行情接进来时具体保存什么，怎样避免“2000”这个数字脱离上下文？

**面试者：** 我保存的不只是价格，还包括 venue、pair、连接代次、快照或增量序号、交易所事件时间、本地接收时间、处理完成时间和质量状态。盘口还要有各档价格、数量和所属版本。这样才能回答这个 2000 对应哪份簿、是否连续、在本机停留了多久。

价格和数量使用定点数或十进制定点表示，明确价格单位是 USDT/ETH、数量单位是 ETH；不能把整数 tick 数与 USDT 数直接相加。本地单调时钟用来计算接收后的等待时间，交易所时间用于辅助判断源端延迟；两所时钟未校准时，不能直接相减就宣称精确测出了跨所领先关系。最后生成不可变的价格输入版本，避免计算 bid 时读到旧盘口、计算 ask 时又读到新盘口。

## 第 3 层：版本连续性在断线和增量缺失时怎样保证？

**面试官：** 既然价格输入依赖盘口版本，收到增量但中间少了一段，能不能暂时沿用旧盘口继续算 F？

**面试者：** 如果该行情协议要求连续增量，缺口出现后就不能再把当前簿标成可信。缺的可能正是某档撤单，继续沿用会制造并不存在的流动性。我会把对应场所的簿标记为失效，停止使用它放行新报价，再按交易所协议获取快照、缓存并衔接快照之后的增量。只有覆盖关系与连续性校验成立，才发布新的可用版本；不同交易所不能强套同一种序号规则。

恢复期间仍保留最后一次有效值用于诊断，但它不等于仍有交易资格。A 或 B 失效也要分别处理：A 簿失效会影响本地报价是否穿价的判断，B 簿失效会影响对冲成本判断。不能因为 B 的 WebSocket 连接还活着，就把缺口以前的深度当作现在能卖出的深度。

## 第 4 层：没有缺口，为什么行情仍可能不可用？

**面试官：** 你已经校验了序号。现在消息连续、连接有心跳，但 B 的价格一直不动，A 却快速下跌，这时怎么办？

**面试者：** 序号连续只能证明协议层没有发现缺失，不能证明经济信息足够新。我还会检查源端事件时间、有效盘口更新时间、本地队列积压、买卖盘是否交叉、有效深度以及跨源偏离。心跳不能刷新业务价格的年龄，重复转发旧报价也不能让它重新变新。

发现异常后先把“价格异常”和“来源异常”分开：市场真的跳变时，不应机械丢弃最新价、继续使用平滑后的旧价；来源冻结时，也不能盲目追随另一条可能同源的流。阈值需要结合市场波动和正常延迟设定，而不是承诺一个万能毫秒值。这个基线下，如果无法确认 B 的执行条件，我会撤掉增加风险的 A 报价、限制新增承诺，而不是靠简单平均把异常源伪装成正常价格。

## 第 5 层：行情有效，为什么仍会“赚价差却亏钱”？

**面试官：** 假设 B 行情没有冻结，F 也是 2000。A 以 1999 买入，不是天然赚一块吗？为什么还要看深度？

**面试者：** 因为买入后的退出方向是到 B 卖 ETH，要看的不是中点，而是 B 买盘对目标数量的可执行加权价格。只看最优买价也不够，最优档可能只有 0.01 ETH，卖出 0.6 ETH 需要吃到更差档位；还要考虑费用、延迟和价格保护下可能只成交一部分。

贯穿案例中，A 买入 0.6 ETH@1999，支出 1199.4 USDT，A 变成 10.6 ETH、98800.6 USDT。如果 B 实际把 0.6 ETH 全部卖在 1998，只收回 1198.8 USDT，忽略手续费也毛亏 0.6 USDT。预交易深度估算可以阻止明显不合算的新增报价，但不是锁定利润；两所不能保证同一时刻成交，所以预算和风险必须容纳估计失效的窗口。

## 第 6 层：价格估计失效后，库存为什么不能靠“计划对冲”归零？

**面试官：** 既然两所不同步，A 先成交、B 卖单还未确认时，下一轮到底用哪个库存算报价？

**面试者：** 用本地已经可靠接纳的确认成交投影来计算总持仓 Q，而不是用计划结果。目标为两所合计 20 ETH，delta=Q−20。A 买入 0.6 后，Q=20.6、delta=+0.6，即使已经发出 B 卖出 0.6 的请求，也不能说实际风险回到了零。

教学偏斜公式是 r=F−k×delta，其中 k=10 (USDT/ETH)/ETH，乘以 ETH 数量后才得到 USDT/ETH 的价格偏移。F 仍为 2000 时，r=1994，按 tick 向下取 bid=r−1、向上取 ask=r+1，得到 1993、1995。未决对冲用带符号剩余量 H 表示，买正卖负并包含 Unknown；此时 H=−0.6、预计残差 E=delta+H=0，只用于避免重复规划对冲。E 不是确认持仓，不能拿它把报价中心提前恢复到 2000。

## 第 7 层：正确输入怎样避免在发单前已经过期？

**面试官：** 你算出了 1993、1995，但行情和成交还在变化。怎样保证执行器不会发出几百毫秒前算好的旧报价？

**面试者：** 策略按 `(accountGroup,pair)` 只有一个逻辑 owner。一次计算引用确定的行情版本、持仓投影版本、预算版本、规则版本和 quoteGeneration，并把报价意图、预算变化与 outbox 放进可靠本地日志或事务。执行前检查它是否仍属于当前允许发送的代次、行情是否仍有效、预算是否仍满足；未发送的过期意图可以作废，不能只靠出队顺序猜测有效性。

但这不等于把交易所调用包进本地事务。命令发出以后，行情仍可能变化，外部 API 无法与本地原子提交。A 的 post-only 拒绝说明到达时已经不满足交易所条件，要取新行情重新计算，并以新意图决定是否继续；不能原价盲重试，更不能自动取消 post-only 改成吃单来完成旧目标。发送后超时则进入未知状态，而不是假定没有挂出。

## 第 8 层：旧报价已经在外部时，行情熔断怎样真正闭环？

**面试官：** 你能阻止未发送的旧意图，但市场失真时旧单可能已经挂在 A，甚至撤单也超时。熔断怎样才不自欺欺人？

**面试者：** 熔断首先阻止新的增加风险的承诺，再对可能存在的旧单发起受控撤销；它不是瞬间删除外部订单。撤单等待和 Unknown 期间继续占预算，并把可能成交量计入最坏敞口。如果撤单 ACK 先到、此前发生的成交后到，仍按交易所确认成交入账，不能以“已熔断”拒收。

恢复也不能只看行情恢复绿色。要确认行情已重建、订单与成交已补齐、余额与预留可解释，才允许新代次报价。验证时可手工推演：先让 B 簿缺口，再让 A 的 0.6 成交与撤单回报乱序到达。预期是价格输入被禁用、Q 最终只增加 0.6、未决 B 卖单仍保留 H 与资金约束，直到 B 确认全成，Q 才回到 20。若系统仅凭新心跳就恢复报价，说明质量门禁没有覆盖真实风险。

## 收束：机制、易错边界与反例验证

- **讲透的机制：** F 的来源可追溯，盘口完整性、时效和执行深度分层检查；报价引用确定版本，行情失效一直传递到存量订单和风险收敛。
- **易错边界：** 中点不等于退出价，连续消息不等于新鲜消息，E=0 不等于 delta=0，撤单请求成功不等于没有成交；本地门禁不能撤回已经发出的外部命令。
- **反例验证：** F=2000、A 买入 0.6@1999、B 卖出 0.6@1998，最终 B 为 9.4 ETH、101198.8 USDT，合计 Q=20、USDT=199999.4。库存数量回归目标而毛损益仍为 −0.6 USDT，足以反证“参考价正确、对冲完成，所以必然盈利”。
