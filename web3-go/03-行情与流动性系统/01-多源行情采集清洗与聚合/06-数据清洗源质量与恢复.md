# 大问题 6：怎样清洗异常源，又不把真实行情误判成错误？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文中的含义与边界 |
|---|---|---|
| 硬清洗／schema | 先确认字段结构和经济含义可解释，再谈数值是否合理。 | 市场、单位、精度、身份或同步有问题的输入先排除，不能等统计算法替它洗白。 |
| 完整 BBO／绝对数量 | 当前最优买卖两边及各自更新后的挂单总量。 | 双边价量均须为正且 bid≤ask；零量、反向买卖价不能自动修成合法事实。 |
| 定点尺度／宽整数 | 用精确整数表示小数，并给中间运算留足范围。 | 价格尺度 10^6、数量尺度 10^8；超尺度拒绝，求和与偏差乘法也要查溢出。 |
| 最新无效／last_good | 当前状态已不可用，与以前曾有过好价格是两件事。 | 已确认新 BBO 无效就不能退回旧价补候选；旧价只能另列并标陈旧。 |
| SYNCING／READY／GAPPED／QUARANTINED | 正在同步、同步依据成立、有缺口、冲突隔离。 | 这是源硬状态；陈旧与本轮离群不是新增永久状态，READY 也不保证绝对真实。 |
| 时间资格／age | 观测按采样 T 计算是否还够新。 | age=T−源事件时间，仅 0 到 2000ms 含端点合格；未来或时钟未知先排除。 |
| 中位数 m／一次离群 | 先取中间参照，再对同一个参照筛一遍。 | 主例先排 E，A—D 得 m=2001，再排 D；不重新选参照反复剔除。 |
| 1%／bp | 相对偏差门槛；100 个基点等于 1%。 | 严格超过才剔除，恰好 1% 保留；在宽整数域做交叉乘法比较。 |
| 独立组 | 按已知的共享上游或共同故障依赖划分的来源组。 | Q1 要至少三源三组，但仍按源等权；域名多不等于独立，也不保证多数绝不会同错。 |
| 恢复证据／状态代际 | 说明失效原因如何被解决，并区分先后状态。 | 缺口须补齐或合法快照，冲突须裁决；不额外偷加“三次好价”防抖。 |
| VALID／UNAVAILABLE／valid_until | 结果包的资格标签、不可用标签与使用截止。 | 不达标则 price=null；年龄等于 2000ms 可参与历史计算，但其贡献会使实时包立即到期。 |
| 失效控制／Outbox | 把不能再用的事实作为可靠交付的业务消息。 | 和源状态、cursor 同事务，按内部交付序列传播；历史修订保留证据，不续当前 TTL。 |

## 把整篇文章压缩成一个故事

质量负责人小夏看到 D 报 2400，准备把它永久拉黑。复核规则后，她先查各源市场、单位、精度和同步证据，再按采样 T 排掉陈旧 E，最后才对 A、B、C、D 求一次中位数 2001。D 偏差超过 1% 被本轮排除，剩下三源三组等权得 2000；恰好在阈值上的报价应保留，D 也没有因此变成永久隔离源。另一次 B 的最新报价买价高于卖价，她没有调换两边，更没有借上一条好价凑数，而是留下拒绝证据并可靠发出失效。若 A、B 被确认共用上游，即使数值不变也只剩两组，必须不可用。缺口恢复要补齐或取得合法快照，冲突隔离要有对应裁决，心跳和正常价都不算证明；满足原条件即可恢复 READY，不偷加防抖门槛。她把失效、恢复和输出进度共同持久，保证旧恢复消息不会盖掉新故障，消费者到期自行停用。最后用多数同错反例提醒团队：清洗能证明按规则选了哪些证据，不能承诺任何攻击下都是真实公允价。

**流程位置与核心机制：** 本题贯穿源 owner 的标准化与硬质量裁决，以及 market owner 的候选过滤。重点是清洗的不可变证据、定点精度、硬排除与轮次离群的区别、独立组门槛、恢复证据和失效交付。身份、序号回补和跨源聚合各有独立母题，这里只说明质量判断所依赖的契约，不重新展开整套实现。

**必要前提：** 采集 CEX 现货 `ETH/USDC` 的完整 BBO 绝对值观测，价格统一为 `USDC/ETH`、数量统一为 ETH，要求买卖价均大于零、`bid<=ask`、两侧数量均为正。`price_scale=10^6`、`qty_scale=10^8`，十进制字符串精确解析，超出 scale 拒绝而非截断，乘加使用宽整数并检查溢出，`mid_int=floor((bid_int+ask_int)/2)`。stream 为 `source+instrument+channel+native_epoch`，主例源协议有连续 native_seq；缺口先 GAPPED，重连不重置源 epoch。不同 API 的连续性契约必须另行说明。

A—E 均已进入持久轮次 T 的冻结可见前缀，配置为五个独立组，BBO 的数量已满足正值条件，具体数量不是本轮计算的权重：

| 源 | bid / ask | mid | age=T-source_event_time |
|---|---|---|---|
| A | 1997 / 1999 | 1998 | 100ms |
| B | 1999 / 2001 | 2000 | 120ms |
| C | 2001 / 2003 | 2002 | 80ms |
| D | 2399 / 2401 | 2400 | 100ms |
| E | 2000 / 2002 | 2001 | 5000ms |

只有 `0<=age<=2000ms` 且事件时间、时钟质量可信才有时间资格。先硬排除，再从前缀内每源最新可信状态取一个 BBO；最新源状态无效时不回退旧好价。E 陈旧而排除，对 A—D 只算一次中位数 `m=floor((2000+2002)/2)=2001`；以宽整数判断 `abs(p-m)*10000>m*100`，剔除超过 1% 的 D，不迭代剔除。剩余至少三源、三个独立组才等权均值，主例为 2000。

源硬质量状态为 `SYNCING / READY / GAPPED / QUARANTINED`，包质量另用 `VALID / UNAVAILABLE`。失败包 `price=null`，旧价只作独立 `last_good`，不续期。合法包 `valid_until=min(T+1000ms, 每个贡献源的 source_event_time+2000ms)`，消费端要求 `now<valid_until`；age 正好 2000ms 的观测可以参与历史计算，但会使结果包当场到期。输出是本轮最新有效观测快照，不是 K 线、Mark 或全球同时可成交价。主例没有链输入。

```text
Raw 不可变持久证据
    ↓
源 owner：校验市场 / schema / 精度 / BBO / 身份与连续状态
    ├─ 不合法 → 保留证据 + 当前源状态失效控制
    └─ 合法 → 带证据引用的 canonical + 源硬质量状态
    ↓
market owner 冻结输入前缀与 T
    ↓
硬状态和时间资格 → 每源一个候选 → 一次中位数离群过滤
    ↓
源数与独立组数门槛 → VALID 结果或 UNAVAILABLE
    ↑
失效、到期、恢复控制同样推动新轮次
```

## 第 1 层：清洗是在修正价格，还是在定义可接受的事实？

**面试官：** 多源行情为什么不能把所有数值解析出来就求均值？你会怎样划分硬清洗、源质量和离群过滤？

**面试者：** 我会把清洗定义为“判断观测能否被解释并作为可信输入”，而不是把价格改到看起来正常。第一层是源 owner 的硬校验，包括来源、市场定义、计价和数量单位、schema、数值范围、完整 BBO、身份一致性及连续状态。比如不能确认是 USDC 还是 USDT 报价，就不能先按 1:1 混进来；bid 大于 ask，也不能自动交换两边后继续当原始事实。

第二层是本轮可用资格。聚合只从冻结前缀里取每源最新可信状态，源若为 GAPPED、QUARANTINED 或尚未完成同步，就先排除；随后按持久 T 和可信事件时间排除陈旧、future、时间未知或时钟质量不明的观测。第三层才是对剩余候选进行主例的一次中位数离群过滤。不能让一个 schema 已冲突的数值先进入中位数，再期待稳健统计消除它。

每次转换都要保留 `source`、`instrument`、`market_definition`、`mapping_version`、Raw hash 和 Raw 位置，原始字节不改写。canonical 是带解释依据的派生事实，拒绝记录也保留 `reject_reason` 和原始证据。这样才能分辨“源确实报了 2400”“适配器小数点错了”“把永续当现货了”，而不是只剩一个清洗后的 2000，失去问题来源。

## 第 2 层：精度和单位清洗怎样避免悄悄改变业务含义？

**面试官：** 你说清洗不能篡改事实。那源给很多位小数、数量单位不同，或者价格很大时，具体怎样转换才不引入隐性误差？

**面试者：** 价格和数量都从十进制字符串做精确解析，不先经过浮点数。`price_scale=10^6` 表示价格最小单位是百万分之一 USDC/ETH，`qty_scale=10^8` 表示数量最小单位是亿分之一 ETH。比如 `"1997.000001"` 得到 `1_997_000_001`，`"0.12500000"` 得到 `12_500_000`。若源有效小数位超过所声明 scale，例如 `"1997.0000001"`，就拒绝并记录精度理由，不截断成 1997。对什么语法可接受也应固定契约，不能某次支持科学计数法、重放时又换一种解释。

单位转换必须由已确认的源字段语义和映射版本决定。主例买卖量都统一为 base ETH；如果某源字段是 quote notional，就不能直接把 `1000 USDC` 当成 `1000 ETH`。若缺少能准确还原 base 数量的契约，就排除而不是临时除以 mid 估计。现货 ETH/USDC、ETH/USDT、反向 USDC/ETH 与永续合约也不能仅凭名称相似混为一谈；需要反向换算时属于显式映射变体，必须说明价格、方向和数量如何一同变换。

数值合法后，先要求两侧价格和数量都大于零，再要求 `bid<=ask`。mid 用宽整数计算两价之和并取下整；离群判断中的差值、绝对值和乘法也在宽整数域检查溢出，最终转换到存储范围时再次检查。不能只检查单个 bid 没溢出，却让 `bid+ask` 或 `abs(p-m)*10000` 溢出；溢出应产生明确拒绝事实，不能绕回负数后误判为便宜价格。

## 第 3 层：最新观测不合法，能否暂时沿用上一笔好价格？

**面试官：** 你会拒绝非法 BBO，但源上一条是合法好价。为了可用性，只丢掉坏消息、继续用旧好价是不是更稳妥？

**面试者：** 不能把“丢弃一条坏消息”实现成“这个源从未发生过失效”。如果最新已识别源状态表明当前 BBO 无效，聚合就不能回退旧好价补位。比如源 A 的 seq 101 合法，seq 102 来自同一已确认 stream，却出现 `bid=2005,ask=2000` 或零数量，owner 应保留拒绝证据并使 A 当前候选失效；不能因为 101 只过去 100ms 就把它当成 102 之后仍可信的当前状态。

状态和理由要分开。首次建立状态或重新同步时是 SYNCING；原生序号断档是 GAPPED；同 id 异业务内容、无法解释的 schema 或市场映射冲突等需要裁决时可进入 QUARANTINED；具备可信完整状态且同步条件满足时才 READY。具体异常走哪条恢复路径必须由契约规定。例如只有不可解析的外层垃圾时，要先确认能归属哪个 stream，不能让一个无法归属的数据包随意撤掉全部源；但已知 stream 的 schema 破坏不能悄悄忽略。

陈旧与本轮价格离群不是永久硬状态。A 可以保持 READY，却因为 age 为 2500ms 被本轮排除；D 可以保持 READY，却因本轮偏离被过滤。反过来，QUARANTINED 的源即使刚好报价 2000、age 只有 1ms，也不能靠数值接近多数派洗白。旧好价若需要展示，只能放进独立 `last_good`，保留原时间、原轮次和不可实时使用的语义。

## 第 4 层：硬排除之后，怎样精确判断本轮价格离群？

**面试官：** 你把永久源状态和轮次理由分开了。那主例 D 的 2400 到底怎样被剔除，为什么不是反复剔到所有价格都接近为止？

**面试者：** 我先固定候选集，再只计算一次中位数。E 的 age 为 5000ms，在进入统计前已经排除；A/B/C/D 的 mid 为 1998、2000、2002、2400，排序后偶数中位数取中间两项的定点整数平均并下整，得到 `m=2001`。注意 D 此时仍参与第一次中位数，不是先凭肉眼把它删掉。

随后对每个候选都相对于同一个 m 判断 `abs(p-m)*10000>m*100`。以十进制展示便于口算，A 差 3、B 差 1、C 差 1、D 差 399；阈值等于中位数的 1%，即 20.01，所以前三者保留、D 排除。底层全部乘以同一 price_scale，在宽整数域计算，scale 会在不等式两边一致保留，不通过浮点百分比比较。条件是严格大于，偏离正好 1% 不剔除；例如独立边界示例 `m=2000,p=2020` 应保留。

过滤后不重算中位数再继续剔除，因为那会变成另一套会改变结果的算法。这里只把 A/B/C 交给等权均值，得到 2000，数量不作为权重，D 也不因此永久变成 QUARANTINED。若本轮硬排除后或过滤后剩余源不足，结果必须不可用，而不是放宽阈值、找回陈旧 E、或用上一轮 2000 顶替。单次中位数规则本身也不是防所有攻击的证明，它只是在既定候选和独立性前提下的一种离群策略。

## 第 5 层：三个源都留下来，为什么还不一定可用？

**面试官：** 你已经保留 A/B/C 三个源，而且价格相近。为什么还要检查三个独立组，不能简单认为三个域名就是三票？

**面试者：** 域名和连接数不等于风险独立性。三个采集入口可能都转售同一个上游行情，也可能属于同一交易场所的多个 API；如果一个上游故障就能让它们一起报错，把它们当三份独立证据会高估可信度。我会用版本化的 `source_group_id` 配置来表达已确认的共同依赖，随轮次记录相应 `source_group_version` 和候选归属，不能重放时拿今天的组配置改写过去。

共享主例明确 A—E 是五个独立组，因此 A/B/C 过滤后既有三源，也有三组，结果 2000 不变。若显式改为独立变体，A 和 B 同组，C 另一组，那么即使还剩三源，也只有两组，应输出 `UNAVAILABLE`、`price=null`。不能为了凑数改数连接、把 D 放回来或把 E 的陈旧观测加入。

本题的组规则是门槛，不自动变成按组等权、每组选一源或给相关源降权的算法；如果以后改聚合权重，那是需要另立版本的规则变体。即使通过三组门槛，也只是基于已知依赖配置，没有证明三组绝无共同云故障、同一计价资产风险或一致错误报价。新鲜度、数值接近和配置独立性都是证据条件，不是“源完全可信”的同义词；未知独立关系也不能由系统临时虚构成多个独立组。

## 第 6 层：源恢复时，什么证据足以重新 READY？

**面试官：** 你不让少数源凑数，但源恢复太慢会一直不可用。遇到缺口或 schema 隔离后，什么时刻可以恢复，是否需要连续几个好价防抖？

**面试者：** 先恢复导致失效的那项保证，而不是只看价格变正常。GAPPED 要么通过有界缓存与回补形成可信连续状态，要么通过源协议授权、具有明确衔接边界的新完整快照同步。比如已应用 101、待处理 103，102 验证后接上 103，可以依据这个闭合事实恢复 READY；重连成功和心跳到达都不证明 102 已经补回。

QUARANTINED 的恢复也要与隔离原因对应。若是 schema 或市场映射冲突，需要有经过确认的适配契约或映射控制版本，并重新获得可解释的完整当前状态；若是同 id 异内容，需要保留冲突事实并有明确裁决和重新同步边界，不能让下一条“看上去正常”的价格自动把冲突抹掉。源 owner 记录 `recovery_reason`、`recovery_evidence_ref`、`sync_generation`、所依据的快照或连续边界，并生成可消费的恢复控制。

主例不额外加恢复防抖：可信连续状态或有效新快照已经满足条件时即可 READY，随后每轮重新判断时间与离群。READY 后若最新观测 age 为 5000ms，仍然不能贡献；D 下一轮价格回到合理区间，也只需通过该轮规则，不需要从“离群源永久黑名单”中解禁。若另设“恢复后连续三次合格才入选”，必须明确是额外独立变体，记录计数和规则版本，解释增加恢复延迟的代价，不能静悄悄改变共享主例三源可用门槛。

## 第 7 层：失效和恢复怎样避免在持久化、交付间撕裂？

**面试官：** 你给恢复要求了证据，但服务可能在修改源状态后、发出通知前崩溃。怎样避免聚合一直用旧状态，或者旧恢复消息把新故障盖掉？

**面试者：** 源 owner 的状态、canonical 或失效控制、输入 cursor 和 outbox 必须同 DB 事务提交，身份和同步元数据也要保持可恢复一致。比如处理 A 的非法 seq 102 时，事务里一起写入拒绝证据引用、源候选失效、源状态代际和待交付控制；不能只提交“102 已消费”，却把通知留在未持久内存。提交前失败就重做原输入，提交后发送失败由 outbox 续发，重复交付由稳定事件身份和消费位置识别。

恢复控制同样携带 `source_state_generation`、原因和证据位置，与 canonical 共同使用源事务分配的连续 `canonical_emit_seq`，不与原生 native_seq 混用。源分区 Outbox 等前条被 market Inbox 持久接纳才发送下一条，接收方校验 `expected_emit_seq`；异常未来序号先 pending 并保守阻断该源，补齐后按序应用，旧 READY 不能盖掉新 GAPPED。每轮保存 T、`input_vector`、候选 canonical 身份、源状态代际、组配置版本与排除理由；聚合状态、round/revision、输入 cursor 和 outbox 再在聚合自己的 DB 事务中提交。这不是跨 owner 的全局事务，而是两侧本地原子性加可重试交付。

缺口、隔离、恢复和到期控制都会推动新轮次，不只正价才触发。若一份 `VALID` 包到达消费端时 `now>=valid_until`，即使内容无误也不能实时使用；不能用消息接收时间刷新期限。普通晚到或回补只进入后续轮次，不给旧冻结轮补候选。只有源撤回、映射纠错等显式更正才追加 revision，保持原 T、原观测 cut 和原 manifest，另记 `correction_manifest`、纠错引用、适用版本和 `supersedes`，重算受影响候选和值而不覆盖原记录；原 Raw 不变，历史修订也不改变当前有效期。这样源质量变化既可解释，又不会通过重试或修订偷偷恢复旧价。

## 第 8 层：全部检查都通过，是否就能承诺价格绝对正确？

**面试官：** 你已经把每轮证据和失效过程都记录下来。若攻击者或共同故障让多个源同时报错，这套机制还能承诺什么，怎样用反例检查而不夸大效果？

**面试者：** 我能承诺按已声明的市场、时间、连续性、硬质量、离群和独立性规则形成结果，不能承诺任意对抗下都是真实公允价。例如显式独立变体中，三个配置为独立组的源都给出约 2400，两个诚实源仍为约 2000，而且所有时间、数量和 schema 都合法，一次中位数可能落在 2400 附近，反而剔除诚实少数。规则没算错，但多数证据本身已经失真；不能用“中位数抗异常”掩盖它的前提。

我会把手工检查分成能区分错误实现的场景。主例应得到 E 陈旧、D 轮次离群、A/B/C 三源三组、`quality=VALID,price=2000`，且 `valid_until=T+1000ms`；把 A/B 改为同组，只改变独立性配置，预期三源两组而不可用；把 B 的最新观测改为已确认无效，预期不能回退 B 的上一好价补足三源；把所有值保留但让 A 的源状态 GAPPED，预期 A 先硬排除，不能先参加中位数再过滤。场景各自独立，不把多个变体叠在一起偷换主例。

还要检查时间和恢复边界：future 或未知时钟即使价格为 2000 也不能通过；age 正好 2000ms 可进入历史轮次，但贡献它的包在 T 已到期；只有心跳不能把 GAPPED 恢复成 READY；一个真实新快照恢复 READY 后，不应被未声明的“三次好价”门槛阻挡。以上是依据规则的手工推演，不宣称已做工程测试。重放相同结果还要求历史输入、T、规则、组配置和控制记录相同；改变输入到达顺序导致中间轮次不同，并不违反这里的确定性承诺。

## 收束：机制、易错边界与反例

**机制：** 源 owner 先保证观测可解释、身份与同步可信，market owner 再按冻结前缀进行时间资格、一次离群过滤和独立性门槛判断。拒绝与恢复都有持久证据，原始记录不可变，失效也可靠交付。

**易错边界：** 硬排除先于统计；最新无效不回退；十进制超 scale 不截断；宽整数覆盖中间运算；离群不永久隔离；独立组门槛不等于改权重；READY 不等于新鲜或绝对可信；重连心跳不恢复 READY；包质量标签与源状态分开；历史 revision 不续当前 TTL。

**反例：** 一个实现先把 E 的接收时间当事件时间，再把 A/B 的同上游入口当独立组，遇到 B 最新非法 BBO 时继续用上一好价，最后声称“中位数已经过滤 D，所以 2000 安全”。即使它偶然也算出 2000，证据链仍不成立。正确性不仅看最终数字，还要看候选为何有资格、来源为何独立、状态是否当前可信，以及结果在消费时是否仍未到期。
