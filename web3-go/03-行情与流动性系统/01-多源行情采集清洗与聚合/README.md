# 多源行情采集、清洗与聚合

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文中的含义与边界 |
|---|---|---|
| Q1／观察参考产品 | 一套明确的教学规则，以及按它选源、计算并交付的参考结果。 | 参数非平台通则；不下单、不结算，不自动成为 Mark、指数或强平授权。 |
| BBO／bid／ask／mid | 最优双边报价、最优买价、最优卖价及其中间值。 | Q1 用现货 ETH/USDC 完整绝对值观测，价格为 USDC/ETH、量为 ETH，不是成交或盘口增量。 |
| Raw／Canonical | 前者保留接收原证据，后者保存按某版本作出的规范解释。 | 原文不覆盖；规范化要核对资产、单位与定点尺度，不能先过 float64 或静默截断。 |
| native_epoch／native_seq | 上游流身份的世代与流内顺序号。 | 连续性只是教学协议前提；本地连接世代不改变业务身份，无序号源不能冒充能检测全部漏包。 |
| owner／数据库围栏 | 负责顺序裁决的唯一写者，以及事务提交时排除旧写者的门禁。 | 源和市场分别管理状态；进程内单协程或租约不能替代单一权威写域内的任期核验。 |
| READY／GAPPED／QUARANTINED | 同步依据成立、有顺序缺口、冲突隔离。 | 与正在同步的 SYNCING 一起构成源硬状态；READY 不等于新鲜、真实或当前产品有效。 |
| Tick(T)／vector／manifest | 持久采样分界、各源应用位置清单与本轮材料清单。 | 固定已经看见的输入切面，不是 T 时全球市场快照；普通晚到只进后续轮次。 |
| age／valid_until | 源观测年龄，以及结果包固定的使用截止。 | 0≤age≤2000ms 可参与历史筛选；实时还须 now<截止，age=2000ms 的贡献会使包立即到期。 |
| 一次中位数／独立组 | 固定一次中间参照筛离群，并核验共同失真依赖组数量。 | 严格超过 1% 才剔除；筛后至少三源三组，再按源等权，不隐含组权重限制。 |
| Inbox／Outbox／至少一次 | 持久输入箱、同业务提交的待发箱，以及可能重复但可重试的交付方式。 | 连续内部交付号与原生序号、发布号、消费进度分别管理；重复无副作用不等于全链恰好一次。 |
| revision／supersedes | 显式纠错的历史更正版与其直接替代对象。 | 保留原 T、cut 和原清单；有旧截止只能收紧，无可用旧截止则至多原 T，不能跨不可用版续期。 |
| UNAVAILABLE／last_good／最终性 | 当前证据不足、单列历史好价，以及链上独立变体的稳定性政策。 | 不可用时 price=null；旧价不补位，链最终性不等于市场新鲜，也不把池价变成 CEX BBO。 |

## 把整篇文章压缩成一个故事

小林要把五家场所的 ETH/USDC 报价送到研究页面。他先留存 Raw，由源负责人核对原生身份、连续顺序、资产单位和精确数值，遇到重复不多算，缺口或冲突就可靠传递失效。市场负责人在持久 Tick(T) 封住已见前缀，记录位置与候选清单：E 已老去 5000ms，先排除；A—D 的 mid 中位数是 2001，一次排掉超过 1% 的 D，A、B、C 满足三源三组，等权得到 2000，原截止为 T+1000ms。价格、质量、进度和 Outbox 一起提交，消费者去重、按轮次应用，实际使用再查到期；断流也要重评估，不能拿 last_good 顶替。消费者还要先收紧已知限制，再补交付缺口；包里价格和质量不能分开更新。崩溃后按快照与同版本日志恢复，围栏挡旧主，重发不续期；明确纠错只在原切面追加修订，旧不可用版也不能借高修订复活。并发与背压守住证据边界，链上变体另查覆盖、重组与最终性，规则演进靠生效记录和隔离影子验证。最终交付的是可追溯、有期限的参考，不是成交保证；总览的最小实践也只做手工推演，不冒充已运行工程。

---

本专题面向 Go / Web3 交易系统面试，沿一轮 ETH/USDC 多源报价的完整处理过程，解释外部数据怎样成为**有证据、有质量、有期限、可恢复的观察产品**。不是交易所接入 SDK 教程，也不把公共行情当成交、账务或风险执行指令。

按[专家提示词](../../go-web3专家提示词.md)组织：文字全流程 → 核心板块 → 核心 20% → 设计与规则 → 母题地图 → 独立连续问答 → 一个简洁 MVP。问答以母题为单位交付，未完成项不创建占位正文。

## 第一部分：文字全流程

### 1.1 讨论基线

采用 **Q1 教学规则**，不是任何交易平台的实际参数或性能承诺。

- **产品**：链下多源现货 ETH/USDC BBO（最优买卖报价）观察与参考价。每源输入是一份完整 BBO，价格单位为 USDC/ETH，买卖量单位为 ETH；不是订单簿增量、成交或滚动 Ticker。
- **交易与资金边界**：外部场所拥有其报价、订单和成交事实，本系统拥有接收证据、规范解释、源质量与聚合产品；本流程不下单、不成交、不托管资产、不结算资金。报价被本系统接收不等于上游可成交承诺。
- **接入协议假设**：教学源具有原生流身份 `source + instrument + channel + native_epoch` 和该流内连续 `native_seq`，完整 BBO 的数量是绝对值。真实协议不一定有连续序号，适配器必须显式声明能力，不能直接照搬本假设。
- **状态归属**：源分区单 owner 负责身份、顺序和规范状态；每个聚合市场单 owner 负责轮次、候选集合和输出。进程内单 owner 不是跨进程排他证明，写入另需数据库围栏。
- **存储与交付**：教学架构使用持久 Raw、PostgreSQL 局部事务、持久聚合 Inbox 与 Outbox；输出至少一次交付。队列或日志是实现选择，不承诺外部 API 到消费者天然恰好一次。
- **链上变体**：第 08 题单独引入 EVM 日志、分叉和最终性，主案例不把 DEX 池价与 CEX BBO直接混算。

### 1.2 一轮贯穿案例

设采样时刻为 `T`。以下五份观测已经接收、完成规范化，并进入本轮冻结的持久输入前缀；其源时钟质量均满足本模型要求，源状态都是 READY。数量均为合法正数，本例不使用数量加权。

| 源 | bid | ask | mid | `T - source_event_time` | 独立组 | 本轮结果 |
|---|---:|---:|---:|---:|---|---|
| A | 1,997 | 1,999 | 1,998 | 100 ms | GA | 保留 |
| B | 1,999 | 2,001 | 2,000 | 120 ms | GB | 保留 |
| C | 2,001 | 2,003 | 2,002 | 80 ms | GC | 保留 |
| D | 2,399 | 2,401 | 2,400 | 100 ms | GD | 轮次离群排除 |
| E | 2,000 | 2,002 | 2,001 | 5,000 ms | GE | 陈旧排除 |

所有价格均为 USDC/ETH。A—E 的独立分组是教学配置，不是从域名数量推导的事实。主例没有同时叠加断线、重组或汇率失效；各题的异常场景是独立变体。

规则先筛状态、字段与时间，再对 A—D 的 mid 做**一次**中位数筛选：中位数为 `(2,000+2,002)/2=2,001`，D 偏离超过 1% 被排除。剩余 A/B/C 满足至少三源、三个独立组，等权平均得到 **2,000 USDC/ETH**。它是本产品的参考价，不自动成为指数、Mark、强平授权或可成交报价。

### 1.3 主流程

```text
下游订阅 ETH/USDC 观察产品；配置控制面声明 Q1 源、资产与分组
    ↓
采集器连接外部源，接收完整 BBO 或源状态消息
    ↓
封装 Raw〔原始载荷、业务身份线索、接收时间、连接世代、内容摘要〕
    ↓
持久保存 Raw：到此只确认“这份输入证据已记录”
    ↓
源分区 owner 按协议解释身份与顺序
    ├─ 重复 → 留接收证据，不重复改变规范状态
    ├─ 缺口／身份冲突／未知语义 → 质量控制事件；必要时回补或重同步
    └─ 可解释且顺序合法
             ↓
       规范化〔资产、单位、定点精度、源时间、规则版本〕
             ↓
       同事务提交源状态 + Canonical/质量事件 + Raw cursor + Outbox
             ↓
       至少一次送入市场聚合 Inbox，按事件身份消重
             ↓
持久 Tick(T) 进入同一市场输入序列，冻结它之前的可见前缀
    ↓
聚合 owner 从该前缀取每源最新状态，记录 vector 与候选清单
    ↓
硬资格检查 → 时效筛选 → 一次中位数离群筛选 → 源数与组数检查
    ├─ 证据不足 → UNAVAILABLE，price=null
    └─ 合格 → 定点等权均值、贡献源、排除原因与 valid_until
                         ↓
同事务提交聚合状态 + 轮次/revision + Inbox cursor + Outbox
    ↓
当前合法发布器至少一次投递完整结果包
    ↓
消费者原子更新去重记录、投影与进度，并在使用时复核期限/版本/已知限制
    ↓
查询与页面展示本轮结果及质量；需要陈旧参考时单独展示 last_good
```

Tick 是计算时点，不保证 T 之前在外部发生的所有事件都已到达。冻结前缀定义“本轮已经观察到什么”，不是全球同时刻市场状态。网络分发与页面刷新也不必同时完成。

### 1.4 主要失败与修订路径

```text
Raw 写入失败 → 不宣称可靠接收；暂停/限流；无法停上游时记录缺口并告警

连接心跳正常但报价不再更新
    → 时间资格失效 → Tick 产出降级/不可用 → 旧价不续期

seq=101 后收到 103
    → GAPPED，暂停该源候选资格
    → 有界缓存 + 回补 102，或取得可衔接的权威新快照
    → 证据闭合后恢复 READY，不靠“重连成功”恢复

同逻辑身份收到不同业务内容
    → 保留两份 Raw → QUARANTINED → 受控查证，不做最后写入覆盖

提交结果后发布超时
    → 从已提交 Outbox 补发原身份 → 消费者去重，不创建新一轮冒充重试

普通迟到／回补
    → 仅进入后续轮次；不向旧冻结轮补候选

源撤回／链重组／映射纠错
    → 保留旧证据与旧产品 → 当前失效控制 + 受影响历史轮次的纠错 revision
    → 原 T/cut 不变，追加 correction manifest 与 supersedes；不续期、不回退当前轮次
```

### 1.5 沿案例解释状态和完成点

1. **接收**：A—E 到达时记录各自接收证据；E 即使刚收到，也仍是 5 秒前的报价。没有余额或资金变化。
2. **规范**：适配器确认 ETH 与 USDC 的资产身份，精确解析 bid/ask；每源 owner 推进其合法流位置。规范状态提交之后，才可说该输入已按指定规则解释，不等于已进入任意一轮。
3. **冻结**：Tick(T) 之前可见的规范事件、质量控制与配置决定本轮输入。候选记录能回指各源业务位置、Raw 和规范版本。
4. **筛选**：先剔除 E，再用一次中位数排除 D；不能先把 E 加入中位数，算完才补贴“已陈旧”。D 的离群是这一轮的决定，不自动永久封禁 D。
5. **提交**：本轮价格、质量、期限和排除原因共同提交。A/B/C 的源事件时刻分别为 `T-100/T-120/T-80 ms`，因此本轮 `valid_until=min(T+1000,T+1900,T+1880,T+1920)=T+1000 ms`。
6. **消费**：投影可见之后，读取方仍需检查 `now < valid_until`。历史回放得出 2,000，并不使它在现在重新有效；源失效通知未到达时也存在有界陈旧，期限不是瞬时全平台冻结协议。

**四类完成不可混同**：Raw 已持久、规范状态已提交、产品轮次已提交、消费者已展示。发布确认不能代替前两项，页面可见也不证明外部数据真实或可交易。

## 第四部分：设计与规则

### 4.1 业务规则与不变量

**语义与数值：**

- 主例只纳入同种现货资产对的完整 BBO。`bid > 0、ask > 0、bid <= ask`；买卖量须为正。零数量不能在此模型里被解释成有效完整 BBO，若协议用零删除价位，应先在其盘口状态中解释。
- 价格定点尺度 `10^6`，数量尺度 `10^8`。从十进制文本精确解析；不能无损表示则拒绝，不先过 `float64`，不静默截断。精度尺度不同于交易 tick/lot，适配时还需按源定义检查。
- `mid_int = floor((bid_int + ask_int)/2)`；加法、求和及交叉乘法使用足够宽的整数并检查范围。这里价格为正，向下取整含义确定。
- 未知单位、side、合约乘数不能默认零或任意值。ETH/USD、包装资产、永续和反向市场只能在显式转换变体中引入，并携带额外依赖。

**身份、状态与时间：**

- 原生逻辑身份标识一次源业务事件；Raw 身份标识一次实际接收。冲突摘要覆盖稳定业务内容，排除接收时间、连接世代等传输字段。无身份的源不能伪造强去重保证。
- 同身份同业务内容重复不重复改变规范状态；同身份异业务内容先隔离。原生 epoch 不由本地重连次数代替。
- READY 只证明已建立本协议要求的同步资格，不证明永远新鲜或绝对真实。缺口产生 GAPPED；恢复需要可信连续性或有效快照证据。
- `age = T - source_event_time`，且 `0 <= age <= 2000 ms`；缺时间、源时间在未来或时钟质量不能确认时，不进入 Q1 新鲜候选。`receive_time` 只证明接收，不改写源时间。
- `T` 及时间质量判断依据是持久输入；进程单调时钟只用于进程内耗时，不序列化为跨进程时钟。消费端墙钟也需受控，不能把时钟异常时的正 TTL 当安全证明。

**聚合：**

1. 冻结持久市场 Inbox 中 Tick(T) 之前的输入前缀，保留各源应用 vector 和实际候选。对每源只取其最新源状态；若最新观测无效，不能退回旧好价伪装当前候选。
2. 先按语义、源状态、字段和时效硬排除，再计算初始候选中位数。偶数中位数取中间两值均值并向最小价格单位下取整。
3. 对初始中位数 `m` 只做一次筛选：`abs(p-m)*10000 > m*100` 表示偏离超过 100 bp；**恰好 1% 保留**。不递归改变参照直到凑足源数。
4. 最终候选不少于三源、三个独立组，才取 `floor(sum(mid_int)/n)`。Q1 是源等权，不是组等权，也没有每组权重上限；同组多源在扩展配置中可能形成集中风险，不能把组数门槛当权重限制。
5. 不达标输出 `UNAVAILABLE、price=null`。无候选时不计算中位数；允许保留独立 `last_good` 展示，但必须标陈旧，不能用于冒充当前有效结果。
6. 合格包 `valid_until = min(T+1000ms, 每个贡献源的 source_event_time+2000ms)`；使用时要求 `now < valid_until`。边界上 age=2000 的候选能参与历史计算，但会使包立即到期，不构成可用实时结果。不可用包不携带可用价格期限。
7. Tick、断流、缺口、配置变化和撤回均能触发重新求值，不能只在有正价格时输出。失效和数值绑定同一结果包；消费者仍须自主到期，不能依赖永不丢失的失效推送。

**修订和恢复：**

- 普通迟到或回补只进入后续轮次，不给旧轮额外补候选恢复有效。历史 revision 只处理源撤回、映射纠错等显式更正：保留原 T、原观测 cut 与不可变原 manifest，追加 correction manifest、原因、纠错依据和 `supersedes`；可重算受影响候选及数值，但不伪称原始输入没有变化。更正后仍不可用则 `price=null`，不携带可用截止；更正后历史合格时，若被 `supersedes` 指向的旧版有可用截止，则新截止取旧截止与按原 T、纠正后依赖重算截止的较小值；旧版若为 UNAVAILABLE、无可用截止，则新截止至多为原 T，只修订历史资格，不授予实时使用。连续多次修订也按此分支递推，不能跨过一次不可用状态恢复旧轮实时资格；当前恢复另开新轮，不续 TTL、不回退当前更晚轮次。
- 当前产品与连续消费进度分开；已知新限制先持久收紧，再补中间缺口。未知版本或未补齐依赖不得恢复有效状态。
- 确定性承诺仅针对相同有序输入前缀、T、控制记录、配置和算法版本。不同到达顺序可能改变 Tick 前缀与中间轮次，不能宣称历史相同。

### 4.2 架构与职责

```text
配置控制面〔版本化资产、映射、源组、协议能力和质量规则〕
          │ 持久生效记录
外部源 → 采集器 → Raw 存储
                      ↓
              源分区 owner + DB 事务
              〔源状态/规范事件/cursor/Outbox〕
                      ↓ 至少一次、稳定事件身份
              市场持久 Inbox + Tick/控制输入
                      ↓
              市场聚合 owner + DB 事务
              〔聚合状态/round/revision/cursor/Outbox〕
                      ↓ 当前合法发布器
              消费者〔去重/投影/进度/限制〕
                      ↓
              查询、展示或显式下游数据契约
```

源分区可按 `source+instrument+channel` 路由；聚合按统一市场路由。在单一数据库权威写域内，每个权威写事务先锁定对应分区的 owner 权威行并校验 `owner_epoch`，持锁至状态与 Outbox 一同提交；接管也锁定并更新同一权威行。这样旧事务要么在接管前合法提交，要么在接管后因 epoch 不匹配被拒绝，不能只做普通 SELECT 后再写业务行。Redis 租约或 goroutine 唯一性不能替代这项围栏；两个独立可写数据库也不因应用携带 epoch 就成为单一权威域。数据库备份、复制与切换策略另决定持久承诺范围，不把一次本机提交冒充零数据损失。

### 4.3 核心数据和交互

| 对象 | 关键字段或内容 | 承诺与限制 |
|---|---|---|
| RawEnvelope | `raw_id、source、receive_time、connection_generation、raw_bytes、raw_hash`，原生身份线索 | 原始载荷及接收证据；敏感头需按策略脱敏，不存 API 密钥 |
| CanonicalBBO | 逻辑事件身份、原生位置、资产/市场/映射版本、bid/ask/量、源时间、Raw 引用 | 指定版本下的规范解释；不是整条外部流完整性的证明 |
| SourceControl | 状态、原因、作用域、证据位置、规则版本、恢复依据 | 失效或恢复是一等输入，不只是一行日志 |
| RoundManifest | `round_id、T、inbox_cut、source_vector、candidate_refs、excluded_reasons、config_versions` | 可复算本轮观察切面，不能证明全局物理同时性 |
| QuoteProduct | `product_id、round_id、revision、T、price、quality、valid_until、rule_version、manifest_ref、supersedes` | 数值、质量与期限共同交付；观察产品不授予风险动作权限 |
| Checkpoint | 状态、连续输入前缀、去重/冲突/限制、版本、生效位置、校验摘要 | 恢复依据，不以文件时间猜测最新进度 |

Raw 与后续规范阶段不是一个全局事务。源阶段把源状态、规范输出、Raw cursor 和 Outbox 一起提交；聚合阶段把聚合状态、产品、Inbox cursor 和 Outbox 一起提交。消费者将去重记录、本地应用和进度绑定。结果重发不生成新业务身份，旧任期合法提交的 Outbox 可由当前发布者补发，但不能续期。

源到市场还需自己的顺序契约：源事务用锁定计数行分配连续 `canonical_emit_seq`，报价、缺口、隔离和恢复控制都进入同一分区序列。发布器按分区串行，上一条被市场 Inbox 持久接纳后才发下一条；接收方按 `expected_emit_seq` 校验、去重，重试不重复分配 Inbox 位置。异常未来事件持久 pending 并保守阻断该源，补齐后按序应用；不能让迟到旧 READY 或旧报价覆盖新限制。它是内部交付序号，不证明外部流完整。产品端另有连续 `publish_seq`，同样与结果事务分配，用于补发与消费缺口检测，不能混成原生 seq、轮次号或 broker offset。

### 4.4 实现选择与专题边界

- Go 接入并发、状态修改串行：I/O goroutine 只生产不可变输入，owner 修改状态，读端使用不可变快照。有界队列明确容量与溢出策略；不能静默丢掉中间事件后声称仍连续。
- 中位数可对小型源集合排序，复杂度 `O(n log n)`；Q1 不为五个源引入复杂选择树。计算数据结构不能替代状态、版本和交付约束。
- 若源本身无连续序号，只能按协议承诺做快照/完整观测替换、checksum 或旁路核查，不宣称能够检测全部漏包。REST 回补能力也须逐源核实。
- [盘口重建行情计算与实时推送](../02-盘口重建行情计算与实时推送/)负责完整 Snapshot/Delta 重建、深度/K线/Ticker 和客户端续传；本专题只说明接入依赖与资格。
- [预言机指数价格与标记价格](../../02-衍生品与风险系统/05-预言机指数价格与标记价格/README.md)负责下游风险价格公式和用价动作。本例复用相近价格数值便于比较，但 Q1 不是该专题 R1 的授权规则。
- AMM、路由与做市需另处理池状态、费用、滑点、库存和执行；从行情观察跳到“保证可同时成交”属于越界。

## 第七部分：工程实践——一个简洁 MVP

### 7.1 目标与范围

手工验证**冻结的一轮候选 → 状态/时间检查 → 一次离群筛选 → 源与组门槛 → 定点均值及期限**。输入已经是精确规范化的完整 BBO，并携带同步资格和时间质量；不实现采集、缺口修复、持久事务、链重组、主备或可靠分发，不创建可运行工程。

### 7.2 核心伪代码

以下整数运算均在足够宽且检查范围的数值域中进行。`frozen` 是本轮每源最新状态的不可变集合，T、采样时钟资格与版本由调用者冻结，不在处理中读取当前网络或墙钟。缺少可信 T 时整轮不可用；缺少源事件时间时只排除该源。

```text
aggregate(frozen, T, sample_clock_ok, rule):
    if T 为空 or not sample_clock_ok:
        return {quality: UNAVAILABLE, price: null, T,
                reason: "采样时间不可信", rule}
    candidates = []; excluded = []
    for s in frozen 按 source_id 排序:
        if s.state != READY or not s.semantic_ok or not s.clock_ok:
            excluded.append(s.id, "资格无效"); continue
        if s.bid <= 0 or s.ask <= 0 or s.bid > s.ask:
            excluded.append(s.id, "报价字段非法"); continue
        if s.bid_qty <= 0 or s.ask_qty <= 0:
            excluded.append(s.id, "数量非法"); continue
        if s.event_time 为空:
            excluded.append(s.id, "事件时间未知"); continue
        age = T - s.event_time
        if age < 0 or age > 2000ms:
            excluded.append(s.id, "时间无效"); continue
        p = floor((s.bid + s.ask) / 2)
        candidates.append(s.id, s.group, p, s.event_time, s.ref)
    if candidates 为空:
        return {quality: UNAVAILABLE, price: null, T, excluded, rule}
    ordered = sort(candidates 按 p、source_id)
    m = 奇数取中值；偶数取中间两值之和除2后向下取整
    keep = []
    for c in candidates:
        if abs(c.p - m) * 10000 > m * 100:
            excluded.append(c.id, "本轮离群")
        else:
            keep.append(c)
    if len(keep) < 3 or count_distinct(keep.group) < 3:
        return {quality: UNAVAILABLE, price: null, T, excluded, rule}
    price = floor(sum(keep.p) / len(keep))
    until = min(T + 1000ms, min(c.event_time + 2000ms for c in keep))
    return {quality: VALID, price, T, valid_until: until,
            contributors: keep, excluded, rule}
```

这里 `semantic_ok/clock_ok/sample_clock_ok` 是明确给定且带版本依据的输入资格，不是伪装成已实现的“保证一致性”函数；源时钟与采样时钟资格分开判断。完整生产协议还需要前文的事件证据、manifest 和提交/消费约束；此段只验证计算闭环。返回 VALID 只表示该轮按计算规则合格，调用者仍须按可信当前时间验证期限。

### 7.3 输入与预期结果

| 独立输入场景 | 预期结果与原因 |
|---|---|
| 主例 A—E | E 陈旧；中位数 2,001；D 离群；A/B/C 均值 2,000，截止 T+1,000ms |
| 主例基础上 C 为 GAPPED | E 陈旧；A/B/D 中位数 2,000，D 离群，剩两源 → UNAVAILABLE |
| 主例基础上 B 与 A 同组 | 数值仍有三源，但仅两独立组 → UNAVAILABLE |
| A/B/C mid 均为 2,000、年龄均为 2,000ms | 能形成历史合格轮次，但截止正好 T；`now >= T` 不可当实时有效价使用 |
| A/B/C mid 为 1,980／2,000／2,020，均合格 | 中位数 2,000，两端恰好 1% 不剔除；均值 2,000 |
| 所有源未来时间、缺事件时间或源时钟质量未知 | 全部硬排除 → UNAVAILABLE，不用接收时间替代 |
| 主例数值不变，但 T 缺失或采样时钟质量未知 | 整轮 UNAVAILABLE，不把异常 T 修成看似正常的时间 |

这些是手工预期，不是 MVP 执行或性能测试结果。复述时应同时说出数值、资格、证据与时效，不能只记“最后算出 2,000”。
