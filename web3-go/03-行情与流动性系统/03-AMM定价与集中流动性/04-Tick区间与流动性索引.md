# 大问题 4：怎样用 tick、liquidityGross、liquidityNet 和 bitmap 正确管理集中流动性？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文中的含义与边界 |
|---|---|---|
| tick / tickSpacing | 价格网格编号，以及允许放LP边界的间隔 | 网格P_raw=1.0001^tick；spacing60约束上下界，不要求当前tick也是60的倍数 |
| sqrt价格 / 存储tick | 精确价格编码，以及说明边界站在哪一侧的状态 | 向左刚跨某边界时存储tick为边界值减1，不能总从价格取对数替代 |
| 活跃L / position L | 当前能用的深度，以及单个头寸提供的深度 | A在[-240,240)、B在[240,480)，起点只有A的100000活跃，不是总资产 |
| liquidityGross | 把此tick当上下界的流动性绝对量之和 | 决定边界是否仍有头寸；tick240为100000+50000=150000 |
| liquidityNet | 向右跨界时活跃L的有符号变化 | tick240为-100000+50000=-50000；向左跨时取反，不是gross |
| initialized / bitmap | 边界是否有状态，以及快速查边界的位索引 | gross归0才可清理；net为0仍可能有费用和头寸状态，不能直接删bit |
| word / bit / 压缩tick | 每256个网格位置一组及其组内位置 | -1按spacing60压缩须floor到-1，落word -1的bit255；单word快不等于全程O(1) |
| Mint / Burn | 增加或减少头寸流动性 | 同时更新上下界、头寸和必要的活跃L；先结算旧L费用，Burn记本金待领不代表转账 |
| cross / limit | 真正越过初始化边界，以及用户允许到的最远价格 | 未到边界不应用net；空word边缘只推进搜索，到limit可结束，不强行跨远处tick |
| 报价子集 / blockHash | 只存模拟必需字段，以及这组状态的版本 | net加初始化信息可供只读报价，不能冒充完整LP账本；补页也须同一hash |

## 把整篇文章压缩成一个故事

后端小周维护一个v3风格池：T1买T0、P=T1/T0，两币18位、输入费0.3%、协议不分成，L用人类尺度讲解。A和B在tick240两侧分别提供L100000和50000；起点只用A，不能合成150000。用户交易走到240时，系统读到绝对量150000、上行净变化-50000，于是切为L50000；若从边界反向，先反向应用net，再向左走，存储tick按239表达左侧。小周用bitmap找下一边界，负tick先floor，空word返回的搜索边缘不当成真实LP进出。后来把B改为100000，240净变化为0但绝对量200000，删掉仍会破坏费用与后续减仓。增减仓同步头寸和上下界，补页绑定同一块哈希。最终从完整同版本头寸核对边界、位图与活跃L；只有部分数据时不冒称全池验证，边界索引正确也不等于LP钱已领取。只读报价可以省去费用字段，但不能丢初始化标记；若还维护增减仓，就需要可靠的绝对量依据。输入不足停在边界前时，不先套净变化再退回来；用户价格限制更近就先停止，避免让搜索优化偷偷改变交换规则。真实链上数量与流动性仍按整数尺度和范围处理，不以显示小数作精确断言。

**流程位置与核心机制：**负责 LP 区间怎样形成可查找、可更新的定价边界。本题讲数据结构和边界语义；跨界后的执行循环见05，费用outside翻转见06。

**必要前提：**采用总览的spacing60、A区间[-240,240)、B区间[240,480)，初始tick0。本例tick索引是价格网格，不是价格或金额的最小精度，也不是每笔成交的序列号。

## 第 1 层：为什么不只存一个池总流动性？

**面试官：**集中流动性池有哪些关键状态，为什么一个总L和当前价格还不够？

**面试者：**它们只够计算不跨边界的单段。头寸在不同价格区间生效，大额交易移动到边界后，原来的L可能减少、增加或不变；不存边界就无法知道后续深度。

池需要当前sqrt价格、存储tick和当前活跃L；每个初始化边界还保存liquidityGross、liquidityNet及费用outside等。区间头寸保存自己的上下界和L，bitmap帮助寻找有状态的tick。它们分别回答“现在有多少”“到哪里改变”“改变多少”和“谁拥有权益”。

本例起点A活跃L100000，B区间外不活跃，不能把池内两笔头寸的L直接合成150000。向上走到tick240才发生切换。

## 第 2 层：同一个边界，gross和net分别记录什么？

**面试官：**你列了两个liquidity字段。能用A/B说明为什么不能只留net吗？

**面试者：**gross是以该tick为上下界的头寸流动性绝对量之和；net定义为从左往右跨该tick时，活跃L需要增加的有符号变化。某头寸在下界给net加L，上界给net减L，两端gross都增加L。

A和B建立后，tick-240的gross为100000、net为+100000；tick240的gross为150000、net为-50000；tick480的gross为50000、net为-50000。从初始活跃L100000上行跨240，加-50000得到50000。

如果改变条件，让B的L也是100000，那么tick240的net为0，但gross为200000。边界依然有头寸和费用状态，不能因net为0删掉，否则LP费用inside的计算和未来Burn更新会失去正确依据。

## 第 3 层：这些字段怎样随Mint和Burn变化？

**面试官：**既然gross不能省，LP增加或移除一部分L时，要在什么范围内同时更新？

**面试者：**增加deltaL时，下界gross增加deltaL、net增加deltaL；上界gross增加deltaL、net减少deltaL。减少流动性做相反变化，且gross不得为负、活跃L和position L不得越界。

position本身要先按旧L更新历史手续费权益，再改变L。如果当前存储tick处在该头寸的有效区间，还要同步调整池活跃L；不在区间则不改变当前活跃L，但边界仍必须更新。相关状态和Mint付款检查、Burn本金记入owed都在各自那笔链上交易原子边界内。

gross从0变成正数时初始化tick并翻转bitmap；从正数归0时才可取消初始化、清理边界状态。net为0不满足删除条件。每个tick还受流动性上限等合约范围约束，不能只检查整个池的L是否还能装下。

## 第 4 层：怎么快速找到下一边界，而不是扫描全部整数tick？

**面试官：**边界更新规则明确了。一次交易怎样快速查下一个initialized tick？

**面试者：**先把tick按spacing压缩为网格编号，再按每256个压缩tick组成一个bitmap word。有初始化状态的位置设bit，通过掩码和最高/最低有效位运算，在当前word沿方向查最近边界，单个word内不需要遍历全部头寸。

负tick必须向负无穷取整。例如-1除以60，数学floor为-1；若按向零截断得到0，归属word和bit会错误。压缩编号-1落在word-1的bit255，不能用无符号强转后再随意右移替代有符号索引。

实际v3查找函数在当前word没有匹配bit时返回该word方向边界，且标记initialized=false，外层循环可能继续扫描下一word。因此复杂度不是笼统O(1)：单word位操作很快，但长距离空白区间仍需要多次推进与读取。

## 第 5 层：边界查找为何要区分左、右和“包含当前tick”？

**面试官：**你说沿方向查最近bit。如果当前价格刚好在tick240，左右都直接查包含240，会发生什么？

**面试者：**会重复跨同一边界或漏跨，必须与存储tick的方向性语义配合。v3在向右跨到tickNext后设存储tick为tickNext；向左跨到该价格后设为tickNext-1。查找时向左采用不大于当前tick的方向，向右则寻找严格更右的压缩位置。

主例上行到240后，tick=240，L已经切换为B的50000，下一次上行不应再处理240。若随后反向，虽然sqrt价格恰在240，先向左跨240，net取反，L恢复A的100000，再向左移动。

这也说明存储tick不总能用 `floor(log(P)/log(1.0001))` 机械替换：向左刚跨边界时，sqrt价格等于该tick价格，但存储tick为它减1。丢掉这一语义，快照即使sqrt价格对，后续活跃集合仍可能错。

## 第 6 层：bitmap查询到边界，就一定要修改L吗？

**面试官：**下一边界已经找到。交易因为输入不够停在边界前，或只碰到未初始化word边缘，是否都要cross？

**面试者：**不都要。先把目标价限定为下一查找边界与用户价格限制中更近的那个，再算本步。如果输入不足，价格停在目标前，就不跨尚未达到的tick，也不应用它的net；需要按实际终点计算存储tick。

如果确实到达查找边界，只有initialized=true才调用真实tick的cross并应用net。到达initialized=false的word边界仅表示搜索进度推进，没有LP在该tick进出，不能凭空改变L。

到达用户limit但未到下一tick，交换可结束，不能为“整理状态”继续跨远处tick。极小输入还可能因取整不移动价格，循环依靠消费预算等明确条件终止，不能只靠“价格每轮必定变化”的错误假设。

## 第 7 层：Go只存活跃tick和净变化够不够？

**面试官：**为了降低内存，报价服务只缓存每个tick的net，省掉gross和全部费用字段行不行？

**面试者：**要按投影用途决定。只读的固定区块Swap模拟，不做Mint/Burn和费用核算，可以维护初始化位置与net的报价子集，不必把全部position和feeGrowth载进来；但必须另外保留initialized信息，不能把net为0误判为无边界。

如果服务还根据Mint/Burn事件持续维护bitmap，就需要gross或等价的可靠计数依据，才能判断边界何时真正消失。若要计算LP精确费用，还需要outside、global、position检查点等，不能声称一个net map重建了完整池状态。

同一报价里的slot0、L、bitmap和net必须来自同一blockHash。中途发现缺页应针对该hash补读；读不到就失败或重新开始，不能用最新net补旧价格。省内存的合理范围是删掉本用途不需要的字段，不是删掉正确性所依赖的身份与版本。

## 第 8 层：边界状态怎样做可检查的不变量？

**面试官：**如果有人把tick240误删了，怎样在上线前或数据核对中发现，而不是等用户价格错了？

**面试者：**可以从同一状态版本的全部头寸重新聚合边界，检验每个tick的gross等于相关头寸L绝对量之和，net等于下界加入减上界退出，bitmap与gross是否为正一致。全范围net总和应为0，按当前存储tick从左累加的net应等于活跃L，并始终不产生非法负L。

针对主例，检查240的gross150000、net-50000，左右跨越应得到100000与50000的正确切换。再把B改为L100000构造net0但gross非0的边界，确认索引仍保留initialized标志。

这些检查有覆盖前提：只取得部分头寸时不能假称已经全池验证；只用Swap末态也无法验证gross。实现验证应固定同一blockHash并对照storage或完整事件历史，不能用不同时间的两份数据制造假差异。

## 本题收束

- **讲透的机制：**gross负责边界生命周期，net负责方向性活跃L变化，bitmap负责查找，存储tick承载精确边界处的方向语义。
- **最容易答错：**net=0即可删tick；current tick也必须是60的倍数；负数除法天然floor；每个word查找结果都对应真实LP边界。
- **反例检验：**A与B流动性都改成100000时，tick240的net为0，gross为200000。若实现删除该tick，说明把“无需改变活跃L”和“没有边界状态”混为一谈。
