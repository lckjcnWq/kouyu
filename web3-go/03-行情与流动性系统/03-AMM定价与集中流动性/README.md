# AMM 定价与集中流动性：从一笔 Swap 到 LP 完整生命周期

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文中的含义与边界 |
|---|---|---|
| AMM / Swap / v3风格 | 用池曲线完成兑换，以及本文选定的集中区间模型 | 限EVM单池标准ERC-20现货，不是撮合、托管账户或所有AMM通则；v2只作对照 |
| T0、T1 / P、s / decimals | 两种币、T1计价的T0价格及其平方根、币小数位数 | P=T1/T0=s²，T1买T0向上走；两币18位，金额和本例人类L上链均放大10^18 |
| sqrtPriceX96 / 原子比例 | 用整数保存的原子单位sqrt价格 | P_raw=(S/2^96)²，人类P另乘10^(decimals0-decimals1)，不等精度不能只看UI比例 |
| tick / spacing / bitmap | 价格网格、可放LP边界的间隔和边界查找索引 | spacing60约束上下界，不约束终态tick353；负索引和左右边界语义须匹配协议 |
| activeL / 虚拟储备 | 当前价格有效深度，以及描述局部曲线的数学储备 | x_v=L/s、y_v=Ls，乘积L²；不是池实余额，跨240时L由100000变50000 |
| 毛净输入 / 输入费 | 实际付入量与扣费后推动曲线的量 | 费率3000/10^6=0.3%、协议不分成，实数主例1500=1495.5+4.5，链上逐步整数舍入 |
| exact-input / minOut / limit / deadline | 输入预算、最少输出、最远价格与执行期限 | 1500 T1不保证全花；1470 T0、tick420和路由期限各自独立，报价不锁价 |
| global / outside / inside | 压缩记录LP分段费用的累计增长与边界标记 | 先按旧活跃L计费再cross，inside增量乘旧头寸L结算；不是最终L分走全部费用 |
| mint / burn / collect / owed | 增L、减L、转出待领资产和已记欠款 | 出界不等于头寸消失；减仓本金记入owed，collect才转币，owed不全是手续费 |
| callback / allowance / revert | 回调收款、花币许可及失败撤销 | 合法池回调按实际delta收足，许可不冻结；同交易路由保护失败全回滚，gas和独立授权除外 |
| blockHash / 不可变快照 / 重组 | 状态版本、共享只读输入及规范分支切换 | Go只模拟和投影，工作态独占；数据库事务不包链上，重组须撤销孤块再重放 |
| HODL / TWAP / 报价预算 | 原币不动基准、历史时间均价及计算资源上限 | 无常损失比较同初始资产，费用成本另计；TWAP非现价或可执行报价，计算截断应报错 |

## 把整篇文章压缩成一个故事

小林要拿最多1500 T1买T0，阿敏则为池提供A区间本金。这里是EVM单池v3风格，两币18位、P=T1/T0、输入费0.3%、协议不分成。Go从同一blockHash独立模拟：A的L100000先承接，到tick240交给B的50000，连续模型输出约1472.669192 T0，A/B费用约3.632402/0.867598 T1。真正执行仍按整数舍入，由合法回调收实际输入、同笔检查minOut1470和tick420限制；少收币或输出不足全部回滚，触限少花也须报告余款。入块后索引事务提交投影与游标，重组则撤旧分支，不能把成功回执当最终性。阿敏出界后本金全T1，减仓先记待领、领取才转账，手续费也不保证跑赢同初始资产持币。工程师逐项核对精度、边界和费用，TWAP只作历史风险参考，过载宁拒绝也不截断假报。最后用实数伪代码串起双区间小闭环，明确它不支持空档等完整能力；手算、方案与检查思路不冒充已运行的链上或性能测试。阅读时先弄清权威状态与执行边界，再推定价和费用，最后沿增仓、退出、确认与恢复核对资产，避免把某一步算对误当全程安全。

## 第一部分：文字全流程

### 1.1 锁定讨论基线

本专题采用 **EVM 上 Uniswap v3 风格的单池集中流动性现货兑换**，不是订单簿、托管交易所、稳定币曲线或永续合约。v2 恒定乘积模型只用于对照；出现它时会明确改变了哪些前提。

| 项目 | 统一前提 |
|---|---|
| 资产 | 标准 ERC-20：token0 为 T0，token1 为 T1；均为 18 位 decimals；不支持转账税、rebase 或恶意回调型代币 |
| 方向 | `P = T1 / T0`，即每 1 T0 值多少 T1；`s = √P`。T1 买 T0 是 `oneForZero`，价格向上 |
| 执行机制 | 用户交易在链上池执行；池的价格、tick、活跃流动性、费用和仓位状态由合约拥有 |
| 路由 | 教学路由检查 deadline、回调来源与最小接收量；不假设所有现存路由接口都具有相同参数或语义 |
| 数量语义 | 主例为 exact-input：1500 T1 是最大输入预算；到达价格限制可以少用输入，仍必须满足最小接收量 |
| 费用与区间 | 手续费 `3000 / 10^6 = 0.3%`，`tickSpacing = 60`；协议分成关闭，手续费全部归符合条件的 LP |
| 成交与结算 | 单笔 EVM 交易内计算、代币转移、回调付款和路由保护一起成功或一起回滚；授权可在独立交易中先完成 |
| 链下组件 | Go 报价、索引和查询是链上状态的投影，不能修改权威池状态，也不能锁住报价 |
| 完成含义 | 报价、签名、广播、入块成功、达到确认策略与页面展示是不同阶段；最终性按所在链的规则处理 |

没有链下撮合引擎，没有交易所式“余额冻结后排队成交”。ERC-20 allowance 是支出授权，不是资金预留；未广播或未入块时也没有已经确定的成交义务。

### 1.2 贯穿案例：一笔交易跨过两个 LP 的交界

假定没有其他交易、Mint、Burn、Collect 或直接转币插入本例；两笔 LP 头寸已建立、没有历史手续费。

| 初始对象 | 状态与含义 |
|---|---|
| 池 | `tick = 0`，`s = 1`，`P = 1 T1/T0` |
| LP A | 区间 `[-240, 240)`，流动性 `L_A = 100000`，初始活跃 |
| LP B | 区间 `[240, 480)`，流动性 `L_B = 50000`，初始不活跃，持有 T0 本金 |
| 用户 | 以最多 1500 T1 买入 T0；余额、授权足够 |
| 执行保护 | `amountOutMinimum = 1470 T0`；上行价格限制为 tick 420 对应的 sqrt 价格；deadline 尚未过期 |

这里的 L 是便于手算的人类可读尺度。由于两币均为 18 位 decimals，换成链上原子单位时，代币数量和本例 L 均乘 `10^18`；不能把表中 L 直接当作合约的 `uint128 liquidity`。存储中的 `sqrtPriceX96` 采用原子单位比例，不直接存人类可读价格。

令：

```text
s_a = 1.0001^(-120) ≈ 0.988072305665616182
s_b = 1.0001^(120)  ≈ 1.012071681663366439    // tick 240
s_c = 1.0001^(240)  ≈ 1.024289088824914535    // tick 480
s_limit = 1.0001^210 ≈ 1.021220979426417490   // tick 420
```

下面的金额展示到有限小数位，均来自实数公式。真实 v3 每步使用整数和明确舍入方向，末尾原子单位及费用可能略有差别，不能将这些小数当作已验证的 calldata 或链上精确断言。

### 1.3 Swap 主流程

```text
用户发起兑换意图〔池、T1 输入预算 1500、接收地址〕
    ↓
Go 报价服务读取一个确定 blockHash 下的池快照
〔slot0、活跃 L、bitmap、将经过的 initialized ticks〕
    ↓
逐段模拟〔扣输入费 → 推进 sqrt 价格 → 算 T0 输出 → 跨 tick 调整 L〕
    ↓
交付估算〔预计输出、区块版本、费用、价格影响、有效性说明〕
    ↓
用户确认保护参数〔minOut=1470、sqrtPriceLimit=tick420、deadline〕
    ↓
检查余额和 allowance，必要时先完成独立授权交易
    ↓
钱包签名并广播 Swap 交易〔签名/广播 ≠ 成交〕
    ↓
区块内按链上顺序执行，路由检查 deadline 并调用池
    ↓
池锁定执行入口，在当时真实状态上逐段 Swap
    ├─ 先在 A 的活跃区间成交并累计 A 的费用
    └─ 跨 tick240：退出 A，进入 B，继续成交并累计 B 的费用
    ↓
池记录执行状态、向接收人转 T0，回调路由收取实际应付 T1
    ↓
路由验证回调来自合法池，按正 delta 付款；池检查输入余额增加
    ↓
路由检查实际输出 ≥ minOut；本交易全部调用成功
    ↓
回执 status=1，交易及事件进入当前规范链〔尚需按策略等待确认〕
    ↓
Go 索引原子推进投影与区块游标，查询展示实际消耗与输出
    ↓
达到所在链确认/最终性策略；若此前重组，撤销孤块投影并重放
```

池在执行中先记录价格等状态，不表示可以带着未支付的结果提交：后续 callback、余额检查或路由保护失败，会撤销整笔交易中的相关状态、代币转移与日志。Gas 支出和失败交易的 nonce 消耗不因此归零。

### 1.4 沿案例解释数量和资金怎样变化

**第一段：从 tick 0 到 tick 240，只有 A 提供活跃流动性。**

```text
A 段净输入 T1 = L_A × (s_b - 1)
              ≈ 1207.168166336643894263
A 段毛输入 T1 = 净输入 / 0.997
              ≈ 1210.800568040766192842
A 段输出 T0   = L_A × (1 - 1/s_b)
              ≈ 1192.769433438381804424
A 段手续费 T1 ≈ 3.632401704122298579
```

在 tick 240 上行跨越时，A 的上界贡献 `-100000`，B 的下界贡献 `+50000`，合计 `liquidityNet = -50000`。因此活跃 L 从 100000 变成 50000，而不是把二者一直相加为 150000。

**第二段：在 B 区间用完余量。**

```text
剩余毛输入 T1 ≈ 289.199431959233807158
剩余净输入 T1 ≈ 288.331833663356105737
最终 s = s_b + 剩余净输入 / 50000
       ≈ 1.017838318336633561
B 段输出 T0 = 50000 × (1/s_b - 1/s)
            ≈ 279.899758686746103800
B 段手续费 T1 ≈ 0.867598295877701421
```

| 结果 | 连续模型的预期 |
|---|---|
| 总消耗 | 1500 T1，其中净输入 1495.5 T1，手续费 4.5 T1 |
| 总输出 | 约 1472.669192125127908224 T0，高于 1470 的最小接收量 |
| 最终池状态 | `P ≈ 1.035994842274346199`，`tick = 353`，活跃 `L = 50000` |
| 平均支付价格 | 含费 `1500 / 1472.669192… ≈ 1.018558687872 T1/T0`，不等于最终边际价格 |
| 价格限制 | 最终 sqrt 价格低于 tick420 限制；主例没有提前停止 |
| A 的本金 | 全部转为 T1，约 2399.937599775025698687 T1；另有 A 的费用权益 |
| B 的本金 | 约 309.371463425720206803 T0、288.331833663356105737 T1；另有 B 的费用权益 |

本例两笔头寸对应的初始 T0 本金合计约 1782.040655550848115027，最终约 309.371463425720206803，差额正好是用户收到的 T0。初始 T1 本金约 1192.769433438381804424，最终净本金约 2688.269433438381804424，再加 4.5 手续费，增加量为用户支付的 1500 T1。**按币种分别守恒，不把 T0、T1 的裸数量相加。**

### 1.5 主要分支及完成条件

```text
授权不足 → 池回调付款失败或路由提前拒绝 → Swap 回滚
独立 approve 成功、Swap 失败 → 授权仍在；无本次成交，但消耗失败交易的 gas

报价后有人先交易 → 链上按新状态执行
    ├─ 输出仍 ≥ minOut 且满足其他条件 → 成交，结果可能不同于报价
    └─ 输出 < minOut → 路由回滚整笔 Swap

到达 sqrt 价格限制且预算未用完
    ├─ 输出达到 minOut → 允许部分使用输入，报告实际消耗与未消耗
    └─ 输出未达 minOut → 整笔回滚，不是“保留前半段成交”

跨过零流动性区间 → 不能套用除以 L 的价格公式
    └─ v3 核心可搜索下一 tick，零额推进到边界；最终仍受价格/数量保护

广播超时或查不到回执 → 状态未知 → 按原 txHash、nonce 与规范链查询
    └─ 不能认为失败后换新 nonce 再成交一次就是“幂等重试”

已入块成功但发生重组 → 原日志退出规范链 → 撤销投影，重新判断交易状态
```

“取消”只能尝试在同 nonce 的替换交易先入块等链上规则下生效；已经执行的 Swap 没有订单簿式撤单。若价格限制与用户“必须花完输入”的产品要求冲突，应在路由增加实际输入检查并整体回滚，而不是偷偷改变主例的部分使用语义。

### 1.6 LP 的完整生命周期

```text
LP 选池、费率、tick 区间和资金预算
    ↓
读取同版本价格，计算可铸造 L、所需 T0/T1 与最小金额保护
    ↓
授权 → 路由/头寸管理器调用 mint
    ↓
池更新上下界 tick、bitmap、position 与必要的活跃 L
    ↓
mint callback 支付应付代币，池核对余额；不足则本交易全部回滚
    ↓
头寸建立〔core 按 owner+lower+upper 标识；NFT 是 periphery 包装〕
    ↓
价格在区间内 → 参与本区间成交并获得相应费用
价格移出区间 → 头寸仍存在，变为单边本金，暂不赚取区间外成交费用
    ↓
LP 减少流动性〔burn / decreaseLiquidity〕
    ↓
减少 L、更新费用权益、将应返本金计入可领取额〔不是已经转到钱包〕
    ↓
collect 转出已记入 tokensOwed 的金额
    ↓
按确认策略更新钱包和头寸展示；满足条件后才可销毁 NFT 包装
```

减仓、领取、销毁 NFT 的接口和前置条件要按实际 periphery 核对，不能把三个动作合称“burn 后钱已到账”。

## 第二部分：核心板块

| 板块 | 为什么核心、拥有的状态 | 与上下游的契约 |
|---|---|---|
| 单段定价与精度 | 决定付多少、收多少；使用 sqrt 价格、L、费率和剩余预算 | 给 tick 循环确定的金额与新价格；必须明确原子单位和舍入 |
| tick 与跨区间执行 | 决定此刻谁提供流动性；拥有 tick gross/net、bitmap 与当前活跃 L | 每段只在当前 L 下定价；跨界后再算下一段 |
| 费用与 LP 仓位 | 决定费用归属和退出权益；拥有 global/outside/inside、position checkpoint 与 owed | 使用跨界前 L 分配费用；Mint/Burn 先结清历史再改变仓位 |
| 链上路由与回调结算 | 决定是否真正支付并满足保护；池与路由各有权限边界 | 同笔 EVM 交易成功或回滚；不把授权当冻结，不信任伪造回调 |
| Go 报价与状态投影 | 决定报价可复现性与查询正确性；只拥有带 blockHash 的缓存/索引 | 读取同一状态版本，隔离本地模拟写入，确认与重组可恢复 |
| 价格使用与容量治理 | 决定是否把执行报价误用于风控，以及过载时是否给错价 | TWAP 说明窗口/有效性；预算超限显式失败，不降级为不安全成交 |

## 第三部分：核心 20%

“20%”是重要性集中，不是把题数压到少数几道。以下机制共同决定本专题是否成立。

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| sqrt 价格与单位 | 状态读取、定价 | 统一方向与金额尺度 | 报价倒置、差 `10^12` 倍 | 原子单位、decimals、Q64.96 |
| 单段金额与输入费 | 每次 swap step | 决定边际价格和实际收付 | 多给输出、费用扣错 | delta 公式、净/毛输入、舍入 |
| tick gross/net/bitmap | LP 变更与 tick 查找 | 决定有效 L 及执行成本 | 漏区间、重复加 L | 负 tick、初始化和边界方向 |
| 跨 tick 循环 | 大额 Swap | 局部公式才能组成全程 | 用单段公式算跨段输出 | 目标价、步数、剩余量、空区间 |
| feeGrowthInside | 费用归属 | 避免区间外或后加入 LP 分走历史费 | 最终 L 分走全部费用 | outside 翻转、checkpoint、Q128 |
| LP 资金与权益 | Mint/Burn/Collect | 退出闭环不等于 L 归零 | 误报到账或漏领费用 | 两币构成、owed、领取边界 |
| 同交易原子性 | 执行与收付 | 防止无支付的成交或绕过保护 | 伪回调、状态已变却欠款 | delta、余额检查、锁和回滚 |
| 同版本快照 | Go 报价 | 一组真实状态才可模拟 | 拼出链上从未存在的价格 | blockHash、缓存版本、big.Int 所有权 |
| 规范链投影 | 确认与查询 | 入块成功不等于最终不可逆 | 孤块成交长留账面 | 事件身份、游标原子性、回滚重放 |
| 风险与资源边界 | LP 收益、预言机、报价服务 | “有价格”不等于安全可执行 | 保本错觉、操纵、过载错价 | HODL 基准、TWAP、扫描预算 |

## 第四部分：设计与规则

### 4.1 业务公式与不变量

1. **价格方向。**`P_raw = raw1/raw0 = (sqrtPriceX96 / 2^96)^2`；人类可读 `P = P_raw × 10^(decimals0-decimals1)`。主例同为 18 位，倍率为 1。反向报价应在适当精度下取倒数，不只交换 UI 标签。
2. **tick 与区间。**tick 的价格网格为 `1.0001^tick`。LP 上下界必须对齐 spacing，但当前 tick 不必；tick 353 合法。活跃区间按池的方向性边界语义维护，不能始终只对 sqrt 价格取对数替代存储 tick。
3. **同一活跃 L 内。**当 `s' > s`，T1 净输入 `L(s'-s)`，T0 输出 `L(1/s-1/s')`；下行时 T0 净输入 `L(1/s'-1/s)`，T1 输出 `L(s-s')`。不能在 L 改变后仍用同一 L 算整段。
4. **虚拟与真实资产。**单段虚拟储备 `x_v=L/s`、`y_v=Ls` 满足 `x_v y_v=L²`；它们不是实际池余额。费用、区间偏移和多个头寸使全池真实余额不能直接套入这条曲线。
5. **费用。**手续费在输入侧计提；连续模型净输入为毛输入乘 `(1-f)`。整数实现采用合约对应的 `mulDiv`、上下取整；exact-input 总消耗不能超预算，输出不能凭舍入多送。
6. **LP 本金。**区间 `[s_a,s_b]`、流动性 L：价格不高于下界时 `x=L(1/s_a-1/s_b), y=0`；区间内 `x=L(1/s-1/s_b), y=L(s-s_a)`；不低于上界时 `x=0, y=L(s_b-s_a)`。这些是未含费用的本金。
7. **跨界。**上行跨 tick 加其 `liquidityNet`，下行取反；本步手续费先归旧活跃 L，再切换。`liquidityGross=0` 才能取消 initialized tick，不能仅因 net 为 0 删除边界。
8. **守恒。**在没有额外转账的标准代币单笔 Swap 中，每个币种分别校验用户/接收人/池的实际变化；费用、协议分成、owed 与本金各有边界，不能重复统计为额外资产。
9. **一致性。**Pool 状态、回调付款、代币转移和路由 minOut 依靠同一交易原子性；链下投影和规范链之间依靠可回滚的版本同步，不存在跨链上/数据库的同一个 ACID 事务。

### 4.2 架构与决策权

```text
钱包/前端
    ├─ 获取 Go 报价〔只读估算；带 chainId、pool、blockHash〕
    └─ 签名发送交易
             ↓
教学路由/头寸管理器〔deadline、minOut、合法回调、用户支付〕
             ↓
单池 Core〔唯一执行顺序；sqrtPrice、tick、L、费用、仓位〕
             ↔ 标准 ERC-20〔余额与 allowance 的权威状态〕
             ↓
规范链区块与交易回执
             ↓
Go 索引器〔按区块版本持久化投影+游标，可撤销重组〕
             ↓
报价快照缓存/查询投影〔不得反向决定池执行结果〕
```

### 4.3 核心对象、交互与提交边界

| 对象 | 必要字段或内容 | 边界 |
|---|---|---|
| 池快照 | chainId、pool、blockHash、parentHash、sqrtPriceX96、tick、liquidity、fee、spacing、必要 ticks/bitmap | 所有读取属于同一确定状态；block number 不足以区分分叉 |
| Tick | index、liquidityGross、liquidityNet、feeGrowthOutside0/1 等 | net 用于过界，gross 用于初始化生命周期；报价副本可只保留必要子集 |
| Core position | owner、lower、upper、L、lastInside0/1、tokensOwed0/1 | 与 NFT tokenId 不是同一种身份 |
| Swap 意图 | chainId、池/方向、预算、minOut、limit、recipient、deadline、签名交易关联 | 报价 ID 不是链上通用幂等键 |
| Swap 计算状态 | remaining、calculated、sqrtPrice、tick、active L、本步费用 | 仅本次执行或模拟所有；不得修改共享报价快照 |
| 规范链事件 | blockHash、txHash、transactionIndex、logIndex、事件参数 | 失败交易日志不落为有效成交；同高度不同 hash 属于不同历史 |
| LP 操作 | 区间、deltaL、amount0/1、手续费检查点、owed、recipient | Burn 与 Collect 的资产完成条件不同 |

**四个不能混淆的边界：**链上单笔交易提交；所在链确认/最终性；索引数据库投影和游标的局部事务；页面观察到投影。回执成功但索引延迟是允许的暂态；付款失败却留下已提交池成交、孤块事件永久算作最终成交是禁止的结果。

### 4.4 实现选择

- 合约语义以 v3 的 `SwapMath`、`SqrtPriceMath`、`TickMath`、`TickBitmap` 为参照，移植必须固定源码/编译版本及整数语义。
- Go 使用任意精度整数处理链上金额和中间乘积，明确宽度检查、舍入和模算术；`float64` 只可用于不承诺精度的展示。
- 对外发布不可变、带版本的池快照；每次报价独立持有可变的临时数值。RPC 批量化不自动提供同一版本保证。
- 索引按 `block → transactionIndex → logIndex` 排序，持久化投影与游标；必要状态从同一 blockHash 的 storage 补齐，不声称只靠 Swap 事件能还原完整费用与预言机状态。
- 性能工作以跨 tick 数、扫描 bitmap word 数、RPC 成本、排队和取消为边界。超过预算返回明确错误，不能将截断结果伪装为完整报价。

## 第七部分：工程实践——唯一的简洁 MVP

### 7.1 目标与范围

只验证一个小闭环：**上行 exact-input 在两个相邻、正 L 的区间逐段定价，旧区间记费，跨界切换 L；minOut 不满足时不发布演算结果。**

这是连续实数模型的核心伪代码，不是 v3 整数兼容实现或链上交易。它不实现 Q64.96、逐步整数舍入、空区间搜索、反向交换、真实授权/回调、事件索引、并发和最终性；gap 明确报不支持，不假装等价于 v3 Core 的零流动性推进。

### 7.2 核心伪代码

segments 为本例 A、B 的有序且不重叠区间，包含 lower/upper sqrt 价格和 L；feeBySegment 只记录本次交易费用，不代替完整 feeGrowth 账本。所有公式在理想实数上运算，代码中的 `min` 等为普通数学操作。

```text
quoteUp(snapshot, grossBudget, sqrtLimit, minOut):
    require grossBudget > 0 and sqrtLimit > snapshot.sqrtP and minOut >= 0
    work = 深拷贝(snapshot)               // 不允许写入共享快照
    s = work.sqrtP; i = work.activeSegment
    remain = grossBudget; out = 0; feeBySegment = 全零数组
    while remain > 0 and s < sqrtLimit:
        require i 存在 and segments[i].L > 0 else 返回 UnsupportedGap
        seg = segments[i]
        require seg.lower <= s < seg.upper else 返回 InvalidState
        target = min(seg.upper, sqrtLimit)
        netToTarget = seg.L * (target - s)
        grossToTarget = netToTarget / (1 - 0.003)
        if remain >= grossToTarget:
            used = grossToTarget; net = netToTarget; next = target
        else:
            used = remain; net = used * (1 - 0.003)
            next = s + net / seg.L
        out += seg.L * (1/s - 1/next)
        feeBySegment[i] += used - net     // 必须在切换 i 前记费
        remain -= used; s = next
        if s == seg.upper:
            i += 1                       // 上行到边界后按右侧区间解释状态
            if i 存在 and segments[i].lower != s: 返回 UnsupportedGap
    if out < minOut: 返回 MinOutNotMet      // 丢弃 work，无部分发布
    work.sqrtP = s; work.activeSegment = i
    work.activeL = segments[i].L if i 存在 else 0
    返回 {work, actualIn=grossBudget-remain, unspent=remain, out, feeBySegment}
```

同一个 snapshot 对应多次报价时，返回的是各自的模拟结果，不会真的串行消耗池资产。“不发布”只指本地演算失败不产生成功结果，链上全交易回滚另由 EVM 和路由完成。

### 7.3 输入与预期结果

每个变体都从原始快照重新开始，不连续叠加。

| 输入 | 手工预期 |
|---|---|
| 主例：1500 T1，limit tick420，minOut1470 | 输出约 1472.669192 T0，使用全部预算，跨 tick240，最终活跃 B；A/B 费用约 3.632402/0.867598 T1 |
| 仅 100 T1，其余同主例但 minOut=0 | 净入 99.7；`s'=1.000997`；输出 `99.7/1.000997` T0，费用 0.3 T1；不跨界 |
| 主例预算但 minOut=1473 | 计算可做完，但最终拒绝；不得交付“已完成一半”的结果，原始快照不变 |
| 1500 T1，limit 改为 tick240，minOut=1190 | 输出约 1192.769433 T0；实际消耗约 1210.800568 T1，未消耗约 289.199432 T1；停在 B 的下界、活跃 L 为 50000 |
| 删除 B，预算仍为1500、limit仍为tick420 | 到 A 上界后还需推进，返回 UnsupportedGap；此教学 MVP 不实现 v3 的 gap 搜索 |
| grossBudget=0 或 limit不高于当前价格 | 参数拒绝；不开始演算 |

检查应逐项问：输入/净额/费用是否对上？T0 输出是否按区间累加？跨界前后 L 是否正确？失败是否不产生成功结果？这些是手工推演验收，不是工程测试记录。
