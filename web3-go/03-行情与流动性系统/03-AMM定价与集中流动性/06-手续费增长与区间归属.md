# 大问题 6：跨越多个价格区间时，手续费怎样准确归属到每个 LP？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文中的含义与边界 |
|---|---|---|
| 输入侧手续费 / 协议分成 | 从用户付入的币收费用，以及协议是否分走一份 | 本例T1输入、费率0.3%、协议分成关闭，费用按承接成交的LP分配 |
| 旧activeL | 本步真正提供深度的全部活跃流动性 | 先用它分配费用再cross；重叠头寸用总L作分母，不用最终L倒分整笔 |
| feeGrowthGlobal / G | 全池共享的每单位活跃L累计费用增长 | T0/T1各记一套，不是全池费用币数；本例主要增长T1这一套 |
| X128 / Q128 | 用2^128放大保存小数增长 | ΔG=floor(费用原子量×2^128/L_chain)，费用和L须用匹配的链上尺度 |
| feeGrowthOutside / O_l、O_u | 上下界保存的、随跨界翻转的增长标记 | cross时新outside=当前global-旧outside，不能固定理解为某侧币余额或每次清零 |
| below / above / inside | 排除区间下方、上方后留下的有效增长 | inside=G-below-above，取哪侧差值依存储tick与上下界关系决定 |
| inside_last / 检查点 | 上次给该头寸结算到哪里的标记 | 新欠款=floor((inside_now-inside_last)×旧L/2^128)，增减仓先结旧L费用 |
| tokensOwed / 惰性结算 | 已经记入待领账的数量，以及用到头寸时才补账 | 原始owed可能未含新应计费用，也可能含退出本金，不等于纯费用或钱包到账 |
| burn(0) / poke / core collect | 不减L地刷新头寸，以及领取已记欠款 | 非零L头寸可先poke再collect；core collect不刷新，零L不能无条件poke |
| 模2^256 / 舍入尘埃 | 固定宽度回绕，以及整数取整留下的零碎量 | 目标v3版本须显式复现模差，2^256-7到5的差为12；不是任意历史都可恢复 |
| blockHash / 回滚 | 费用读取绑定的区块版本，以及失败撤销 | 回调或minOut失败不留下该笔费用；重组退出规范链的收入投影也须撤回 |

## 把整篇文章压缩成一个故事

LP甲发现交换结束只剩B活跃，页面竟把4.5 T1全给B。工程师小许沿同一笔T1买T0追账：两币18位、输入费0.3%、协议不分成。连续模型先由A的L100000承接到tick240，赚约3.632402 T1；再由B的50000承接余量，赚约0.867598 T1，链上按整数舍入。系统不逐户写余额，而是先按旧活跃L增加T1的global，再跨界翻转outside，算出A/B各自inside。最终A虽出区间，历史费用仍属于它；头寸更新时再以旧L和检查点结算，新增L不能追领过去的费。小许把应计费用与已记tokensOwed分开展示，领取前按core接口条件刷新，不能拿collect当万能结算。Go还须复制Q128和模2^256差值，不能把回绕误算成负收入。最后核对付款及minOut确已成功、区块仍在规范链；失败交易或孤块收益要撤回，整数尘埃不能成为把A费用转给B的借口。他还把两种币各自的增长和欠款分账，禁止先换算成展示币再混合检查点；零深度段跳过费用除法，已有头寸增减前结清旧权益。账面应计、已结算欠款与已经领取，是三个不同的完成位置。

**流程位置与核心机制：** 从 swap 每步计费追到 tick 边界、头寸检查点和待领余额，不讨论收益率。公共基线与单位见总览；本题重点沿用输入侧 0.3% 手续费、协议分成关闭，以及 A/B 在 tick240 交接活跃流动性的条件。

```text
用户最多付 1500 T1 买 T0 → 路由检查 deadline → 池内逐步交换
    → 按本步旧 activeL 计费 → 更新费用增长 → 跨 tick 翻转 outside
    → 切换 activeL → 完成付款回调和路由最低输出检查
    → 后续头寸更新：结算 inside 增量 → tokensOwed → collect
任一链上检查失败 → 同一交易内的交换与费用状态全部回滚
```

主例为 oneForZero，amountOutMinimum=1470 T0、价格上限 tick420。最终约出 1472.669192125127908224 T0，s=1.017838318336633561，P=1.035994842274346199，tick=353，activeL=50000。以下是连续实数手算；整数执行逐步舍入，不声称已上链验证。

## 第 1 层：总共收了 4.5 T1，为什么不能按最终流动性分？

**面试官：** 这笔交换最终只有 B 活跃，4.5 T1 手续费是不是全部归 B？

**面试者：** 不是。手续费归属取决于每一步实际承接交易的活跃流动性，而不是交易结束时的快照。价格从 s=1 走到 tick240 的 s_b=1.0001^120=1.012071681663366439，只有 A 承接；跨过边界以后才由 B 承接。A 虽然最终退出活跃区间，之前已经赚取的费用不会消失。

本例全部 1500 T1 被消耗，净入为 1495.5 T1，总费 4.5 T1。区间不同、活跃 L 不同，必须先把交换拆步，再分别分摊；不能用最终 L=50000 去除整个交易的费用，更不能按两人初始投入的资产市值比例分。

## 第 2 层：拆步以后，先收费用还是先切换 L？

**面试官：** 既然要拆步，正好抵达 tick240 的那一步如何避免把边界费用算给 B？

**面试者：** 本步先用 A 的 L=100000 算到边界：净入 1207.168166336643894263 T1，毛入 1210.800568040766192842 T1，输出 1192.769433438381804424 T0，费用为 3.632401704122298579 T1。这笔费先进入旧活跃 L 对应的增长值，然后才能 cross。

向右跨 tick240 时，liquidityNet 为 -100000+50000=-50000，活跃 L 才从 100000 变成 50000。余下净入 288.331833663356105737 T1，输出 279.899758686746103800 T0，产生 0.867598295877701421 T1 费用。两段费用合计 4.5。若把 cross 提前，本应属于 A 的 3.6324 会错误使用 B 的分母，后续再靠最终余额对账也修不回正确的历史归属。

## 第 3 层：不遍历所有 LP，费用增长怎么记？

**面试官：** 你按区间算清了，但池里可能有上万头寸，难道每步都要写它们的余额？

**面试者：** 不需要逐户更新。池对两种币分别维护 feeGrowthGlobal0X128 和 feeGrowthGlobal1X128，表示每单位活跃流动性的累计费用增长。本例输入 T1，因此只推进 T1 的增长；协议费关闭，本步手续费全部进入 LP 分配。每步概念上增加：

`ΔG1 = floor(fee1_atomic × 2^128 / L_chain)`。

A 的链上 L 是 100000×1e18，费用也必须换成原子单位，不能拿“3.6324 个币”直接除链上 L。swap 循环先推进局部增长值，并把新值传给 cross，循环结束再落全局存储，不代表每一步都做一次全局存储写入。若活跃 L=0，源码跳过除法；空区间推进价格不意味着凭空给不存在的 LP 分配费用，也不保证订单能足额成交。

若同一区间还有其他头寸重叠，本步分母必须是所有活跃头寸的总 L，而不是某一个 LP 的 L；每个头寸之后再乘自己的 L 领取份额。global 因而不是全池累计收了多少币的直接余额，更不能把增长值相加当作收入。两种输入方向要分别记账，不能因为最终都换算成 T1 展示，就把两种币的增长混在同一个检查点里。

## 第 4 层：global 为什么不会把区间外费用也送进来？

**面试官：** global 把两段都累加了，A 看它的增量不就连 B 那段也拿走了吗？

**面试者：** 所以头寸不直接使用 global，而是借助上下界 tick 的 feeGrowthOutside 计算 inside。对某种币令全局为 G，下界、上界保存值为 O_l、O_u，当前池 tick 为 t：

- 下方增长 below：t≥lower 时取 O_l，否则取 G-O_l。
- 上方增长 above：t<upper 时取 O_u，否则取 G-O_u。
- 区间增长 inside=G-below-above。

初始化边界时，若边界 tick≤当前 tick，就把 outside 起点设为当时 global；否则保留新记录的零值。这样新加入的区间不会凭空获得加入前的历史费用。每次跨越已初始化边界，都执行 `outside_new=global_now-outside_old`，不是一直累加。outside 是按当前所在一侧解释的累计量，必须和当前位置一起解读，不能把名字机械理解成一块永远固定的地理区域。

## 第 5 层：用主例证明 outside 翻转真的分对了吗？

**面试官：** 不要只背公式；跨 tick240 前后，A、B 的 inside 分别是多少？

**面试者：** 为隔离历史，假定本段开始时增长基线为零。省略 Q128 缩放与取整，记 g_A=3.632401704122298579/100000，g_B=0.867598295877701421/50000。跨 tick240 前 global=g_A；cross 后该边界 outside=g_A；最终 global=g_A+g_B。

最终 tick353 已经高于 A 上界。A 的 lower outside 为零，上方增长为 global-g_A=g_B，因此 inside_A=global-0-g_B=g_A。B 的下方增长是 g_A，上方增长为零，所以 inside_B=g_B。各自乘以原来的 L，就分别还原 3.6324 与 0.8676 T1。

若之后价格向左跨回，outside 再做一次“当前 global 减旧 outside”，公式仍成立；不能在每次 cross 时把 outside 清零，否则第二次穿越就会重算甚至漏算历史。

## 第 6 层：inside 正确了，为什么界面待领费用可能还是零？

**面试官：** 你已经算出 A 应得 3.6324，链上 positions.tokensOwed1 却没变，是漏记了吗？

**面试者：** 不一定。头寸采用惰性结算，保存 liquidity、feeGrowthInside0LastX128、feeGrowthInside1LastX128 和 tokensOwed0/1。swap 更新共享增长状态，不逐个修改 positions。头寸被更新时才计算：

`新增欠款=floor((inside_now-inside_last) × L_old / 2^128)`。

随后更新检查点并累加 tokensOwed。mint 增仓前先按旧 L 结算，新增 L 不分享过去费用；burn 减仓前也用旧 L 结算，被移除的那部分不会丢失已赚费用。读取原始 tokensOwed 只看见已结算欠款，展示完整应计费用还需模拟增长差。core collect 本身不刷新增长，通常先对有流动性的头寸 burn(0) 做 poke；零流动性头寸的这种 poke 会失败，不能无条件调用。

## 第 7 层：增长值绕回零，程序会不会把费用算成负数？

**面试官：** 既然靠两个检查点相减，uint256 累计量溢出后，你的 Go 计算还能跟链上一致吗？

**面试者：** 要按目标合约版本复现模算术。原版 v3 使用 Solidity 0.7.6，增长差和 outside 差依赖无自动溢出检查的 uint256 语义，即差值按模 2^256 解释。Go 的 big.Int 不会自动回绕，直接相减可能得到负数；应显式归约到对应位宽，再做与 FullMath 一致的乘除和向下取整。

例如检查点为 2^256-7、新增长值为 5，合法模差为 12，而不是负的大整数。但这个例子只验证位宽行为，不意味着任意多轮回绕都能恢复真实历史；迁移与离线重建仍必须限定目标版本和可解释的增长区间。

移植到 Solidity 0.8+ 不能直接让这些差值触发默认溢出回滚，也不能把整个函数粗暴放进 unchecked；流动性上限、类型转换和业务约束仍需分别处理。tokensOwed 是 uint128，还有窄化及累加边界，不能宣称数学上无限累积。多次 poke 的逐次取整可能留下少量尘埃，因此验证应匹配整数规则，而不是要求实数手算的小数位全部相等。

## 第 8 层：怎样区分舍入尘埃、记账错误与交易失败？

**面试官：** 允许舍入和延迟结算以后，你怎样证明不是用这些理由掩盖费用分错？

**面试者：** 我会固定池地址、合约版本和同一 blockHash，分开核对“每步费用进入增长”“inside 排除区间外增长”“旧 L 结算欠款”三道关系。主例 A/B 的分段归属必须成立，允许的仅是按步整数舍入，不允许把 4.5 全记到 B。边界判断使用池保存的 slot0.tick；向左恰好跨界时它可能是边界 tick-1，不能随意从 sqrtPrice 重算后替代。

再加入反向跨界、增仓前已有费用和 L=0 的变体，检查新增资金不追溯获费、重复 poke 不重复领取。若回调付款不足或路由最低输出失败，整个交易回滚，不应留下任何已赚费用。链下读取失败不能填零；未确认或被重组的交易也不能直接确认为收益，展示数据应绑定块哈希并支持撤回。

## 收束：讲透机制、易错边界、反例验证

- **讲透机制：** 费用先归本步旧 L，再用 global/outside/inside 压缩历史，最后按旧头寸 L 和检查点惰性结算。
- **易错边界：** 最终 activeL 不代表全程归属；core collect 不等于刷新费用；半开区间、模减法和两类舍入不能省略。
- **反例验证：** 主例结束时 A 已不活跃却仍应赚约 3.6324 T1。任何实现若给 A 零、给 B 全部 4.5，即使总额守恒，也违反时间与区间归属。
