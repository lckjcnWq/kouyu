# 行情与流动性系统：大白话导读任务清单

## 目标与范围

面向懂一些后端开发、但尚不熟悉盘口、流动性、AMM、做市和 RFQ 等交易业务的读者，为本目录下全部 **70 个现有 Markdown 文件（65 篇正文 + 5 篇专题 README）** 添加前置导读。本文是执行清单，不属于待添加导读的业务文章。

每个文件在原有一级标题之后、原正文之前增加：

1. **先看懂：关键词大白话解释**：用表格解释本文的交易名词、英文缩写、公式符号及关键工程概念，说明在本文中的具体含义。
2. **把整篇文章压缩成一个故事**：沿一个具体人物或系统事件串起起因、处理过程、结果和不能理解错的边界。

## 编写与验收标准

- 保留原有标题、正文、链接、公式和问答，不借导读改变原文规则。
- 各篇导读独立可读，不用“同上”代替解释；词表按本文内容选择，不机械复制通用名词。
- 先解释真实业务，再解释后端如何保证业务成立；比喻不能替代单位、方向、时效和状态边界。
- 区分行情参考价、买卖报价、最新成交价与真正可执行的交易价格；不把行情聚合描述成交易授权。
- 区分源事件序号、产品发布序号与客户端应用进度；不把心跳正常、重连成功或内部序号连续当成外部数据完整。
- 区分盘口数量覆盖与数量增减、快照与增量、事件时间与接收时间；缺口不能靠继续发布旧盘口掩盖。
- AMM 故事注明币种方向、精度和费用假设；区分现价、平均成交价、滑点保护与实际执行结果，不把池子总资产当作当前区间的有效流动性。
- 区分 LP 本金、累计手续费和可领取金额；无常损失须说明比较基准，不把手续费或集中流动性收益说成保本承诺。
- 做市区分报价意图、交易场所真实订单、已成交库存与在途可能敞口；撤单请求不是撤单成功，对冲超时不是确定失败。
- RFQ 区分展示报价、签名报价、库存预占、接受、链上执行与最终履约；签名不替代余额、授权、有效期和执行域校验。
- 区分链上观察、确认与最终性；数据库事务、交易原子性及幂等均说明适用范围，不把重组和跨系统未知态抹掉。
- 教学数字、阈值、协议参数、舍入和策略不泛化为所有交易平台或 AMM/RFQ 协议规则。
- 用结构检查验证 70 个文件均有且只有一套前置导读；与修改前快照比较，确认原文逐字保留。
- 检查新增 Markdown 表格、相对链接和故事中的关键算式，更新清单及复利记录。不创建 Go 工程，不声称运行链上实验、生产故障或性能测试。
