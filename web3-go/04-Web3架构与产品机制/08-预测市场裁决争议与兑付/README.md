| EVM / S / K | 合约执行环境／本模型市场合约／固定仲裁合约。 | S 管权利与资产，K 在规定状态和期限内提供枚举裁决，Go 不拥有改结果权。 |

| proposeBy / `[readyAt, proposeBy)` | 首次提报截止／含起点不含终点的窗口。 | 到终点已不能首次提报；无人提报由公开 NoProposal 入口结案。 |
| challengeEnd / arbitrationEnd | 挑战截止／仲裁截止。 | 挑战期由提报块起两小时，仲裁截止固定为挑战截止加 24 小时，不因挑战重新计时。 |
| rulesHash / evidenceHash | 规则字节指纹／证据字节指纹。 | 需保存可取回原文，哈希不证明规则无歧义、来源时间可信或赛事真实。 |
| Awaiting / Proposed / Disputed | 等待首次提报／暂定结果／有效挑战后的争议阶段。 | 结果阶段不等于交易开关；提报或挑战都还没有给持有人付款授权。 |
| Finalized / finalizationId | 唯一业务终局／稳定终局身份。 | 身份为 `(chainId,S,marketId)`；只写一次向量，不代表用户都已领或链已最终。 |
| reason / KVerdict / ArbitrationTimeout | 结案原因／及时有效仲裁／仲裁超时。 | 相同 INVALID 也可有不同原因，超时优先双方各返 10 C，不能只比结果奖励 Q。 |
| BondVault / escrow / 提款信用 | 独立保证金金库／待分配保证金／已确定待提额度。 | 双方各 10 C 不挪用市场抵押；最终化只分配信用，真正提款是另一笔事务。 |
| nY / nN / D / 兑付向量 | 两类兑付分子／正分母／共同付款比例。 | YES `[1,0]/1`、NO `[0,1]/1`、INVALID `[1,1]/2`，分子和等于分母。 |
| qY / qN / floor / pay | 本人两类最小单位余额／向下取整／实际应付整数。 | `pay=floor((qY*nY+qN*nN)/D)`，同地址先求和再取整，不按历史成交成本算。 |
| L / 有理负债 / 尾差 | 剩余理论应付／可有分数的负债／整数付款舍弃部分。 | 用 `reserve*D >= totalYES*nY+totalNO*nN` 检查覆盖，未领抵押不能全叫尾差。 |
| redeem / burn / 重入防护 | 主动领取／消费份额／防外部调用绕回重复操作。 | 本人一次烧全部两类余额并收 C，失败全回滚；非零份额即使兑付零也能消费。 |
| oracle / UMA OOv3 / Conditional Tokens | 外部裁决依赖／两类参考协议。 | 本稿是自定义教学状态机，不复刻接口，断言 false 不天然等于市场 NO。 |
| clientRequestId / txHash / replacement | 请求身份／候选交易哈希／同发送者同 nonce 替换。 | 同意图可有多个候选，广播超时是未知，不是可随意换 nonce 重做的失败证明。 |
| RPC / canonical / finalized | 节点接口／当前规范分支／共识层最终确定阶段。 | 回执属于具体块与分支，业务 Finalized 不替代链共识最终性。 |
| Inbox / Outbox / undo / revision | 本地去重／待发通知／撤销资料／修订号。 | 与完整块投影、游标可靠衔接；重组发更正不补款，通知不驱动第二次兑付。 |
| keeper / lease / epoch | 公开到期调用执行者／任务租约／接管代次。 | keeper 只用受限钱包付 Gas，租约围栏与取消等待不能撤销已签交易。 |
| MVP / atomic / div | 最小验证模型／复制后整体提交／整数除法。 | 下文伪代码用于说明局部状态与不变量，不是可运行工程或已经通过的合约测试。 |
| 治理边界 / 转账资产假设 | 谁能介入既有市场／抵押币行为约束。 | 本例无管理员暂停、改判、升级或追回；排除扣费、rebase 和回调，也不能消除冻结、脱锚与停链。 |

## 把整篇文章压缩成一个故事

**起因：** A、B 准备参与 M1，先确认 E1 常规时间赛果的源顺序、截至 02:00 的事实版本界限、取消延期与数据缺失条件已写死。A 实存 100 C 铸 100 YES＋100 NO，B 在 00:00 截止前付给 A 24 C，买走 40 YES；于是 A 剩 60 YES＋100 NO、B 有 40 YES，市场抵押仍是 100 C，成交价 0.60 C 只是价格。

**处理及异常：** 观察界限为 01:00，02:00 才允许提报；P 在 02:10 报 YES 并独立交 10 C，挑战截止为 04:10。主例无人挑战，04:10 及以后有人触发最终化，S 写入唯一 YES 向量并给 P 保证金信用，A、B 再各自销毁份额领取。独立异常中，Q 在 04:09 有效挑战就必须走 K 或次日 04:10 的超时 INVALID，不能仍按无争议 YES 支付；领取转币失败须连同销毁回滚，广播未知继续追踪，重组撤销旧投影而不是另付补偿款。

**结果及边界：** YES 主例 A 领 60 C、B 领 40 C，100 C 恰好付完；算上二级成交，A 为 −100＋24＋60＝−16 C，B 为 −24＋40＝16 C。独立 INVALID 变体则领 80 C、20 C，不退 B 的 24 C；另一个最小单位变体把一对份额拆给两人，双方各领零仍会留下 1 个最小单位尾差。最终化、保证金信用、持有人付款、页面同步和链最终性须分别说明；固定 K 仍可能错，公开超时入口仍需有人发交易，教学基线也没有管理员改判、扫尾差或替被冻结资产保证退出的能力。

## 第一部分：文字全流程

### 1.1 固定讨论基线

本专题自行设计单链 EVM 合约 `S`，使用六位小数抵押币 `C`，数值单位按 USDC 计价。假定 `C` 无转账扣费、无 rebase、无回调，采用安全转账封装，并核验入账数量；现实抵押币还存在发行方冻结、脱锚等风险。Gas 不计入案例损益。

- **足额抵押二元市场**：锁定 1 C，铸造 1 YES＋1 NO。份额同为六位小数，一个份额最小单位和一个 C 最小单位具有相同数量尺度。
- **链上权威**：`S` 持有按市场分账的抵押和 YES／NO 余额，负责铸造、合并、转让、成交、裁决状态与领取。Go 服务只编排交易和构建查询投影，不拥有结果或余额的最终修改权。
- **成交机制**：仅支持全量履约的签名限价卖单，买方提交后在一个链上事务内完成份额和付款交换。签名锁定份额数量及总付款整数，不推导浮点价格；没有链下成交即生效的义务，也不引入 AMM。
- **截止规则**：新铸造、普通份额转让、成交均要求 `block.timestamp < closeAt`。截止后冻结外部份额转让；完整集合并允许到市场最终化之前，内部领取销毁不受普通转让开关限制。
- **教学裁决器**：一次乐观提报、一次有效挑战、固定仲裁合约 `K`。提报和挑战各交 10 C，存入独立保证金合约 `BondVault`，不占用抵押池。所有普通路径均有链上期限和可公开触发的终局入口。
- **终局后不可改判**：`S` 只写入一次兑付向量。没有管理员暂停、改结果、追溯修改规则、升级当前市场或追回已付款的能力；没有重新提报和无限上诉。截止后单边持有人没有按买入成本退出的通道。要采用其他治理模式，必须显式改变这些前提。
- **用户主动领取**：终局后的当前持有人销毁该市场全部 YES／NO 余额，向其自己的地址领取 C；不遍历持有人、不后台统一打款、不根据订单成本计算兑付。

这是借鉴完整集与乐观争议思想的**自定义状态机**，并非 UMA OOv3 或 Conditional Tokens 的接口复刻。尤其不把 oracle 的 `assertion=false` 自动翻译为市场 NO。

### 1.2 贯穿案例 M1

问题是：**指定赛事 E1 的主队是否在常规时间内获胜？** 规则固定赛事身份、官方赛果源及备用源顺序、常规时间不含加时／点球、UTC 时间、取消与数据缺失的解释。YES、NO、INVALID 分别表示满足条件、不满足条件、按规则无法形成有效二元结果；INVALID 是异常结案向量，不是第三种可交易份额。

| 字段 | M1 固定值与含义 |
|---|---|
| `closeAt` | 2026-11-01 00:00 UTC，等于该时刻已经禁止新铸造、外部转让与成交 |
| `observeAt` | 2026-11-01 01:00 UTC，结果观察界限，不等于交易截止或提报时刻 |
| `readyAt` | 2026-11-01 02:00 UTC，等待一小时发布缓冲，开始允许提报 |
| `proposeBy` | 2026-11-02 01:00 UTC，只允许在 `[readyAt, proposeBy)` 首次提报 |
| 挑战期 | 从提报交易所在块的时间戳起两小时；`t < challengeEnd` 可挑战，`t >= challengeEnd` 不可挑战 |
| 仲裁期 | 固定 `arbitrationEnd = challengeEnd + 24 小时`，不是从挑战时刻重新计时 |
| 取消／延期 | 无独立管理员退款入口；官方取消，或赛事延期越过观察界限，按已锁规则裁为 INVALID；不延长旧市场截止时间 |
| 数据缺失 | 按固定源优先级与证据截止规则判断；仍不可判定时 INVALID，不默认 NO |

证据解释固定为：按主源及合格备用源优先级，采用**截至 readyAt 已发布、可核验的最新有效记录**；readyAt 后的修订不追溯改变事实集。后续挑战可以补交证明该界限前记录的证据。来源时间缺乏可验证证明时，K 对证据真实性的判断仍是信任边界；哈希和抓取时间本身不证明现实真相。

主例：A 锁定 **100 C**，获得 **100 YES＋100 NO**；A 以每份 0.60 C 的等价总价，将 **40 YES** 卖给 B，B 支付 **24 C**。此后 A 持有 60 YES＋100 NO，B 持有 40 YES，市场抵押仍为 100 C。

主例首次提报：P 在 11 月 1 日 02:10 UTC 提报 YES，存入 10 C，`challengeEnd=04:10`。无人有效挑战时，任何地址可在 04:10 及以后调用最终化，写入 YES 向量，P 获得 10 C 保证金提款信用。A 领取 60 C、B 领取 40 C，合计 100 C；A 的交易款另来自 B，A 净损益 −16 C，B 净损益 +16 C。

后文的争议、NO、INVALID、舍入和重组是**独立异常变体**，不叠加到同一笔主例。

### 1.3 主链路

```text
创建者提交市场规则、源优先级、时间表和合约绑定
    ↓
S 校验并保存 marketId、rulesHash、C、BondVault、K 与不可修改的时间参数
    ↓
A 授权并锁定 100 C → S 实收 100 C → 铸造 100 YES＋100 NO
    ↓
A 签署全量卖出 40 YES、总收款 24 C 的限价意图
    ↓
B 在 closeAt 前提交成交交易
    ├─ S 检查签名域、nonce、期限、A 余额与 B 付款能力
    └─ 同一事务：消费订单身份、转移 40 YES、B 向 A 支付 24 C
    ↓
达到 closeAt → S 的时间校验阻止新铸造、外部转让和成交
    ↓
到 observeAt 观察事件 → 到 readyAt 才允许提报
    ↓
P 提交绑定 M1、rulesHash 和枚举结果的证据承诺，并向 BondVault 存入 10 C
    ↓
S 进入 Proposed，固定 proposalId 和 challengeEnd
    ├─ 无挑战：到 challengeEnd 后，任何人触发最终化
    └─ 有效挑战：Q 存入 10 C → S 进入 Disputed → 等待 K 或超时
    ↓
S 在一个链上事务内：写唯一兑付向量和 finalizationId，BondVault 分配保证金信用
    ↓
各持有人调用 redeem(M1)
    └─ 同一事务：读取自身份额 → 计算兑付 → 销毁份额 → 扣减抵押 → 转 C
    ↓
Go 按规范链完整索引事件、核对状态，并按链的最终性策略提升查询状态
    ↓
页面分别显示结果是否终局、领取是否执行、链上是否最终、到账是否可查
```

合约不在 `closeAt` 自动运行一笔交易；即使 Go 定时器停机，`S` 仍会在每次受保护操作时检查链上时间。到期也不自动最终化，需要有人提交有效交易。

### 1.4 主要异常分支

```text
参数／规则不合法 → 创建失败，不收取市场抵押
成交在截止后才上链 → 整笔回滚，不能凭签名时间强行履约
observeAt 已到但 readyAt 未到 → 拒绝提报，不把观察完成等同于可裁决
Awaiting 且 t >= proposeBy → 任何人触发 INVALID，无提报保证金可处理
Proposed 且挑战在 t < challengeEnd 成功 → Disputed，禁止无争议最终化
Disputed 且 K 在 t < arbitrationEnd 给出有效裁决 → 按裁决最终化
Disputed 且 t >= arbitrationEnd → 任何人按预定规则最终化 INVALID
领取转账失败 → 销毁、抵押扣减和事件全部回滚，用户仍有原份额
广播超时／暂查无回执 → 标记未知并追踪原意图，不直接假定未执行
非最终区块被重组 → 撤销本地投影并重放，不凭旧日志发送独立补款
```

保证金独立变动：无挑战返还 P 的 10 C；有挑战且 K 在期限内有效裁决，结果等于提报结果时 P 获得 20 C 信用，等于挑战方明确提交的替代结果时 Q 获得 20 C，第三种结果时双方各返还 10 C。**仲裁超时优先按双方各返 10 C 处理，即使 Q 主张的恰好是 INVALID 也不算胜诉。** 因此须保存 KVerdict、Unchallenged、NoProposal、ArbitrationTimeout 等终局原因，而不只比较结果。全部是本模型规则，不是通用预言机费率。信用分配在最终化事务内完成，实际提款为另一笔交易。

若仲裁判 NO，A 的 100 NO 兑付 100 C，B 的 YES 为零；若 INVALID，采用 `[1,1]/2`，A 领取 `(60+100)/2=80 C`，B 领取 `40/2=20 C`。INVALID 下 A 净收益 4 C，B 净亏损 4 C，**并不是 B 买入花了 24 C 就退 24 C**。

## 第二部分：核心板块

| 核心板块 | 决定什么／为何核心 | 权威状态与上下游契约 |
|---|---|---|
| 问题与规则注册 | 决定哪些现实事实映射到哪种结果，防止事后改题 | S 保存规则哈希、时间与裁决器；证据服务提供内容，不可改写市场 |
| 抵押与头寸 | 决定每单位兑付权是否有资产覆盖 | S 保存市场抵押、份额余额与供应；交易只改变所有权 |
| 交易与截止 | 决定用户何时取得什么权利 | S 在成交执行时同时检查时间、订单身份、余额与付款，链下签名本身不占资 |
| 提报与争议 | 决定暂定结果何时可被接受或挑战 | S 保存唯一提报、挑战、截止；BondVault 保存保证金，不混用抵押 |
| 仲裁与最终化 | 决定唯一、不可普通改判的兑付参数 | K 在限定时间内向 S 裁决；S 原子提交向量与保证金分配 |
| 领取与链观察 | 决定权利是否消费、付款是否发生、查询是否可靠 | S 原子销毁和付款；Go 投影跟踪规范链、最终性及恢复水位 |

## 第四部分：设计与规则

### 4.1 状态机与两种终局

```text
Awaiting（结果阶段初始状态；交易权限另由 closeAt 判断）
    ├─ readyAt <= t < proposeBy，首次提报 → Proposed
    └─ t >= proposeBy，无人提报 → Finalized(INVALID)

Proposed
    ├─ t < challengeEnd，有效挑战 → Disputed
    └─ t >= challengeEnd，无挑战 → Finalized(提报结果)

Disputed
    ├─ K 有效裁决且 t < arbitrationEnd → Finalized(K 的结果)
    └─ t >= arbitrationEnd → Finalized(INVALID)

Finalized → 不再改判；各用户可分别 redeem
```

`Awaiting` 不是“交易开放”的同义词；本模型结果状态与交易权限分开。`Finalized` 表示合约普通裁决终局，仍需等待底层链的最终性。合约执行只读取当前规范分支上的状态，不能等待未来最终区块；Go 的最终性门槛用于对外承诺和外部不可逆动作。

### 4.2 数量与资金不变量

所有以下数量均用最小单位整数表示：`100 C = 100_000_000`。

1. `reserve = 累计实收铸造抵押 − 累计合并返还 − 累计兑付款`，不含保证金、二级成交款或外部直接捐入余额。
2. 最终化前，`totalYES = totalNO = reserve`；完整集合并同时减少两边供应和抵押。这里总量是尚未销毁的供应，不是历史累计铸造。
3. 结果向量为 YES `[1,0]/1`、NO `[0,1]/1`、INVALID `[1,1]/2`；分子非负，分母为正，分子和等于分母。S 只接受这三个白名单向量。
4. 最终化后的剩余理论负债为 `L = (totalYES*nY + totalNO*nN)/D`，作为有理数比较时要求 `reserve*D >= totalYES*nY + totalNO*nN`。禁止浮点比较。
5. 一个用户一次领取该市场全部两类余额：`pay = floor((qY*nY + qN*nN)/D)`。先求和再取整是**本模型规则**，不假设其他份额协议相同。
6. 领取原子消耗非零份额并支付；即使只持输方、兑付为零，也可由本人调用销毁。两边余额均为零则拒绝，不用全局 `claimed[marketId]` 屏蔽其他人。
7. 向下取整不会超付，但可能留下尾差。基线不承诺零尾差、不强制到期、不提供管理员扫走抵押的接口；尾差留在 reserve，并在对账中单列。
8. BondVault 的 `escrow + 未提信用 + 已提保证金 = 历史实收保证金`，按同一规范链前缀核算。S 无权把市场抵押用于争议奖励或运营支出。

合约共用物理地址时也必须按市场保存 reserve；不得用其他市场的余额覆盖 M1 缺口。ERC-20 的直接捐赠造成物理余额大于分账合计，不自动铸造份额或提高兑付比例。

### 4.3 架构与职责

```text
钱包／前端
    ├─ 签名订单 → Go 接入与订单查询 → 买方构造链上成交
    ├─ 证据查询 → Go 证据归档〔原文、来源、时间、内容哈希〕
    └─ 自行签署创建／铸造／提报／挑战／领取交易
                         ↓
S：规则、份额、抵押、结果状态、唯一兑付向量
    ├─ 与 BondVault 同事务收取／分配保证金〔仅分配信用，不即时外部支付〕
    └─ 接收固定 K 的枚举裁决〔验证市场、提报、规则与期限〕
                         ↓
规范链日志＋块内顺序＋合约指定块查询
                         ↓
Go 索引器 → 数据库投影／Outbox → 查询与通知
    └─ 区块哈希连续性、回滚、重放、最终性水位与不变量对账
```

K 是明确的信任边界，不承诺现实事实一定真实；本模型只把获授权裁决映射为执行规则。合约时间推进和交易可被包含是活性前提，链停机或抵押币冻结不可能靠 Go 定时器消除。

### 4.4 核心对象与身份

| 对象／身份 | 必要字段及用途 |
|---|---|
| 市场 | `chainId, S, marketId, rulesHash, C, BondVault, K, closeAt, observeAt, readyAt, proposeBy`；规则内容须可获得，哈希不能代替存档 |
| 订单 | `maker, marketId, side=YES/NO, shareQty, collateralTotal, orderNonce, expiration, taker限制, domain`；全量成交，成交与消费 nonce 同事务 |
| 提报 | `proposalId, marketId, rulesHash, proposer, proposedOutcome, evidenceHash, proposedAt, challengeEnd`；一个市场仅一个有效提报 |
| 挑战 | `proposalId, challenger, alternativeOutcome, evidenceHash, arbitrationEnd`；替代结果必须不同，只有一次有效挑战 |
| 最终化 | `finalizationId=(chainId,S,marketId), outcome, nY,nN,D, reason, block位置`；身份固定，观察位置可能因重组变化 |
| 领取意图 | `clientRequestId, chainId,S,marketId,owner, payloadHash`；用于界面幂等，不能取代链上份额消费 |
| 交易尝试 | `sender, txNonce, txHash, replacement关系, receipt.status, blockHash`；同一意图可能有多个候选哈希 |
| 链上观察 | `chainId, blockHash, txHash, logIndex` 加块高、交易序号；按完整规范块应用，不以 txHash 单独作为事件键 |
| 投影 | `market/owner revision, canonical cursor, finalized cursor, inbox/outbox status`；缓存和队列不成为权威余额 |

S 使用单市场串行状态语义与链上事务原子性，不引入分布式锁来裁决合约竞争。Go 不持用户私钥，也不替用户签署新资格；系统 keeper 可持受限热钱包，只调用公开到期入口。Go 使用有界 worker、持久任务和按发送地址串行的 nonce 分配；lease／epoch 与 context 取消不能撤销已签链上交易，同 nonce replacement 属于原业务的交易尝试。数据库事务只覆盖投影、Inbox／Outbox 与游标，绝不声称与 EVM 形成一个大事务。

## 第七部分：工程实践——一个简洁 MVP

### 7.1 目标与范围

只手工验证“受挑战的提报不能按无争议路径确认；唯一终局后，领取原子消费份额且不超付”。输入为已创建、已抵押、已完成交易的内存状态；不实现签名、证据真实性、仲裁、保证金、链重组、转账合约或可运行 Go 工程。

### 7.2 核心伪代码

下列 `atomic` 表示本地模型的复制后提交：任一 `require` 或模拟转账失败即丢弃全部本次变更。它不表示数据库与真实链上可以共同提交。整数在模型中不溢出；真实合约需采用有界数值与安全乘除。

```text
step(m, cmd, now, caller):
  atomic copy(m):
    if cmd.type == CHALLENGE:
      require m.state == Proposed and now < m.challengeEnd
      require cmd.alternative in {YES, NO, INVALID}
      require cmd.alternative != m.proposedOutcome
      m.state = Disputed                  # 保证金处理不在 MVP 范围
    else if cmd.type == FINALIZE:
      if m.state == Proposed:
        require now >= m.challengeEnd
        outcome = m.proposedOutcome
      else if m.state == Disputed:
        if caller == m.K and now < m.arbitrationEnd:
          require cmd.outcome in {YES, NO, INVALID}
          outcome = cmd.outcome
        else:
          require now >= m.arbitrationEnd
          outcome = INVALID
      else:
        require m.state == Awaiting and now >= m.proposeBy
        outcome = INVALID
      (m.nY, m.nN, m.D) = vector[outcome]
      m.state = Finalized                 # 此后没有修改向量的入口
    else if cmd.type == REDEEM:
      require m.state == Finalized
      (y, n) = m.balance[caller]
      require y + n > 0
      pay = (y*m.nY + n*m.nN) div m.D
      require m.reserve >= pay
      m.balance[caller] = (0, 0)
      m.totalYES -= y; m.totalNO -= n
      m.reserve -= pay
      require not cmd.simulateTransferFailure
      output Payment(caller, pay)         # 仅提交后才可观察到此输出
    else:
      reject
    if m.state == Finalized:
      require m.reserve*m.D >= m.totalYES*m.nY + m.totalNO*m.nN
    else:
      require m.totalYES == m.totalNO and m.totalYES == m.reserve
  return committed state and output
```

负债检查按状态区分：未终局时要求完整集供应与抵押相等；终局后按固定向量检查剩余负债。MVP 不把未填的兑付向量当成默认 YES，也不允许未终局领取。

### 7.3 输入与手工预期

每行均从独立初态开始，除非显式写明连续操作。

| 输入 | 手工预期 |
|---|---|
| 主例 Proposed，P 于 02:10 提报 YES，04:10 无人挑战，依次 FINALIZE → REDEEM(A) → REDEEM(B) | 最终化先写 `[1,0]/1`，此时 reserve 仍为 100 C；再分别支付 60 C、40 C，reserve 才归零 |
| 04:09 挑战成功；04:10 普通地址尝试按 YES 提报最终化 | 已为 Disputed，未到次日 04:10 仲裁截止，拒绝；无份额或抵押变化 |
| Disputed，次日 04:09 K 给出 NO | 写 `[0,1]/1`；A 可领 100 C，B 可销毁 YES 但付款为 0 |
| Disputed，次日 04:10 K 尝试给出 YES | 仲裁已超时，走 INVALID，而非接受迟到 YES；A 可领 80 C，B 可领 20 C，尚未领取时 reserve 仍为 100 C |
| 已最终为 YES，A 领取模拟转账失败，再正常重试 | 首次全部回滚，A 仍有 60 YES＋100 NO；重试只支付 60 C 一次 |
| 已最终为 YES，A 成功领取后再次领取 | 两边余额均为零，拒绝，不影响 B 的 40 C 权利 |
| INVALID，抵押 1 个最小单位，U 持有 1 YES 最小单位、V 持有 1 NO 最小单位，依次 REDEEM(U) → REDEEM(V) | 各自领取均为 0，双方主动销毁后 reserve 留 1 最小单位；不超付但有尾差 |

这些是手工推演的预期，不是已经运行的单元测试或合约测试。
