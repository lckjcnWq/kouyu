# 大问题 7：仲裁怎样形成唯一终局，并处理超时、取消和延期？

<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| S / K | 保存权利与状态的合约／创建时固定的仲裁合约。 | S 检验 K 的资格再接受结论，K 不能绕过状态或直接给任意兑付参数。 |
| marketId / proposalId / rulesHash | 市场身份／提报身份／规则指纹。 | 三者必须匹配，不能拿别场比赛或另一份提报的结论注入 M1。 |
| Awaiting / Proposed / Disputed | 尚无提报／有提报无有效挑战／争议中。 | 三种状态对应不同最终化来源，不能混成一个“到期就支付”分支。 |
| Finalized / finalizationId | 已形成唯一业务终局／其固定业务身份。 | 不是任意管理员可覆盖的结果，也不是全体用户已经领取。 |
| 兑付向量 / 白名单 | 固定的两类份额付款比例／允许的参数集合。 | YES `[1,0]/1`、NO `[0,1]/1`、INVALID `[1,1]/2`，不接受任意分母或比例。 |
| KVerdict | K 在限定期内给出的有效裁决。 | 只有 Disputed 且 `t < arbitrationEnd` 才能按此原因最终化。 |
| arbitrationEnd / deadline | 仲裁资格截止／执行有效期。 | 截止前发出不等于及时执行；恰等于截止不再接受普通 K 裁决。 |
| ArbitrationTimeout | 仲裁未能按时完成的退出原因。 | 到期后公开触发 INVALID，双方保证金各返 10 C 信用，不宣称证明了真实赛果。 |
| proposeBy / NoProposal | 首次提报截止／无人提报的终局原因。 | Awaiting 到期后可公开最终化 INVALID，不编造 proposalId，也无保证金可分。 |
| Unchallenged | 提报经过挑战期仍未被有效挑战。 | 到期后可按原提报最终化，但必须仍是 Proposed。 |
| BondVault / 信用分配 | 独立保证金金库／记录后续可提取的归属。 | 与写入终局向量同事务，分配不是给用户立即外部打款。 |
| reserve / 改判缺口 | 剩余抵押／付款后换结果造成的新负债不足。 | B 按 YES 领 40 C 后只剩 60 C，若改 NO 却会欠 A 100 C。 |
| INVALID / 取消延期 | 异常兑付结果／按原规则判断的赛事事件。 | 不是管理员退原始铸造本金的理由，也不会自动把旧份额迁到新市场。 |
| keeper / 公开入口 | 帮忙发到期交易的人／任何地址可合法触发的路径。 | 无 keeper 不等于无权限推进，但没人发交易也不会自动结案。 |
| redeem / 链共识最终性 | 按当前终局消费份额／底层历史稳定性保证。 | S 可在当前分支授权领取，Go 的链外不可逆承诺另等最终性。 |
| 安全性 / 活性 | 不发生冲突终局／在前提满足时可继续推进。 | 唯一向量解决前者，有限公开超时出口帮助后者；都不能保证 K 永不误判或停链时准点退出。 |

## 把整篇文章压缩成一个故事

**起因：** M1 的提报已被挑战，S 等固定 K 在仲裁截止前裁决。K 必须带对市场、proposalId 和 rulesHash，S 才会把合法枚举映射为唯一向量，并与保证金信用分配一起提交；K 在截止前发出但到截止才执行，也不能再采纳迟到 YES。

**处理及异常：** 本文用一个改判反例解释为什么终局只能写一次：B 先按 YES 领取 40 C，烧掉 40 YES，抵押从 100 C 变成 60 C。若随后改 NO，A 仍有 100 NO，就会需要 100 C，形成 `100－60＝40 C` 缺口。正确设计不开放普通改判；若 K 一直不回复，到期由任何人触发 INVALID，而不是无限等待或偷偷延长旧市场。

**结果及边界：** 正常及时裁决、无争议到期、无人提报到期和仲裁超时分别保留原因；后两类虽都可 INVALID，却不代表比赛真的取消。取消或越界延期也按创建时规则走，不给管理员临时退款或迁移权。S 的业务终局只在当前规范分支成立，链共识最终性仍是另一层；唯一终局和公开退出路径不保证现实结论永远正确，也不消除停链与资产冻结风险。

**流程位置与核心机制：** 负责 Disputed／Awaiting 到 Finalized 的有限路径与不可改判边界。沿用固定 K、固定 arbitrationEnd 和三种白名单向量；不引入管理员追溯改判或多轮上诉。

## 第 1 层：收到仲裁结论后怎样安全落到合约

**面试官：** 已经有争议了，仲裁器认为 YES，S 怎样接受这个结果并最终化？

**面试者：** S 只接受创建时绑定的 K 发来的枚举裁决，要求 marketId、proposalId 和 rulesHash 全部匹配，状态为 Disputed，且链上时间小于 arbitrationEnd。校验通过后在同一事务里写入 YES 的 `[1,0]/1`、唯一 finalizationId、原因 KVerdict，并让 BondVault 分配保证金信用，最后提交事件。K 不是传一段任意向量让 S 无条件采用；S 自行把白名单枚举映射到固定参数。这样把“谁有权提供结论”和“结论怎样改变资产权利”分开，既防止串市场，也避免分母为零或分子和不为分母的恶意配置。

## 第 2 层：为什么必须限制只写一次

**面试官：** 如果 K 后来发现判断错了，为什么不能再提交 NO，修正之前的 YES？

**面试者：** 因为第一次最终化就已经授权持有人消费份额领取。B 可能先按 YES 领走 40 C，并销毁自己的 40 YES；此时 reserve 为 60 C，A 仍持有 60 YES＋100 NO。随后改成 NO 就会让 A 的 100 NO 获得 100 C 权利，超过剩余抵押 40 C，且已销毁或已转出的链上事实不能由改一个枚举追回。本基线没有改判入口，Finalized 不再接受普通仲裁回调，也不允许管理员覆写向量。它选择有限终局和确定兑付，代价是最终错误需要在系统外讨论赔偿或新规则，不能从旧抵押中悄悄挪款。如果产品需要可上诉，就必须在可领取前把完整上诉过程结束，而不是先付款再普通改判。

## 第 3 层：K 到截止仍不回复，谁能推进

**面试官：** 不允许改判也不能一直等 K，那仲裁器失联后怎么结束？

**面试者：** 到 arbitrationEnd 及以后，任何地址都可调用超时入口，把仍为 Disputed 的市场最终化 INVALID，使用 `[1,1]/2`，reason 为 ArbitrationTimeout，保证金双方各返信用 10 C。它不需要 K 签名，也不修改原定 closeAt 或 observation。这个机制给出公开的有限等待界限，但不证明 INVALID 是现实赛事真相，而是协议对无法及时完成裁决的预设退出政策。若无人提交到期交易，状态不会自动变化；keeper 只是降低主动推进成本的工具，不能成为唯一有权限的人，更不能把自己的离线时间当作推迟期限的理由。

## 第 4 层：截止边界附近的 K 结论与超时怎样互斥

**面试官：** K 在最后一秒发出 YES，但交易到仲裁截止才执行，同时有人调用超时，谁赢？

**面试者：** 依据执行时的链上时间，而不是 K 发出或 Go 收到的时间。KVerdict 要求 t 小于 arbitrationEnd；在恰等于该界限时，普通裁决资格已结束，允许的是超时 INVALID。在同一个时间戳的块中两种条件不会同时成立；如果 K 的有效裁决已经在更早块成功，状态变成 Finalized，之后超时入口也不能再改。延迟交易的签名真实性只能证明谁发出，不赋予它越过 deadline 的权利。实现可以让统一 finalize 在超时后选择 INVALID，也可以让迟到 KVerdict 拒绝而由公开入口推进，但绝不能仍采纳迟到 YES。

## 第 5 层：没有人首次提报，是否也需要 K

**面试官：** 你刚才都在说 Disputed，如果压根没有提报，K 又没有 proposalId，怎么退出？

**面试者：** Awaiting 在 readyAt 至 proposeBy 之间接受首次提报；到 proposeBy 仍为 Awaiting，则任何人可按 NoProposal 原因最终化 INVALID，不需要编造一个 proposalId，也没有提报或挑战保证金可分。S 的最终化函数必须区分三条来源：Awaiting 无提报到期、Proposed 无挑战到期、Disputed 仲裁或到期。不能在一条“now 超过某个时间就支付原提报”的分支里混用，尤其不存在的原提报结果不能默认为 YES。事件应保留 reason，审计才能区分数据无法裁决与市场无人运营两种不同问题。

## 第 6 层：赛事取消或延期是否要给管理员紧急退款权限

**面试官：** 官方宣布比赛取消了，管理员直接取消市场、退本金会不会更简单？

**面试者：** 本模型不增加这种权限。取消或延期越过 observeAt 属于预先定义的 INVALID 事实，经合法提报和可能的争议进入终局；如果没有提报，则仍由 NoProposal 路径退出。用户已经在二级市场转移份额，管理员按原始铸造者退款会剥夺 B 的 40 YES 权利，按买入成本退款也缺少可逆资金来源。旧市场不延长交易或观察期限；若有必要可以另建反映新赛程的市场，但需要新的明确参与和资金流。这个选择可能牺牲即时退款速度，却避免临时政策改变已经流通的兑付权。

## 第 7 层：终局确认是否必须等链上最终性才能执行 redeem

**面试官：** 既然终局很重要，S 能否等到未来区块最终之后再开放当前向量领取？

**面试者：** 在本模型中，S 根据当前规范分支的 Finalized 状态授权 redeem，合约本身不等待某个 Go 服务宣布未来最终性。区块内先最终化后领取也可能合法，若该块被重组，向量、burn 和 C 转账都按同一分支规则一起回退。Go 对外的“最终不可逆”承诺和链外可提现信用则应使用选定链的最终性水位，而不是把一次打包当成链最终。若改为链上强制额外等待区块数，需要明确延迟和安全假设，等待 N 个块也不是所有链上的绝对最终证明，不能把市场的普通无上诉终局和底层共识最终性合成一个概念。

## 第 8 层：有限终局的保证与不可保证分别是什么

**面试官：** 你这套设计最终到底能承诺什么，不能承诺什么？

**面试者：** 我能在合约代码正确、链按假设运行、有效交易能被包含的条件下，承诺状态机存在有限可公开触发的结案路径，单市场只提交一个向量，所有后续领取沿用它，且份额抵押约束不因改判而破坏。我不能承诺 K 绝不误判、主源绝不出错、错误提报一定被挑战，或链停机也能准时退出。验收时要将安全性和活性分开：两个冲突终局都能提交是安全失败，永远等一个失联 K 且没有到期出口是活性失败。预设 INVALID 是确定的退出政策，不是消除了现实争议和信任成本。

## 本题收束

- **讲透的机制：** 权限绑定、三条最终化来源、时间资格互斥和单次不可改向量，使争议可以在有限规则内结束。
- **最容易答错的边界：** 截止前发出的仲裁不保证截止前执行；取消不等于撤销历史成交；Finalized 不是现实真相或链最终性的无限保证。
- **反例检验：** B 先按 YES 领 40 C 并销毁 40 YES，剩余 reserve 为 60 C，A 仍持 60 YES＋100 NO。若 K 又改成 NO，就会出现 100 C 权利对应仅 60 C 抵押的缺口，说明“可随时纠错”破坏了既有偿付边界。
