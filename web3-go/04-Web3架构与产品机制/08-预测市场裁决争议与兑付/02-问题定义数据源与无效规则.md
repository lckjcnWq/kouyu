# 大问题 2：怎样定义可裁决的问题、数据源和无效规则？

<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| E1 / M1 | 被观察的指定赛事／围绕它创建的市场。 | 先唯一确定哪场比赛，不能只凭“主队能不能赢”的标题交易。 |
| 常规时间 | 本市场明确约定的赛程范围。 | 需说清补时口径，明确不含加时和点球，不能事后换成最终晋级结果。 |
| YES / NO | 满足问题条件／有效比赛结果不满足条件。 | 正常完赛的平局或客队胜是 NO，不是数据缺失。 |
| INVALID | 按已锁规则无法形成有效二元结果。 | 取消、越过观察界限的延期或合格证据不足可归入此类，不代表按成本退款。 |
| S / K | 保存市场状态的合约／获授权的仲裁合约。 | 规则约束判断口径，最终写链还必须遵守 S 的状态和 K 的权限。 |
| rulesHash | 按确定编码对原始规则字节计算的指纹。 | 可发现事后换文，但不能证明问题无歧义，也不能代替可下载的规则原文。 |
| marketId / 版本绑定 | 市场编号／把操作绑定到特定规则版本。 | 订单、提报、裁决必须指向同一个 M1，网页改字不改变原权利。 |
| 主源 / 备用源优先级 | 预先排好的证据采用顺序。 | 主源不满足启用条件才查合格备用源，不按链接数量表决或挑喜欢的结果。 |
| closeAt / observeAt | 交易截止／事件观察界限。 | 旧市场延期不赋予管理员延长交易时间的权力。 |
| readyAt / 发布缓冲 | 开始允许提报的时刻，也是本例事实版本界限。 | M1 采用截至 02:00 已发布、可核验的最新有效记录。 |
| proposeBy / 超时原因 | 首次提报截止／为何没能正常完成的记录。 | 无人提报超时与比赛取消可同为 INVALID，但不是同一事实原因。 |
| 证据提交时间 / 来源发布时间 | 何时拿来证明／该记录何时已经存在。 | 后补证据可证明 02:00 前的记录，不能借此纳入 02:05 新更正。 |
| evidenceHash / 归档 | 证据字节指纹／保存原响应、版本和获取信息。 | 哈希不证明发布者身份与时间；本地抓取时间也不是现实真实性证明。 |
| C / 当前份额 | 六位小数抵押币／现在还持有哪些权利。 | 兑付依据当前余额，不追溯每次二级转让的买入成本。 |
| `[1,1]/2` | YES、NO 每份各按半份 C 结算。 | INVALID 下 A 的 60 YES＋100 NO 领 80 C，B 的 40 YES 领 20 C。 |
| 信任边界 / 有限裁决 | 仍要信谁／何时不再纳入新版本。 | 锁定规则使判断可复核，不保证官方源、K 或无人挑战的提报永不出错。 |

## 把整篇文章压缩成一个故事

**起因：** M1 要让 A、B 交易 E1 主队“常规时间获胜”的权利。创建前就必须把赛事身份、补时与加时口径、主源和备用源顺序、取消延期及数据缺失条件写清，并让用户看到与链上 rulesHash 对应的原始规则，不能只给一句会变动的网页标题。

**处理及异常：** 官方 01:55 发布一版赛果，02:05 又更正，P 准备 02:10 提报。按 M1 事先锁定的 02:00 界限，后来的更正不能重写这个市场的事实集；挑战者仍可晚些提交能证明界限前记录的证据。若主源无有效记录，按预定条件检查备用源；全部不合格才按规则 INVALID，不能把缺失当 NO，也不能用截图上的时间或本地抓取时间假装来源时间已被证明。

**结果及边界：** 独立的 INVALID 变体中，A 的 60 YES＋100 NO 按 `(60＋100)/2＝80 C` 兑付，B 的 40 YES 按 `40/2＝20 C` 兑付，总额仍是 100 C；B 花过 24 C 不构成退 24 C 的权利。规则固定换来可重复裁决，不等于现实最后真相，也不赋予管理员改题、延长旧市场或绕过合约终局流程的能力。

**流程位置与核心机制：** 从创建前的问题语义追到现实证据的可复核性。采用总览 M1；本题解释何种事实对应 YES／NO／INVALID，不负责替代合约权限和最终化状态机。

## 第 1 层：一个预测问题怎样才算可以进入交易

**面试官：** 用户提交“主队能不能赢”，你会直接创建二元预测市场吗？

**面试者：** 不会直接创建。我需要先消除事件和结果的歧义：赛事 E1 的唯一身份、双方球队、常规时间定义、是否包括补时、明确不含加时和点球、观察界限、官方发布渠道，以及取消和延期怎么办。M1 的 YES 表示按规则认定的常规时间主队获胜；正常完赛但主队未胜，包括平局和客队胜，属于 NO；按规则无法产生有效赛果才是 INVALID。还要验证 closeAt、observeAt、readyAt、proposeBy 的顺序和争议期限。仅有一句问题标题不能构成可执行的金融权利，标题必须和完整规则一起供用户确认。

## 第 2 层：规则怎样防止创建后被悄悄改写

**面试官：** 你说完整规则，但如果网站管理员后来把“常规时间”改成“含点球”，链上怎么发现？

**面试者：** 我把有版本、明确字段顺序和编码方式的规则内容计算为 rulesHash，创建时写入 S，并绑定 marketId、时间和裁决器。订单、提报和裁决都针对该市场及原始规则；网站文案改了不会改变链上绑定。服务必须长期提供原始规则字节与可核验哈希，用户签名前看到的是同一版本，而不是只存一条可变 URL。哈希只能证明内容未被替换，不能保证描述本身无歧义，也不能保证原文未来可下载。因此创建准入还需要审阅语义，并对原文做多份可获取归档，而不是把“上链一个哈希”当成所有问题都已解决。

## 第 3 层：多个数据源相互矛盾时听谁的

**面试官：** 原文没改，但官方源、备用源和媒体结果不一致，裁决是不是谁拿到的链接多就赢？

**面试者：** 不是投链接数量。M1 应在原始规则里明确主源身份、备用源顺序及启用条件，例如只有主源在证据界限内没有有效记录，才按指定顺序采用第一份有效备用记录，而不是主源内容不合心意就换源。有效记录要对应 E1、明确常规时间赛果、具有可核验发布时间和状态。主源与媒体矛盾时按事先规则解释，多个媒体相互复制不增加权威性。如果主源无法核验且备用也不能满足条件，就进入 INVALID 语义，而不是让程序在相互冲突的字符串中多数表决。

## 第 4 层：赛果晚发布或后来修订，采用哪个版本

**面试官：** 你说“证据界限”，如果官方 02:05 更正了 01:55 的错误结果，02:10 才提报，应该采用哪个？

**面试者：** 必须先固定修订规则。为让 M1 可复核，我采用“截至 readyAt 即 02:00，符合规则的最新官方有效记录”；readyAt 后的追溯更正不改变本市场事实集，后续提交证据只是在证明截至该界限已经存在的记录。因此 02:05 才发布的更正不直接重写 M1 的判断。这个规则牺牲了吸收晚到更正的能力，换取有限、可重复的裁决边界，并不等于现实世界最后真相。若业务希望吸收更长的更正，应在创建时延长缓冲或显式设计修订窗，不能看到更正后再临时延长当前挑战期。

## 第 5 层：怎样证明记录在界限前就已经存在

**面试官：** 那一张截图标了 01:55，你就相信它是 02:00 前的原始记录吗？

**面试者：** 不相信截图时间本身。我会归档原始响应或发布物、赛事和来源标识、采集时间、内容哈希、获取路径及可获得的来源签名或版本记录；同时保存有冲突的版本，避免只留最终页面。链上 evidenceHash 证明的是提报引用了哪些字节，不证明发布者身份、发布时间或事件真假。没有来源可验证签名或可信历史证明时，K 对证据来源及时间判断仍是信任边界。系统不能把本地 HTTP 抓取时间包装成密码学证明；证据无法满足预设可核验条件时，应按规则采用备用源或 INVALID，而不是编造确定性。

## 第 6 层：INVALID 为什么不能按每人买入成本退款

**面试官：** 证据不足会 INVALID，那是不是直接把每个用户买入花的钱退回去就最公平？

**面试者：** 不能混淆产品政策和已有权利。M1 在创建时承诺 INVALID 使用 `[1,1]/2`，按当前份额数量兑付，不保存每一次转让的成本基础，也没有保证二级成交可逆。A 卖给 B 的 40 YES 收了 24 C，INVALID 时 B 持有的份额只值 20 C；A 的 60 YES＋100 NO 值 80 C。按成本退 B 24 C，就需要从 A 或其他资金来源额外追回 4 C，这已经不是原完整集的向量规则。若产品真要按成本退款，必须设计交易撤销、资金追索与权利转移账本，不能在本基线中口头加上一个“公平退款”。

## 第 7 层：取消、延期和长时间无人提报怎样区分

**面试官：** 那取消和延期都走 INVALID，会不会把正常的 NO 也混进去？

**面试者：** 必须区分事实原因和最终向量。正常完赛但主队没赢是 NO；官方取消、延期越过 observeAt 或截至证据界限无法得到有效结果，按 M1 规则是 INVALID。无人提报直到 proposeBy、或仲裁直到截止未完成，则是活性超时导致 INVALID，并不代表证明了比赛取消。它们可以产生相同向量，但 reason 和证据应不同，以便用户和审计解释。延期没有给管理员修改 closeAt 的权限；需要交易另一个时间范围的事件，可以创建新市场，但旧市场份额不会自动变成新市场份额。

## 第 8 层：规则清晰是否就保证结果真实可靠

**面试官：** 语义、时间和证据都锁住了，是不是最终结果就一定等于真实赛果？

**面试者：** 仍然不能这么承诺。规则清晰只让“按什么标准判断”可审查；主源可能发布错误，归档可能缺失，K 可能判断错误，错误提报也可能在无人挑战时最终化。工程正确性保证的是合法输入依规则经过唯一状态机并按固定向量执行，不是替代现实事实的可信度。创建准入应把源依赖、修订界限、仲裁权限和无人挑战风险向用户公开。我会用取消、平局、点球胜、02:00 前后更正、主源缺失等成组样本让独立读者得出相同结果；若仍需临时口头解释，就说明规则还不适合上市。

## 本题收束

- **讲透的机制：** 事件身份、数据源优先级、版本界限和异常语义共同定义可裁决权利；哈希绑定与证据可信度是不同问题。
- **最容易答错的边界：** INVALID 不等于 NO，也不等于撤销所有历史成交；readyAt 后提交的证据不意味着可以接受 readyAt 后新发布的事实版本。
- **反例检验：** M1 创建后将规则改为含点球，或把 02:05 更正当作 01:55 原始内容，都会在不改份额的情况下改变权利，必须被识别。
