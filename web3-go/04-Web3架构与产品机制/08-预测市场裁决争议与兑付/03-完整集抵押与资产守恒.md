# 大问题 3：YES／NO 完整集怎样保证兑付资产足额？

<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 完整集 | 同一市场中一对互补的 YES 和 NO 权利。 | 无论合法结果是哪种，一整对合计只兑付 1 C，不是两张各保底 1 C 的债券。 |
| C / 最小单位 | 抵押币／记账所用的最小整数格。 | C 与份额同为六位小数，比较数量时统一尺度，不用浮点数凑守恒。 |
| S / M1 | 市场合约／本例独立市场。 | S 按 M1 分账，不能因共用地址就混用其他市场抵押。 |
| reserve | 还留给该市场权利的抵押额度。 | 只由实收铸造、合并返还和兑付款改变，不含二级成交款与保证金。 |
| totalYES / totalNO | 尚未销毁的两类份额总供应。 | 终局前要求两边总供应和 reserve 相等，不要求 A 自己两边余额相等。 |
| allowance / 实收抵押 | 代币使用许可／实际到账的 C。 | 授权 100 不等于收到 100；必须验实收才可铸造。 |
| 铸造 / 原子性 | 产生份额／相关变化共同提交或回滚。 | 收 C、记 reserve、增两边余额与供应须在同一 EVM 事务完成。 |
| 扣费代币 / rebase | 转账少到账／余额会自动调整的资产。 | 基线排除这些行为，不能收到 99 C 却照样铸 100 对。 |
| 二级成交 | 份额持有人之间的付款与权利交换。 | B 付 A 24 C 买 40 YES，市场仍只有 100 C 抵押。 |
| merge / 完整集合并 | 同一人交回成对份额取回等额抵押。 | 最终化前合并 60 对，同销毁 60 YES 和 60 NO，并返还 60 C。 |
| 兑付向量 / nY / nN / D | 两类兑付分子／共同分母。 | YES 为 `[1,0]/1`、NO 为 `[0,1]/1`、INVALID 为 `[1,1]/2`；分子和等于分母。 |
| `reserve*D >= totalYES*nY + totalNO*nN` | 抵押要覆盖剩余权利的交叉相乘检查。 | 用整数比较有理负债；终局后不再强求两类供应相等。 |
| redeem / burn | 按终局领取／销毁已消费权利。 | A 在 YES 结果下烧 60 YES＋100 NO，支付 60 C，之后只剩 B 的 40 YES。 |
| BondVault / 捐赠 | 独立保证金金库／直接转给合约的额外资产。 | 两者都不能自动增加 M1 reserve 或给捐赠人增发份额。 |
| 尾差 / 向下取整 | 整数兑付留下的小额余额。 | 一个最小单位抵押分属两个单边持有人，INVALID 时可各领零而留下一个单位。 |
| 足额 / 可领取性 | 数量覆盖负债／交易真的能执行并转出。 | 冻结、脱锚或停链不是守恒公式能消除的风险；转账失败须保留原权利。 |

## 把整篇文章压缩成一个故事

**起因：** A 实际向 S 存入 100 C，拿到 100 YES＋100 NO，再把 40 YES 卖给 B 收 24 C。A 自己剩 60 YES＋100 NO 不成对没关系：全市场仍是 100 YES＋100 NO，抵押仍为 100 C；两边互补才是它不会欠 200 C 的原因。

**处理及异常：** 在本文的独立合并变体中，A 于最终化前交回 60 对，S 同事务烧掉两边各 60 份并返还 60 C。此时 A 剩 40 NO、B 有 40 YES，reserve 也剩 40 C。若铸造时只收到 99 C，或者试图拿别的市场抵押补 M1，系统必须拒绝，不能把授权额或合约总钱包余额当成足额凭证。

**结果及边界：** 合并变体若最终为 YES，B 领 40 C；若为 NO，A 领 40 C；INVALID 时两人各领 20 C，均只花剩余 40 C。未合并主例则按原来的 100 C 单独核算，不能混用状态。终局后改查向量负债覆盖，允许舍入尾差但不允许超付；足额不保证 C 不被冻结，领取转账失败时销毁和扣抵押必须一起回滚。

**流程位置与核心机制：** 负责铸造、完整集合并、二级转让和领取之间的资产约束。沿用六位小数 C、同尺度份额、无手续费的主例；不将保证金、交易款或其他市场抵押混入 reserve。

## 第 1 层：锁 100 C 为什么能够铸造两边各 100 份

**面试官：** A 只锁了 100 C，却拿到 100 YES 和 100 NO，怎样证明没有凭空创造 200 C 的兑付义务？

**面试者：** 因为两边不是各自固定兑付 1 C 的独立债权，而是同一个市场的互补权利。YES 结果下每份 YES 兑付 1、NO 兑付 0；NO 结果反过来；INVALID 时两边各 1/2。同一完整集的两份权利合计兑付始终是 1 C，核心不变量是向量分子和等于分母。最终化前 totalYES＝totalNO＝reserve，数量均用最小单位表示。因此 100 C 对应两边各 100 份是足额的。不能脱离互斥结果把两边名义份额相加，再直接当作总付款金额。

## 第 2 层：铸造时怎样证明抵押真的进来了

**面试官：** 你依赖 reserve，那用户只是给了 allowance，你就能先增加 reserve 并铸造吗？

**面试者：** 不行。allowance 只是授权，不是抵押事实。S 要在同一 EVM 事务内收取 C、验证实际入账与请求数量一致、增加该市场 reserve，并增加两类份额余额和供应；任一步失败全部回滚。合约使用安全转账封装，限定 C 的行为，并防止重入绕过状态检查。如果是扣费代币，请求 100 只到账 99，却铸 100 对，就已经形成缺口；本基线明确排除这种资产，不通过悄悄少记 reserve 继续放行。成功事件也只能对应事务最终提交后的实收抵押，不能凭 Go 看到授权事件就认定铸造完成。

## 第 3 层：二级成交怎样改变这条等式

**面试官：** A 卖掉 40 YES 后，A 的两边数量不相等，完整集不变量是不是被破坏了？

**面试者：** 不变量约束市场总供应，不要求每个持有人余额相等。成交后 A 是 60 YES＋100 NO，B 是 40 YES，合计仍是 100 YES＋100 NO，reserve 仍为 100 C。B 的 24 C 直接支付 A，不进入市场铸造入口，也不增加供应。用户可以只持单边市场风险，但所有单边权利组合起来仍由最初完整集抵押覆盖。Go 展示时应区分钱包现金、持仓数量和按不同结果计算的可兑付金额，不能因为单用户不成对就判断系统抵押不足，也不能把二级交易额累加进 reserve。

## 第 4 层：完整集合并会不会提早拿走别人的抵押

**面试官：** A 还有 60 YES 和 100 NO，如果 A 在最终化前合并 60 对取回 60 C，B 的权利还有覆盖吗？

**面试者：** 有。S 同事务销毁 A 的 60 YES 和 60 NO，并从 M1 reserve 返还 60 C。此后 A 持有 40 NO、B 持有 40 YES，总供应两边各 40，reserve 为 40 C；无论 YES、NO 还是 INVALID，都只需要兑付这剩余 40 C。合并要求同一市场、同一持有人拥有足够的两类份额，不是拿 NO 抵消别人的 YES。本模型只允许在最终化前合并，终局后统一走 redeem，避免两个退出入口的计算和状态重复。该变体需从主例单独推演，后续主例不能再沿用 100 C 未合并状态的数量。

## 第 5 层：最终化后两边供应不相等还能怎样核算

**面试官：** YES 胜出后 A 领取，你会把 totalYES、totalNO 和 reserve 仍强行保持相等吗？

**面试者：** 不会。A 领取会销毁 60 YES 和 100 NO，支付 60 C，剩下 totalYES＝40、totalNO＝0、reserve＝40。最终化后的正确约束是 `reserve*D >= totalYES*nY + totalNO*nN`，不是继续要求两边供应相等。这样 B 的 40 YES 有 40 C 覆盖，已被销毁的输方不再计负债。INVALID 存在取整时，reserve 还可能大于剩余有理负债。对账必须按状态选择不变量，否则会把正常领取报警成供应异常，或反过来忽略真正的无抵押增发。

## 第 6 层：共用地址里还有别的市场和保证金怎么办

**面试官：** 如果 M1 少了 1 C，但 S 的钱包里其他市场还有很多 C，用合约总余额对账不就看不出来了吗？

**面试者：** 所以物理余额只是外层约束，我还要逐市场保存 reserve 和累计实收、合并、兑付事实。M1 的领取只能扣 M1 reserve，不能从其他市场的分账额度补洞；每个市场单独验证对应的剩余负债。保证金由独立 BondVault 保管，不计入 S 的抵押，二级成交款也不计。S 收到用户直接转来的捐赠时，物理余额会大于分市场 reserve 合计，但不会自动为某个市场增发份额。检查顺序是先逐市场验证负债覆盖，再核对物理余额足以覆盖分账总额及已知额外余额，而不是看到钱包里有钱就认为全部业务正确。

## 第 7 层：抵押足额为什么仍可能无法领取

**面试官：** 数学上足额是不是就保证用户一定能把 C 提走？

**面试者：** 不完全。足额解决的是负债数量是否被覆盖，不解决抵押资产自身的可转移性和价值。现实 C 可能脱锚，发行方可能冻结 S 或用户地址，链也可能无法包含交易。在本模型里若转账失败，整次 redeem 回滚，份额和 reserve 不变；不能把用户标成已领取，也不能把失败的兑付当成尾差扫走。产品应披露抵押币和链的依赖，监控转账失败原因。改用另一种资产、跨链退出或保险补偿都是新增规则与资金来源，不能在追问中直接把原抵押替换掉来声称原保证仍然成立。

## 第 8 层：怎样用少量反例验证完整集机制

**面试官：** 如果只做静态推演，你会选哪些边界来检验刚才的守恒关系？

**面试者：** 我会先验 100 C 铸造两边各 100，再验卖出 40 YES 后供应和 reserve 不变，然后独立验合并 60 对后两边各 40、reserve 40。终局分别代入 YES、NO、INVALID，检查累计兑付不超过原抵押扣除合并额。还要加入一个最小单位的 INVALID：两边分属不同人，各自向下取整为零，说明足额不等于无尾差。最后用“实际到账 99 却铸 100 对”“M1 超额领取但从 M2 补上”作为必须拒绝的负例。每个检查都在同一规范块状态上计算，不能拿旧供应和新 reserve 拼出假的缺口或覆盖。

## 本题收束

- **讲透的机制：** 完整集的互补向量、实收后铸造、成对销毁返还，以及终局前后不同的偿付不变量。
- **最容易答错的边界：** 单个用户不成对是正常持仓；总供应成对才是终局前约束。抵押币数量足额不等于资产价格、可转移性和链活性无风险。
- **反例检验：** 用户实际只转入 99 C，却凭 100 C 授权记录铸造两边各 100，已在进入争议阶段之前形成无法靠正确裁决修复的缺口。
