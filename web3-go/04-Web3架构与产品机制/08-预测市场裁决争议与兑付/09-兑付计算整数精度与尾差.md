# 大问题 9：兑付怎样计算，整数精度与尾差怎样处理？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| C / micro C | 抵押币／其百万分之一单位。 | `1 C=1_000_000 micro C`，链上输入输出均为最小单位整数，展示时才格式化。 |
| micro YES / micro NO | 百万分之一份对应方向的权利。 | 与 C 最小单位同尺度，不是每算一步都再乘除百万。 |
| qY / qN | 当前持有人两类份额余额。 | 一次读取本人全部余额，按当前权利算，不查买入花过多少钱。 |
| nY / nN / D | 两类兑付分子／共同正分母。 | 只允许 YES `[1,0]/1`、NO `[0,1]/1`、INVALID `[1,1]/2`。 |
| floor / pay | 向下取整／本次实际应付的最小单位数。 | 对 `(qY*nY+qN*nN)/D` 先共同求和再取整，不逐类先舍掉余数。 |
| INVALID | 用半份比例异常结案，不是撤销买卖。 | 主例 A 领 80 C、B 领 20 C，B 的 24 C 成本不变成保底。 |
| 同地址聚合 | 同一个人的两类权利共用一次整数除法。 | `1 micro YES＋1 micro NO` 可合领 1 micro C，不跨不同用户拼余数。 |
| 尾差 / reserve | 舍入后留存的额／市场剩余抵押分账。 | U、V 分持一边最小单位时可各领零，最后留下 1 micro C。 |
| L / totalYES / totalNO | 剩余有理负债／两类未销毁供应。 | `L=(totalYES*nY+totalNO*nN)/D`；用 `reserve*D` 与分子精确比较。 |
| 未领负债 / 全领取后尾差 | 还有人能领的权利／供应全清零后的舍入留存。 | 尚有份额不能把全部 reserve 称为尾差，也不能把捐赠混入分账。 |
| sweep / 最后一人拿余款 | 管理员扫款／把剩余全部奖励给末位领取者。 | 基线都不提供；添加这些入口会改变原权利和领取顺序激励。 |
| math/big.Int / 深拷贝 | Go 大整数／独立复制数值对象。 | 方法会改接收者，共享指针会污染余额或并发复算，宽度足够不代表用法正确。 |
| float64 / Quo | 浮点类型／大整数截断除法。 | 金额不先过浮点；仅在已验证非负和正分母后，Quo 才等价于 floor。 |
| uint256 / U | 256 位无符号整数／其最大值 `2^256-1`。 | qY、qN 各合法，INVALID 的和仍可能需 257 位，不能先溢出再除二。 |
| `/` / `%` / 余数进位 | 整数商／余数／两个半单位合成整单位。 | INVALID 安全重排为 `qY/2+qN/2+((qY%2+qN%2)/2)`，保留共同取整。 |
| 规范块 / 成功消费 | 绑定同一有效块哈希的数据／真正提交的销毁与付款。 | 失败回滚不累计兑付或尾差；重组和索引差不能用调整尾差掩盖。 |

## 把整篇文章压缩成一个故事

**起因：** A 存 100 C 并把 40 YES 以 24 C 卖给 B 后，A 有 60 YES＋100 NO，B 有 40 YES。独立 INVALID 变体采用 `[1,1]/2`：按最小单位计算，A 得 `(60_000_000＋100_000_000)/2＝80_000_000 micro C`，B 得 `40_000_000/2＝20_000_000 micro C`，不是退 B 原成本。

**处理及异常：** 为看清舍入，本文另起一个只有 1 micro C 抵押的最小变体。同一 U 持有 1 micro YES＋1 micro NO 时，先加再除得 1 micro C；若截止前拆成 U 只持 YES、V 只持 NO，两人分别 `floor(1/2)＝0`，主动销毁后仍留 1 micro C。Go 必须复现这个地址内聚合规则；合约还要防大数相加溢出，不能用逐类舍入或浮点捷径偷换算法。

**结果及边界：** 主例 INVALID 的 80＋20＝100 C 守恒，最小变体却证明“不超付”不等于“保证无尾差”。只在两边供应都清零并核对流水后，才能把该市场剩余 reserve 认作全领取后尾差；有人未领时仍是负债覆盖。失败转账不能记已付或新增尾差，尾差也没有管理员扫走或跨市场补洞的权限，这套聚合算法不能冒充所有外部协议的通用标准。

**流程位置与核心机制：** 在 S 已固定终局向量之后，把当前持有人的两类余额确定地换算成 C 最小单位，解释聚合取整、整数范围、Go 复算与尾差对账。本题不重建裁决流程，也不为每次领取另设工程或 MVP。

**必要前提：** C、YES、NO 均为六位小数，`1 C=1_000_000 micro C`；`1 micro YES` 与 `1 micro NO` 各表示百万分之一份。锁定 1 C 足额铸造 1 YES＋1 NO。S 仅允许 YES `[1,0]/1`、NO `[0,1]/1`、INVALID `[1,1]/2`，不支持任意有理向量。

**固定算法：** 当前持有人一次销毁该市场全部两类余额，`pay=floor((qY*nY+qN*nN)/D)`；先加权求和，再共同向下取整。截止后份额不能转让、终局后不能重新 mint。尾差留在市场 reserve，不到期没收，不设置管理员扫走接口。

**贯穿案例：** A 抵押 100 C 得到 100 YES＋100 NO，卖给 B 40 YES、收 24 C。A 持 60 YES＋100 NO，B 持 40 YES，市场 reserve 为 100 C；YES 下兑付 60／40 C，INVALID 独立变体为 80／20 C。

## 第 1 层：输入输出的单位和计算顺序怎样固定？

**面试官：** 如果用户余额有小数，兑付公式怎样写，才能避免前后端算出不同金额？

**面试者：** S 中 `qY、qN、reserve、pay` 都用最小单位非负整数，不用浮点数。向量分子、分母是无量纲比例；先算 `qY*nY+qN*nN`，最后除以正整数 D 向下取整，结果已经是 micro C，不能再乘或除一遍百万。只有展示层才把整数格式化为六位小数。

例如 60 YES 保存为 `60_000_000`，YES 向量下得到 `60_000_000 micro C`，即 60 C。Go 接口接收十进制字符串并按六位拆解，超精度、负数和越界直接拒绝，不能先转 float64 再截断。

真正执行前还要检查 Finalized、向量白名单和非零份额；预估结果不能替代链上计算。若事务回滚，不能把本次算出的金额提前记成已付，付款与余额消费以 S 成功执行的结果为准。

## 第 2 层：为什么兑付看余额而不看买入成本？

**面试官：** 你说按当前余额计算，那 B 花了 24 C 买 40 YES，INVALID 时为什么不是退 24 C？

**面试者：** 因为二级成交把已有兑付权从 A 转给 B，24 C 是 B 付给 A 的交易款，不是 S 新收的抵押。截止冻结后，A 的 `qY=60_000_000、qN=100_000_000`，B 的 `qY=40_000_000、qN=0`；S 的 reserve 仍是 `100_000_000`，领取不查询订单成本。

YES 下 A、B 分别得到 60 C、40 C；NO 独立变体中 A 得 100 C，B 的 YES 可销毁但兑付为零；INVALID 下 A 的两类余额先相加除二得 80 C，B 得 20 C。INVALID 不是买卖撤销，B 的损益因此为负 4 C。

BondVault 的保证金返还也不改变这些金额。提报者或挑战者按争议规则取得信用，即便某地址同时持仓，也必须分开计算、分开提款，不能把保证金计入 B 的份额赔付公式。

## 第 3 层：为什么必须先合并两类加权余额再取整？

**面试官：** 你对 A 把 YES 和 NO 一起除二，逐类先取整再相加不是更简单吗？

**面试者：** 两者在最小单位边界会不同。一个地址持有 `1 micro YES＋1 micro NO` 时，INVALID 下本模型得到 `floor((1+1)/2)=1 micro C`；若分别取整，则 `floor(1/2)+floor(1/2)=0`。丢掉的两个半单位本来能在同一领取中合成一个可转账单位。

所以 S 的接口读取该地址全部两类余额，聚合后计算一次，再同事务销毁两边；Go 不能为了并行而先算两个整数 pay 再求和。计算拆分方式是兑付规则的一部分，不是无关紧要的性能优化。

有的外部份额协议按单槽或每个 index set 分别计算并截断，即使一次调用传入多个槽，也未必共享余数。这类协议必须按其版本实现复算，不能把本模型的聚合算法说成 Conditional Tokens 通用规范；对接时差异未核实就必须停止承诺金额。

## 第 4 层：奇数最小单位怎样产生真实尾差？

**面试官：** 同地址聚合能救回两个半单位，那么完整集总是成对发行，是否就不会再有尾差？

**面试者：** 不会。独立最小单位变体是：锁定 `1 micro C`，铸造 `1 micro YES＋1 micro NO`，在截止前让 U 只持 `1 micro YES`、V 只持 `1 micro NO`。INVALID 后 U 计算 `floor(1/2)=0`，V 也得到零；两人各自主动销毁后，供应清零，reserve 仍残留 `1 micro C`。

它与上一层不矛盾：聚合仅覆盖一个当前地址的两类余额，不跨用户合并分子，也不允许系统把别人的半单位任意配给某人。若两类最小单位原本都归 U，才会一次领到 1 micro C。

零付款不等于没有有效领取，S 应允许销毁非零输方或截断为零的份额，必要时跳过零额 ERC-20 调用。截止后不能再转份额来拼整，也不能销毁后重新 mint，因此不能承诺用户事后总有办法把尾差取回。

## 第 5 层：尾差留存怎样证明不会变成超付或挪用？

**面试官：** 两个用户都领零而池子有余额，怎样界定尾差，而不是让管理员把未领资产也当尾差？

**面试者：** 先用固定向量算剩余有理负债 `L=(totalYES*nY+totalNO*nN)/D`，要求 `reserve*D` 不小于分子。每次领取从负债移除精确权利值，却只支付其向下取整值，所以不会降低偿付覆盖；每人的舍弃部分严格小于 1 micro C，但多人累积可以明显，最小单位反例甚至留下全部抵押。

还有份额未销毁时，reserve 同时覆盖未领权利和已产生舍入差，不能整体标注为可分配尾差。只有确认两边供应清零，再按同一块的资金流水核算，才可把剩余记成全领取后的尾差；直接捐入合约的 C 也不能混入市场 reserve。

基线没有尾差领取、截止没收或管理员 sweep 接口，所以它仍留在该市场分账里。新增“最后一人拿余款”会改变收益与领取顺序激励，不是对原规则的小修补，也不能拿尾差补保证金或其他市场亏空。

## 第 6 层：Go 的大整数复算还有什么陷阱？

**面试官：** 你要求精确核对有理负债，Go 用 math/big 就一定不会算错或污染状态吗？

**面试者：** `math/big.Int` 解决数值宽度，不解决可变对象别名。运算写入接收者，若把 qY 同时作为乘法结果，会覆盖原余额；把同一个 `*big.Int` 填入多个账户，后续修改还会污染别的记录。复算应给输入做 `new(big.Int).Set(source)` 深拷贝，为乘积、加权和、商分别准备独立接收者；并发 worker 不共享可写实例。

输入必须先验证十进制整数格式、非负、份额与 reserve 的 uint256 上限，以及三种向量白名单。因为所有分子非负，使用整数 `Quo` 截断才等价于向下取整；不能依靠它纠正非法负余额，也不能让 D 为零。

Go 可用任意精度保留 `reserve*D` 与理论负债分子，不提前取整再比较。数据库持久化用精确十进制字符串或足够范围的整数列，禁止 `Int64／Uint64` 截断；输入和输出审计记录应绑定同一块哈希，避免算术正确却复算了不同状态。

## 第 7 层：uint256 的范围和中间值溢出怎样处理？

**面试官：** Go 可以扩宽，但合约只有 uint256；qY、qN 都合法，求和是否仍可能溢出？

**面试者：** 可以。令 `U=2^256-1`，单个余额、供应和 reserve 都限定在 `[0,U]`，但 INVALID 的 `qY+qN` 最大可到 `2U`，需要 257 位。不能以“最终 pay 不超过 reserve”为理由先做会溢出的加法；`mulDiv` 若接到的参数已经是溢出的和，也救不回来。`reserve*2` 的负债比较同样要扩宽。

对本模型只有 0／1 分子和 1／2 分母的范围，可精确使用 `qY/2+qN/2+((qY%2+qN%2)/2)` 算 INVALID。前两项之和至多 `U-1`，最后进位至多 1，所以最终至多 U；YES、NO 则直接取对应余额。此重排保留共同取整，绝不是逐类取整后丢掉余数。

铸造入账、供应和 reserve 的累加仍须检查溢出，不能循环回零；比较用扩宽整数或经证明等价的安全表达式。上述范围证明仅适用于白名单向量，若改成任意 uint256 分子与分母，就需要重新论证完整精度乘加除，不能照搬结论。

## 第 8 层：怎样同时核对金额、尾差和失败边界？

**面试官：** 你给了等价算法，怎样验证它没有改变聚合规则，也没把失败领取计入尾差？

**面试者：** 我会先用大整数公式作参考，在相同规范块和向量上比较链上结果。覆盖主例 YES 的 60／40 C、INVALID 的 80／20 C，以及同地址 `1Y＋1N` 最小单位领 1、跨两地址各领零的成对反例；再检查最大 uint256 附近的奇偶组合，确认安全重排保留进位且不会回绕。这些是手工校验条件，不声称已经执行工程测试。

对每次成功领取核对 `qY、qN、pay`、销毁量、供应和 reserve 变化。转 C 失败必须全回滚，不能累计兑付款或舍入差；成功的零付款则要消费份额，重复领取应因余额全零被拒绝，不能再增加尾差记录。

最后以实收铸造减合并返还减规范链成功兑付核对 reserve，另列剩余有理负债与已形成舍入差。索引落后或重组先恢复规范状态，不通过“调整尾差”消除账差；保证金账本、直接捐赠及二级成交款始终不进入这个公式。

## 本题收束

**讲透的机制：** 同尺度最小单位、固定白名单向量、同一持有人两类余额先加权再共同向下取整，构成可确定复算的金额规则。向下取整保证不超付，不保证全部抵押必然流出；尾差必须连同剩余权利、供应和规范流水解释。

**易错边界：** 不能按成本退款，不能把 INVALID 当可交易第三份额，不能把聚合计算冒充外部单槽协议规范。math/big 仍有接收者修改、指针别名和并发问题；uint256 的输入合法不代表中间求和合法，范围证明不能扩展到未支持的任意向量。

**反例检验：** 1 micro C 完整集拆给 U、V，各持 1 micro 的相反份额，INVALID 时两人各取 0，销毁后残 1 micro C；若同一地址持有这两份，则可取 1 micro C。任何把这两种结果算成相同、或允许管理员把未领 reserve 一并扫走的方案，都已经偏离本题基线。
