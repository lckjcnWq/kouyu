## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| V / EVM / 现货订单簿 | V 是金库，EVM 是合约执行环境，订单簿组织买卖报价。 | 先充值、按订单锁资、链下撮合，再在单链金库内交割，不是钱包直接拉款。 |
| A / B / WETH / USDC | A 买、B 卖，WETH 是基础资产，USDC 是报价资产。 | A 充值 5,000 USDC，B 充值 2 WETH；中继 Gas 另计。 |
| lockOrder / 最终锁资 | 把金库可用权利转成订单专属占用，并等待链最终确定。 | A 锁 2,012.01 USDC，B 锁 1 WETH；签名或广播成功不等于可撮合。 |
| maker / T1 / 成交义务 | maker 是先到挂单方；T1 是日志确定的这笔成交承诺。 | 本轮预算 0.4 WETH 后暂停，按 B 的 2,000 成交；800 货款加 0.8 买方费用不会随重试改变。 |
| Q / open / pending / settled / cancelled / defaulted | 总量与未成交、待交割、已交割、取消、违约五种去向。 | Q 等于五项之和；pending 可以等链，但不能用撤单删掉。 |
| COMMITTED / INCLUDED / SETTLED_FINAL | 可靠成交提交、某块内执行、最终交割三个阶段。 | 第一步能说成交，最后一步才能据最终证据核销待交割义务。 |
| orderHash / tradeId / payloadHash / planHash | 订单摘要、成交身份、成交载荷摘要和计划摘要。 | 各管不同对象；换批、重启或加速不能把 T1 变成新经济义务。 |
| fillSeq / nextFillSeq | 每订单成交序号及合约期待的下一序号。 | T1 双方均为 1，共享订单的后笔不能绕过前驱。 |
| txNonce / txHash / attempt | 发送序号、签名交易哈希和一次执行尝试。 | 一笔义务能有多个尝试，尝试失败不等于成交消失。 |
| executed / 幂等 / 原子交割 | 执行记录、重复不增效果、相关资产共同更新。 | 同身份同载荷不再扣款，冲突载荷拒绝；双方余额、费用和序号同事务变化。 |
| receipt.status / RPC / UNKNOWN | 回执执行结果、节点接口和结果未知。 | status=1 还非最终，status=0 不删义务，超时或 null 不能当失败释放资金。 |
| blockHash / logIndex / canonical / finalized | 区块身份、日志位置、规范链和最终性。 | 成功证据要带分支并查完整前缀，不能只看 txHash 或固定确认数。 |
| projection / revision / 水位 | 查询投影、对外修订号和处理截止点。 | 重组撤回旧观察并发新修订，不能因已见过 tradeId 就吞掉修订。 |
| Outbox / ACID | 持久待发记录及本地事务属性。 | 成交和交付事实一起耐久，但不存在数据库、消息与 EVM 的全局一次提交。 |
| D / closeLock / expireUnlock | 截止时间、正常关锁、到期解锁。 | fill 允许时间等于 D；到期解锁要求大于 D；撤余量不能立即释放锁资。 |
| DEFAULTED_UNSETTLED / EXPIRED | 已成交未交割的违约状态，以及未成交余量的过期取消原因。 | 最终查全历史后分别归类，不能把违约数量说成未成交取消。 |

## 把整篇文章压缩成一个故事

A 拿 5,000 USDC、B 拿 2 WETH 充值金库，分别签下买 1 WETH、限价 2,010 和卖 1 WETH、限价 2,000 的订单。金库最终锁住 A 的 2,012.01 USDC 和 B 的 1 WETH 后，订单才进入撮合。本轮只撮合 0.4 WETH 并暂停新增撮合，先到的 B 给出成交价 2,000；可靠日志提交 T1，双方未成交量降到 0.6，待交割量升到 0.4。页面此时能说“已成交、待结算”，不能说买到的币已经可提现。

结算服务持久保存原条款，交给受限出口广播。V 在一个事务内扣 A 锁资 800.8 USDC、B 锁资 0.4 WETH，给 A 可用 0.4 WETH、B 可用 800 USDC和费用账户 0.8 USDC。重复投递同一 T1 不再扣款；接口超时只恢复原尝试，失败回执也不删除成交。观察器即使看见入块成功，仍须查目标执行覆盖、规范分支和最终性；若重组，就撤回观察，而不是重新撮合或凭数据库补币。

等最终证据经同一撮合日志把 pending 核销后，双方才撤掉 0.6 余量，并等 closeLock 最终释放锁资。A 得到可用 4,199.2 USDC、0.4 WETH，B 得到 800 USDC、1.6 WETH，费用账户 0.8 USDC；币仍在金库。若异常拖过 D，则查全最终截止前历史，已履约与违约二选一，未成交余量另按过期取消。能保证局部原子、义务耐久和证据化退出，不意味着无条件交割，也不意味着合约能证明撮合顺序公平。

## 第 1 层：从充值讲到余量关闭，哪些步骤才构成完整交易

**面试官：** 一笔链下成交怎样走到链上结算完成？请用 T1 从用户资金准备开始讲，不要从撮合服务接到订单就直接跳到“上链成功”。

**面试者：** 我会先区分资金准备、成交确定和资产交割，再顺着一笔业务讲。A 向 V 充值 5,000 USDC，B 充值 2 WETH；充值要在最终规范链上成立。A 签买入 1 WETH、限价 2,010 的订单，B 签卖出 1 WETH、限价 2,000 的订单。接入检查签名、资产、数量价格网格、费率和截止时间，再由授权中继提交 `lockOrder`。V 验签并建立专属锁资：A 锁 2,012.01 USDC，B 锁 1 WETH。签名和广播都不算锁资完成，必须等建锁最终确定后才进入链下准入与排序。

主例采用教学单轮基础量预算 0.4 WETH，按价格时间顺序匹配该量后，暂停该交易对新增撮合，结算与撤余量继续，关闭前不恢复；否则双方各 1 WETH 的交叉限价单会继续成交，不能自然剩下 0.6。B 是先到的 maker，撮合日志按规则确定 T1：0.4 WETH，价格 2,000，名义金额 800 USDC，买方费用 0.8 USDC。一次可靠提交使双方 `open` 从 1 变成 0.6、`pending` 从 0 变成 0.4，并固定成交身份和双方 `fillSeq=1`。这一刻可以回报“已成交、待结算”，但不能说 A 已取得可用的 0.4 WETH。

随后结算服务读取义务、固定计划、按订单依赖组批，经过 nonce 管理和受限签名出口广播。V 在同一事务内扣 A 锁资 800.8 USDC、扣 B 锁资 0.4 WETH，同时增加 A 可用 0.4 WETH、B 可用 800 USDC、费用账户 0.8 USDC。观察器确认目标执行证据、规范链和最终性后，把最终证据作为带稳定身份的命令交回撮合状态所有者，经同一日志裁决才把 T1 核销为 `SETTLED_FINAL`、把 `pending` 转为 `settled`。主例再撤销双方剩余 0.6，等正常关闭条件满足、`closeLock` 最终完成后释放剩余锁资。这才讲完本例的订单与资金处理；提到外部钱包仍是独立提现流程。

## 第 2 层：既有成交日志又有链状态，谁有权宣布哪一种完成

**面试官：** 你刚才把“日志提交”“金库交割”“最终观察”分成三个时刻。如果页面已经显示成交，而链上余额还没变，谁是权威？是不是出现了两个互相矛盾的真相？

**面试者：** 不是同一个事实有两个权威，而是不同事实分别归属不同边界。撮合复制日志拥有订单接纳顺序、匹配关系、成交条款和撤单裁决；V 拥有可用余额、每订单锁资、执行标记、累计交割量和锁终态。观察器把规范链事实投影到业务系统，它不能自行制造资产，也不能反过来删除日志已经确认的成交。页面只是这些事实的展示，不具有裁决权。

因此订单要同时表达数量分类与链上进度。链下用 `Q = open + pending + settled + cancelled + defaulted`；成交用 `tradeId`、双方订单摘要、数量、价格、费用版本和状态；链上锁对象用 `orderHash`、`filledBase`、`remainingLocked`、`nextFillSeq` 和 `status`。T1 提交后 `pending=0.4`、金库资产尚未变化，是允许的暂态；若页面把这个状态直接写成“资产可提现”，才越过了权威边界。

查询结果还要带撮合日志位置、依据区块和最终水位。链上累计量已经变化而本地仍 pending，可能只是观察落后；比较不同水位不能据此判定资产丢失。关键约束是：每一条完成回报必须说明它依据哪一种事实，不能用一个没有阶段含义的 `success=true` 贯穿全流程。

## 第 3 层：成交权威怎样落实为不会丢失的提交边界

**面试官：** 你说撮合日志有权确定 T1。假如服务已经返回“成交”，却在写入结算任务前崩溃，T1 会不会只剩页面上的一行记录？具体要把什么放在同一个提交里？

**面试者：** 在这个模型中，“成交已提交”必须以约定复制确认的日志位置为边界，不能以进程内撮合函数返回或单机缓存更新为边界。对于 T1，同一原子提交必须共同确定 A、B 的 `open -= 0.4`、`pending += 0.4`，保存完整经济条款、双方序号和成交身份，并保存可恢复的交付事实。可以由同一结果日志确定性派生交付，也可以在对应本地事务中保存 Outbox，但不能先承诺成交，再指望一个易失 goroutine 补发。

T1 的身份按总览使用 `tradeId=H(venueId,logPartition,commitSeq,matchIndex)`，日志位置不能被新结果复用。数量、价格、maker、双方 `orderHash/fillSeq`、固定费率版本都跟该身份绑定；提交之后，后续模块没有重新撮合或重新定价的权限。回复丢失时按原请求身份查提交结果，不能因为调用方没收到回复就产生另一个 T1。

提交前崩溃且没有达到可靠边界，系统不能把内存候选结果当成交；提交后崩溃，则从日志和交付记录恢复原义务。计划服务也要在自己的本地事务中共同完成消费去重、义务与计划绑定及 Outbox。这里有多个局部可靠边界，但没有“撮合数据库、消息系统、签名设备和 EVM 一次全提交”的全局 ACID。

## 第 4 层：交付可以重复，为什么经济效果不能跟着重复

**面试官：** 你用可恢复交付消除了“忘发”，但重启后可能重发；广播加速又会换 txHash。怎样保证这些新尝试仍然只履行一次原来的 T1？

**面试者：** 要把成交身份、结算计划身份、交易尝试身份和观察身份分开。`tradeId` 标识经济义务；`payloadHash` 绑定这笔义务的完整结算载荷；`planHash` 绑定具体计划、规则版本和依赖；`sender + txNonce` 标识发送顺序位置，`txHash` 只标识一次签名交易。加速、重新交付或者安全重组批次不能因此生成一份新成交，也不能把 800 USDC 改成另一个价格。

链下消费去重只能保护本地处理，最终还要在资产执行处防重复。V 先要求当前授权结算出口，再检查 `executed[tradeId]`：相同身份与相同载荷不再次改变状态，不同载荷必须拒绝。重复判断在新 fill 的序号检查之前，否则成功过的 T1 重放时，双方 `nextFillSeq` 已经变成 2，会被误判为一次序号错误。对于真正的新 fill，仍要检查双方下一序号、累计量、限价、期限与锁资。

T1 的执行标记、双方累计量、序号、锁资、可用与费用在同一个 EVM 事务内变化；不能先写去重标记再异步扣款，也不能先扣买方再等待另一笔事务给卖方入账。结算过程中只改变 V 内部权利，不调用任意 token 向外转账。共享订单的跨批后继须等前驱最终交割；未最终的前驱和后继只能同批有序执行或先等待。这样重复投递只增加尝试或观察证据，不增加经济效果，但还没有回答该效果何时可称最终。

## 第 5 层：receipt 成功为什么仍不足以完成结算

**面试官：** 既然执行标记和双方余额在同一个 EVM 事务内改变了，看到 `receipt.status=1` 为什么还不能立即把 pending 转成 settled？

**面试者：** 因为 EVM 事务内原子性只解释“这个块里的调用怎样共同成功”，不解释“这个块会不会离开规范链”。`status=1` 后还要核验目标 V、载荷及完整批次覆盖：新执行项核对本次目标事件，幂等返回的重复项引用既有执行证据，不能强求无状态变化的重复项再次发出新交割事件。先标记 `INCLUDED`。观察证据至少带 `chainId、blockHash、parentHash、number、txHash、logIndex`，不能只存 txHash 和一个成功布尔值。

观察器以完整区块为本地提交边界，把该块日志、可撤销投影、进度和相应 Outbox 一起保存；不能先推进游标，再异步补余额事件。随后核验规范祖先关系和完整前缀，按本链最终性策略推进最终水位。只有 T1 所在规范块满足最终条件，观察器才把带稳定身份、tradeId、载荷依据和最终水位的证据命令交回撮合状态所有者；所有者去重并经同一日志裁决双方 `pending -= 0.4、settled += 0.4`，再可靠发布最终结算回报。观察线程不能绕过这一序列并发改订单，重复交付同一证据也不能再次减 pending。

如果未最终块被重组掉，要撤销对应观察层变化，T1 回到待观察或待重新提交，而不是删掉原成交。对外使用同一 `tradeId` 加新的 `revision` 发布修订，不能因普通消费者已经见过这个 tradeId 就吞掉撤销或恢复通知。T1 暂时入块时看到的 A 锁资 1,211.21 USDC、B 锁资 0.6 WETH，是可撤销观察；最终交割后才成为最终投影。因此“事务成功”和“业务终局”必须分开回答。

## 第 6 层：不能确认或确认失败时，为什么不能撤销成交

**面试官：** 你说重组后仍保留 T1。那 RPC 超时、交易 revert，甚至拖过签名截止时间 D，是否都只能一直等待？什么情况下能结束这笔 pending？

**面试者：** 先区分尝试失败、结果未知与最终排除履约。广播超时或查无 receipt 只能说明这次查询不知道结果；旧签名交易可能仍会生效，所以保留原义务、锁资和交易尝试链，按原身份继续查验或恢复。`status=0` 则说明该次调用的金库状态变更整体回滚，但中继 nonce 和 Gas 不会因此回滚，T1 仍是已经提交的经济义务。attempt 的失败不能覆盖 obligation 的身份和条款。

也不能无限期承诺一定履约。主例双方同一 D，V 只允许 `block.timestamp <= D` 的 fill；不同 D 是明确的变体，执行必须满足双方期限，锁资分别按各自 D 退出。最终规范前缀越过相关截止边界并完整核验历史后，才可区分“截止前已经交割但本地没看到”和“确实未交割且未来已不可能通过原 fill 履约”。这依赖总览限定的规范后继时间戳严格递增与可查询最终性。最终证据仍交回撮合所有者，经同一日志裁决前者为 `SETTLED_FINAL`，后者为 `DEFAULTED_UNSETTLED`、相应 pending 转为 defaulted；两种终态不能同时成立。

若到期仍有未成交 open，也由同一日志的过期裁决转入 cancelled，记录 `reason=EXPIRED`；不能混入 defaulted，更不能把已成交 pending 一并取消。到期后可触发 `expireUnlock` 返还剩余锁资，但返还不等于 T1 已履行，更不等于 T1 从未成交。历史义务与违约证据必须保留。单凭本地时钟超过 D、一次失败 receipt 或运维改表，都不能跳过最终规范历史的核验。这套基线提供有条件的履行通道和证据化退出，不是无条件交割保证。

## 第 7 层：正常撤余量与违约退出怎样保持资金口径不混淆

**面试官：** 既然到期解锁不是履约，那回到正常主例：T1 最终交割后，用户撤掉 0.6 WETH 余量，什么时候才能释放资金？能否按撤单成功立即给 A 增加可用 USDC？

**面试者：** 不能。撤单成功首先是撮合日志对 open 的裁决，正常 `closeLock` 才是 V 释放剩余锁资的动作。主例在 T1 最终交割后，双方 `open=0.6、pending=0、settled=0.4`；撤单把 0.6 从 open 转入 cancelled，金库此刻还保留 A 的 1,211.21 USDC 和 B 的 0.6 WETH 锁资。模型不提前释放部分撤单量，也不提前返还价格改善和费用余量。

授权出口要确认该订单无 open、全部已提交成交最终交割、最终观察水位对齐，才生成 `closeLock(orderHash,expectedFilledBase)`。V 检查当前角色、锁状态和预期累计成交量并关闭锁；关闭成为终态，同摘要不能重新建锁。但 `expectedFilledBase=0.4` 本身不能证明链下没有另一笔尚未提交到链上的义务，所以这是明确的受信出口边界，不能说合约自动证明了整个日志已清空。

观察最终关闭结果后，A 的 USDC 可用才变成 `2,987.99 + 1,211.21 = 4,199.2`，B 的 WETH 可用变成 `1 + 0.6 = 1.6`；A 另有 0.4 WETH，B 另有 800 USDC，费用账户 0.8 USDC。关闭广播超时仍不得提前加可用。若 T1 尚 pending 就发生到期退出，应走上一层的违约核验，而不是套用这条正常关闭流程。

## 第 8 层：局部约束都成立后，系统仍然没有保证什么

**面试官：** 你刚才承认 closeLock 依赖授权出口正确理解链下日志。把这些边界合起来，这个方案到底保证什么、还信任什么，怎样检查自己没有把“最终一致”说成万能承诺？

**面试者：** 我会把保证限定为三件事：可靠日志使已提交成交具有耐久且不可因结算失败删除的身份；V 在用户授权、锁资、数量、序号和期限约束内执行双边原子交割并阻止重复经济效果；观察与退出协议用规范链证据区分最终履约和最终未履约。它允许有依据、可恢复的暂态，但禁止用暂态资金承担第二份义务。

仍然信任撮合方正确确定匹配与价格时间顺序，也信任授权出口不提前关闭含未决义务的锁。合约能检查双方限价、声明 maker 属于双方且执行价等于该 maker 限价，却不能独立证明它确实先到；它能检查授权角色和成交载荷，却不能仅凭一个 tradeId 判断哪份日志合法。预存锁资减少钱包余额变化带来的失败，并没有消除链停顿、出口失效、截止时间和恶意运维造成的违约可能。若要无条件保障交割，必须改变到期退出或承诺登记、抵押和信用兜底条件，不能只增加一句“最终一致”。

静态检验时，我会沿同一 T1 同时核对数量分类、逐资产守恒、身份不变和证据水位：重复回报不能再入账，未最终 receipt 不能触发释放，撤单不能吞掉 pending，过期也不能抹去义务。正常闭环应有 `4,199.2 + 800 + 0.8 = 5,000 USDC`、`0.4 + 1.6 = 2 WETH`，且双方 `Q=0.4 settled+0.6 cancelled`。这是机制推演的预期，不是工程测试或安全审计结果。

## 本题收束

- **机制：** 用“签名约束—最终锁资—可靠成交提交—不可变计划—链上原子执行—规范链最终观察—余量关闭”串起完整业务；各阶段各有权威，不存在跨数据库和 EVM 的隐含全局事务。
- **边界：** 成交、交割、最终结算、锁资关闭与提现分别成立。COMMITTED 是不可因结算失败删除的经济义务，不是无条件的链上履约保证；正常关闭不能替代到期违约退出。
- **验证：** 从 T1 提交后广播超时这一检查点独立推演：旧交易迟到成功时不能重复交割，也不能因提前释放而支持第二笔占资；若原交易始终未履行且最终跨过 D，则保留违约事实。再按总览核对正常路径的数量与资金守恒，不将这种静态核对称为工程测试。
