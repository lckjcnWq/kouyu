## 目标与范围

面向懂一些后端开发、但尚不熟悉 DEX、链上授权、交易确认、事件索引和预测市场业务的读者，为本目录下全部 **118 个现有 Markdown 文件（110 篇正文 + 8 篇专题 README）** 添加前置导读。本文是执行清单，不属于待添加导读的业务文章。

每个文件在原有一级标题之后、原正文之前增加：

1. **先看懂：关键词大白话解释**：用表格解释本文的业务名词、英文缩写、公式符号及关键工程概念，说明在本文中的具体含义。
2. **把整篇文章压缩成一个故事**：沿一个具体人物或系统事件串起起因、处理过程、结果和不能理解错的边界。

## 编写与验收标准

- 保留原有标题、正文、链接、公式和问答，不借导读改变原文规则；使用 `<!-- 大白话导读开始 -->` 与 `<!-- 大白话导读结束 -->` 标记新增范围。
- 各篇导读独立可读，不用“同上”代替解释；词表按本文内容选择，不机械复制通用名词。故事沿用本文案例，不另造一套互相冲突的产品假设。
- 采用费曼式解释、单一具体案例与反例检查：先讲用户要完成什么业务，再讲后端和合约怎样保证业务成立；通俗比喻须说明边界。
- 区分状态权威、执行权限与观察来源；Go 数据库和 RPC 返回值不能创造或改写链上资产。
- 区分报价、模拟、签名、广播、包含、业务语义核验、最终性和页面同步，不用一个“成功”替代全部阶段。
- 区分签名授权、代币 allowance 与真实锁资；普通 approve 不随随后独立 Swap 的失败一起回滚。非托管不等于没有治理、代码和依赖风险。
- 区分价格影响、相对报价的滑点容忍与总经济成本；minOut、deadline 和私有广播不保证公允价格、公平排序、及时成交或零 MEV。
- 拆单与多跳计算须按实际执行顺序更新共享流动性；费用比较采用相同币种与口径，金额以明确精度和整数舍入为准。
- 区分业务意图、订单 nonce、交易 nonce、交易 hash 与分支内观察；超时和查无结果不等于确定失败，不能无条件用新 nonce 重做经济动作。
- 区分单笔合约原子性、本地数据库事务和端到端一致性；回滚边界不含所有 Gas、独立前置交易和链外记录，不宣称全局 exactly-once。
- EVM 的事件身份、规范链、确认与最终性须带区块和分支证据；去重需兼容撤回及重新激活，投影修复不能冒充链上退款。
- Solana 的 owner、PDA、账户锁、slot、commitment 和 blockhash 有独立含义，不直接套用 EVM 的 EOA nonce 或区块确认模型；订阅不天然提供完整历史。
- 预测市场的问题定义、提报、挑战、仲裁与兑付按原文机制区分；提报不等于终局，业务裁决终局与链共识最终性不是同一层保证，兑付遵循抵押与资产守恒。
- 保留各篇的产品、链、合约权限及数据源适用范围；教学金额、挑战窗口、期限等号、确认策略和执行规则不泛化为所有协议。
- 用结构检查验证每个已完成文件均有且只有一套前置导读；与修改前工作区快照比较，确认移除新增导读后原文逐字节保留。
- 检查 Markdown 表格、本次新增相对链接和故事中的关键算式，按实际文件更新清单及复利记录。不创建 Go 工程，不声称运行链上实验、生产故障、性能测试或合约安全审计。
