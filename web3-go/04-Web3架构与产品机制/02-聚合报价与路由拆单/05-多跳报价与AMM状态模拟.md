# 大问题 5：多跳报价怎样逐步模拟 AMM 状态，才能与 Router 的真实调用语义一致？
<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| AMM 与 v2/v3 | AMM 是自动做市商；v2 常用两侧储备定价，v3 使用分价格区间的流动性。 | 两种协议必须各按自己的数学与状态转移模拟，不能只换费率。 |
| EVM、DEX 与非托管 | EVM 是以太坊虚拟机，DEX 是去中心化交易所；非托管表示资产仍归用户钱包控制。 | Go 算建议，链上裁决执行，不能把模拟值记作用户资产。 |
| ERC20、USDC、WETH 与 rebase | ERC20 是代币标准；USDC 是稳定币，WETH 是包装 ETH；rebase 会重设余额。 | 本题无税、无 rebase，USDC 6 位、WETH 18 位，不用特殊代币语义补算。 |
| ExactIn、raw 与 decimals | 固定输入、最小单位整数及小数位数。 | 10,000 USDC 是 10,000,000,000 raw，精度只用于金额转换，不再塞进公式乘一次汇率。 |
| a、Rin、Rout 与 floor | 输入数量、输入币储备、输出币储备及向下取整。 | 方向决定哪边是 Rin；先完整乘法再整除，不能提前把 997a/1000 取整。 |
| 997/1000 与池费 | 0.3% 手续费在报价中的有效输入系数。 | 报价已计池费，真实入池仍是完整 a，不能把手续费从储备增量中删掉。 |
| 多跳与拆单 | 多跳是输出接着成为下一步输入；拆单是把总输入分给多个路径。 | 多跳每一步先取整再传 raw，不能先乘几个汇率最后才取整。 |
| 快照与 overlay | 快照是共同只读底稿，overlay 是候选计划的私有可写状态层。 | 同计划复用池时读前一步新状态，候选之间不能串改储备。 |
| 实际余额、储备与捐赠 | 代币实际持有量不一定等于池记录的储备，别人可直接转币给池。 | 本简化适配器先同块核对相等；不相等就拒绝，不能沿用简式更新。 |
| big.Int 与深拷贝 | Go 大整数对象会改写运算接收者；深拷贝才真正复制数值。 | 临时运算不能写共享储备，复制结构体不代表内部整数已隔离。 |
| uint112 与 uint256 | 合约中分别最多容纳 112、256 位的无符号整数。 | Go 算得出大数也要检查目标合约范围，不能假定任意精度等于链上可执行。 |
| tick、tickSpacing 与 liquidity | v3 的价格刻度、可用刻度间隔及活跃流动性。 | 必须覆盖输入实际经过的区间，并随跨界更新；缺数据就失败或同块补齐。 |
| Quoter 与价格限制 | Quoter 是协议报价工具；价格限制是不能继续推进的价格边界。 | 独立调用不自动知道共享池前步变化；有输出但剩余输入没用完也不满足本文全额 ExactIn。 |
| minOut、bps 与 gas | 最低收币量、万分之一比例及用户另付执行费。 | 总毛输出取 50 bps 下限，不逐跳重复扣，不扣 gas，也不再扣池费。 |
| calldata、deadline 与原子回滚 | 实际合约指令、执行截止时间及同笔交易全退机制。 | 完整模拟要用最终指令；执行时任何腿失败或最终不足，全部换币状态撤销但仍耗 gas。 |
| CEX 与 RFQ | CEX 是中心化交易所，RFQ 是询价交易机制。 | 两者不在本题 AMM 状态模拟主线，不能套用本文单笔 Router 执行语义。 |

## 把整篇文章压缩成一个故事

小林把 10,000 USDC 交给聚合器报价。系统从同一快照读取 A 池 600,000 USDC／300 WETH、B 池 400,000／200，按 0.3% 池费做完整整数计算：全 A 得 4.903519845238290407 WETH。若候选是多跳路线，系统不会把几个汇率直接相乘，而是把第一跳取整后的 raw 输出原封不动交给第二跳，再继续推进。

小林的另一条候选可能再次碰到同一个池。这时系统先核对实际余额等于储备，再在该计划自己的 overlay 中把输入储备增加完整输入、输出储备减去实际输出；下一步必须读新值。其他候选仍读原快照，Go 的大整数也要真正复制，不能一次运算改坏所有人的底稿。若换成 v3，就逐价格区间模拟；跨到未知 tick 或到价格限制后还剩输入，不能为了给出数字就冒称全额可执行。

最后，小林选的独立 A 6,000／B 4,000 得到 4.935790171985306493 WETH，50 bps 对应 4.911111221125379960 WETH 的整计划下限。系统用完整合约指令、真实调用者和授权条件模拟，但仍不保证未来成功；最终由 Router 在链上检查下限和期限。第二腿失败或到账不足，第一腿一起撤销，gas 另付，绝不以“模拟曾成功”代替执行保护。

**流程位置与核心机制：** 承接候选路径搜索，把路径、输入数量与同块状态转换为可核验的逐跳输出；拆单优化再以此评价完整计划。关键不是调用一个“报价组件”，而是精确复现整数运算、状态转移与失败语义。

统一边界为同链 EVM 非托管 DEX 聚合、ExactIn、普通 ERC20，无转账税或 rebase，无平台费或返佣；USDC 6 位、WETH 18 位。不跨链、不执行 CEX、不以 RFQ 为主线。池储备与余额以链上为权威，Go 只持同一 `(chainId, blockNumber, blockHash)` 的不可变快照。多路径在一个 Router 交易中顺序执行且全回滚，quote 不锁价、不占资，用户另付 gas。

## 第 1 层：一次报价的输入，怎样才能没有单位和状态歧义？

**面试官：** 候选路径已经找到，向报价模块传一个金额和池列表够不够？

**面试者：** 还要固定链、快照身份、输入输出代币地址、每条边的方向和协议参数。金额使用原始整数：10,000 USDC 是 10,000,000,000 raw，不是 WETH 的 18 位单位。储备必须按当前兑换方向映射成 Rin、Rout，不能假设 token0 永远是输入资产；代币精度只负责展示与人类金额转换，不在 AMM 公式中额外乘一次汇率。输入需为正、池状态完整且输出可用，否则返回明确的报价失败。混块储备、浮点金额或方向不明都会污染后续每一跳，即使最后显示的小数看起来合理，也无法证明其可执行。

## 第 2 层：v2 的手续费和向下取整应放在哪一步？

**面试官：** 方向和单位固定后，0.3% 手续费应该先从整数输入中扣掉吗？

**面试者：** 本例直接计算 `out = floor(997*a*Rout/(1000*Rin+997*a))`，先保留完整整数乘积，最后做一次整除；不能先把 `997*a/1000` 向下取整，否则小额输入会多损失精度。A 的原始储备为 600,000,000,000 USDC raw 和 300×10^18 WETH raw，输入 10,000,000,000 raw 得到 4,903,519,845,238,290,407 WETH raw，即 4.903519845238290407 WETH。B 储备为 400,000 USDC/200 WETH，同额得到 4.863770519794131277 WETH。该费率是本题已确认的池参数，不能推广为所有 v2 分叉的默认常量。实现还要拒绝分母为零、输出为零或输出不小于输出储备等不可执行情况。计算后可用调整后余额检查手续费不变量；不能为了接近展示金额向上补一单位，否则可能直接触发池合约回滚。

## 第 3 层：多跳为什么不能把几个汇率相乘后只取整一次？

**面试官：** 单跳公式明确了，路径 USDC→中间代币→WETH 能否直接相乘得到总输出？

**面试者：** 不行。第二跳的输入必须等于第一跳实际输出的 raw 整数：第一跳完成整除，再把结果按第二跳方向送入其公式，之后继续逐跳推进；中间代币不应转换成人类小数再解析回来。每跳都要记录输入、输出、池身份及所读状态，前一跳输出为零时该路径不可行，不能为了凑流量改成最小一单位。路径最终值是这些状态转换的复合，而不是初始汇率的乘积。本题数值案例仍只使用 A、B 两个独立 v2 直接池；多跳在这里说明通用推进规则，不额外虚构一组储备来支撑结论。

## 第 4 层：逐跳输出算完后，为什么还必须更新池储备？

**面试官：** 如果下一跳或另一条路径再次用到同一个池，能否继续读取原始快照？

**面试者：** 不能。先按总览核对同块实际余额等于储备；普通 ERC20 也可能被直接捐赠，余额不等时本简化适配器拒绝，而不是照搬储备转移。若支持该状态，必须同时模拟实际余额、Pair 输入识别和写回。满足这一前提后，一次 USDC→WETH 的 v2 兑换应在私有 overlay 中写入 `Rin' = Rin+a`、`Rout' = Rout-out`，输入侧增加完整 a，而不是仅增加 0.997a；手续费留在池中，不能从真实入池余额中抹掉。反方向访问时读取同一池的已更新储备并交换输入输出角色。底层快照始终不改，候选计划各自拥有隔离的 overlay；同一计划内则按真实调用顺序共享它。路径内部重复池在搜索基线中已被禁止，但拆单的不同路径仍可能相交，必须按这一规则整计划重放，或显式拒绝该组合。

## 第 5 层：Go 的大整数实现，怎样避免算对公式却改坏快照？

**面试官：** overlay 隔离了，使用 Go 的 big.Int 是否就自动满足精度和并发安全？

**面试者：** 不是，`big.Int` 的运算会修改接收者，结构体复制或切片复制也不代表内部整数已深拷贝。读取快照后应复制数值，再用独立临时变量计算分子分母，不能把共享储备指针当作运算接收者。缓存键至少绑定快照、输入量、方向与协议参数；若已处于共享池 overlay，还需绑定所依赖状态，不能命中旧快照缓存。任一步出现缺状态、非法储备或不支持的协议语义，都应携带原因使候选失败，不得转成零值成功。任意精度也不等于 EVM 任意精度，还需遵守目标合约的数值范围、溢出与回滚规则。例如标准 v2 的储备更新要满足 uint112 范围，报价中的 uint256 乘法也需核对上限；不能因为 Go 能算出一个更大的整数，就认定链上仍能成功。

## 第 6 层：候选换成 v3 类型，为什么不能沿用两储备公式？

**面试官：** v2 的整数与隔离解决了，增加一个 v3 池适配器只需换个费率吗？

**面试者：** 不够。v3 报价依赖当前平方根价格、活跃流动性、tick、tickSpacing、费率及可遍历的初始化 tick；输入可能跨越多个价格区间，每跨界就要依据方向更新流动性，并按合约规则计算手续费和舍入。只有覆盖本次输入实际经过区间的完整 tick 数据，才能确认报价完整；跨到未知区间就应失败或补齐同块数据，不能拿当前流动性外推。也可对指定区块调用受信任的 Quoter 交叉核验，但独立调用不会自动看到本计划前一步的共享池变化。达到价格限制时还可能存在未消耗输入，本题要求全额 ExactIn，不能只看返回输出就判定成功；必须核验剩余输入为零，否则拒绝该候选。若另行支持部分成交与退款，需要显式产品语义并按实际消耗重新评价。适配器名称不提供正确性，必须展示状态读取、跨 tick 推进与失败处理的实际语义。

## 第 7 层：多条路径的报价怎样汇总成用户的 minOut？

**面试官：** 各协议都可报价了，本例独立 A、B 拆分后怎样形成最终保护值？

**面试者：** A 输入 6,000 USDC 输出 2.961474103191183896 WETH，B 输入 4,000 输出 1.974316068794122597 WETH，独立池可相加为 4.935790171985306493 WETH，即 4,935,790,171,985,306,493 raw。最大滑点 50 bps 时，`minOut=floor(total*9950/10000)`，得到 4,911,111,221,125,379,960 raw，即 4.911111221125379960 WETH。该阈值保护整计划最终输出，不是对每一跳重复扣 50 bps。用户另付 gas，不能从输入扣气费，也不能从 minOut 再扣一次气费；净收益排序与链上最少收币量是两个不同指标。50 bps 表达的是用户对报价到执行之间的容忍范围，不是池内的 0.3% 交易手续费，不能在算完池公式后再次按手续费比例扣减输出。

## 第 8 层：离线结果与链上执行之间，最后还有哪些不能省略的校验？

**面试官：** minOut 已经算好，能否保证用户签名后一定获得报价输出？

**面试者：** 不能。应将实际 calldata、执行顺序、发送者及必要授权前提带入整交易模拟，核验中间资产流向和最终接收方的余额增量；模拟使用固定区块只说明在该状态与前提下可执行，并不替代当前余额、授权和 gas 检查。上链前可能出现新成交、重组或排序变化，因此 Router 必须在链上校验 deadline 和最终 `actualOut >= minOut`。一条腿失败或最终不足时整个交易回滚，前腿也不保留；已经消耗的 gas 仍由用户承担。不能吞掉失败改走未获授权的替代路径，更不能声称 quote 已锁定价格。共享状态的具体反例见[执行顺序题](07-共享流动性与执行顺序.md)。

## 本题收束

- **机制：** 原始整数输入沿真实调用顺序逐跳推进；协议特定舍入、私有 overlay 和完整失败传播共同决定输出，不能只靠组件名保证一致。
- **最易答错边界：** v2 更新完整入池金额；多跳每跳各自取整；v3 必须有实际遍历区间的完整 ticks；只读快照不代表无需模拟中间状态。
- **反例验证：** 把 `Rin+a` 写成 `Rin+0.997a` 会虚构后续可兑换储备；把 gas 从 minOut 扣除，则允许用户少收币但仍通过错误阈值。正确阈值是 4.911111221125379960 WETH，而不是气费调整后的净值。
