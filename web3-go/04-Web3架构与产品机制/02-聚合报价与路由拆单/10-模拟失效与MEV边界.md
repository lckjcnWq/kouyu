## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| EVM、DEX 与非托管 | EVM 是以太坊虚拟机，DEX 是去中心化交易所；非托管表示平台不保管钱包资产。 | Go 和节点都不能为报价预留用户余额或池流动性。 |
| ExactIn、ERC20 与 rebase | ExactIn 固定输入；ERC20 是代币标准；rebase 会自动重设余额。 | 本题只算普通无税、无 rebase 代币，全输入在单笔 Router 交易中完成。 |
| USDC、WETH 与 raw | USDC 是稳定币，WETH 是包装 ETH；raw 是最小单位整数。 | USDC 6 位、WETH 18 位，报价为 4935790171985306493 raw WETH，不是已到账。 |
| AMM v2/v3 | AMM 是自动做市商，v2 用储备曲线，v3 使用集中在价格区间的流动性。 | 逐池输出正确仍不等于整笔调用可执行，v3 还受实际价格区间变化影响。 |
| eth_call 与 from/value/calldata | eth_call 是在指定状态临时试执行；后三者是调用者、附带原生币和合约指令。 | 完整试执行不留转账、授权或持久回执，指定 from 也不代表用户已经同意。 |
| RPC、EIP-1898 与 requireCanonical | 节点接口、按块哈希查询的约定及查询时要求区块规范的选项。 | 不支持所需快照能力就说明证据不足，不能暗换 latest。 |
| blockHash 与计划哈希 | blockHash 识别具体区块，请求、有序计划和 calldata 的哈希识别计算与签名内容。 | 必须记录模拟基于哪份状态和哪份计划，改变参数后旧证据不能直接复用。 |
| allowance、spender 与 approve | 转账额度、获准拉款地址及授予额度的交易。 | 授权未生效是前提不足，不是提高滑点能修好的池问题；授权后用新快照复核。 |
| state override 与 trace | state override 是临时假设某些状态不同，trace 是细看调用执行轨迹的工具。 | 可辅助诊断，却不能把假设授权或临时执行记录当真实成交。 |
| minOut、bps 与价格影响 | 最低输出、万分之一及本次交易本身沿池曲线造成的价格变化。 | 池内价格影响已进入报价；50 bps 是报价到执行的容忍范围，不是消除排序风险的保证。 |
| MEV 与夹击 | MEV 是利用交易排序等机会提取的价值；夹击常是在用户前后各做一笔交易牟利。 | 满足输出底线仍可能受不利排序，报价与底线差额不是攻击者固定利润。 |
| deadline 与 block.timestamp | 已签执行期限及包含交易的区块时间。 | 缩短期限改变风险与成功概率，不保证入块；本地过期也不证明此前没成交。 |
| gas、gwei 与失败成本 | 执行费、ETH 单价单位及失败时仍付出的执行成本。 | 回滚避免低于底线交割，却不等于没有经济损失；gas 不从 minOut 扣。 |
| mempool、私有中继与 rawTx | mempool 是公开待处理交易池，私有中继是较少公开暴露的转交通道，rawTx 是完整已签交易字节。 | 私有通道不保证必达、无泄露或无抢跑，转公池需遵守预先同意的策略。 |
| txHash、nonce 与 UNKNOWN | 交易指纹、发送者交易序号及证据不足的未知状态。 | 超时后追原候选及同 nonce 替换，不新开 nonce、不自动放宽保护。 |
| CEX 与原子范围 | CEX 是中心化交易所；原子范围说明哪些操作可随同一笔失败撤销。 | 本文单交易全回滚不能推广到中心化交易所、跨链或多笔链上交易。 |

## 把整篇文章压缩成一个故事

小林花 10,000 USDC，准备按 A 6,000、B 4,000 换成预计 4.935790171985306493 WETH。系统不只分别计算两池，还拿最终 Router 指令、真实付款人、授权条件和固定块哈希做完整 eth_call。调用成功只说明在这份状态中，拉款、两腿与最终收款检查可以通过；它不会留下资产转账，更不能证明小林已经签名或未来一定成功。

小林签名后，别人可能先交易池子，自己的另一笔操作也可能花掉余额或撤掉授权。若实际输出降到 4.92 WETH，仍高于 50 bps 对应的 4.911111221125379960 WETH 下限，交易可能成功，却不代表没遭受不利排序；降到 4.90 WETH 就应整笔回滚，gas 仍付。把下限收紧、期限缩短或提高费用，都只能改变取舍，不能同时保证最佳价格、必定入块和没有 MEV。

小林选择私有中继减少公开暴露，中继却超时了。系统不会自动转公池、降低 minOut 或另开 nonce，而是按约定的通道策略，用原已签交易身份继续查原 hash 和同 nonce 候选。即使本地期限已过，也要检查是否早在到期前入块；最终依据规范链证据交付已有结果或确认回滚。模拟管条件证据，合约管交割底线，广播策略管暴露范围，谁也不能冒充未来成交保证。

[返回专题总览](README.md)

**流程位置与核心机制：** 本题位于计划构造之后、交易广播与入块之前，沿着“完整模拟—前提变化—滑点保护—广播策略”追问。基线为同链 EVM 非托管 DEX 聚合 ExactIn，普通 ERC20，无税、无 rebase，用户自付 Gas。主线采用 v2/v3 AMM，例子是两个独立 v2 池：A 为 600,000 USDC／300 WETH，B 为 400,000 USDC／200 WETH，费率均为 0.3%。

10,000 USDC 按 A 6,000、B 4,000 顺序执行，quotedOut 为 `4935790171985306493 raw = 4.935790171985306493 WETH`；50 bps 滑点的 minOut 为 `4911111221125379960 raw = 4.911111221125379960 WETH`。USDC 为 6 位、WETH 为 18 位精度。quote 不预留资金、不锁价；单 Router 交易执行全部腿，全成功或回滚，没有部分填充。模拟是某个链上快照下的条件证据，不是未来成交凭证。

## 第 1 层：为什么逐腿算对仍要模拟整笔交易？

**面试官：** 两个池相互独立，Go 已分别算出输出，模拟 A 和 B 各自成功后相加，不就能证明计划可执行吗？

**面试者：** 不能，逐腿成功没有覆盖同一次拉款、执行顺序、中间余额、adapter 调用和最终收款检查。我会使用最终 Router 的完整 calldata，以实际 caller 作为 from，携带真实 value，在显式 blockHash 上发起 eth_call；通过支持 EIP-1898 的接口指定 blockHash，并尽可能要求 requireCanonical。quote 同时记录 chainId、blockNumber、blockHash，以及 policyVersion、canonicalRequestHash、orderedPlanHash、caller／recipient、amountIn、minOut、deadline、router／spender／value／calldataHash。两池独立不代表合约调用上下文独立。from 在 eth_call 中可以指定，模拟成功本身不证明用户同意执行，钱包签名与 spender 授权仍须分别确认。如果节点不支持所需快照能力，应报告模拟证据不足，不能悄悄退回 latest，再把结果说成原快照的验证。

## 第 2 层：eth_call 成功究竟证明了什么？

**面试官：** 完整 eth_call 已经没有报错，能不能把它返回的输出直接保存成用户已经收到的资产？

**面试者：** 不能。eth_call 在指定状态上临时执行，结束后不保留 transferFrom、swap、allowance 修改和资产转账，也没有已入块 receipt。如果 Router 入口本身强制全量消耗输入、隔离历史余额、检查 recipient 本次 WETH 增量至少为 minOut，那么调用成功说明这些断言在该快照和调用条件下成立。诊断需要时，可使用可信节点的 trace 或合约明确返回的执行数据，但普通 eth_call 不会自动提供可作结算凭证的持久日志。还要核对目标 Router 的代码与可信 adapter 路径，否则成功可能只是调用了一个不做事的合约。模拟结果应保存快照和参数哈希，不能写成“已成交”。链上快照包含当时的区块时间，模拟通过只意味着相对该时间未过期；未来区块的时间条件仍待实际执行裁决。

## 第 3 层：授权尚未上链时怎样解释模拟失败？

**面试官：** 你要求真实 allowance，但用户正准备先 approve；此时完整调用因授权不足失败，是路线不可用还是模拟方法有问题？

**面试者：** 这是执行前提未满足，要与池内流动性不足分开。先查询该快照下 owner 对绑定 spender 的 allowance 和余额；若 approve 尚未确认，只能说“当前状态不可执行，待授权生效后复核”。支持 state override 的节点可以辅助诊断“假设已授权”的路径，但必须明确覆盖了哪些状态，不能把它当成真实授权，更不能假装 eth_call 会留下 allowance。授权成功后取新块哈希，以最终 calldata 重新模拟，并判断报价是否需要重算；独立 approve 成功也不保证 swap 成功，后者回滚不会撤销前者。USDC 授权地址、chainId、caller 或金额任一改变，都使之前的模拟前提失效。单次调用失败应记录可解析的回滚原因和调用快照，先定位授权不足还是交换约束失败，不能用“提高滑点”去修复 spender 配错。

## 第 4 层：重模拟后还有哪个失效窗口关不掉？

**面试官：** 授权已经生效，广播前又模拟了一次，为什么仍不能对用户保证接下来必然成功？

**面试者：** 因为最后一次读取与实际执行之间仍有区块排序窗口。别人先交换会改变储备；用户另一笔交易可能花掉 USDC 或修改 allowance；交易可能晚于 deadline 执行，Gas 条件也可能不同。就算两个池相互独立，其他参与者仍可分别交易它们；v3 还涉及执行时价格与流动性区间变化。Go 和 RPC 不能预留这些链上资源。模拟还可能建立在随后被重组掉的 blockHash 上，因此需记录并复核规范性。能保证的是：可信 Router 执行时若任一条件不成立就整体回滚，而不是保证调用一定成功。失败原因应保留链上证据，不能仅凭旧模拟成功就判节点或用户有错。

## 第 5 层：50 bps 的 minOut 为什么不能叫防 MEV？

**面试官：** 既然最终低于 4.911111221125379960 WETH 就回滚，攻击者还能从这笔拆单里获得什么？

**面试者：** minOut 限制本次最差到账，不限制别人如何安排交易。攻击者可能先买入推高 WETH 价格，让用户在仍满足 minOut 的位置成交，再反向交易；是否盈利还取决于池深、手续费和竞争。报价与底线相差 `24678950859926533 raw WETH`，即约 0.02467895 WETH，这不是系统预留给攻击者的固定利润，但确实是用户允许的输出退让空间。两池拆单分散了价格冲击，不自动消除排序攻击；同时，价格改善不必因 minOut 存在而被截走。minOut 是输出下限，不是最佳执行证明，也不覆盖用户另付的 Gas、机会成本或所有形式的 MEV。保护针对最终总输出，不能据此推断每个池都没有受到不利排序；用户看到总到账合格，也不等于各腿价格保持了报价时的水平。

## 第 6 层：更紧滑点与更短期限能否消除窗口？

**面试官：** 那把 minOut 拉到 quotedOut、deadline 缩到下一秒，再提高 Gas 费，是不是就能同时消除 MEV 和执行失败？

**面试者：** 不能，这只是改变成交概率与风险取舍。零容忍滑点也可能因普通价格波动而回滚，短期限会增加来不及入块的概率，提高费用也不是排序保证。deadline 是绝对链上时间，最后由包含交易的区块 block.timestamp 判定，服务端倒计时不具裁决权。2 gwei 下，单路 120,000 Gas 约 0.00024 ETH，双路 180,000 约 0.00036 ETH，实际费用以执行为准，不能从 minOut 中扣掉。回滚仍耗 Gas，所以“没有低价成交”不等于“没有经济损失”。用户签署的 minOut、deadline 或 calldata 一旦改变，需要重新确认并签名，不能后台自动放宽以提高成功率。

## 第 7 层：私有中继减少了什么，又引入什么？

**面试官：** 上一答说明公池排序不可控，那把签名交易交给私有中继，并在超时后自动转公池，能不能解决？

**面试者：** 私有通道可以减少交易在公开 mempool 的提前暴露，但不能保证必达、及时入块、无抢跑或绝不泄露；中继、构建者和验证者仍有各自策略。超时也不等于交易从未被转发，自动回退公池会改变用户原先接受的暴露范围。应预先约定允许的通道、等待窗口和回退条件，必要时先提示风险，再使用同一已签 rawTx；多处广播同一 rawTx 仍是同一个 hash，不是多笔业务。若需同 nonce 提费替换，也应归入同一候选组并保留旧 hash。平台只能转发用户提供的签名，不能假定自己能签替换，更不能因中继超时另开 nonce 或放宽 minOut。

## 第 8 层：超时且过期后怎样收束风险？

**面试官：** 私有中继没回执，公池查询也没有 receipt，现在 deadline 已过；为了用户体验，能直接宣告失败并推荐一笔新交易吗？

**面试者：** 还不能，UNKNOWN 描述的是证据不足，不是链上失败。旧交易可能已经在到期前入块，只是查询节点落后；同 nonce 的旧候选或替换候选也可能已经胜出。应保留 signedTxHash、sender、chainId、nonce、计划与请求映射，追踪整个候选 hash 组，核对规范 receipt、区块哈希和必要的 sender nonce 消耗证据；查不到只说明当前节点未提供证据。若出现重组，已有成功判断也要按规范链退回。只有消除旧执行仍可能成立的窗口，才考虑新业务请求；即便重新报价，也必须重新绑定状态和签名。此时不自动降 minOut、不重用旧模拟、不把手机时间当失败证明，才没有把广播不确定性变成重复成交风险。即便最后确认因输出不足回滚，也只能说明保护条件被触发；要归因为夹击，还需交易排序和池状态变化证据，不能凭失败文案指认 MEV。

## 本题收束

- **机制：** 完整 calldata、真实 from／value／授权状态与显式 blockHash 共同限定模拟证据；链上 minOut 和 deadline 限定实际执行；广播通道策略限制暴露，但不提供成交保证。
- **错边界：** eth_call 不持久化，不锁储备；逐腿成功不等于组合成功；模拟成功不等于未来成功；minOut 不覆盖全部 MEV；私有中继不等于必达或无抢跑。跨交易、CEX、跨链不能继承本题单交易原子性。
- **反例验证：** 模拟后别人的交换把输出推到 4.92 WETH，交易可能成功但仍存在不利排序；推到 4.90 WETH，则全笔回滚但用户仍付 Gas；中继超时后发现旧交易在 deadline 前已经入块，应交付已有结果而非自动重做。三种情况分别检验输出底线、失败成本与 UNKNOWN 的边界。
