## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| EVM、DEX 与非托管 | EVM 是以太坊虚拟机，DEX 是去中心化交易所；非托管表示平台不保管钱包资产。 | Go 服务负责找路、估算和生成计划，链上合约才负责改变资产。 |
| ExactIn、quote 与 QUOTED | ExactIn 固定输入，quote 是估算单，QUOTED 表示已经完成报价。 | 报价不锁价格、不占用户或池资金；工程伪代码到此为止，不代表已成交。 |
| ERC20、USDC、WETH 与 rebase | ERC20 是代币接口标准；USDC 是稳定币，WETH 是包装 ETH；rebase 会自动调整余额。 | 本题普通代币无税、无 rebase，USDC 6 位、WETH 18 位，不含平台费和返佣。 |
| raw、decimals、floor 与 ceil | raw 是最小单位整数，decimals 是小数位，floor/ceil 分别向下/向上取整。 | 10,000 USDC 是 10,000,000,000 raw，逐腿按统一合约规则取整，不用界面小数反推。 |
| AMM、v2、v3 与 tick | AMM 是自动做市商；v2 用储备曲线，v3 把流动性放在价格区间，tick 是价格刻度。 | 主例只用两个 v2 直接池；v3 不能照搬同一储备公式，还需完整跨区间数据。 |
| inRaw、outRaw、Rin 与 Rout | 原始输入、原始输出，以及按兑换方向映射的两侧储备。 | 997/1000 表示 0.3% 池费后的价格系数；更新储备仍增加完整输入。 |
| Pair、实际余额与未同步捐赠 | Pair 是池合约，实际余额可能被别人直接转币改变而尚未写入储备。 | 本简化适配器先同块核对两者相等，不等就拒绝，不能认为普通代币自动保证相等。 |
| chainId、blockNumber、blockHash 与 H | 链、块高、具体区块指纹；H 是教学中对该状态身份的符号。 | 所有计算绑定同份状态，H 不是声称实际取得的一条链上记录。 |
| EIP-1898、latest 与规范链 | EIP-1898 支持按块哈希查询，latest 是节点最新状态，规范链是当前被认可的分支。 | requireCanonical 只检查查询时分支有效，不能保证以后不重组，也不能把并发 latest 当同块。 |
| 流动性图、poolID 与有界搜索 | 资产是图的点，具体池是有方向的路，poolID 标识真实池。 | 同币对可有多个池；教学限制最多 3 跳、2 条拆分路径，候选截断要明说。 |
| 多跳、拆单与腿 | 多跳把前一跳输出继续兑换；拆单把输入分到几条路；腿是一份分配。 | 6,000／4,000 必须合计完整 10,000 USDC，每一步输入输出用真实整数串联。 |
| overlay、共享池与顺序 | overlay 是计划自己的临时状态层；共享池表示多个调用碰到同一储备。 | 后调用读前调用更新后的状态，不能两次使用初态；换顺序就是需要重新评价的计划。 |
| gas、wei、gwei 与净价值 | gas 是工作量，wei/gwei 是 ETH 单价单位；净价值是毛输出减同币种费用估值。 | 2 gwei 下 120,000／180,000 gas 对应 0.00024／0.00036 ETH，ETH/WETH 仅按 1:1 估值，费用用户另付。 |
| EIP-1559、maxFee 与 effectiveGasPrice | 交易费规则、每 gas 最高单价及实际有效单价。 | 预算上限不是实付；实际以规范回执的 gasUsed 和有效单价核算，其他链附加费另列。 |
| 价格影响、slippageBps 与 minOut | 价格影响来自本次交易沿池曲线移动；slippageBps 是允许的执行偏差；minOut 是最低收币量。 | 池内影响已进报价，50 bps 是再允许输出恶化 0.5%；下限不扣 gas，不重复扣池费。 |
| Router、adapter、caller 与 recipient | 执行合约、协议适配器、付款调用者与收款人。 | 只拉本次输入、只分配本次产出，收款人新增输出而非历史余额决定是否达标。 |
| allowance、spender、approve 与 EOA | 转账额度、获准拉款地址、设置额度的交易及私钥控制的普通账户。 | 授权不预留资金；默认 EOA 直发，独立授权不属于换币回滚范围。 |
| calldata、orderedPlanHash 与 deadline | 实际合约指令、有序计划指纹及执行截止时间。 | 展示计划和待签指令要对应，保护由合约检查实际输出和 block.timestamp 区块时间，哈希不自动防重。 |
| 原子性、revert 与部分填充 | 原子性指同笔全成全退，revert 撤销状态，部分填充是只保留部分执行。 | 本题不支持保留成功腿；失败 gas、交易 nonce 和其他独立交易不随换币撤销。 |
| txHash、sender、nonce 与替换组 | 交易指纹、发送者、账户交易序号及同序号的多个候选。 | 同 nonce 在规范链上只有一个胜出者，但新 nonce 可重复执行同份报价；业务防重需额外能力。 |
| UNKNOWN、receipt、confirmed 与 finalized | 结果未知、执行回执、达到产品确认策略及达到链相关最终性。 | 广播超时不判失败；有回执仍要核对目标业务、分支和确认，不把阶段都折成 success。 |
| 重组、revision、outbox 与 eventId | 分支变化、结果修订号、待发事件表及稳定消息身份。 | 旧成功可被撤回，结果和事件同库提交，消费者去重保序，通知失败只重送通知。 |
| big.Int、worker、collector 与 RPC | Go 大整数、计算任务、汇总决策者与节点接口。 | 独占可写对象、有界并发、单处稳定决策；同候选集可确定，时间预算不保证收齐同集合。 |
| DP、best-found/incomplete 与 MVP | DP 是动态规划，best-found/incomplete 表示已发现最好但未搜完，MVP 是最小可行验证。 | 有限候选赢家不是全局最优；本篇 MVP 只是两个独立 v2 池的报价伪代码，没有新建工程或运行测试。 |
| CEX、RFQ、L2 与 SDK | CEX 是中心化交易所，RFQ 是询价交易，L2 是二层网络，SDK 是开发工具包。 | CEX、RFQ、跨链不在主线；接新链另建费用与最终性模型，工具包和源码链接不能替代固定部署版本的验证。 |

## 把整篇文章压缩成一个故事

小林想把 10,000 USDC 换成 WETH，钱包里另有付 gas 的 ETH。Go 服务在同一个符号为 H 的快照上看到 A 池 600,000 USDC／300 WETH、B 池 400,000／200，手续费均为 0.3%，实际余额与储备相等。它比较全 A、全 B 和 A 6,000＋B 4,000 三份计划，按整数逐腿得到拆分毛输出 4.935790171985306493 WETH。按 2 gwei、双腿 180,000 gas 的教学假设，净值为 4.935430171985306493，胜过已评的单池方案；小林并没有因此预占资金或锁定池价。

小林接受 50 bps 执行滑点，系统从毛输出算出 4.911111221125379960 WETH 下限，把接收者、顺序、金额和期限写入最终指令；若授权不足先单独 approve，再按新条件复核。模拟只是指定状态下试执行，真正上链仍由 Router 检查全部输入用完和本次收款增量。不能重复使用共享池初态，也不能拿 Router 旧币凑下限；任一腿失败则全退，已耗 gas 和先前独立授权仍在。若小林改为只换 100 USDC，拆分毛增益又不够新增费用，就不应照搬大额六四比例。

广播时节点超时，系统沿原 hash、sender、nonce 和替换组恢复，不另开 nonce 再换一次；查到回执后核对业务证据、规范链与确认阶段。若成功块重组，保留旧证据并用新 revision 撤销投影，通知重复或失败只靠事件去重和补投解决，不再触发兑换。14 篇正文就沿这次交易逐段拆解证据、算法、权限和恢复；末尾 MVP 只演示固定快照三个候选的报价选择，所有数值与验收方法都是教学推演，不是生产经历、实测 gas 或已完成的工程测试。

## 第一部分：文字全流程

### 1.1 先锁定讨论基线

| 项目 | 本专题约定 |
|---|---|
| 产品与交易机制 | 同链 EVM、非托管 DEX 聚合器；Go 服务发现池、读取状态、搜索路径、估算报价、生成执行计划；链上 Router 执行兑换 |
| 主能力 | ExactIn：给定准确输入数量，在用户约束内选择预计净价值较高的可执行计划；多跳与拆单不是同一件事 |
| 流动性类型 | 支持按能力接入 v2 恒定乘积池、v3 风格集中流动性池；贯穿数值例只使用两个 v2 直接池，不把储备公式用于 v3 |
| 资产与费用 | 普通 ERC-20；USDC 为 6 位，WETH 为 18 位；无转账税、无 rebase、无平台费、无返佣；池手续费已计入池报价 |
| 状态归属 | 代币余额与 allowance、池储备或 tick 状态、EOA nonce、执行结果由链上合约与规范链决定；Go 的缓存与数据库不是这些事实的权威来源 |
| 执行与结算 | 所有拆分腿在同一笔 Router 交易内按计划顺序执行；全部准确输入被使用、最终输出满足保护才整体提交，否则整体回滚；不支持成功保留部分腿 |
| Gas 与授权 | 用户另付原生 ETH Gas，不从输入 USDC 或输出 WETH 中暗扣；独立 approve 是另一笔交易，不属于 Swap 回滚范围 |
| 排除范围 | 跨链、CEX 子单、RFQ firm quote、求解器竞价与托管账户拆单不进入主线；比较这些方案时明确改变的状态归属和原子边界 |

教学搜索策略限制最大 3 跳、最多 2 条拆分路径，只允许白名单资产、池和适配器。生产策略可以改变这些值，但必须记录策略版本、重新评估搜索预算与执行成本；它们不是行业标准。

### 1.2 一笔贯穿全文的业务

用户以 **10,000 USDC 兑换 WETH**，采用 ExactIn。用户已有足额 USDC，并另持足够 ETH；如授权不足，先完成对受信 spender 的有限授权。所有池状态取自同一 `(chainId, blockNumber, blockHash)`；示例将区块身份记作符号 `H`，不是实际链上记录。

| 池 | USDC 储备 | WETH 储备 | 输入手续费 |
|---|---:|---:|---:|
| A | 600,000 USDC | 300 WETH | 0.3% |
| B | 400,000 USDC | 200 WETH | 0.3% |

两池独立且初始边际价格相同，不共享底层储备。主例还要求 H 上池的两种代币实际余额分别等于其储备，没有未同步捐赠；普通 ERC-20 本身不保证这一点。简化适配器须同块读取并核对余额与储备，不相等时拒绝候选；若支持这种状态，须按 Pair 实际余额、输入识别与储备写回完整模拟，不能只更新 `Rin+a`。USDC 输入原始整数为 `10,000,000,000`。对某个方向，v2 模型的整数报价为：

```text
outRaw = floor(997 × inRaw × reserveOutRaw /
               (1000 × reserveInRaw + 997 × inRaw))

在初始实际余额等于储备、普通转账及本次调用模型下，执行后的储备：
reserveInRaw'  = reserveInRaw + inRaw
reserveOutRaw' = reserveOutRaw - outRaw

0.997 × inRaw 只用于价格公式；不能把储备增加也写成净输入。
```

本例先评估三个计划：全走 A、全走 B、A 分配 6,000 USDC 且 B 分配 4,000 USDC。金额原始整数逐腿计算、向下舍入，不从界面小数反推执行值。

| 计划 | 预计毛输出 WETH | 教学 Gas 估计 | Gas 的 WETH 等值 | 预计净价值 WETH |
|---|---:|---:|---:|---:|
| 全 A | 4.903519845238290407 | 120,000 gas | 0.00024 | 4.903279845238290407 |
| 全 B | 4.863770519794131277 | 120,000 gas | 0.00024 | 4.863530519794131277 |
| A 6,000 + B 4,000 | 4.935790171985306493 | 180,000 gas | 0.00036 | 4.935430171985306493 |

Gas 使用 **2 gwei 的估计成交单价**，且把 ETH 按 1:1 原生价值换算为 WETH 等值；这不是声称 ETH 和 WETH 具有相同合约地址或无限流动的免费包装能力。两种 Gas 单位数只是教学假设，不是 `estimateGas` 或压测结果。主例无需额外包装，比较表假设授权已完成；新增授权、L2 数据费等条件变化另算，不能漏算或重复计费。

拆分两腿分别得到 `2.961474103191183896 WETH` 和 `1.974316068794122597 WETH`。总报价原始整数为 `4,935,790,171,985,306,493`；用户接受最大 50 bps 执行滑点：

```text
minOutRaw = floor(4,935,790,171,985,306,493 × 9950 / 10000)
          = 4,911,111,221,125,379,960
          = 4.911111221125379960 WETH
```

`minOut` 约束实际兑换收到的 WETH，不是扣 Gas 后的净价值。向下取整只放宽不到 1 个输出最小单位。若产品要求严格按有理数比例不低于阈值，可改为向上取整，但必须统一接口和合约规则，不能两处各用一种口径。

本例的 60/40 与相同费率、相同初价、储备成比例有关。它是上述已评估候选中的赢家，不是对任意流动性图、整数舍入和动态 Gas 条件的全局最优证明。数值稿同时核对 `gasUnits × gasPriceWei` 与净价值：`120000 × 2 × 10^9 = 240000000000000 wei`，避免把 gwei、ETH 与输出最小单位之间的换算藏在小数表里。

### 1.3 从请求直到业务完成

```text
用户请求兑换〔链、USDC、WETH、ExactIn数量、收款人、滑点、期限〕
    ↓
Go 接入层校验〔地址、整数精度、金额上限、资产能力与策略〕
    ↓
状态读取层固定区块身份 H
    └─ 读取资产元数据、池状态与相关配置 → 发布完整不可变快照
    ↓
候选搜索〔白名单图、跳数、路径数与计算预算〕
    ↓
适配器模拟〔逐跳整数计算、候选私有状态、不可重复使用旧池深度〕
    ↓
拆单优化〔总输入守恒、整计划Gas、外生换算、稳定择优〕
    └─ 输出 quote：计划、毛输出、费用、净价值、H、完整性与过期信息
    ↓
用户确认；构造并核对执行计划
    ├─ 授权不足 → 独立approve完成 → 重新检查必要状态和执行条件
    └─ 固化 chainId、caller、recipient、amountIn、orderedPlan、minOut、deadline
    ↓
针对完整 calldata / from / value 做执行前模拟
    ├─ 状态、授权、期限或能力不满足 → 拒绝、重报或请用户重新确认
    └─ 模拟通过 → 用户钱包核对并签名
    ↓
记录可恢复的提交身份 → 广播已签名交易
    ├─ 返回哈希 → 追踪原交易
    └─ 超时/断连 → SUBMISSION_UNKNOWN → 按哈希、sender、nonce追踪
    ↓
链上 Router 在实际执行状态下裁决
    ├─ 检查期限、调用者、目标与授权；拉取本次准确输入
    ├─ 按固定顺序执行 A、B；统计本次实际资产增量
    └─ 检查全部输入使用、最终recipient增量 >= minOut
           ├─ 任一失败 → 整笔Swap回滚，仍可能消耗Gas
           └─ 全部通过 → 池状态与用户资产在同一交易内提交
    ↓
观察规范链回执与受信执行证据〔入块、成功/回滚、实际输入输出〕
    ↓
按目标链策略推进确认/最终性；发现重组时撤回旧分支投影
    ↓
本地结果修订与outbox同事务提交 → 幂等投影、通知、查询
    ↓
页面展示带证据阶段的结果；达到约定最终性才承诺对应业务终态
```

用户自行广播时，平台不替用户“记录签名”或占有签名权；钱包负责可恢复提交，平台在得到 `txHash` 后跟踪。若平台提供代广播，才在广播前持久化已签名交易哈希、sender/nonce、执行计划关联与发送记录。数据库不能与链上提交组成一个本地事务。

### 1.4 主要分支不要混成“失败重试”

```text
没有合格路径 → NO_ROUTE；不等于用户资产不足，不产生Swap
搜索预算耗尽但已有合格候选 → 明示 best-found / incomplete；不称全局最优
用户取消签名 → 不提交Swap；已成功的独立approve仍然存在
报价过期或原区块被重组 → 旧quote不再用于新构造；已有提交单独追踪
模拟失败 → 按原因重报/拒绝；不通过放宽minOut偷偷修复
广播未知 → 原交易结果未定；不能换新nonce再做一笔相同兑换
deadline已过但结果未知 → 查是否在到期前已入块；不能仅按本地时间判失败
某一腿失败或最终输出不足 → 同笔交易全回滚；不是保留成功腿再链下补差
入块成功后重组 → 撤回旧确认与资产投影，追踪规范链上的原交易/替换交易
```

如果改变为多笔链上交易、跨链或 CEX 子单，则 A 已成交、B 失败可能是真实的部分完成；需要残余资产、风险暴露、补偿与用户授权规则。反向卖回不等于撤销原成交，本专题不把这种变体塞回单笔原子模型。

### 1.5 贯穿案例中的状态与资金

| 阶段 | 发生什么 | 没有什么承诺 |
|---|---|---|
| 已报价 | Go 返回 H 上的预计输出与成本 | 不锁池价格、不冻结 10,000 USDC，也不冻结池流动性 |
| 已授权 | token 合约允许指定 spender 在额度内转账 | 不是资金预留；用户可能花掉余额或撤销授权 |
| 已签名/已广播 | 一笔受 nonce 和费用条件约束的交易可以被执行 | 未确认会被打包，也未证明已经兑换 |
| 原子执行成功 | 用户少 10,000 USDC，recipient 收到本次实际 WETH；A/B 分别增加 6,000/4,000 USDC、减少实际输出 | 实际输出可以不同于旧报价，但必须满足 minOut；Gas 另计 |
| 原子执行回滚 | 本次 Swap 的转账与所有池变化撤销 | Gas 和交易 nonce 的链上处理不会随合约状态回滚；独立授权不撤销 |
| 规范链确认与展示 | 依据有效回执及受信 Router 证据生成带修订的本地结果 | RPC 返回、数据库写成功、页面显示都不能替代链上最终性 |

## 第二部分：核心板块

1. **报价契约与快照。** 决定“比的究竟是不是同一笔业务”。Go 拥有请求解释、状态证据与估算版本，不拥有链上资产；向搜索层交付可复现快照，向用户交付明确保护和过期语义。
2. **流动性图与适配器。** 图决定候选可达性，适配器决定某数量在某状态下的输出与状态变化。边不能只有一个固定汇率；集中流动性缺 tick 数据时不能假装无限深度。
3. **整计划拆单与费用优化。** 决定分给哪些路径、每条多少、按什么顺序执行。拥有计划与选择证据，必须处理整数输入守恒、共享池和新增腿成本，而非只挑显示价格最高者。
4. **计划构造与链上保护。** 把估算转换为受用户约束的调用。Router 拥有本次执行的临时状态，最终由 EVM 提交或回滚；Go 不能用缓存校验代替 minOut、deadline 与目标限制。
5. **提交追踪与结果交付。** 管理未知、确认、重组与投影，不重新裁决池成交。链上事实与本地结果分别提交；通过交易身份、修订和可靠交付收敛。
6. **Go 容量与验证证据。** 在有限预算内保持前述规则：不可变快照、私有数值对象、有界并发、可解释降级、差分与回放验证。

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| ExactIn 与整数单位 | 请求、模拟、构造 | 输入输出语义一致是后续比较的前提 | 小数截断、方向颠倒、数量超支 | token地址/decimals、向下舍入、逐跳传递 |

## 第四部分：设计与规则

### 4.1 共同不变量

- `sum(leg.amountInRaw) == request.amountInRaw`，每腿为非负整数，实际参与的腿必须为正；中间资产按本次上一步实际输出传递，不能凭空补资。
- 独立路径可独立计算后求和；共享池路径必须按**真实执行顺序**在同一个候选私有 overlay 上整计划模拟，或明确拒绝该类计划。候选之间绝不共享可写 overlay。
- `netValueOut = quotedOutRaw - estimatedCostInOutputRaw`。池输入费已经体现在 `quotedOutRaw`；不得再扣一次。若新增平台费，必须修改语义、实现与用户展示，不默认为零费基线已覆盖。
- `minOut` 与 `deadline` 必须进入用户确认的实际 calldata，Router 对实际输出和 `block.timestamp` 裁决。报价 TTL 是服务端可用性规则，不是链上防护。
- 收款人本次输出增量达到 `minOut`，全部本次输入被使用；本基线不允许留下未声明的输入或中间币。若真实适配器可能部分使用输入，必须拒绝该计划或显式增加余额隔离、余款退款与重新报价规则。
- 单笔 Router 内全部外部调用和最终校验一起回滚；独立 approve、Gas、nonce 和其他人的交易不在其回滚边界内。
- 允许“报价有效但最终执行回滚”“广播未知”“成功待确认”“重组后结果修订”等暂态；禁止“没回执就按失败开新 nonce”“一腿预期输出记成已成交”“本地成功覆盖链上失败”。
- 同一输入、同一快照、同一策略和同一已收集候选集应稳定输出同一计划；不同预算下候选集不同必须可解释，不能宣称所有请求必然全局确定最优。

### 4.2 架构、决策权与执行权

```text
客户端/钱包：用户意图、确认与签名、按约定承担广播恢复
       ↕
Go API：规范化请求、幂等查询身份、策略与预算
       ↓
Snapshot Manager：显式区块读取 → 完整性检查 → 只读发布
       ↓
Graph Search → Protocol Adapters → Plan Optimizer
       │             │                  │
       │         每候选私有overlay       └─ 费用、约束、稳定tie-break
       └───────────────────────────────────↓
                 Quote / Ordered Plan / Builder
                                   ↓
                       Full-call Preflight
                                   ↓
                         钱包签名与广播
                                   ↓
链上：Token合约 ↔ 受限Router/Adapters ↔ AMM池
       余额/授权       执行约束          储备/ticks
                                   ↓
Chain Observer：规范链身份、回执、重组与最终性
                                   ↓
本地 Result + Outbox〔一个DB事务〕→ 查询投影/推送消费者
```

服务可以合并部署，但不能合并事实边界。预检 RPC 不裁决未来成交；搜索层不分配权威链上流动性；Observer 不因本地意图而创造链上成交。

### 4.3 核心数据与交互

| 对象 | 必要内容 | 提交/确认边界 |
|---|---|---|
| QuoteRequest | chainId、tokenIn/out、ExactIn、amountInRaw、caller、recipient、slippageBps、期限要求、客户端请求键 | 规范化后计算 requestHash；同键不同载荷报冲突，不只按金额缓存 |
| StateSnapshot | chainId、blockNumber、blockHash、池地址/类型/fee、储备及同块实际余额核对结果或完整tick依赖、资产元数据、协议版本、数据完整性 | 全部依赖可解释后一次发布；不边更新边让请求读取 |
| QuoteResult | quoteId、requestHash、snapshotId、policyVersion、候选覆盖、毛输出/费用/净价值、validUntil、拒绝原因 | 只是估算；quoteId不可充当资金凭证或链上业务nonce |
| OrderedPlan | 路径和调用顺序、逐腿整数输入、适配器/池、输入输出币、router/spender、caller/recipient、minOut、deadline、value、calldataHash | `orderedPlanHash` 绑定顺序；任一保护/目标改变重新构造并获确认 |
| Submission | chainId、sender、nonce、signedTxHash、替换哈希组、plan关联、广播记录 | 可恢复身份先于代广播；无用户签名权时只记录其提交证据 |
| ExecutionResult | 交易与区块身份、status、受信执行证据、actualIn/out、Gas、确认阶段、revision | 规范链观察事实；本地状态更新和outbox原子提交，不与链上组成事务 |
| ResultEvent | 稳定eventId、业务身份、revision、状态及撤销/替代关系 | 至少一次交付，消费者在本地事务中去重和推进修订 |

Hash 采用显式字段、类型与版本的规范编码，不依赖 Go map 遍历或任意 JSON 序列化。若 Router 没有业务意图 nonce 存储，就只能获得 EOA 交易 nonce 的链上防重范围，不能把平台 requestHash 说成链上至多一次保证。

### 4.4 实现选择与完成语义

- **搜索：**资产节点使用 `(chainId, tokenAddress)`，池是带方向的多重边；先受限搜索，再按具体金额准确模拟。小候选可枚举，较大候选可用 DP/边际启发式，但要写明独立性、凹性和固定成本限制。
- **数值：**Go 1.21+ 的整数/`big.Int` 表达金额；每个 worker 独占可写接收者及 scratch。金额缓存和路径拓扑缓存分开，前者必须包含数量、方向、状态身份与规则版本。
- **并发：**有界 worker、候选上限、RPC配额和请求总预算；单候选失败是带类型的结果，不应无意取消全部任务；超时后的晚到结果不得改已交付计划。
- **存储：**可复现证据、提交身份和结果修订持久化；缓存丢失可重建，不把缓存作为签名恢复或用户资金的唯一记录。
- **终态：**`QUOTED`、`SIMULATED`、`SUBMISSION_UNKNOWN/PENDING`、`INCLUDED_SUCCESS/REVERTED`、`CONFIRMED`、按链策略的 `FINALIZED` 分开。报价过期是报价状态；不能让 `QUOTE_EXPIRED` 覆盖已经入块的成功交易。
- **确定性：**净价值降序，再比较整计划Gas与规范planId等稳定次级键；策略包含计算预算、候选集规则和费用来源。收益打平时不以 goroutine 返回先后裁决。

## 第七部分：工程实践——一个简洁 MVP

### 7.1 目标与范围

只验证：**固定快照上的两个独立 v2 池、整数分配、整计划 Gas 扣除、稳定选择与 minOut 生成**。输入明确的三个候选，输出已评估候选中的净价值赢家；状态从请求到 `QUOTED`，不宣称锁价或成交。

不实现图搜索、v3、共享池、RPC、钱包、链上 Router、广播恢复或消息系统，也不执行工程测试。这里的伪代码不是完整 Go 工程。

### 7.2 一段核心伪代码

```text
quote(request, snapshot, candidates):
  require request is ExactIn and amountInRaw > 0
  require request is USDC(6) -> WETH(18) on snapshot.chainId
  require 0 <= slippageBps < 10000 and snapshot.complete
  results = []
  for plan in candidates:
    require sum(plan.inputRaw) == request.amountInRaw
    require every participating leg.inputRaw > 0
    require plan has no repeated poolID       // MVP不支持共享池
    totalOut = 0
    for leg in plan.legs:
      pool = snapshot.pools[leg.poolID]
      require pool exists and pool.type == V2 and pool.fee == 3/1000
      require pool.blockHash == snapshot.blockHash
      require pool.direction == USDC -> WETH and reserves > 0
      require pool.balanceInRaw == pool.reserveInRaw
      require pool.balanceOutRaw == pool.reserveOutRaw // MVP拒绝未同步捐赠
      a = leg.inputRaw
      out = (997*a*pool.reserveOutRaw) // (1000*pool.reserveInRaw + 997*a)
      require out > 0 and out < pool.reserveOutRaw
      totalOut += out                       // 不修改共享快照
    require plan.gasUnits > 0
    gasCostWethRaw = plan.gasUnits * 2 * 10^9
    netRaw = totalOut - gasCostWethRaw       // ETH/WETH等值的特定简化
    results.append(plan, totalOut, netRaw, gasUnits, canonicalPlanID)
  if results is empty: return NO_ROUTE
  sort results by netRaw descending, gasUnits ascending, canonicalPlanID ascending
  best = results[0]
  minOut = best.totalOut * (10000-slippageBps) // 10000
  return QUOTED(snapshot.blockHash, best.plan, best.totalOut,
                best.netRaw, minOut, searchScope="given-candidates")
```

`//` 表示整数向下除法。所有乘法使用足够宽的整数或任意精度整数，生产适配器还需核验目标合约的溢出、乘除顺序与舍入口径。此 MVP 不模拟执行后的池状态，因为候选内禁止重复池、候选之间只读同一快照；不能把这一简化复制给共享池或多跳实现。

### 7.3 输入与预期结果

| 输入 | 手工推演的预期结果 |
|---|---|
| 主例 10,000 USDC；候选全A、全B、A6000+B4000；50bps | 选择拆分，`quotedOutRaw=4935790171985306493`，`netRaw=4935430171985306493`，`minOutRaw=4911111221125379960`；状态是 QUOTED，不是已成交 |
| 独立变体：100 USDC；候选全A、全B、A60+B40 | 全A毛输出 `0.049841717967864339`，拆分毛输出 `0.049845030450464088`；增加的毛收益小于额外 `0.00012 WETH` 等值Gas，选择全A |
| 把主例某候选改成 A6000+B3999 | 输入总量不是10,000，拒绝该输入；不能用向下取整解释丢失1 USDC |
| 把主例某候选两腿都指向 A | 返回MVP未支持的共享池输入，不独立计算后相加 |
| B 的 blockHash 与 H 不同 | 拒绝混合快照；不把缺少B自动解释为“全市场只有A” |
| A 的实际 USDC 余额大于同块储备（有人直接捐赠未同步） | 本MVP拒绝候选，不沿用 `Rin+a`；支持该场景需要实际余额及Pair输入识别的完整模拟 |

真实执行若 recipient 本次只增加 `4.90 WETH`，应由 Router 因低于本例 `minOut` 回滚；这是前文执行契约，不是这段报价伪代码已经实现的能力。所有预期结果都属于算术与规则推演，不是工程测试通过记录。

### 已核对的公开依据

- [Uniswap v2 Library](https://github.com/Uniswap/v2-periphery/blob/master/contracts/libraries/UniswapV2Library.sol)：`getAmountOut` 的 997/1000 费用公式、储备方向与逐跳整数传递。
- [Uniswap v2 Pair](https://github.com/Uniswap/v2-core/blob/master/contracts/UniswapV2Pair.sol)：按实际余额计算输入、手续费调整后校验不变量，再把实际余额写回储备；因此输入储备增加完整输入，而不是 0.997 倍输入。
- [Uniswap v3 SwapMath](https://github.com/Uniswap/v3-core/blob/main/contracts/libraries/SwapMath.sol)：逐区间计算净输入、输出、下一平方根价格与手续费，不能用单一 v2 储备公式替代。
- [EIP-1898](https://eips.ethereum.org/EIPS/eip-1898)：用 blockHash 指定状态查询，`requireCanonical` 可要求查询时仍属于规范链，但不保证将来不重组；具体 RPC 能力仍须实测。
- [EIP-1559](https://eips.ethereum.org/EIPS/eip-1559)：maxFee 预算、baseFee 与有效小费的关系；实际费用按 gasUsed 与有效单价计算，不把上限当实付。

源码链接是核对时的公开分支入口，不是已固定的部署版本或安全审计证据；生产接入应另存具体提交、部署地址和配置。这里的教学 Router 约束不代表上述协议自带完全相同的聚合接口。

本稿没有调用真实聚合器 API、广播交易或验证特定 Router 部署。接入真实协议须固定地址、合约与适配器版本、Token 能力、RPC 能力和目标链费用/最终性规则，再按第 14 题提出的方法实施验证。
