## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| EVM / 非托管 / EOA | 合约执行环境、用户自持密钥、普通私钥账户。 | A 自己掌管资产私钥，平台不索取或备份它；不等于合约和依赖没有风险。 |
| A / X / R | 用户、兑换执行合约、代付转发账户。 | 均为教学符号；X 不可升级，R 的 Gas 密钥不控制 A 的用户资产。 |
| USDC / WETH / 最小单位 | 两种教学代币及整数计量单位。 | 精度分别为 6 和 18，只讨论指定普通 ERC-20 消耗模型。 |
| approve / allowance / spender | 设置使用额度、剩余额度、获授权使用者。 | A 已独立确认给 X 恰好 1000 USDC 额度，不代表冻结或已经兑换。 |
| SwapIntent / EIP-712 | 一次具体兑换意图、结构化内容的签名规范。 | 用户签业务条件，不是直接签一笔可广播的 R 交易，也不是登录。 |
| domain / chainId / verifyingContract | 签名环境、链编号、验权执行合约。 | 固定为 OneTrade / 1 / 链 1 / X；类型和域共同限制授权用途。 |
| typeHash / structHash / digest | 类型指纹、具体结构指纹、最终签名摘要。 | 由固定类型与完整字段按规则生成，不是直接哈希 JSON。 |
| Keccak / ABI / 0x1901 | 哈希算法、有类型编码、固定原始字节前缀。 | 用 Ethereum Keccak、标准编码及字节前缀，不能替换为 SHA3 或文本拼接。 |
| uint256 / big.Int / float64 | 协议非负整数、Go 精确大整数、浮点表示。 | 金额检查范围、保持不可变且不经浮点，避免验签与实际调用数值漂移。 |
| amountIn / minAmountOut | 精确输入、最低实际输出。 | 1000 USDC 对应 1000000000，0.49 WETH 对应 490000000000000000；0.50 仅为样例。 |
| owner / recipient / routeHash | 授权人、收款人、规范路线指纹。 | owner 与 recipient 都是 A，路线既须与签名匹配，也须满足内置能力限制。 |
| selector / call / delegatecall | 函数入口标识、普通外部调用、借用代码的调用方式。 | 用户签过路线不代表 X 可以任意调用未知目标或借用任意代码。 |
| intentNonce / epoch / unavailable | 一次性业务号、权限代次、不可用位。 | X 管 A/7/42，同键最多成功消费一次，不按不同 digest 各给一次机会。 |
| txNonce / Permit nonce / challenge | 账户交易序号、Token 授权签名序号、登录挑战。 | 与 X 意图 nonce 分属不同状态机，数字相同不表示权限互通。 |
| deadline / block.timestamp | 执行期限、执行区块时间。 | 本例 T0+120 秒，等于期限仍允许，超过才拒绝，不看请求到达时刻。 |
| 预检 / 模拟 / ACCEPTED | 历史状态下提前检查、本地已受理。 | 既不锁资也不保证成交，Token 与 X 才掌握执行时的权威状态。 |
| 原子性 / revert / Gas | 本笔共同提交、整笔回滚、执行成本。 | 本次资金、nonce、事件一起成败；历史独立 approve 与 R 的已耗 Gas 不随之消失。 |
| cancelNonce / raiseEpoch | 取消一个当前代次的权限、提高代次批量失效旧权限。 | 由 owner 链上发起，与执行竞争；删任务、登出或停 R 都不能代替。 |
| Permit / EIP-2612 | 以签名修改 Token allowance 的扩展机制。 | 非基线能力；签名提交期限不使已建立额度自动到期，新入口须明确合约与域。 |
| ERC-1271 / 委托密钥 | 合约钱包验签标准、代表钱包执行受限动作的密钥。 | 显式改成钱包 owner 后按当前状态验权；只读验签不独自消费累计预算。 |
| SIWE / 会话 | 钱包登录身份声明、服务端访问凭据。 | 挑战消费与会话创建共同原子提交，登录成功不产生兑换签名或 Token 额度。 |
| jobID / payloadHash / 策略版本 | 签名任务号、固定载荷指纹、准入规则代次。 | 独立签名服务绑定 R 的完整交易、审批和费用预算，派发前复核当前权限。 |
| HSM / KMS / MPC | 受保护密钥硬件、管理服务、多方协作签名。 | 保护材料或分散控制，不自动理解业务合法性、费用风险和撤权需求。 |
| 超时 / 围栏 / keyVersion | 结果未及时返回、拒绝旧工作资格、本地密钥版本。 | 沿原任务恢复可能已签结果；本地停用或围栏不能撤回已生成的有效交易签名。 |
| 回执 / 最终性 / 重组 | 执行结果、声明的确认政策、规范分支变化。 | 签名、广播、包含和最终确认分开；分支变更时撤回旧观察并重查。 |
| 审计证据 / 受限结果存储 | 最小充分留痕、专门保存恢复所需材料的位置。 | 日志只作关联，不散布可复用签名、原始交易、私钥或秘密份额。 |

## 把整篇文章压缩成一个故事

**起因：** 小林的普通账户 A 有 1500 USDC、0 WETH，已在一笔独立且确认的 approve 中给不可升级合约 X 恰好 1000 USDC 额度。小林审阅并签下一次花 1000 USDC、至少收 0.49 WETH 的结构化意图，域是 OneTrade / 1 / 链 1 / X，收款人仍为 A，nonce=42、epoch=7、deadline=T0+120 秒，路线也固定。签名不锁钱、不广播，基线不包含 Permit、合约钱包或平台托管用户密钥，业务费为 0，任何 Relayer 均可转发。

**处理及异常：** Go 严格解析并预检后保存固定载荷，独立签名服务检查 R 发往 X 的完整交易和 Gas 预算，用受保护的 K_R 签外层交易。X 在执行时重新验域、业务字段、签名、期限、epoch 和 nonce，在重入保护下先标记权限再拉币与受控兑换；若实际只有 0.48 WETH，本次资金、额度消耗、nonce 和事件一起回滚，但原独立 approve 仍在，R 可能付 Gas。若签名调用超时，先恢复原作业，不当作未签；小林若请求取消，须发链上取消或提高 epoch，与已经在途的兑换争先成功提交，单纯停 R 或登出都无效。

**结果及边界：** 成功样例实际到账 0.50 WETH，A 变为 1500−1000=500 USDC、0.50 WETH，本教学普通消耗模型的 allowance 为 0，A/7/42 不可再成功使用；系统还要核验业务事件、区块身份与确认政策，遇重组修正旧观察。一般只保证输出不少于 0.49，期限相等仍可执行，不保证公允价格、及时成交或撤销抢先成功。登录、Token 授权、兑换意图和 R 费用权限分别治理；HSM/MPC、换钥和本地围栏不能消灭既有签名，审计也不能靠扩散这些签名来换可见性。本专题是防御性教材与手工推演，不是已部署、实测或审计通过的系统。

## 一、文字全流程

### 1.1 先锁定讨论基线

本专题采用 **EVM 非托管钱包 + EIP-712 一次性兑换意图 + Relayer 代付 Gas + 合约原子执行** 的教学模型。

- 用户普通 EOA `A` 自持私钥；平台不保管、不索取、不备份该私钥。
- `X` 为不可升级的兑换执行合约；教学域为 `name=OneTrade`、`version=1`、`chainId=1`、`verifyingContract=X`。`A`、`X`、`R` 均为符号占位，不是可运行地址或真实品牌服务。
- USDC 精度为 6、WETH 精度为 18；只支持普通 ERC-20，不支持扣税、重基准或任意回调型代币。题中余额与 allowance 消耗遵循本教学代币模型，不能外推所有代币。
- 用户已经在一笔**独立且已确认的 approve 交易**中向 `X` 授权恰好 1000 USDC。主流程不假设每笔兑换都再次 approve，也不默认使用 Permit。
- 一份意图精确输入 1000 USDC，至少收到 0.49 WETH，全部成交或全部回滚，不允许部分成交；协议业务费为 0，Gas 由 Relayer `R` 承担。
- `X` 同时约束资产、收款人、路线和最小输出。任何 Relayer 都可提交同一合法意图；基线不承诺只有本平台能够执行它。
- 链下服务做预检、任务管理和查询；Token 合约掌握余额与 allowance，`X` 掌握意图 nonce、epoch 与执行结果。链下数据库没有撤销链上权限。

合约钱包、Permit、委托密钥、MPC、可升级合约均在相关母题中**明确改变前提后**比较，不把它们偷偷加入基线。

### 1.2 贯穿案例：1000 USDC 换取至少 0.49 WETH

| 项目 | 初始值或约束 | 成功后的结果 |
|---|---|---|
| 用户资产 | 1500 USDC、0 WETH | 500 USDC、0.50 WETH |
| 用户到 X 的授权 | 1000 USDC | 本模型中消耗后为 0 |
| amountIn | `1000000000` 个 USDC 最小单位 | 精确花费 1000 USDC |
| minAmountOut | `490000000000000000` 个 WETH 最小单位 | 实际到账 `500000000000000000` |
| 业务 nonce | `42` | 当前 epoch 下该 nonce 不可再次使用 |
| epoch | `currentEpoch[A]=7` | 本次兑换不改变 epoch |
| deadline | `T0+120 秒` | 必须在链上时间不晚于 deadline 时执行 |
| recipient | `A` | 不能由提交者改成其他地址 |
| Gas | R 支付 | 即使兑换回滚，R 仍可能支付 Gas |

`T0` 与 deadline 均为 Unix 秒级时间戳，后续使用链上 `block.timestamp` 比较，不把服务端收到请求的时间当成执行时间。数值中的“实际 0.50 WETH”仅为成功分支输入，不是签名保证的固定报价。签名保障的是不少于 0.49 WETH；预检时的价格也不是最终执行承诺。

### 1.3 主链路：从意图到资金结果

```text
用户在钱包界面确认兑换意图
    输入：链、执行合约、资产、1000 USDC、最小 0.49 WETH、收款人、路线、期限
    ↓
前端构造并展示完整 EIP-712 消息
    域绑定 chainId=1 与 X；应用 nonce=42、epoch=7
    ↓
钱包 A 依据自身确认策略签名
    产生签名，不广播交易、不冻结1000 USDC、不消耗链上 nonce
    ↓
Go 接入服务接收〔结构化意图、签名、请求身份〕
    严格解析整数与地址 → 重算摘要 → 验签 → 检查域/期限/路线
    读取指定链状态进行余额、allowance、nonce 与 epoch 预检
    ├─ 不满足 → 拒绝或标记暂不可执行，不伪造链上终态
    └─ 满足 → 持久记录不可变载荷与任务，准备转发
                    ↓
Relayer R 构造发往 X 的外层交易
    签名服务独立核对完整交易、策略与 Gas 上限
    使用 R 的 Gas 密钥签名；不是代替 A 签署兑换意图
                    ↓
广播并跟踪该外层交易
    广播返回/进入内存池都不代表兑换完成
                    ↓
X 在同一 EVM 事务内作最终裁决
    检查当前域、业务字段、deadline、epoch、nonce、A 的签名
    启用重入保护 → 先标记 nonce 不可用 → transferFrom A
    按受控路线兑换 → 校验精确输入与实际输出 → 将输出交给 A
    ├─ 任一步失败 → 本事务资金、nonce 和事件一起回滚
    └─ 全部成功 → 余额变更、nonce 消费与执行事件一起提交
                    ↓
Go 索引服务读取回执、事件与区块身份
    先标记链上已包含，再依据目标链最终性政策升级确认状态
    重组时撤回旧投影，重新核对 nonce、资金与交易归属
                    ↓
用户看到带确认等级的兑换结果
    成功：500 USDC + 0.50 WETH；nonce 已消费；R 支付 Gas
    失败：本次兑换未动用户资产，但先前独立 approve 不会因此消失
```

`X` 的受控路线不是“用户给什么 calldata 就执行什么”。它只支持批准的交易目标、选择器、代币和池，规范化路线先做哈希再纳入签名；不得任意 `call` 或 `delegatecall`。内部向交易场所的必要授权也要按精确额度和限定目标管理，不能让用户的有限授权变成合约对未知目标的无限授权。

### 1.4 主要异常与取消分支

```text
用户拒签 / 消息域错误 / 整数越界 / 编码不一致
    → 不生成可受理的合法意图，不进入后续执行

链下预检通过 → 用户随后转走 USDC 或撤回 allowance
    → X 执行时失败并回滚；预检不预留资金

用户请求链下取消
    → 停止自身未发任务只是本地措施
    → 真正撤销：A 发 cancelNonce(7,42) 或提高自身 epoch
    → 取消先被链上执行：兑换拒绝
    → 兑换先被链上执行：取消不能逆转已完成资金转移

R 的签名调用超时 / 广播请求超时
    → 标记对应阶段结果未知，恢复原任务与签名/交易身份
    → 不把超时当作未签、未发、未执行

链上输出不足 0.49 WETH
    → 兑换、转账和 nonce 标记全部回滚；R 可能损失 Gas
    → 不等于意图永久作废，在期限内仍可能再次成功

交易已包含但未达到最终性政策
    → 对外只承诺当前确认等级
    → 重组后重新核验，不让离线“已完成”覆盖新链事实
```

### 1.5 分开理解状态与完成含义

| 对象 | 状态归属 | 当前状态能证明什么 | 不能证明什么 |
|---|---|---|---|
| 钱包签名 | A 的钱包 | A 签过特定摘要 | 钱被冻结、业务已受理、签名未泄露 |
| 任务 ACCEPTED | Go 持久任务 | 服务记录了固定意图 | 链上有足额资产、一定成交 |
| Relayer 签名 | R 的签名系统 | 某外层交易可能具备广播能力 | 已广播、签名仅有一份、A 的权限扩大 |
| 已广播 | 节点/网络观察 | 某次提交已尝试 | 必定上链、永不被替换 |
| 已包含成功 | 区块中的 X/Token 状态 | 该区块上下文内执行成功 | 不会重组、任意链都已有相同最终性 |
| 已确认/最终化 | 目标链政策与证据 | 达到声明的确认条件 | 可以把别链的确认规则直接套用 |
| 链下取消 | 本地任务 | 自身可以停止部分后续动作 | 其他 Relayer 不能使用已取得的签名 |
| 链上 nonce 失效 | X | 指定作用域的意图已不可执行 | ERC-20 allowance 已清零 |

## 二、核心板块

| 核心板块 | 决定什么、为什么核心 | 权威状态与上下游契约 |
|---|---|---|
| 意图表达与钱包确认 | 用户究竟同意了哪些资产动作；错一个字段就可能错一项权限 | 前端展示与钱包实际签名须对应同一消息；合约重建同一摘要 |
| 密码学与账户验证 | 谁能代表 owner 认可这份摘要 | 普通 EOA 恢复地址；扩展的已部署合约钱包按 ERC-1271 验证 |
| 授权生命周期 | 一份签名能用几次、在哪里用、何时失效 | X 的 nonce/epoch/期限裁决；Token 的 allowance 是另一套状态 |
| 执行与资产边界 | 授权是否只造成预期资产变化 | X 的局部原子性覆盖 nonce 与资金调用；签名不替代余额检查 |
| 服务端签名与密钥托管 | Go 服务被滥用时能否扩大 Gas 或资产权限 | 独立策略、固定载荷、有限密钥操作；HSM/MPC 不自行理解交易业务 |
| 恢复与审计 | 超时、轮换、失陷后能否知道还剩哪些有效权限 | 不可变任务身份、签名证据、链上撤销和受控应急动作 |

链上交易构造、广播、替换与最终性只保留本题所需的签名边界；撮合、定价和资金账本不展开成另一套专题。

## 三、核心 20%

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| 域与完整字段绑定 | 生成意图、合约验签 | 确定权限对象和用途 | 同一签名被改收款人、换链或换执行合约 | 类型哈希、动态字段、routeHash、版本 |
| 严格验签与整数编码 | Go 入口、X 执行 | 两端必须认可同一个摘要 | 验签通过却执行不同数据，或误拒合法签名 | Keccak、uint256、low-s、v、合约账户 |
| nonce 原子消费 | X 执行 | 防同域多次成功 | 两个 Relayer 重复转走资产 | owner/epoch/nonce 作用域、先标记、回滚 |
| 取消与 epoch 裁决 | 用户撤销、链上执行 | 撤销必须落实到权威状态 | 以为删任务就撤销已外泄权限 | 链上排序、期限边界、最终性 |
| approve/permit/意图分离 | 资产授权、兑换 | 三者授权对象不同 | 把 allowance 到期、签名到期和兑换完成混为一谈 | spender、permit nonce、已有授权残留 |
| 身份与能力分离 | 登录、交易接入 | 登录只能建立有限会话 | 一次登录被当成任意转账授权 | SIWE 域、挑战、会话、操作权限 |
| 独立签名策略 | R 交易签名 | 防“任何哈希都签”的签名机 | 密钥未泄露也可被远程滥用 | 完整交易绑定、策略版本、费用预算、TOCTOU |
| 密钥不可导出与权限治理 | HSM/KMS/MPC | 限制秘密泄露与单点控制 | 把硬件保管误当成业务防火墙 | 阈值、审批、管理员、备份、恢复 |
| 未知结果恢复 | 签名与广播超时 | 有效签名产生后不可当没发生 | 重签、双发、误释放预算 | jobID、payloadHash、原结果查询、阶段证据 |
| 撤权与失陷收敛 | 轮换、事故 | 停用旧密钥不等于撤销旧权限 | 旧签名、旧地址余额和 allowance 遗留 | 地址迁移、epoch、allowance、未决交易 |

这里的“20%”是对正确性和架构影响最大的机制，不是只讲 20% 的流程，也不是把题数压到固定五题。

## 四、设计与规则

### 4.1 签名对象与摘要

自定义意图类型固定如下；字段顺序和类型也是协议的一部分：

```text
SwapIntent(
    address owner,
    address tokenIn,
    address tokenOut,
    uint256 amountIn,
    uint256 minAmountOut,
    address recipient,
    uint256 nonce,
    uint256 epoch,
    uint256 deadline,
    bytes32 routeHash
)

SwapIntentTypeHash = keccak256("SwapIntent(address owner,address tokenIn,address tokenOut,uint256 amountIn,uint256 minAmountOut,address recipient,uint256 nonce,uint256 epoch,uint256 deadline,bytes32 routeHash)")
routeHash = keccak256(abi.encode(固定类型、规范编码的路线计划))
structHash = keccak256(abi.encode(SwapIntentTypeHash, 按声明顺序编码的全部字段))
digest = keccak256(0x19 || 0x01 || domainSeparator || structHash)
```

域类型为 `EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)`，其结构哈希包含域类型哈希、`keccak256(bytes(name))`、`keccak256(bytes(version))`、chainId 和 X 的标准 32 字节 ABI 编码。摘要中的 `0x19`、`0x01` 是原始字节，不是字符串字符。

这不是直接哈希 JSON，不额外加 `personal_sign` 消息前缀；EIP-712 也不自动提供同域一次性执行保证。`routeHash` 绑定的是路线内容，不代表路线天然安全，`X` 仍需检查其可执行范围。界面至少明确展示链、合约、资产、额度、最小输出、recipient、期限和路线语义；签了无法理解的哈希并不会消除盲签风险。

Go 使用受界限约束的整数解析和独立 `big.Int` 值，不经 `float64` 转换。签名编码只接受明确支持的格式，并在协议边界完成 `v` 适配；不在失败后轮流尝试不同哈希/前缀直至“有一种成功”。

### 4.2 业务规则与不变量

1. **完整绑定**：本例同一摘要固定 owner、输入/输出代币、输入金额、最小输出、recipient、nonce、epoch、期限与路线，不能只签金额。
2. **单次成功**：在同一链历史中，对键 `(chainId,X,owner,epoch,nonce)` 最多有一次成功执行；同键签两个不同内容也不能各成功一次。
3. **权限有效**：执行时要求 `epoch == currentEpoch[owner]`、`block.timestamp <= deadline`、nonce 未使用/取消且签名有效。deadline 相等允许，超过才拒绝。
4. **原子提交**：nonce 消费、用户输入扣除、受控兑换与输出交付同属一个 EVM 事务；任意一步 revert，这些变化一起回滚。重入锁覆盖涉及相同权限和资产状态的外部调用路径。
5. **资产结果**：本模型中 `USDC_A_after=1500-1000=500`；`WETH_A_after-WETH_A_before >= 0.49`，成功样例为 0.50；不能拿“路由声称输出”替代真实到账核对。
6. **不做资金预留承诺**：签名后用户仍能花掉资金或改变 allowance。Go 预检只描述所读区块状态，不给执行保证。
7. **独立授权不倒退**：独立 approve 不随兑换失败回滚；Permit 的期限限制提交，不让已建立的 allowance 自动到期。
8. **取消有作用域**：取消意图不撤销 Token allowance，不撤销 SIWE 会话；轮换 R 的 Gas 密钥不撤销 A 的意图签名。
9. **外层权限有限**：R 的签名只能使外层交易可提交，不能代替 A 修改意图；任何人可转发合法意图，故停止自身 Relayer 不是全局撤销。
10. **证据分阶段**：受理、签发、广播、包含、最终性分别给证据，不用“失败”一个词覆盖明确拒绝与未知结果。

### 4.3 架构、决策权与执行权

```text
A 的钱包〔用户密钥、意图确认〕
    └─ 仅交付结构化消息和签名，不交付私钥
               ↓
Go 接入/任务服务〔预检、不可变任务、查询投影〕
    ├─ 读取目标链 X / Token 状态；没有权力代替它们裁决
    └─ 提交明确交易方案给独立签名服务
                        ↓
签名策略服务〔调用方鉴权、载荷验证、费用预算、审批、keyVersion〕
                        ↓
HSM/KMS〔保存 R 的密钥并执行批准的密码运算〕
    或明确替换为 MPC〔由参与方联合执行签名〕
                        ↓
Relayer 广播与跟踪〔外层交易身份，不拥有用户资金权限〕
                        ↓
EVM：X〔验意图、nonce/epoch、受控执行〕
     Token〔余额与 allowance〕
     受支持的兑换场所〔兑换资产流〕
                        ↓
回执/事件/区块 → Go 查询投影 → 用户可见结果
```

托管提现模型会改变资金控制者，需要另一套平台资产审批与密钥基线；不能把本例中 R 的 Gas 密钥描述成控制用户 1500 USDC 的“平台热钱包”。

### 4.4 核心对象与交互边界

| 对象 | 必要字段 | 提交或核验边界 |
|---|---|---|
| 用户意图 | 完整 SwapIntent、domain、signature、digest | 钱包所签内容与 X 重建内容一致 |
| 意图权威状态 | `currentEpoch[owner]`、`unavailable[owner][epoch][nonce]` | X 的同一 EVM 事务；不可用位由成功执行或链上取消设置 |
| Token 授权 | owner、spender=X、allowance | Token 合约；不是 Go 任务字段 |
| 转发任务 | intentID/digest、requestID、固定 payloadHash、阶段、证据引用 | 持久受理；同请求不同内容明确冲突 |
| R 签名任务 | jobID、chainId、R、to=X、value=0、calldataHash、txNonce、Gas/费用上限、policyVersion、keyVersion | 独立验证、额度预占、签名结果与状态记录 |
| 外层交易 | 完整编码载荷、签名/交易哈希、替换关联、广播尝试 | 密码学签发不与数据库或广播原子提交 |
| 链上结果 | blockHash/number、txHash、logIndex、digest、确认等级 | 回执/事件投影可撤回；最终性政策单独声明 |
| 审计证据 | 调用身份、决策、策略/密钥版本、载荷摘要、状态迁移、链上引用 | 不记私钥、助记词、MPC 秘密份额或通用日志里的可复用签名原文 |

用于后续恢复、必须保留的完整签名/已签交易，应放入访问受控、可审计的专门结果存储；“不进通用日志”不等于“恢复所需数据一律不保存”。

nonce 命名空间必须分开：

```text
意图 nonce：      X 解释的 owner/epoch/nonce，本例为 A/7/42
R 交易 nonce：   目标链 R 的外层交易顺序
A 交易 nonce：   A 发 approve/cancel 等普通交易时的顺序
Permit nonce：   Token 合约维护的授权签名序号
登录 challenge：服务端维护的随机一次性挑战
```

### 4.5 实现选择与边界

- X 使用 owner/epoch/nonce 不可用位或可验证的位图；位图优化不能改变作用域和取消语义。执行前写入，失败时依 EVM 事务回滚，不在链下“补偿”已确认资产结果。
- Go 层使用不可变意图对象、持久唯一键、有限队列及恢复任务；进程内 mutex 不能覆盖多实例、外部 Relayer 或链上并发。
- 为 R 的签名做独立策略解析和有限预算。审批绑定完整有效载荷与策略/密钥版本；“HSM 不导出私钥”不意味着它能识别错误 recipient 或恶意 calldata。
- 普通 EOA 验签和已部署 ERC-1271 合约验签分别处理；真实钱包还可能涉及委托代码或反事实账户，不能仅凭 `hasCode` 把所有现实钱包永久二分。本专题不实现这些额外账户标准。
- 模拟结果不能代替执行时检查；用户/链状态、区块时间、合约钱包策略和兑换价格都可能变化。
- 性能优化只能缓存具有正确生命周期的材料；不得永久缓存 ERC-1271 的“有效”、nonce 可用性或撤销后的策略批准。

## 七、工程实践：唯一简洁 MVP

### 7.1 目标与范围

只手工验证 **同域意图的单次消费、取消竞争、epoch 作废、失败回滚** 这一小闭环。不实现 Token 转账、兑换路线、Relayer、HSM、登录或可运行合约；`执行后续成功`只是模拟本次 EVM 事务后续是否 revert 的布尔输入，绝不表示真实资金结算完成。

签名校验使用明确的密码学原语：`严格恢复EOA(digest,signature)` 校验长度、r/s 范围、low-s、v 后恢复地址，失败即报错；摘要按第四部分的固定 EIP-712 类型与域计算。这里不展开椭圆曲线算法，不用其代替 nonce 或原子性的实现。MVP 的输入范围限定为本例 A 签出的、路线与资产字段均已确定的普通 EOA 意图；伪代码中的字段合法性要求是这个小闭环的前置条件，不冒称实现了通用路线验证器。

### 7.2 核心伪代码

以下是 EVM 原子事务语义的教学伪代码，不是数据库能与区块链共用事务的承诺。`暂态写集`只在该事务成功时提交；revert 丢弃整个写集。

```text
常量 本链 = 1，执行合约 = X，固定域 = (OneTrade, 1, 本链, X)
状态 currentEpoch[A] = 7；unavailable[owner, epoch, nonce] 默认 false

执行意图(i, signature, now, 传入域, 执行后续成功):  // 一次原子事务，禁止重入
    要求 传入域 == 固定域
    要求 i 的地址、uint256范围、资产、recipient与受控routeHash均合法
    要求 i.epoch == currentEpoch[i.owner]
    要求 now <= i.deadline
    k = (i.owner, i.epoch, i.nonce)
    要求 unavailable[k] == false
    typeHash = keccak256(第四部分固定SwapIntent类型字符串)
    structHash = keccak256(abi.encode(typeHash, i的全部字段且顺序固定))
    domainHash = keccak256(按EIP712编码固定域)
    digest = keccak256(0x19 || 0x01 || domainHash || structHash)
    要求 严格恢复EOA(digest, signature) == i.owner 且 owner非零
    暂态写集.unavailable[k] = true
    如果 执行后续成功 == false:
        revert，丢弃写集与暂态事件；输出“本次失败，nonce未消费”
    否则:
        暂态写集.事件 += Executed(digest, k)
        原子提交写集；输出“本次消费成功”

取消nonce(owner, epoch, nonce, caller):  // 另一笔原子事务
    要求 caller == owner 且 epoch == currentEpoch[owner]
    k = (owner, epoch, nonce)
    如果 unavailable[k]: 返回 AlreadyUnavailable（不revert），不重复产生取消事件
    否则: 原子写入 unavailable[k] = true 并记录 Cancelled(k)

提高epoch(owner, newEpoch, caller):     // 另一笔原子事务
    要求 caller == owner
    要求 newEpoch在uint256范围 且 newEpoch > currentEpoch[owner]
    原子写入 currentEpoch[owner] = newEpoch
```

真正的 X 把资金调用放在 nonce 暂态标记之后、事务提交之前，任意后续错误 revert。这里刻意不编造一个名为“安全兑换()”的函数来假装已实现路线白名单、资产守恒与重入防护。

### 7.3 输入与预期结果

除“继续执行”明确说明外，以下各行**独立重置为 A/7/42 未使用、合法签名、deadline=T0+120**。这些是手工推演的预期，不是已执行测试报告。

| 输入或时序 | 预期结果 |
|---|---|
| `now=T0+30`，执行后续成功 | 消费成功，`unavailable[A,7,42]=true`，产生 Executed |
| 上一行之后，另一个 Relayer 再提交同一意图 | 拒绝，不产生第二次 Executed |
| 同一个 nonce=42 的另一份不同金额意图也有合法签名，先后执行 | 第一份成功后第二份仍拒绝；不是“每个 digest 各一次” |
| `cancel(A,7,42)` 先执行，再执行意图 | 取消成功，兑换拒绝；不承诺 Token allowance 变化 |
| 执行意图先成功，再 cancel 同键 | 返回已不可用；取消不能逆转兑换 |
| `now=deadline`，其余合法 | 允许消费；`now=deadline+1` 则拒绝 |
| 提高 epoch 到 8，再执行 epoch=7 的签名 | 拒绝；把签名中的 epoch 改成 8 也会破坏原签名 |
| 执行后续失败，再在期限内以成功条件重试 | 第一次丢弃不可用位和事件，第二次可成功 |
| 传入不同 chainId 或不同 verifyingContract | 域不匹配，拒绝，不消费 nonce |
| B 作为 caller 取消 A 的 nonce | 拒绝；不能让任意提交者替 owner 撤权 |

MVP 不模拟重组。主文中的“一次成功”限定在同一有效链历史；发生重组时，链下应恢复到新链状态，不能拿旧链的事件强行标记新链 nonce 已消费。

## 八、规范依据与交付边界

- [EIP-712](https://eips.ethereum.org/EIPS/eip-712)：结构化数据摘要与域隔离；**不自行提供重放保护**。
- [ERC-2612](https://eips.ethereum.org/EIPS/eip-2612)：Permit 的 nonce、deadline 与 allowance 语义。
- [ERC-1271](https://eips.ethereum.org/EIPS/eip-1271)：合约签名验证与返回魔数；有效性可以依赖状态。
- [ERC-4361](https://eips.ethereum.org/EIPS/eip-4361)：SIWE 登录消息、域、挑战和会话约束。
- [OpenZeppelin 密码学工具文档](https://docs.openzeppelin.com/contracts/5.x/api/utils/cryptography)：ECDSA 严格验证与 SignatureChecker 的账户边界；具体实现仍需锁定实际使用的库版本。
