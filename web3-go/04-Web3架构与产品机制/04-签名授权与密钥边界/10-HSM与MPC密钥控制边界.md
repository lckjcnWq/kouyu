# 大问题 10：HSM 与 MPC 分别保护哪一层密钥权限，为什么都不能替代业务风控？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| HSM / KMS | 硬件安全模块、密钥管理服务。 | 保护并受控使用 R 的 Gas 私钥，不是托管 A 的用户私钥。 |
| K_R / 不可导出 | R 的秘密密钥、不能按普通接口取出密钥材料。 | 降低秘密泄露面，不阻止持合法凭据者请求设备签出坏交易。 |
| 设备调用授权 / 业务合法性 | 谁能调用签名接口、该交易是否值得且允许签。 | 设备允许一次密码运算，不说明 recipient、路线和 Gas 风险正确。 |
| secp256k1 / ECDSA | 目标曲线、普通 EVM 账户的签名机制。 | 设备须实际支持，不能因名称叫 KMS 就默认兼容。 |
| digest / Keccak | 交易的待签摘要、以太坊使用的哈希。 | 不能让设备误做二次哈希，也不能混成 A 的 EIP-712 意图摘要。 |
| DER / r / s / low-s | 一种签名编码、两个签名整数、s 的规范范围。 | 严格解码、检查并规范化，再核对预期密钥和摘要。 |
| v / 恢复位 / 地址 R | 恢复信息、用于恢复公钥的选择、预期发送账户。 | 按交易类型正确封装并验证，不随便猜 v 或套消息签名规则。 |
| policyVersion / keyVersion / TOCTOU | 策略版本、密钥版本、检查与使用间条件变化。 | 派发前仍要复核当前权限，设备已接受后的签名不能靠本地停用抹掉。 |
| MPC / 门限签名 | 多方计算、达到规定人数才联合产生签名。 | 明确替换 R 的基础设施，不是拼几段普通签名或自动变成链上多签。 |
| 2-of-3 / 份额 | 三方中两方协作的阈值、各方持有的秘密材料。 | 正常签名目标是不重构完整私钥，但仍需具体安全协议与实现。 |
| DKG / R_m | 分布式密钥生成、替代方案的新 Relayer 地址。 | 新生成公钥通常意味着新地址，其 Gas 和交易 nonce 单独管理。 |
| 独立故障域 / 协调器 | 不会被同一次失陷一起控制的边界、组织多方协议的节点。 | 同一管理凭据或镜像驱动足够参与方，会削弱名义门限收益。 |
| sessionID / payloadHash | 门限协议会话号、固定业务载荷指纹。 | 参与方须对齐同一内容与版本，不能盲信协调器给出的裸摘要。 |
| 预签名材料 / 轮次 | 协议中的预计算秘密及中间状态、协作步骤。 | 重试必须遵守一次性与恢复规则，不随意复用或跨摘要混用。 |
| 份额刷新 / 备份恢复 | 更新持有份额、从备份重建可用能力。 | 同公钥刷新不撤销旧签名；备份若集中到一人可恢复，就形成旁路单点。 |
| 阈值不足 / 业务风控 | 无法达到必要参与数、预算与异常请求治理。 | 应停止签名而非降低阈值；足够参与方也可能共同批准规则内的危险请求。 |

## 把整篇文章压缩成一个故事

**起因：** 小林的 A 自己签了花 1000 USDC、至少收 0.49 WETH 的意图，平台只为转发者 R 保管 Gas 私钥 K_R。团队把 K_R 放进 HSM，希望业务进程失陷时也难以导出秘密。接入时仍要逐项核对目标曲线、输入摘要方式、DER 输出、r/s、low-s 和恢复信息，确认签名确实属于 R 的这份外层交易。

**处理及异常：** 假设攻击者拿到了合法调用凭据，提交规则内却浪费 Gas 的请求，HSM 未必会拒绝，因为“不导出密钥”和“不签坏业务”是两层。团队比较 2-of-3 MPC 替代方案：新一轮密钥生成通常对应新地址 R_m，参与方要有独立控制边界，并核对同一载荷或可信审批，而不是全听一个协调器。若某方掉线超时，先恢复原会话与结果，不任意复用预计算材料，也不能认定其他参与方还没拿到最终签名。

**结果及边界：** HSM 降低材料暴露风险，真正独立的门限方案分散签名控制，但达到阈值的参与方仍可能共同批准错误规则，二者都离不开策略、预算、审批与异常治理。刷新份额若保留公钥，已签交易不会失效；停用设备、本地版本号和围栏也不能撤回已生成签名。备份恢复不能让单个管理员收齐足够份额，阈值不足应停止而非明文降级；A 的意图、Token allowance 与 X 的执行规则仍须分别保护，本文不声称已测某款设备或门限库。

**流程位置与核心机制：** 本题位于签名服务通过策略审批后，到密钥设备或多方协议产出外层交易签名的边界。核心是区分私钥材料保护、签名调用授权、分布式信任与业务合法性，并说明超时、轮换和份额恢复不会自动撤销既有签名。

**沿用基线与扩展边界：** 用户 A 为自持私钥的普通 EOA，初始 1500 USDC、0 WETH，已独立 approve 不可升级的 X 恰好 1000 USDC。用户意图域是教学 `chainId=1 / OneTrade / 1 / X`，字段固定为 `owner、tokenIn、tokenOut、amountIn、minAmountOut、recipient、nonce、epoch、deadline、routeHash`，取 `recipient=A、nonce=42、epoch=7、deadline=T0+120秒`，截止相等允许。兑换花 1000 USDC、至少得 0.49 WETH，示例得 0.50 WETH，不部分成交、业务费为 0。基线只有 Relayer R 的 Gas 私钥 K_R 交给 HSM/KMS；绝不是把 A 的资产私钥托管给平台。MPC 是明确替换 R 签名基础设施的对比方案，不会顺带把用户 EOA 改造成合约钱包或委托账户。

## 第 1 层：不可导出私钥究竟解决了什么

**面试官：** 把 R 的私钥放进 HSM/KMS，就可以说这套非托管兑换协议已经没有密钥风险了吗？

**面试者：** 不能。设备的主要价值是让 K_R 按配置在受保护边界内生成或使用，限制导出、访问和管理操作，降低磁盘泄露、进程内存读取等攻击面。它不等于消除了调用凭据失陷、设备配置错误、供应链或可用性风险，更不等于理解了兑换业务。非托管资产边界来自 A 自持私钥，以及 X 只按用户有效意图执行受限扣款；HSM 保护的是另一个 EOA R 的 Gas 签名权。如果设备被滥用，攻击者可能消耗 R 的 Gas 或签出 R 有权发起的交易，但不能据此伪造 A 的 SwapIntent。反过来，用户签错意图或 X 的执行约束有漏洞，也不会因为 R 用了 HSM 自动变安全。

## 第 2 层：设备签出的 ECDSA 怎样接入 EVM

**面试官：** 你说设备只负责 R 的签名。那么 Go 收到 HSM 的 ECDSA 输出，直接放进以太坊交易字段就可以了吗？

**面试者：** 要先确认具体设备与接口支持 secp256k1，并明确输入是消息还是已计算的 digest，避免设备再次 SHA-256 或误用 SHA3-256。Go 应按交易类型构造精确签名载荷，用 Keccak-256 得到待签 digest；这不是 A 的 EIP-712 意图 digest。设备可能返回 DER 编码的 r、s，需要严格解码、检查范围及非零值，按要求规范化 low-s，再针对预期公钥和 digest 确定正确恢复位并验证地址为 R，不能随便猜一个 v。交易封装与个人消息签名的 v 规则不同，不能从 EIP-155 交易 v 盲减常数来复用。设备是否支持这些步骤必须逐项核对，不能因为叫 KMS 就假设其算法、曲线与编码天然兼容。

## 第 3 层：为什么设备不导出密钥仍可能被滥用

**面试官：** 上一答已经校验签名确实来自 R。如果业务账号有合法调用凭据，却让 HSM 签一份恶意载荷，设备会因为私钥不可导出而拒绝吗？

**面试者：** 通常不会。不可导出约束的是密钥材料，获授权签名请求本来就是设备允许的功能；HSM 不会自动知道 recipient、路线和 Gas 是否合理。因此独立签名服务必须校验链、R、到 X、value 为 0、允许的 selector、完整 calldata hash、txNonce、Gas、费用及 policyVersion、keyVersion 和审批绑定，禁止业务传任意 hash 即签。策略检查到设备派发之间还要有明确的版本复核和撤销切点，防止 TOCTOU。设备一旦接受请求就可能产生有效签名，超时或晚到的停用不能证明没有签过。即使所有技术检查都通过，规则范围内的恶意代付请求仍需额度、频率、异常行为和人工复核等业务风控处理。

## 第 4 层：改用 MPC 改变了哪一个信任假设

**面试官：** 你说单个合法账号仍可能请求危险签名。把 R 的签名改为三方中任意两方参与的 MPC，是否就能去掉独立策略服务？

**面试者：** 不能。这里明确进入替代方案：采用经过审查、支持目标曲线的门限签名协议，让多个参与方持有份额，由达到阈值的参与方协作生成普通 ECDSA 签名，设计目标是不在正常签名过程中重构完整私钥。它不是把两段普通签名字节拼在一起，也不是把 EOA 自动变成链上多签钱包。如果采用新一轮分布式密钥生成，通常会得到新的公钥和地址 R_m，需独立管理其 Gas 与 `(chainId,R_m)` 交易 nonce，不能宣称仍是原 R。MPC 改变的是攻击者需要控制多少密钥参与方；交易语义是否正确仍需各参与方或可信审批层独立判断，A 的资产意图签名权也不会转交给这些参与方。

## 第 5 层：多个参与方为什么仍可能只有一个故障域

**面试官：** 你要求多个参与方判断语义。若三方都运行在同一团队的容器里，只接收协调器发来的 digest 并自动同意，是否已经得到两方门限的安全收益？

**面试者：** 收益会非常受限。同一个管理凭据、同一镜像或同一被攻陷协调器如果能驱动足够参与方，名义上的多方并没有形成独立信任域。参与方应认证请求来源，并绑定同一 sessionID、不可变 payloadHash、链、发送地址、目标、selector、calldata、txNonce、费用、策略及密钥版本；需要按职责独立验证完整载荷或可信审批证明，而不是盲信协调器声称“已审核”。门限协议解决份额协作和签名安全，不自带业务规则。即便协议能抵御少于阈值的恶意方，也不能阻止达到阈值的参与方共同批准坏交易，不能阻止全部诚实参与方执行一条设计错误的规则，更不自动提供限额和反欺诈。

## 第 6 层：门限轮次失败为什么不是可以随意重开

**面试官：** 上一答把请求绑定到 sessionID。如果一方掉线导致门限签名超时，换个会话复用原来的预计算材料，是否只是性能优化？

**面试者：** 不能随意复用。门限 ECDSA 的随机数、预签名材料和轮次状态有协议特定的一次性与恢复要求，错误重用或跨 digest 混用可能泄露密钥信息；不能自己拼接若干 RPC 当作完整协议。应按所选协议持久化会话、参与方集合、轮次和材料状态，隔离不同密钥代际与 payload，重试与恢复遵守实现的安全约束。超时也不证明没有有效签名：协调器或其他参与方可能已拿到最终结果。业务 jobID 与 payloadHash 仍保持不变，先恢复原会话与结果，不另开相同业务权限；签名的字节差异不能当成新的业务身份。若实现无法可靠查询或恢复，应明确未知状态并保守控制权限和预算，而不是声称门限天然恰好一次。

## 第 7 层：份额刷新和备份恢复是否等于撤销旧权限

**面试官：** 你说材料状态要持久化。为了恢复能力，我们备份所有份额并定期刷新，是不是既能保证永不丢失，又能让旧权限立即失效？

**面试者：** 两个保证都不能直接成立。备份必须加密、分离权限和故障域，恢复流程不能让一个管理员轻易收集达到阈值的份额，否则退化回单点控制；可恢复性与防失陷需要共同设计。失去足够份额、达不到阈值时就是不能签，不应自动降级为较低阈值或明文重构完整私钥。刷新份额如果保留原公钥，不会让已经生成的 ECDSA 签名失效；若攻击者保留了足够的旧有效份额或已取得签名，不能仅凭刷新就断言其能力消失。更换本地 keyVersion 也不会改变链上密码学事实。真正换成新公钥会改变 Relayer 地址及相关运营状态，但仍不会撤销 A 之前签给 X 的意图或已经存在的 Token allowance。

## 第 8 层：最终应该如何选择与承诺

**面试官：** 上一答说明恢复和撤权都有代价。那么这套兑换协议应该选择 HSM 还是 MPC，才能给用户一个准确的安全承诺？

**面试者：** 应先按 R 的威胁模型选择，而不是按产品名判断。若主要目标是减少单进程私钥暴露，且接受设备运营方与独立签名策略的信任边界，HSM/KMS 可能更直接；若确需让单个运营方无法独立签名，且能承担多方治理、协议安全、通信和恢复复杂度，才考虑有独立故障域的 MPC。两者都不替代用户意图验签、X 的原子 used 消费、Token allowance、路线白名单和最小输出约束，也不替代业务风控。可以手工检查“合法凭据请求恶意代付”“门限已出签但调用超时”“轮换后旧意图仍有效”三类反例。准确承诺应分别说清材料保护、调用授权、门限假设和剩余风险，不能声称设备或门限让所有获授权恶意请求自动无效。

## 本题收束

- **讲透的机制：** HSM/KMS 着重保护密钥材料和设备访问边界，MPC 把签名能力分散到达到阈值的参与方；两者服务的都是 R 或替代 Relayer 的签名权，不是 A 的资产私钥。
- **最易答错的边界：** 不可导出不等于不能滥用签名接口；门限不等于业务共识或风控；调用超时不等于未签；份额刷新、keyVersion 和设备停用不等于已签消息失效。
- **检验反例：** 两个独立参与方收到同一份带有真实审批、但业务规则错误的载荷并共同签名。MPC 完全可以正确完成协议，同时生成业务上危险的签名。这说明密码学阈值不能替代权限设计、预算与异常请求判断。
- **剩余风险：** 设备曲线与编码兼容性、管理面失陷、门限串谋、相关故障域、恢复旁路和策略 TOCTOU 都需要具体实现与流程证据，不能由“HSM”或“MPC”两个名称推出。
