# 大问题 5：用户签好 Swap 后谁决定执行顺序，滑点、截止时间和 MEV 保护分别能保证什么？

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| Swap / A / C / R / P | 换币动作、主用户、另一交易者、路由合约、池。 | A 用 2000 U 换 W；C 的前置交易是单独变体，不是每个案例都预先发生。 |
| 签名权 / 排序权 / 执行规则 | 用户允许做什么、区块里先做什么、每笔调用按什么代码运行。 | Go 先收到请求不代表能决定链上顺序，R/P 也不负责挑选交易顺序。 |
| Ethereum PoS / 提议者 / 构建者 | 以太坊权益证明共识，以及提出区块、组织交易负载的角色。 | 提议者可自行构建或采用构建者负载，仍须满足有效性和共识规则。 |
| FIFO / mempool | 先到先处理、节点持有待处理交易的集合。 | 服务端队列和公开交易池都不是全链 FIFO 保证。 |
| Q1 / H0 / 储备 | 基于某具体区块的报价、区块身份、池中定价所用资产数量。 | Q1 没有预订储备；前序交易改变储备后，A 必须按新状态执行。 |
| minOut / 滑点容忍 | 最低输出，以及相对报价允许的输出下降范围。 | 本例下限是 990040858528094978 个 W 原子单位，不等于相对公允价的损失上限。 |
| MEV / 夹子形状 | 利用交易纳入和排序等机会提取的价值；常见形状是前买、用户买、后卖。 | 出现这个顺序不自动证明获利，必须计算费用、舍入和 Gas 后结果。 |
| deadline / block.timestamp | 执行期限、区块执行时使用的时间戳。 | 本 R 要求严格早于 t0+120，不保证两分钟内成交，也不证明过期前从未成交。 |
| Gas / 优先费 | 链上执行资源、为纳入交易提供的费用激励。 | 出更高费用不等于买到强制先到先得权。 |
| 顶层交易 / 原子性 | 一笔完整交易及其内部调用共同提交或回滚的边界。 | 别的顶层交易可在 A 整笔之前或之后，不会插在其内部两步之间；内部合约风险另论。 |
| 私有通道 / 保护服务 | 先把签名交易交给指定接收方，而不直接公开传播的路径。 | 改变披露与包含依赖，不保证绝无泄露、零 MEV 或必定成交。 |
| I1 / nonce / txHash | 应用意图、账户交易序号、签名交易哈希。 | 同字节切换入口仍是同交易；同 nonce 替换竞争；新 nonce 可能多换一次。 |
| canonical / receipt / finalized | 当前规范链、执行回执、共识最终确定。 | 先核对实际调用与保护结果，再核对最终检查点祖先关系，不能只信广播反馈。 |

## 把整篇文章压缩成一个故事

小林拿到 2000 U 换 W 的报价，却不知道另一人先用 2000 U 买了 W。池子变了，小林按原报价签名也不会锁住旧价格：本文这个变体中，小林收到 991057653949317359 个 W 原子单位，比原报价少，但仍高于最低输出，所以可以成功。这说明合约兑现下限，不等于没有受交易顺序影响。

如果那个人又卖回 W，也不能只看外形就喊“夹子一定赚钱”。按本文同一费用和整数规则，他们只能换回 1995.966179 U，不计 Gas 已亏 4.033821 U。另一个独立变体若前置买入改成 10000 U，小林输出会低于下限，Swap 应整体拒绝；这才是最小输出保护能给出的具体边界。

小林可以提高费用或换私有通道，但都不能买到必定先成交的承诺，更不能因此撤掉最低输出和期限。私有入口超时后，可继续追踪或重广播原交易，不应悄悄换新 nonce 再买一次。最后看规范链的真实结果和最终性，而不是按哪个接口先说“收到”来裁决。

[返回专题总览](README.md)

**流程位置与核心机制：** 本题覆盖“参考区块报价 → 签名与广播 → 区块构建和排序 → 合约执行 → 包含及最终性核验”。重点是签名授权、区块排序与状态执行三种权力的区别，以及用户保护条件为什么不能等同于公平排序、必定成交或零 MEV。

**必要前提：** 产品、R/P 权限和贯穿金额见[总览](README.md)第 1.1—1.2 节。本题讨论 Ethereum L1 顶层交易的顺序，不引入链下撮合或 FIFO 承诺；A 使用原有 minOut、严格期限和 nonce42。前置交易及私有通道均作为明确的独立变体，不累积改变基线。

## 第 1 层：签名权、排序权和合约执行权分别属于谁？

**面试官：** A 已经签好 2000 U 的 Swap。Go 服务先收到它，是不是就能决定它先于其他交易成交？Ethereum PoS 里的排序和执行究竟由谁决定？

**面试者：** 不能。A 的签名授权的是确定的链、nonce、目标、调用参数和费用约束，不是指定交易在区块中的位置。Go 服务可以构造和转发，节点可以接收或传播，但接收先后不是链上的 FIFO 承诺。区块提议者可以自己构建有效执行负载，也可以采用构建者提供的负载；负载中的交易顺序必须符合 nonce 等有效性规则。网络按共识规则确定 canonical 链，各验证节点按同样顺序执行 EVM。R、P 决定每笔调用怎样转移资产和更新储备，却不能挑选交易先后。因此平台先回“广播成功”，不代表取得了排序权，更不代表该价格已经成交。

## 第 2 层：报价已固定，前面插入一笔合法交易会改变什么？

**面试官：** 你说 P 只按实际顺序执行。现在只增加一个约束：另一用户 C 在 A 前面以 2000 U 买 W，而 A 仍拿 H0 的报价发单，A 会得到原来的数量吗？

**面试者：** 不会。C 先按 H0 的储备获得 `995015938219190933` W 原子量，随后 P 的输入储备变成 1002000 U，输出储备变成 `499004984061780809067` W 原子量。A 的 2000 U 必须按这组执行前储备重新计算，输出变成 `991057653949317359` W 原子量，小于旧报价，但仍高于原 minOut，所以可以成功。这是另一条独立的排序变体，不能再引用无前置交易时 P 的最终余额。QuoteId Q1 只标识基于 H0 的计算，不锁住储备；链上保护的是签入交易的约束，而不是保证重现报价时的市场状态。

## 第 3 层：minOut 通过了，能不能说明这笔交易没有被 MEV 影响？

**面试官：** 上一答中 A 少拿了一些 W，但 minOut 仍通过。如果 C 还在 A 后面卖回 W，这是否就证明发生了可获利夹子攻击？minOut 能否防住这种排序影响？

**面试者：** minOut 只规定最少收到多少，不保证价格没有被顺序影响，也不保证夹子无法获利。但不能看到“前买、用户买、后卖”就编造盈利：在本例 C 前置买入 2000 U、随后把所得 W 全部卖回，按同一费率和整数舍入只能取回 `1995.966179 U`，不计 gas 已亏 `4.033821 U`。它说明用户成交受前序影响，并不构成可盈利攻击的证明；其他规模和外部机会需要重新计算。若单独把前置买入改为 10000 U，A 理论输出降至 `975458386509269124` W 原子量，低于 minOut，整笔 A Swap 应 revert。这个下限只相对 Q1 限定输出，不承诺相对外部公允价的最大损失，更不是公平排序证明。

## 第 4 层：既然价格下限不是顺序保证，deadline 能否限制等待和追溯取消？

**面试官：** 你说 minOut 允许范围内的价格变化。那加上 120 秒 deadline，是否就能保证 A 在两分钟内成交，或者两分钟后证明这笔交易从未成功？

**面试者：** 都不能。deadline 是 R 在实际执行时检查的条件，不是区块提议者必须接纳交易的服务承诺。本例在 `t0+12` 执行可以继续；单独改成 `block.timestamp=t0+120`，由于条件是严格小于，Swap 应 revert，而不是再给一个等号宽限。交易也可能一直未包含，过期不自动产生收据或退费事件。更重要的是，当前时间超过 deadline 不能证明过去没成交：它可能已经在 `t0+12` 的区块中成功，只是服务端漏看。正确做法是追踪原交易及同 nonce 的竞争交易，核实历史包含和 canonical 状态，再给结论，不能依据超时直接新发一笔业务。

## 第 5 层：提高 gas 出价，能不能把时间保护升级成先到先得？

**面试官：** 上一答无法保证及时包含。如果 A 提高优先费，或者平台按请求到达时间排队再广播，能否保证自己先于 C？C 能不能插在 A 的转入和转出之间？

**面试者：** 优先费可以影响交易被选择的经济激励，却不是强制 FIFO 规则；区块构建还可能考虑交易组合、套利收益和其他约束。平台队列只能控制自己的发送次序，不能约束其他入口和区块提议者，同一 A 的连续 nonce 也只限定该账户内部有效顺序。另一方面，本例 A 的转入、P 交换和转出在同一笔原子交易中，其他顶层交易不能被插入其中两步之间；C 能做的是排在整笔 A 之前或之后。合约内部外部调用带来的风险是另一种执行边界，不能混称成 mempool 排序。本模型代币标准、R 入口固定，但仍需代码本身正确，原子性不等于没有漏洞。

## 第 6 层：公开排序不可控，私有通道是不是就等于没有 MEV？

**面试官：** 你把可抢占的位置限定在整笔交易前后。如果 A 不走公开 mempool，改用私有通道或宣称有 MEV 保护的入口，是不是就可以取消 minOut 和 deadline？

**面试者：** 不能。改变广播路径只改变交易先向谁披露，以及依赖谁尝试纳入区块，不改变 P 在执行时读取实际储备的规则。私有入口可能减少公开泄露和抢跑机会，但仍依赖接收方的隐私、转发、构建与包含策略，也未必覆盖所有提议者；不能据此承诺绝不泄露、绝无不利排序或一定及时成交。即便没有恶意观察者，其他合法交易也可能先改变储备，所以 minOut、deadline 和费用上限仍必须保留。若私有路径超时后回退公开广播，需要向用户说明披露条件已经改变，不能默默改成更宽滑点，更不能把“已发送给保护服务”展示为链上已成交。

## 第 7 层：私有路径超时，怎样重试才不会把防 MEV 变成重复 Swap？

**面试官：** 你说私有通道没有包含保证。假设服务端超时后转公开广播，为什么不能给同一个 IntentId I1 再分配一个新 nonce，直到某笔能查到成功？

**面试者：** 因为 I1 只是业务关联标识，P 没有消费 intent 的链上屏障。相同原始交易换入口重广播仍是相同 txHash，不会因此增加一笔可独立执行的 Swap。若为了加价重新签名，仍使用 A 的 nonce 42，txHash 会变化，需要同时追踪两个候选；同一最终链前缀里只能有一笔 nonce 42 被消费，但不能预先指定谁胜出。若改用 nonce 43，原 42 仍可能先成交，43 随后也成交，I1 并不能阻挡第二次扣款。本例 A 起初有 5000 U，不能拿余额不足假装自然去重；额度也可能足够。因此路径切换要先管理原尝试的不确定性，而不是用新 nonce 掩盖超时。

## 第 8 层：只有一笔最终入链，怎样判断保护条件真的兑现了？

**面试官：** 你用 nonce 限制了候选竞争，但收据查询可能先看到 A 成功，随后所在区块又被重组。保护服务和 Go 系统应该在什么时候宣布“按约束最终完成”？

**面试者：** 先把声明拆开：广播回执只证明某入口受理；canonical 收据说明当前链包含；最终完成还要求目标调用语义、minOut、deadline、P 事件及 U/W 转移和状态相互匹配，不能只看 `status=1`。无前置交易的主例应核实 A 获得 `995015938219190933` W 原子量、P 变成 1002000 U 及 `499004984061780809067` W 原子量；有 C 前置的变体则按变体结果核实。最终性依据经验证节点给出的 finalized 区块与交易区块的祖先关系，不按固定区块数拍板。重组就撤回旧观察并重新追踪；最终性破坏则停机人工处置。系统能证明具体约束被兑现，不能证明世界上不存在 MEV。

## 本题收束

**机制：** 签名确定用户授权，区块负载确定交易顺序，R/P 在该顺序下确定资产变化，共识决定哪些执行结果属于 canonical 链及最终前缀。报价不保留执行位置，minOut 限定最差输出，deadline 限定可执行的区块时间，私有通道改变披露和包含依赖。

**易错边界：** 到达时间和高优先费不是 FIFO；同一交易内部原子执行不代表其他交易不能排在其前后。滑点保护不是零 MEV，出现夹子形状也不自动证明盈利。过期不能证明过去未成交，私有入口超时不能触发无条件新 nonce 重试，canonical 已包含不能冒充 finalized。

**具体反例验证：** 仅让 C 在 A 前面买入 2000 U，再按更新储备手工计算 A 的输出，得到 `991057653949317359` W 原子量。该值低于 Q1 报价而高于 `990040858528094978`，所以“minOut 通过就说明未被前序交易影响”被直接否定。再计算 C 的反向卖出可发现扣除池费后不盈利，说明对用户影响、排序机会与攻击者实际收益必须分别举证，不能互相替代。
