## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| DEX / Swap | DEX 是由合约等机制执行交易的去中心化交易系统；Swap 是交换两种资产。 | 这里是单链现货换币，不是买永续合约，也没有平台内部可提款余额。 |
| AMM / 恒定乘积 | AMM 是自动做市商，用池内资产和公式计算交换数量；恒定乘积是其中一种定价规则。 | 教学池持有 U/W，输出随输入和储备变化，不由 Go 撮合买卖单。 |
| A / EOA | A 是案例里的用户地址；EOA 是由私钥控制、能够签交易的外部账户。 | A 自行签名，Go 不保管 A 的私钥；签名也不保证内容符合用户本意。 |
| R / Router / P / LP | R 是组织调用的路由合约，P 是流动性池；LP 是提供池内资产并持有份额的角色。 | R 检查执行条件，P 管池规则和份额；交易者 A 没有 LP 赎回权。 |
| ERC20 / U / W / 原子单位 | ERC20 是一类代币接口；原子单位是金额可表示的最小整数单位。 | U 有 6 位小数，W 有 18 位；W 是封装 ETH 式教学资产，不等于支付 Gas 的原生 ETH。 |
| balance / reserve / allowance | 分别是代币余额、池的储备记录、允许某合约使用的代币额度。 | 余额和授权记在代币合约，储备缓存记在 P；三者不能混成一笔数据库余额。 |
| approve / spender / transferFrom | approve 设置授权；spender 是获授权的使用者；transferFrom 是按权限划转代币。 | A 授权 R，R 只从当前调用者拉取输入；授权不是付款，也不冻结 2000 U。 |
| x / y / a / floor | x、y 是池内两种资产的储备，a 是输入；floor 表示向下取整。 | 用原子整数算输出；997/1000 表示扣除 0.3% 池费后的定价系数，完整输入仍留在池内。 |
| minOut / deadline / recipient | 最小可接受输出、执行期限、收款人。 | 本例收款人为 A，执行时间必须严格早于期限；0.5% 是相对报价的容忍，不是总损失上限。 |
| EVM / 原子性 / revert | EVM 是以太坊执行合约的环境；原子性指一笔交易内相关变化共同提交；revert 是执行回滚。 | Swap 内部失败不能留下半笔换币，但已包含失败的 Gas、账户 nonce 和此前独立 approve 不一起撤销。 |
| Gas / nonce / txHash | Gas 是链上执行资源；nonce 是账户交易序号；txHash 是签名交易的哈希标识。 | 同字节重广播还是原交易，同 nonce 候选相互竞争，新 nonce 则可能再换一次。 |
| I1 / Q1 / attempt | 分别标识应用意图、报价和具体交易尝试。 | 它们帮助 Go 恢复流程，但 P 不识别 I1，不能靠应用唯一键保证链上只换一次。 |
| RPC / canonical / blockHash | RPC 是访问节点的接口；canonical 是当前接受的规范链；blockHash 区分具体区块。 | 节点响应是证据来源，不是资产裁决者；同高度不同哈希不能混用。 |
| included / finalized | included 表示交易被某块包含；finalized 表示在相应共识前提下已最终确定。 | 本例核验包含块与已验证最终检查点的祖先关系，不用固定确认数替代最终性。 |
| observation / active | observation 是某分支内的观察实例；active 表示当前规范归属有效。 | 旧块退出时撤回，重新成为规范历史时可再激活，不是“见过就永久丢弃”。 |
| projection / revision / 水位 | projection 是方便查询的派生视图；revision 是本地修订号；水位说明完整处理到哪里。 | 页面版本不是资产本身；扫描完整与业务关联、核验完整还要分别记录。 |
| Outbox / Inbox | 在本地事务中登记待发消息、已处理消息的可靠交付机制。 | 可恢复投递并识别重复，不把链、数据库和消息系统变成一个共同事务。 |
| MEV / 非托管 / 治理 | MEV 是利用纳入和排序等机会获取的价值；非托管描述资产控制方式；治理涉及修改规则的权限。 | 非托管不保证公平排序、代码无漏洞或无条件退出；本例 R/P 无管理员是明确教学前提。 |

## 把整篇文章压缩成一个故事

小林就是案例里的 A，手中有 5000 U，想拿 2000 U 换 W，另备 ETH 付链上执行费。Go 像计算和办事助手：读取同一区块的池状态，给出报价和最低可收数量；钱包核实链、合约、收款人及权限后由小林签名。需要时先单独授权 R，但授权后钱还在小林地址，既没冻结也没成交。

在本文没有其他状态变化的主例里，R/P 真正执行成功后，小林剩 3000 U，收到 0.995015938219190933 W；池子收进完整的 2000 U。若执行时数量低于下限或已到期限，Swap 内部整体回滚；此前独立授权可能仍在，已包含的失败交易也仍会付 Gas。若广播接口只是超时，助手应该查原交易，不能让小林不知情地用新序号再买一份。

最后还要分清“这条链上看见成功”“按共识要求最终确定”和“页面已更新”。链换了尚未最终确定的分支，页面应撤回旧观察；漏了索引就补扫和重建，而不是再兑换或凭数据库补币。整篇文章反复回答的是同一件事：谁有权动资产、谁只负责观察、每一句成功或退出承诺究竟凭什么成立。

## 一、文字全流程

### 1.1 固定讨论基线

- **产品**：单链现货交换，不涉及保证金、永续持仓或预测市场。
- **机制**：单池恒定乘积 AMM，精确输入、全量交换；链下不撮合订单，不保证报价成交。不采用集中流动性，定价细节不是本专题主线。
- **执行环境**：Ethereum PoS L1，`chainId=1` 是教学链身份；不将 Rollup 排序器回执套成 L1 最终性。
- **参与者**：A 是自行签名发交易的 EOA；Go 服务只提供报价、构造、可选广播、追踪和索引，不持用户私钥、不维护可提款的内部余额。
- **合约**：R 是不可升级、无管理员的教学 Router；P 是不可升级、无管理员的教学池。R 只支持固定的标准代币交换路径，没有任意外部调用或捕获失败后继续返回成功的分支。P 检查输入、费用调整后的不变量并更新储备，持有 LP 份额账本。
- **资产**：教学币 U 为 6 位小数，W 为 18 位小数的 WETH 式封装资产。本例不 unwrap；两币均假设标准 ERC20、无转账税、无 rebase、无升级和黑名单。名称不代表任何实际代币部署。
- **权限**：A 对 R 的 allowance 是资产使用权限，不是给 P 的权限，也不是资金冻结；必要的普通 approve 是独立交易。R 只能从本次调用者 `msg.sender` 拉取输入，主例为 `transferFrom(A,P,amountIn)`，不能让任意调用者指定另一个已授权地址作为付款人。随后调用池；合约不保存应用 `intentId` 消费屏障。
- **执行保护**：接收人固定为 A；R 要求 `block.timestamp < deadline`，检查 `amountOut >= minOut`，任何必要转账失败都向外回滚。等于 deadline 时拒绝是本教学 R 的规则，不泛指所有协议。
- **完成标准**：规范链执行结果、最终性和索引进度分别表示。采用经验证节点提供的 `finalized` 检查点及祖先关系判断正常最终性，不用固定确认数冒充最终性；极端最终性破坏进入应急处置。

上述权限和合约行为是明确的教学假设，不是实际部署审计结论。替代产品、代理升级、特殊代币和其他执行环境只在标明改变前提后比较。

### 1.2 一笔贯穿案例

报价快照是区块 `B0/H0`：

| 对象 | 初始状态 |
|---|---|
| A | 5000 U、0 W，另备原生 ETH 支付 Gas |
| P | 1,000,000 U、500 W；无未同步转入、无其他并发操作的主例快照 |
| 交换 | A 精确输入 2000 U，即 `2000000000` 个 U 原子单位 |
| 费用 | 输入计价费率 0.3%，留在池内；不是再从 A 额外收一笔 U |
| 时间 | `t0=1800000000`，`deadline=t0+120`；主例执行时间为 `t0+12` |
| 身份 | 应用意图 I1、报价 Q1、A 的 Swap 交易 nonce 为 42；若需要 approve，用已完成的前置 nonce 41 |

以原子单位计算，`x=1000000×10^6`、`y=500×10^18`、`a=2000×10^6`：

```text
quotedOut = floor(a × 997 × y / (x × 1000 + a × 997))
          = 995015938219190933 个 W 原子单位
          = 0.995015938219190933 W

minOut = floor(quotedOut × 995 / 1000)
       = 990040858528094978 个 W 原子单位
```

0.5% 是相对本次报价的容忍设置，不是相对外部公允价的最大损失，也不是只有 0.5% 价格影响。主例成功后：

- A：3000 U、`0.995015938219190933 W`；Gas 另以 ETH 支出。
- P：1,002,000 U、`499.004984061780809067 W`。池中计入完整输入，费用没有从储备中再次减掉。
- 无其他主体增减 U/W，逐币种守恒；不能把 U、W、ETH 数值相加证明守恒。

所有异常从该主例单独改变条件，不把多个变体连续叠加成新的隐含基线。

### 1.3 主流程：从用户意图到有证据的结果

```text
A 发起 I1：输入 2000 U 换 W，收款地址 A
    ↓
Go 报价服务验证资产身份与精度，读取同一区块 B0/H0 的池状态
    ↓
计算 Q1：预期输出、minOut、期限、R/P/资产身份与状态版本
    └─ 此时无资金冻结、无成交，也无链上排序优先权
    ↓
钱包核对 chainId、R、调用数据、接收人、输入上限与 Gas
    ↓
若额度不足：A 单独签名 approve(R,额度) → 链上确认可用授权
    └─ approve 完成只改变 U.allowance(A,R)，没有交换 U/W
    ↓
钱包签署 Swap 交易：A、nonce=42、目标 R、固定路径与约束
    ↓
保存意图与交易尝试关联 → 广播原始签名字节 → 跟踪原 hash/nonce
    ├─ RPC 返回 hash：仅表示该接口接受/识别了交易
    └─ RPC 超时：传播未知，不能直接标失败或用新 nonce 再买一份
    ↓
交易进入某个规范区块，按链决定的顺序执行
    ↓
R 检查期限与输出下限，将 U 从 A 转入 P，调用 P 交换 W 给 A
    ↓
P 验证实际输入及费用调整后的不变量，更新储备并产生日志
    ├─ 任一必要步骤失败 → Swap 内部变化整体回滚，已包含失败仍耗 Gas/nonce
    └─ 成功 → U/W 余额、池储备和有效日志构成本分支的交换结果
    ↓
观察并核验调用语义、receipt、区块哈希、相关池与资产事实
    ↓
该包含区块仍在规范链，且成为已验证 finalized 检查点的祖先
    ↓
将结果标为满足本模型最终性 → 索引消费事务更新查询与通知
    ↓
页面展示“最终确认/同步水位”，保留完整身份与证据链
```

R 可以在转账前计算本次输出并检查下限，但必须以执行时状态和真实转账为准；池末尾仍验证不变量。步骤画在同一交易里不表示中间状态已经对下一笔交易提交。

### 1.4 主要分支与完成含义

```text
报价过旧/链身份不符/代币不支持
    → 拒绝构造或要求重新确认；不产生资产交换

approve 成功，随后 Swap 回滚
    → 无 U/W 交换，但 allowance 可能仍在；不能显示“全部授权已撤销”

广播超时或长时间 pending
    → 保留原 attempt，重查/重广播同一原始交易；不自动换新 nonce 执行

用户请求取消
    → 本地停止等待不撤销已签交易；同 nonce 取消交易与 Swap 竞争
    → 以规范链实际包含内容为准，可能取消失败而 Swap 成功

receipt.status=0
    → 本次链上调用无交换效果；Gas 和 EOA nonce 不随内部回滚

receipt.status=1，但目标/事件/收款语义不匹配
    → 不能标 I1 成功；保留证据并报告异常，不伪造本次预期成交

已包含后重组
    → 撤回旧分支投影，恢复待核验；同交易可能重入新区块或再次被移除

最终性来源不可用或 RPC 分歧
    → 保持未知/已包含未最终确认，不按墙上时钟升级成功
```

| 阶段 | 权威变化或承诺 | 不能推出什么 |
|---|---|---|
| Q1 已报价 | Go 保存了对 B0/H0 的计算结果 | 资产已锁定、未来执行价不变 |
| 已授权 | U 合约中的 allowance 变更 | 已成交、R 不可能误用额度 |
| 已签名/已广播 | 出现了可传播交易及本地尝试记录 | 已包含、没有重复经济动作 |
| 已包含且核验成功 | 某个当前规范分支完成了这次交换 | 永不重组、页面已经同步 |
| 满足最终性 | 正常共识假设下，该规范前缀已最终化 | 不依赖共识、代币或合约规则 |
| 投影完成 | 数据库和通知进度跟上指定链位置 | 数据库获得了修改链上资产的权力 |

## 二、核心板块

| 核心板块 | 决定什么、为什么核心 | 拥有的状态与上下游契约 |
|---|---|---|
| 产品与权力划分 | 先确定何种权利在交易，避免混用托管账本与非托管钱包 | 定义产品、成交机制、资产控制、排序执行和退出假设；约束所有接口承诺 |
| 钱包与资产授权 | 谁能让用户的资产移动，签名到底允许什么 | A 控制签名；U/W 记录余额与授权；R 只能按已授权代码路径执行 |
| R/P 链上执行 | 在一个原子边界里决定交换是否成立 | R 执行用户保护；P 检查池规则与储备；失败必须贯穿整笔调用 |
| 链共识与观察 | 哪个执行历史被接受，何时可提高承诺级别 | 节点提供区块、回执和最终性；客户端核对身份、规范归属与祖先关系 |
| Go 协调与索引 | 为用户提供可恢复流程，而不冒充链上资金裁决者 | 管理 I1/Q1/attempt、扫描游标、事件激活状态、projectionRevision 和通知 |
| 治理、依赖与退出 | 业务停服或权限失效时，用户究竟还保有什么能力 | 检查不可变性、依赖代币、接入路径与 LP/交易者角色；不承诺无条件即时退出 |

## 三、核心 20%

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| 权威、权限、证据分离 | 全流程 | 查到一个值与有权修改它不同 | 用数据库覆盖资产事实 | authority / capability / observation，按状态逐项划分 |
| 区块绑定快照 | 报价、模拟、查询 | 单项真实不等于组合一致 | 用不同块储备得到不存在的报价 | blockHash、配置版本、祖先校验、过期降级 |
| 授权不是锁资 | approve 到执行 | 权限与履约能力不同 | 将签名/allowance 当余额冻结 | spender、额度、独立交易、并发消费 |
| 执行时保护 | R/P 执行 | 报价不能承诺未来状态 | 只做前端滑点检查 | recipient、minOut、deadline、真实转账结果 |
| 排序与原子边界 | 包含执行 | 排序影响结果，原子性有作用域 | 宣称 FIFO 或跨链下原子 | 链序、MEV、失败传播、Gas/nonce例外 |
| 多层身份与未知态 | 广播与重试 | 网络失败不能证明没有执行 | 新 nonce 重试导致两次交换 | intent/attempt/observation，替换关系和有效历史 |
| 规范链与最终性 | 结果确认 | 成功执行不等于不可撤销 | 把孤块日志当最终资产 | finalized祖先关系、信任来源、异常处理 |
| 可撤回、可再激活投影 | 索引、重组 | 去重必须兼容链历史变化 | 重组撤回后永久丢失重新规范事件 | active 状态、区块事务、revision和水位 |
| 控制面与退出检验 | 治理、故障 | 非托管仍可依赖强权限 | 将“可签名”当“可提现” | 代理权限、代币限制、替代入口与角色差异 |

“20%”是选择决定正确性的机制，不是只允许讲少数题。定价推导、签名编码、路由搜索等相邻机制只说明本专题需要的契约，不各扩展成另一套教材。

## 四、共同设计与规则

### 4.1 不变量与允许暂态

1. **逐币种守恒**：标准代币主例下，Swap 中 `ΔU(A)+ΔU(P)=0`、`ΔW(A)+ΔW(P)=0`。另行处理 ETH Gas，不能当成交易部分成交。
2. **执行保护**：成功必须满足实际输出不少于 minOut，接收者为 A，执行时间严格小于 deadline；不能靠链下记录豁免。
3. **池约束**：费用调整后的乘积检查使用整数算术；本例单向输入时相当于 `(1000×(x+a)−3a)×(y−b) >= 1000xy`。成功后储备记录完整输入 `x+a`，不是 `x+0.997a`。
4. **原子作用域**：同一 Swap 的必要代币转移、池状态和日志一起生效或回滚；已包含交易的 Gas/EOA nonce、前一笔 approve、链下数据库不在这个回滚范围。
5. **不虚构业务防重屏障**：I1 的唯一约束仅防服务重复编排；P 不识别 I1。同 nonce 的替换互斥不能阻止 A 用不同 nonce 做两次有效交换。
6. **未知不等于失败**：允许 Signed、BroadcastUnknown、Pending、IncludedUnfinalized、ReorgPending 等暂态；禁止因为 RPC 查无或本地超时就认定从未交换。
7. **证据必须绑定位置**：链上观察带 chainId、blockHash 和查询/扫描水位；同高度不同哈希不是同一个事实。
8. **投影可修订**：规范 active、应用关联/核验资格与各投影已应用贡献分开；补证可在 active 不变时补记，失活撤回、重新规范化可再应用，均在本地事务内提高 revision。扫描完整不等于语义完成，普通乱序回报也不能冒充重组撤回。
9. **最终性有前提**：采用已验证节点的最终化前缀；节点不可用时不升级状态，最终性矛盾时停止依赖结果开展不可逆动作。
10. **无权限则不能补偿**：Go 服务不能“冲正”链上余额；本例没有资金托管和授信，重建派生视图不产生新的财产权利。

### 4.2 架构与职责

```text
A / 钱包〔签名权与用户确认〕
    ├─ 请求报价、获取构造数据 → Go API / 报价服务
    │                             ├─ 区块绑定快照与规则版本
    │                             └─ I1 / Q1 / attempt 数据库
    └─ 签名交易 → 可选 Go 广播接口 / 自选 RPC
                            ↓
                  Ethereum 验证与区块执行
                            ↓
             R〔期限、输出保护、固定路径〕
                ├─ U.transferFrom(A,P,a)
                └─ P.swap → W.transfer(P,A,b)
                            ↓
             U/W 余额与授权；P 储备与 LP 份额
                            ↓
          节点回执/区块/最终性 → Go 追踪与索引
                            ↓
          观察表 + 查询投影 + 游标 + Outbox〔本地事务〕
                            ↓
                  查询 / 有阶段与版本的回报
```

数据库不与 EVM 共用事务。数据通知可以至少一次投递，由消费身份和事务避免重复派生效果；不能因此声称链、数据库和消息系统全局 exactly once。

### 4.3 核心对象与身份

| 对象 | 必要字段 | 有权说明什么 |
|---|---|---|
| Intent | intentId、owner、requestKey、payloadHash、明确执行约束、关联 attempts | 用户在应用中的一次请求；不是链上消费状态 |
| Quote | quoteId、chainId、R/P、token地址与精度、输入/输出/minOut、deadline、blockHash、rulesVersion | 某个明确状态下的估算和构造条件 |
| Attempt | chainId、sender、txNonce、txHash、目标/调用摘要、签名字节引用、replacement关系、观察进度 | 一份可传播的签名交易及其跟踪；hash不同不必是不同意图 |
| ChainObservation | chainId、blockHash、parentHash、height、txHash、logIndex、active、核验结论 | 某分支上的执行/日志实例，是否属于当前接受历史 |
| Checkpoint | chainId、finalizedHeight/hash、来源、获取时刻、验证状态 | 最终性依据和来源，而不是单独一个“确认数” |
| Projection | intentId、执行事实、关联/核验版本、各观察的已应用贡献、finality阶段、projectionRevision、sourceBlock、indexedThrough及语义完成水位 | 指定水位的派生查询；不能发起资产补扣或补发 |

**提交边界**：签名前固定用户确认的调用摘要；经 Go 广播时，先核验并持久化签名字节、本地计算的 hash 与 attempt 关联，再广播。钱包自行发送不受该顺序约束，服务须补关联且不能声称已记录所有尝试。链上以区块执行提交状态。链下每个完整扫描块的观察变更、投影、游标与 Outbox 在一个事务内提交；重组较大时采用可恢复重建版本并原子切换可见视图，不边重扫边无标识地混用两条历史。观察身份只标识对象，激活、撤回、再激活以及迟到核验/关联修订分别使用新的 transitionId/sourceRevision 发布；各投影比较目标贡献与已应用贡献，扫描完整和语义完成分别记水位，组合查询需要共同的分支版本与完整水位。

### 4.4 实现取舍与相邻专题

- 报价读取不可变快照；Go 的 `big.Int` 是可变对象，深拷贝后交付，不能共享指针边读边改。并行 RPC 限制并发、有界排队，失去新鲜度时拒绝报价，不牺牲区块一致性换吞吐。
- 数据库唯一约束绑定 requestKey 与 payloadHash；状态更新使用版本条件，记录证据而非盲目按状态编号单调推进。重组另有显式撤回路径。
- 常规恢复先恢复已提交游标与观察，再按规范链补齐；高可用提升服务可达性，不会让旧签名失效，也不能由新主重新发起未知交易。
- 本专题只解释相邻主题必须交付的结果：路由提供受约束调用，签名限定真实权限，广播提供原交易身份，索引提供完整水位与重组修订。对应目录未有正文时不将目录当成已完成教材。
- 详细 AMM 定价可参考[AMM 专题](../../03-行情与流动性系统/03-AMM定价与集中流动性/README.md)，该专题采用 v3 风格基线，不能直接把其 Tick/回调规则移植成本例 P；[RFQ 专题](../../03-行情与流动性系统/05-RFQ报价与履约/README.md)同样有独立签名与结算假设。

## 七、工程实践——一个简洁 MVP

### 7.1 目标与范围

只手工验证**权威事实不应被派生展示反向改写**：同一 Intent 的分支观察、执行结果、最终性和查询版本分开处理。它不广播、不运行 EVM、不验证共识/密码学、不实现余额账本或完整索引器。

输入由可信验证边界提供：`canonical[height]` 是当前接受的规范链前缀，`F` 是已验证最终检查点，`verifiedSwap` 是已完成目标、调用约束、相关池与资产事实核验的结果。伪代码只消费这些事实，不把真实性藏在一个“保证一致性()”函数里。为简洁起见，主例只跟踪 I1 的一份交易，显式串行处理重组，未解决多 nonce 重复意图。

### 7.2 核心伪代码

```text
state = {intent: I1, txHash: Htx, observations: {},
         acceptedFinalized: 空, revision: 0}

onBranchUpdate(canonical, F, candidates):
    begin local_transaction
    if 已处于最终性异常暂停状态: rollback; return
    oldF = state.acceptedFinalized
    if canonical 未覆盖 F 或非空 oldF 的高度:
        rollback; return                       // 证据不足，不发布降级
    if canonical[F.height] != F.hash
       or (oldF != 空 and canonical[oldF.height] != oldF.hash):
        保存异常证据并暂停确认; commit; return
    acceptedF = F if oldF == 空 or F.height > oldF.height else oldF
    for o in state.observations:
        o.active = (canonical[o.height] == o.blockHash)
    for c in candidates:                       // 输入包含成功或失败回执
        if c.chainId != 1 or c.txHash != Htx: continue
        key = (c.chainId, c.blockHash, c.txHash)
        o = state.observations.upsert(key, c)   // 保存实例，可再次激活
        o.active = (canonical[o.height] == o.blockHash)
    current = 当前 active 的 Htx 包含观察或空
    if current == 空:
        result = 未知或待包含                   // 不伪造失败，不重新 Swap
    else if current.status == 0:
        result = 已包含失败
    else if current.verifiedSwap != true:
        result = 执行语义异常待核验
    else:
        result = 已包含交换成功
    final = current != 空 and canonical[current.height] == current.blockHash
            and current.height <= acceptedF.height
            and canonical[acceptedF.height] == acceptedF.hash
    state.acceptedFinalized = acceptedF
    state.revision += 1
    保存(state, result, final, 源区块)           // 检查点与观察、投影共同持久化
    写入outbox(I1, result, final, revision)       // 与投影同一本地事务
    commit
```

`final` 是观察的最终性维度，`status=0` 的失败也能最终化，不代表最终化只能确认成交。`canonical` 是输入验证边界提供的同一连续前缀：同时命中新旧检查点哈希才说明历史相容，再取其中高度更高者作为 `acceptedFinalized`，不能让迟到的旧 F 覆盖更高锚点。输入前缀不足时保留已发布结果、等待补证；冲突时持久化暂停状态，解除暂停不在本 MVP 范围内。真实实现还要记录扫描完整性、父哈希连续性和旧事件失活后的派生撤回；本 MVP 没有余额增减，因此不靠省略撤回来伪装资金一致性。

### 7.3 输入与预期结果

| 输入 | 手工预期 |
|---|---|
| Htx 在 H1 成功，语义核验通过，F 仍在 H1 之前 | 已包含交换成功，final=false；不增加任何链下可提款余额 |
| 同一 H1 观察重复输入 | 结果不重复产生资产效果；只产生可识别的新查询revision，通知可按revision识别 |
| H1 所在分支被移除，当前规范链无 Htx | 原观察 active=false，结果回到待核验；不得凭旧日志保持最终成功 |
| H1 随后重新成为规范历史且在 F 前缀内 | 原实例重新active，成功且final=true；不能因历史去重永久屏蔽 |
| Htx 以 status=0 在规范前缀最终化 | 最终失败，无交换；不能推导前置approve也被撤销 |
| status=1 但 verifiedSwap=false | 保持语义异常，即使区块已最终化也不报预期交换成功 |
| 交易在 110 高已由 120 高检查点最终确认，随后收到同链 105 高 F | 保留 acceptedFinalized=120，final 仍为 true，不以迟到旧证据降级 |
| 已接受 120 高检查点，但本次 canonical 只覆盖到 105 高 | 保留原检查点与已发布结果，不提交投影变化；补齐证据后再处理 |
| 本地已保存的最终前缀与新 F 或 canonical 矛盾 | 持久化暂停并记录异常，不静默回滚不可逆业务 |

这些是伪代码手工推演结果，不是工程测试、链上实验、性能测量或合约安全证明。

## 八、事实、来源与交付边界

本专题将实际 EVM/ERC20 的通用语义与教学 R/P 的自定规则分开。ERC20 规范可支持余额、授权与 `transferFrom` 的接口理解，但不能单凭接口合规证明任意代币安全；最终性与 RPC 的信任也不能被 URL 或状态字段替代。

本次只读核验使用了以下官方规范、文档与官方源码，未核验任何实际部署地址或对教学 R/P 进行安全审计：

| 官方来源 | 支持的事实与边界 |
|---|---|
| [ERC-20](https://eips.ethereum.org/EIPS/eip-20) | balanceOf、approve、allowance、transferFrom 的接口含义；标准接口本身不排除额外管理权限 |
| [Uniswap V2 Router 源码](https://github.com/Uniswap/v2-periphery/blob/master/contracts/UniswapV2Router02.sol) | Router 作为 spender 转入 Pair 的常见路径；本例不是该源码或实际部署的逐行复制，尤其期限规则单独声明 |
| [EIP-140 REVERT](https://eips.ethereum.org/EIPS/eip-140)与[Geth 状态转换源码](https://github.com/ethereum/go-ethereum/blob/master/core/state_transition.go) | 执行回滚与已包含失败交易的 Gas/nonce 边界；REVERT 不等于总是烧完全部 Gas |
| [Ethereum JSON-RPC](https://ethereum.org/en/developers/docs/apis/json-rpc/)与[EIP-1898](https://eips.ethereum.org/EIPS/eip-1898) | 回执、区块位置、历史调用与区块哈希绑定；接口结果仍需其可信验证来源 |
| [Engine API forkchoice](https://github.com/ethereum/execution-apis/blob/main/src/engine/paris.md) | head、safe、finalized 的不同语义；最终检查点必须关联同一祖先历史 |
| [Ethereum 节点与客户端](https://ethereum.org/en/developers/docs/nodes-and-clients/)与[Geth 模拟接口](https://geth.ethereum.org/docs/interacting-with-geth/rpc/ns-eth) | 自行验证与第三方 RPC 依赖、模拟不等于提交或未来包含保证 |
| [OpenZeppelin ERC20 文档](https://docs.openzeppelin.com/contracts/5.x/api/token/erc20) | 代币可能具有暂停等扩展机制；不能反推所有 ERC20 都有这些权限 |

Uniswap 文档站的读取未成功；没有引用其未读取正文。官方仓库源码用于核对通用路径，不据此宣称任意同名 Router、代币或代理部署安全。本次不创建可运行项目、不执行工程测试或链上实验，不提交、推送或外部发布。
