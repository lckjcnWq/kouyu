# 大问题 11：前端、Go 服务或 RPC 故障时，交易者能否自主交易和退出，哪些条件会使这条路径失效？

<!-- 大白话导读开始 -->

## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 非托管 / trader / LP | 平台不直接掌控用户资产、交易者、流动性提供者。 | A 默认只换币，没有 LP 份额或平台内部可提余额。 |
| A / R / P / U/W | 用户、路由合约、池、两种教学代币。 | A 可换入口继续调用已核查的 R，不能因此取得 P 的额外提款权。 |
| EOA / L1 / Gas | 私钥控制的外部账户、基础链、链上执行资源。 | 这里是 Ethereum L1，A 另备原生 ETH；持有封装资产 W 不等于能付 Gas。 |
| 自主访问 / 退出 / 赎回 | 不依赖指定服务访问、结束当前资产或风险安排、按特定凭证取回资产。 | 转走 W、再卖 W、按 LP 份额取出 U/W 是不同权利，不承诺恢复原成本。 |
| approve / allowance / spender | 设置代币权限、使用额度、获授权合约。 | 批准 R 不等于批准 P 或新 Router，换网页不改变这项权限。 |
| minOut / deadline / recipient | 最低输出、执行期限、收款人。 | 备用工具仍须保留用户保护，不能为“自主”丢掉原子组合或身份核对。 |
| I1 / Q1 / attempt / txHash | 应用意图、报价、签名交易尝试、交易哈希。 | 旧结果未知先恢复原尝试，不因换入口就重做同一经济动作。 |
| nonce / 同 nonce 竞争 | 账户交易序号、不同交易争夺同一序号。 | 新发43可能再换一份；同字节重广播还是42原交易；取消也非必胜。 |
| revert / 已包含失败 / 未包含过期 | 回滚、进块但执行失败、尚没进块而期限已过。 | 前者仍耗 Gas/nonce；后者不会因时间流逝自动消耗 nonce；独立 approve 不随 Swap 回滚。 |
| 流动性 / 审查 / 活性 | 市场可用于交换的资产、持续拒绝纳入交易、链能否继续处理。 | 有私钥和备用 RPC 也不保证及时包含或按旧价成交。 |
| removeLiquidity / burn / pair | 移除流动性入口、销毁份额领取资产、池合约。 | 只有实际持份额才有资格；份额转入和赎回应在经核查路径内原子组合。 |
| 原子组合 / 独立先转账 | 把相关步骤放进同一交易、先单独把币或份额发送给池。 | 后者可能使资产与本人后续领取脱离绑定，不能作为安全默认操作。 |
| Rollup / sequencer / 强制包含 | 依赖基础链结算的一类扩容系统、排序器、特定协议的替代纳入机制。 | 基线没有这些逃生机制；对比时须核实协议，并仍考虑 L1 可用性。 |
| RPC / canonical / finalized / 投影 | 节点接口、规范链、最终确定、派生页面记录。 | 备用接口不替代结果核验；页面落后补展示，不补发兑换。 |

## 把整篇文章压缩成一个故事

小林刚签完 2000 U 换 W 的交易，网站和 Go 服务就停了。第一步不是“找平台提现”，因为这里没有平台内部余额：若没换，U 还在小林地址；若已经成功，持有的就是 W。小林可以换工具和可信节点访问，但必须先查清旧交易，不能带着未知结果用新 nonce 再买一份。

若要继续换币，备用工具应核对原 R、授权、最低输出、期限与 ETH 费用，不能把批准 R 的额度当成 P 的拉款权限，更不能先独立把币转入池再期待后一步补救。链拥堵、审查、流动性不足时，备用入口也不保证成交。已经完成的 Swap 想换回 U，是按新价格做另一笔交易，不是按旧成本退款。

小林默认没有 LP 份额，所以不能凭“我曾付过 2000 U”按比例提池资产。只有明确换成真正持份额的 LP，才讨论经核查且原子组合的份额销毁与资产赎回；Rollup 的特殊逃生口也不能凭空移植到这套 L1 主例。本文把自主访问限定为可替代入口和真实权利，不把它夸成任何故障下都能立即原价退出。

[返回专题总览](README.md)

**流程位置与核心机制：** 本题从“报价或提交入口故障”沿交易身份、授权、L1 执行和资产访问一直追到退出条件。核心是区分本地服务不可用、执行结果未知、链上拒绝与底层活性受限，不能把一个备用入口当成无条件取回资产的保证。

**必要前提：** 公共状态机与数值依据[专题总览](README.md)。基线为 Ethereum PoS L1、`chainId=1`；A 是自己签名并持原生 ETH 付 gas 的 EOA，Go 无私钥。R/P 不可升级、无管理员、无紧急暂停；U/W 为标准教学代币，W 不 unwrap；精确输入单池恒定乘积 AMM，无订单簿和内部托管余额。A 默认是没有 LP 份额的 trader；LP 退出与 Rollup 均在明确改变角色或网络前提后比较。

## 第 1 层：服务宕机时，A 究竟要从哪里退出？

**面试官：** 如果 DEX 的前端和 Go 服务一起不可用，A 能不能不经运营方同意取回自己的资产？请先说明这里的“自己的资产”在哪里。

**面试者：** 可以不经运营方同意访问自己地址中的资产，但不能先假设存在一个可提取的“平台内部余额”。在这套基线中，A 没有把资产存进 Go 的托管账户，U/W 合约分别记录 A 与 P 的余额，P 的储备缓存不是运营方的一张可任意改写账单。若 swap 尚未执行，A 仍有原来的 U；若它已经成功，A 持有交换所得 W。服务宕机不会自动把已转入 P 的输入重新归还，也不会把已经收到的 W 变成 Go 欠 A 的兑付债务。

对 A 而言，自主访问可以是通过别的可信入口查询余额、自行构造交易，或者把地址中现有 U/W 转到另一个由自己控制的地址；若想把 W 换回 U，那是新的市场交易，不是按原价赎回。A 默认没有 LP 份额，所以不能要求 P 按比例退还储备。若原 swap 的结果未知，第一步也不是再发一笔“退出单”，而是确认旧交易的链上状态。这一拆分很重要：入口可替代说明运营方没有必经的签名权，但能否成交、能否转账、能否达到最终性，还要看代币规则、授权、流动性和 L1 活性。

## 第 2 层：绕过前端，为什么不等于绕过 Router 的授权？

**面试官：** 你说 A 可以自己构造交易。现在 A 只有对 R 的 U 授权，备用工具建议直接调用 P，让 P 从 A 拉走 2000 U。这是不是更独立的访问方式？

**面试者：** 不是，这个建议把访问入口与 spender 权限混淆了。U 的 allowance 是由 owner 和 spender 共同确定的，A 批准 R，并不等于批准 P，更不是所有调用者都能消费这份权限。若 P 或某个备用合约以自身身份执行 `U.transferFrom(A,...)`，它不能借用 `U.allowance(A,R)`。而且也不能凭空假定 P 暴露了与 R 相同的用户入口。直接访问合约必须满足该入口真实的资金到位方式和检查条件，不能用“去中心化”绕过这些条件。

在原始基线下，更直接的自主路径是更换客户端或 RPC，仍由 A 自行核对并签署发往原 R 的交易，保留正确的 `chainId=1`、U/W、输入量、recipient=A、`minOut` 和 deadline。R 再按既有授权路径组织调用，前端不在链上授权链里。若确实改用新 Router，则必须说明 spender 变了，A 需要决定是否建立新授权，并重新检查新合约；不能自动继承旧授权。也不应建议把 U 先单独转给 P，随后再期待第二笔交易完成交换：两笔交易之间没有本例 Router 调用所提供的原子组合，自主访问不能以丢掉资金与操作的绑定为代价。

## 第 3 层：备用入口可用，但原 swap 广播结果未知时怎么办？

**面试官：** 那么继续使用原 R。A 的 I1/Q1 已签成 nonce 42 的 swap，旧 Go 广播后超时，备用入口现在可用。它能否直接用 nonce 43 再发一次相同交换，保证业务完成？

**面试者：** 不能，因为超时只说明旧入口没有给出确定答复，不证明 nonce 42 未传播或未执行。P 没有 `intentId` 屏障，不认识 Go 数据库里的 I1，因此 nonce 42 和 43 可以被当作两笔合法交易顺序执行。A 初始有 5000 U，第一笔花去 2000 U 后还有 3000 U；不能拿“余额不够再做一次”当作通用去重。第二笔在相同旧 `minOut` 下可能因价格变化失败，但如果工具重新报价、扩大授权并让 A 签署，它就可能再次成交。不能依赖偶然失败来保证业务只做一次。

正确处理是保留原签名交易的哈希、sender、nonce、calldata 与 I1/Q1 的关联，换可信节点查询该 attempt 的 receipt 和规范链关系，也观察同一 sender/nonce 是否被其他交易消费。查不到交易仍然是未知，不是未执行证明。相同签名原文再次广播只是在传播同一笔交易，不会凭空制造新 nonce 的第二次交换；若要加费替换或取消，仍需 A 自己签署，并跟踪同 nonce 的不同 attempt。Go 应分开 intent、attempt、chainObservation 和 projectionRevision，防止服务重启或换入口后把“没查到旧回包”误映射成“允许再消费一次业务意图”。

## 第 4 层：旧交易过期或回滚后，哪些影响仍然留下？

**面试官：** 假设备用节点后来发现 nonce 42 的交易在 deadline 处才被包含，并且执行失败。既然交换已经回滚，能否说这次故障完全没有成本，原授权也恢复成未批准状态？

**面试者：** 不能。这里的约束是严格的 `block.timestamp < deadline`，不是小于等于。`t0=1800000000`、`deadline=t0+120=1800000120`，如果区块时间恰好等于 1800000120，交易就不满足截止条件。若它已被包含并回滚，swap 调用内部的 U/W 转移、储备修改和内部日志不会留下半笔结算，但 A 的 gas 消耗、交易级 nonce 消费仍然保留。先前已经完成的 nonce 41 approve 是另一笔交易，不会因为 nonce 42 失败而自动撤销或变成“从未批准”。

主例如果在 `t0+12` 执行、池状态仍为 B0/H0，则 2000 U 输入按 0.3% 留池费用计算，输出为 `995015938219190933` 个 W 原子单位，满足 `minOut=990040858528094978`。成功后 A 为 3000 U 与 `0.995015938219190933 W`，P 为 1002000 U 与 `499004984061780809067` 个 W 原子单位；过期失败则不能写出这些成功后的交换余额。还要区别“已包含失败”与“仍未包含但已过期”：后者不会因时间流逝自动消耗 nonce，只是未来按该 deadline 执行将失败。新的报价或取消需要重新组织并由 A 签名，服务不能修改原签名里的截止时间来复活旧请求。

## 第 5 层：能自行签名，是否就保证一定能及时进入 L1？

**面试官：** 你把失败成本和未知结果分开了。现在 A 已经准备好正确的新交易，并更换了客户端与 RPC。如果 L1 持续不包含它，提高 gas 或多发几个节点能否保证及时退出？

**面试者：** 不能作这样的保证。备用节点能解决某些单点故障或传播问题，提高费用也可能改善正常拥堵下的包含机会，但这些手段都不能把“交易已传播”变成“规范链必须在期限内包含”。如果 A 的交易持续遭到审查，或链本身活性受限，前端、Go 和数据库没有权限命令出块者执行它。A 还必须拥有原生 ETH；持有 W 不等于已经具备支付 L1 gas 的原生余额，本题不执行 unwrap，也不引入代付机制补齐这个条件。

即使最终得到包含，退出所需的市场交易仍要满足当时的余额、allowance、池流动性和 `minOut`。B0/H0 的报价不是对未来储备的预留，签名也不锁定池中的 W；别人先交易或撤走可撤的流动性，都可能让旧报价失效。`minOut` 保护的是低于底线时不按该条件交换，不是保证总能成交。收到成功 receipt 后还要追踪其区块是否属于经验证 finalized 头的祖先链，不能用 RPC 返回成功或本地等待时间代替最终性。这就界定了自主访问的真实承诺：不依赖运营方批准，但仍依赖代币可执行、链上可包含和资产可用，而不是无条件的即时退出权。

## 第 6 层：如果流动性不足，trader 为什么不能直接按份额拿走池储备？

**面试官：** 既然流动性会让换回 U 失败，A 能否绕过价格，调用 removeLiquidity，按自己先前投入的 2000 U 从池里取回资产？

**面试者：** 不能。swap 的输入是交换对价，不是给 A 记下一份随时可提回的本金。A 在主例中是 trader，没有因为输入 2000 U 就获得 LP 份额；交换完成后，他对收到的 W 拥有代币余额，而不是对 P 的原输入保持一份债权。P 的储备属于池的资产状态，按 LP 份额规则参与流动性退出，不能由交易者拿历史 swap 回执替代份额证明。否则任何成交者都能先拿走输出，再按输入额赎回储备，同一笔投入就被重复使用了。

A 可以在代币规则允许且 L1 能包含交易时转移现有 W，也可以接受新的价格再交换回 U；这两种操作都不承诺恢复到最初 5000 U。W 在本题是教学封装资产，当前讨论也不通过 unwrap 走另一条赎回路径。如果改变角色，假设 A 另行拥有可用于退出的 LP 份额，才可以讨论按份额赎回池里当时可用的 U 和 W。那是新的权利基础，得到的通常是两种资产的组合，而不是返还原始成本或保证外部法币价值。因此“有退出入口”必须同时说清谁拥有调用资格、依据什么资产凭证，以及入口交付的是哪一类资产。

## 第 7 层：换成 LP 后，为什么份额转入与 burn 也必须原子组合？

**面试官：** 现在明确改变角色：A 确实持有 LP 份额。有人建议在前端故障时，先独立把 LP 转给 pair，再单独发 burn 取出资产。这是否就是可靠的自主退出？

**面试者：** 不能把这种两笔操作当成安全默认路径。对于采用“LP 先转入 pair、pair 再 burn 所持份额并向指定接收人转出资产”的设计，必须核查真实接口和 recipient 约束，并让份额转入、burn 与 U/W 转出在同一笔交易中原子组合。独立先发送 LP 可能使份额与 A 的取款动作脱离绑定；在某些公开 burn 接口设计中，其他调用者可能利用 pair 已持有的份额发起向其他接收人的 burn。不能假定合约会自动记住独立转账者并替他保留资产。

因此应优先使用经核查、具有相应移除流动性入口的调用路径，且只在真实存在该入口时讨论。如果该路径需要 R 拉取 LP，所需的是 LP 份额 token 对 R 的授权，原来的 U allowance 不能代替它。赎回数量取决于所烧份额、相应总份额规则及池中实际可转出的资产，P 的缓存不能凭空补足余额。任一转出失败应使组合调用整体回滚，而不是先永久烧掉份额再等待运营补偿。若另外改变前提加入暂停或可黑名单代币，还必须逐项判断暂停是否覆盖转账、burn 或移除入口；“只暂停 swap 所以退出必然畅通”不是未经代码核查就成立的结论。原始 R/P 则没有这种管理员暂停能力。

## 第 8 层：L1 都无法包含退出时，能否用 Rollup 逃生口来证明基线安全？

**面试官：** 你已经把 LP 的原子退出讲清，但它仍然需要 L1 包含交易。有人说“排序器停机可以强制退出”，因此这里也总有最后的逃生口。这个结论哪里发生了前提跳跃？

**面试者：** 它把 Rollup 的排序器和特定桥接机制加进了原本的 Ethereum L1 模型。基线没有 sequencer，也没有一份题设自带的强制退出合约；R/P 的不可升级性不会自动生成新的赎回通道。若明确改为某个 Rollup，才需要另外核实其强制包含入口、数据可用性、状态证明或争议流程、等待期、L1 桥接合约及升级权限。不同系统的能力不一样，强制包含也不等同于任意 DeFi 资产可以立即换回原资产。即使机制确实存在，提交强制消息或提款证明通常仍需 L1 的可用性与包含能力，不能拿它反证 L1 自身的审查问题已经解决。

对本题应形成可执行的故障判断顺序：先区分只是前端或 Go 不可用，还是旧 attempt 结果未知；再确认现有余额与权限，选择仍符合授权的入口；之后判断交易能否进入 L1、合约是否接受、结果是否达到最终性。trader、LP 和 Rollup 提款者对应不同资产凭证，不能共用一句“随时退出”。例如 nonce 42 早已在 `t0+12` 成功，只是索引宕机，恢复服务应补上那次观察，而不是自动再交换；若交易根本未被包含且已过 deadline，则应处理仍占用的 nonce 路径，而不是假造一个成功资产变化。这两个反例能直接检验故障分类是否尊重链上事实。

## 结尾收束：自主访问是可替代入口，不是无条件兑付承诺

- **讲透的机制：** 服务故障不产生或消灭链上余额；结果未知要恢复原交易身份；访问原 R 仍需正确授权和签名；链上交易受期限、滑点、流动性及包含能力约束。trader 仅持交换所得资产，LP 则以真实份额参与资产赎回。
- **易错边界：** 批准 R 不等于允许 P 拉款；未包含过期不等于 nonce 自动消费；已包含回滚不返还 gas，也不撤销独立 approve；LP 不能不安全地独立先发送给 pair；基线没有治理暂停或 Rollup 逃生口。
- **具体反例验证：** nonce 42 已成功但 Go 未记录时，用 nonce 43 重新报价并再次签 swap 可能造成第二次交换，P 不会因两次都叫 I1 而去重。反过来，没有 LP 的 A 即使能直接访问 P，也不能用第一次交换的输入额要求按比例赎回储备。两种反例分别约束故障恢复与退出资格。
