## 先看懂：关键词大白话解释

| 关键词 | 大白话解释 | 在本文里怎么理解 |
|---|---|---|
| 托管提现 / 用户账本 | 平台代用户管理资产，账本记录平台对用户的权益义务。 | 用户 U 的可用余额与热钱包 H 的链上库存不是同一个账户。 |
| U / B / H / T / W1 | 用户、外部收款地址、平台付款钱包、代币合约和本次提现意图。 | W1 要向 B 付 100 T，平台另外承担网络费。 |
| EOA / Ethereum PoS L1 | 普通外部签名账户，以及以太坊权益证明主网。 | H 无代码委托且由服务独占，不讨论账户抽象、桥或二层网络。 |
| ERC-20 / raw / decimals | 代币接口、最小单位整数和小数位数。 | 已核验 T 为 6 位，100 T 编成 100000000，不能经浮点数转换。 |
| ABI / calldata / value | 合约调用编码规则、具体指令和附带的原生币数量。 | to=T，data 指示向 B 转 T，value=0，不是直接向 B 发 ETH。 |
| requestKey / payloadDigest | 请求去重键及规范化业务内容摘要。 | 相同键同内容找回 W1，改金额却复用键必须拒绝。 |
| 冻结 / 钱包预留 | 账内暂不可用的用户权益，以及平台内部占住的付款容量。 | 受理后 U 为可用 900、冻结 100 T；H 的 T 与 ETH 容量另行检查。 |
| nonce_slot / attempt / txHash | 钱包执行序号槽、具体候选交易及签名交易指纹。 | 槽位为链 1、H、42；付款 X1、加速 X2、取消 Xc 有不同 hash。 |
| EIP-1559 / type-2 | 将基础费、优先费和总单价上限分开的交易费用规则。 | maxFee=40、优先费上限=2 gwei，不等于一定按 40 支付。 |
| gasLimit / gasUsed / gwei | 执行工作量上限、实际用量及 ETH 的小单价单位。 | 1 gwei 为十亿 wei；预算 65000×40 对应 0.0026 ETH，实付按回执算。 |
| draft / signer request / raw | 已批准交易草稿、签名请求身份和可外发的签名交易字节。 | 签名超时找回原请求；raw 一旦外泄，本地删记录无法撤销它。 |
| RPC / mempool / UNKNOWN | 节点接口、节点待处理交易集合和结果未知。 | 广播超时不证明未付款，单个节点也不掌握全网所有待处理交易。 |
| 同 nonce 替换 / 取消 | 让新候选竞争同一个钱包执行序号。 | 取消是另一笔交易，不是让旧付款的签名失效；全部候选继续追踪。 |
| receipt / status / Transfer | 执行回执、顶层是否回滚及代币转账事件。 | status=1 还要结合准确载荷、可信 T 的事件和候选操作类型判定。 |
| canonical / safe / finalized | 当前规范链及不同强度的共识进度。 | 入块先作临时观察；默认核验回执块属于 finalized 祖先链才结账。 |
| 重组 / blockHash / 祖先关系 | 链分支切换、具体区块身份及父链连接。 | 同高度不等于同一块，旧回执可撤回；高度较低也不自动属于最终链。 |
| Outbox / 唯一结算键 | 与本地结果一起提交的待发消息，以及防重复记账身份。 | 可重复交付通知，但 W1 的冻结核销与账本结果只能应用一次。 |
| epoch / 围栏 / RPO | 主任期、拒绝旧主权限的检查及容许的数据丢失范围。 | 数据库和签名出口都要保护；已签 raw 不受本地任期撤销。 |

## 把整篇文章压缩成一个故事

小林在平台有 1000 T，想提 100 T 到外部地址 B。平台先把他们的账内权益改为可用 900、冻结 100，并建立 W1；这时链上尚未付款。调度器为钱包 H 的 nonce 42 占好 100 T 和最多 0.0026 ETH 的费用容量，准确编码 T 的 transfer，再完成模拟、审批和签名，把交易原字节、hash 与发送任务一起保存。

广播突然超时，平台没有退款，也没换 nonce 43 再付。它继续查原交易；要加速就另批同序号 X2，要取消则另批同序号自转 Xc，三者都要盯住。即使 Xc 曾在一个分叉显示成功，也不能先放开冻结：重组后最终获胜的仍可能是原付款。收到付款回执，还需核对合约、收款人、金额、事件及最终链祖先关系。

主例最终付出 100 T，真实 Gas 为 50000×32 gwei，即 0.0016 ETH；H 剩 9900 T 和 0.9984 ETH，小林可用仍为 900 T，冻结清零。账本、预算核销和待发通知本地一起提交，响应丢失就重试记账而不是重新付款。故事讲的是证据驱动的一次义务闭合，不是一次 RPC 返回成功，更不是全链与数据库共同提交的神奇事务。

这里讨论的不是“调用 SDK 发一笔交易”，而是：**一次已经冻结资金的付款意图，怎样被正确构造、授权、签名、广播和追踪，并在失败、替换、取消、重组和重启之后，仍然不重复付款、不错误释放、不把节点响应当作业务终态。**

所有实现均为教学设计，不代表个人生产经历；Gas 数值为统一推演样本，不是链上实测。“高频”表示按业务关键性与岗位相关性选题，不代表经过面试频率统计。

## 第一部分：文字全流程

### 1.1 讨论基线

- **产品**：托管平台的一笔 ERC-20 提现。账户域拥有用户账本，交易服务拥有付款意图与执行记录，链决定交易执行结果。相邻账户域只讲本专题所需的预留与结算契约，不扩展成完整充提专题。
- **网络**：Ethereum PoS L1，`chainId=1`。普通、没有代码委托的 EOA 热钱包 H 由本服务独占；不把其他系统或人工钱包同时使用 H 当成正常运行方式。
- **交易机制**：EIP-1559 type-2 普通交易，调用白名单代币合约 T 的 `transfer`。不讨论 ERC-4337、EIP-7702、Blob 交易、跨链桥与 L2 费用／最终性模型。
- **代币**：T 为已核验行为的标准 ERC-20，6 位小数，没有转账税、rebase、黑名单或额外转账分支；余额足够且参数合法时，按指定数量转账、返回 true 并发出对应事件。这个固定行为来自对 T 的核验，不是声称 EIP-20 排除了返回 false。本基线能够依据准确调用与对应 `Transfer` 日志判定转账；其他代币行为必须单独适配，不能只换合约地址。
- **存储与并发**：PostgreSQL 保存本地事实；钱包行锁与唯一约束分配 nonce，受控签名服务管理密钥与授权。RPC 是链观察和交易传播入口，不是本地任务锁、全网 mempool 或业务幂等服务。
- **完成策略**：入块先记为临时观察，默认核验到 `finalized` 祖先关系后才终结用户资金。`safe` 可作进度提示；固定确认块数不冒充协议最终性。
- **资金口径**：用户与钱包分别管理预留；100 T 提现金额不额外扣 Gas，Gas 由平台支付。主路径不自动换钱包或新 nonce 再付一次。

### 1.2 贯穿案例与单位

用户 U 从平台向独立外部地址 B 提现 100 T，B 与 H、T 均不同，业务意图为 W1。

| 项目 | 初始值或构造值 | 含义 |
|---|---|---|
| U 的账本 | 可用 1,000 T、冻结 0 T | 受理后变为可用 900 T、冻结 100 T |
| H 的链上资产 | 10,000 T、1 ETH | 平台钱包资产，不等于 U 的个人账户余额 |
| nonce 基线 | 已核验最终链上的下一 nonce 为 42，且初始化无其他未决交易 | 正常分配槽位 `(1,H,42)`，不是每次重新向 RPC 取号 |
| ERC-20 金额 | `100 × 10^6 = 100000000` 最小单位 | 不经浮点数转换 |
| type-2 载荷 | `to=T`、`value=0`、`data=transfer(B,100000000)` | 交易接收者是合约 T，代币接收者才是 B |
| Gas 教学值 | 估算 52,000，批准 `gasLimit=65,000` | 估算不构成执行保证 |
| 费用教学值 | `maxFeePerGas=40 gwei`，`maxPriorityFeePerGas=2 gwei` | 不代表任何节点通用替换门槛 |
| 入块教学值 | `baseFee=30 gwei`、`gasUsed=50,000` | 有效单价为 `min(40,30+2)=32 gwei` |
| Gas 预算与实际 | 预算上限 `65000×40 gwei=0.0026 ETH`；实际 `50000×32 gwei=0.0016 ETH` | 差额 0.001 ETH 是未消耗预算，不是给用户的额外收入 |

正常最终结果：B 增加 100 T；H 剩余 9,900 T 与 0.9984 ETH；U 可用仍为 900 T，冻结清零，100 T 已核销为完成提现。链上资产变化与用户负债核销对应；内部钱包预算并不是又发生一次链上扣款。

### 1.3 主流程

```text
U 提交提现请求〔requestKey、chainId、T、B、金额〕
    ↓
账户／意图受理事务
    校验身份、白名单、地址、精度、余额与载荷摘要
    唯一请求身份绑定 W1，原子冻结 U 的 100 T
    ↓
钱包调度事务
    锁定 H 的调度行，核验钱包健康度、T 容量与 ETH 预算
    为 W1 分配唯一 nonce 槽位 (1,H,42)，保留付款与费用预算
    ↓
交易构造与预执行
    编码 to=T、value=0、transfer(B,100000000)
    选择可记录的链状态，执行 eth_call／estimateGas，确定费用与限额
    固化审批载荷、draft 身份与可恢复签名请求
    ↓
受控签名与耐久落盘
    签名服务检查授权、链、钱包、nonce、载荷及费用上限
    校验返回签名恢复的 sender 与全部交易字段
    本地计算 txHash1，持久 raw1、attempt X1 和广播任务
    ↓
广播执行器发送完全相同的 raw1
    ├─ 节点接收／already known → 记录传播证据，不宣告付款成功
    └─ 网络超时／响应丢失 → UNKNOWN，保留原槽位与预留
    ↓
追踪器扫描链与查询同一槽位的全部 attempt
    订阅只唤醒任务；持久游标、区块哈希与补扫负责完整性
    ├─ 未入块 → 继续查询／同 raw 重播／按策略申请同 nonce 加速
    └─ 找到回执 → 校验规范链、交易载荷、执行状态与业务日志
    ↓
记录 INCLUDED 临时观察
    ├─ 重组离开规范链 → 撤销临时观察，重新追踪全部 attempt
    └─ 位于已核验 finalized 链前缀 → 形成最终结果
    ↓
账户结算事务
    成功：核销 U 的冻结 100 T，记录实际 Gas 与钱包预算终结
    执行失败／最终取消：有未付款证据后释放 100 T，仍核算实际 Gas
    唯一结算键与状态版本防止重复终结，同事务生成回报 Outbox
    ↓
查询与通知展示确定结果
    可用、冻结、付款结果、txHash 与最终性水位分别表达
```

数据库受理完成、签名生成、广播返回、交易入块、业务校验通过、最终结算和页面可见是不同阶段；接口返回必须明确承诺停在哪一阶段。

### 1.4 关键异常分支

```text
请求重复
    ├─ 相同 requestKey、相同摘要 → 返回 W1 与原进度，不再冻结
    └─ 相同 requestKey、不同摘要 → 冲突拒绝，不修改旧意图

冻结成功但尚未签名
    └─ 恢复同一 W1 与槽位；取消须先关闭未签授权与在途签名请求
       不能因调用超时就假定没有签名

签名返回或广播调用超时
    └─ 找回原 draft／raw／hash，追踪同一执行权利
       UNKNOWN ≠ FAILED；没有证据时不释放、不换新 nonce 重付

X1 长期 pending
    ├─ 加速 X2：同槽位、同业务载荷，提高费用并重新校验预算
    └─ 取消 Xc：同槽位自转 0 ETH，独立授权，与 X1／X2 竞争
       发出取消不使付款交易失效；最终规范链获胜者决定结果

收到 receipt
    ├─ status=0 → 本次执行失败，nonce 与 Gas 仍被消耗
    ├─ status=1、取消载荷 → 取消执行成功，不是原付款成功
    ├─ status=1、付款证据吻合 → 临时付款成功，继续等待最终性
    └─ 交易或日志不吻合 → 隔离核查，不自动释放，也不冒认成功
```

### 1.5 案例中的状态与资金变化

| 阶段 | U 可用／冻结 | H 的预留与链上状态 | 完成含义 |
|---|---|---|---|
| 接口可靠受理 | 900／100 T | 尚未分配钱包也可保持待调度 | 本地承诺继续处理 W1，不承诺已经付款 |
| 分配并批准 X1 | 900／100 T | 为槽位预留 100 T 和 0.0026 ETH 费用容量；链上还未扣款 | 本地执行资格与资金预算建立 |
| 广播 UNKNOWN | 900／100 T | 保留预留；raw1 可能已在网络传播 | 不能当作付款失败 |
| X1 规范链入块、未最终 | 900／100 T | 链上已变化，观察与预算须按同一水位核销，不能重复扣减或提前放开 | 可展示“已入块”，用户冻结仍保留 |
| X1 付款 finalized | 900／0 T | H 为 9,900 T／0.9984 ETH，终结该槽位义务 | 一笔最终付款与一次用户负债核销对应 |
| 独立变体：X1 执行失败 finalized | 1,000／0 T | T 未转出；ETH 按失败回执的实际 Gas 扣除 | 原付款确定未完成，本次执行费用仍真实发生 |
| 独立变体：Xc 最终获胜 | 1,000／0 T | Xc 消耗 nonce 和其实际 Gas，T 不转出 | 原 nonce 已被最终取消占用，才排除旧付款将来在该槽位执行 |

失败与取消变体不复用主路径的 50,000 Gas 数值；它们各自按真实回执计费。后文异常反例都是单独改变条件，不把多个变体叠加成一笔交易。

## 第二部分：核心板块

| 核心板块 | 决定什么、为何核心 | 权威状态与上下游契约 |
|---|---|---|
| 意图与资金准入 | 决定是否形成付款义务，阻止重复请求与超额承诺 | 本地 W1、请求摘要、用户冻结；只向钱包调度交付已可靠受理意图 |
| 构造与执行预算 | 决定到底给哪个合约、哪个账户、多少资产，以及能承受多少费用 | 固定资产单位、ABI、draft 与批准参数；模拟是观察，不是预留或保证 |
| nonce 与签名边界 | 决定同一钱包执行顺序和谁拥有可外发交易 | 持久槽位、授权、签名审计与 raw；数据库不能撤销已经签出的交易 |
| 广播与多尝试协调 | 决定不确定调用如何恢复，以及加速、取消与付款如何竞争 | attempt 集合与发送任务；节点接收只代表局部传播 |
| 链观察与终局裁决 | 决定哪个 attempt 属于最终规范链、是否满足业务目标 | 以链的执行与最终性为权威，本地观察包含区块身份与可撤销阶段 |
| 账务与恢复闭环 | 决定何时减少义务、释放冻结、通知外部，故障后是否继续正确 | 原子结算、唯一结算键、持久游标、Outbox、恢复水位及签名出口隔离 |

## 第三部分：核心 20%

| 核心机制 | 流程位置 | 为什么核心 | 不掌握的后果 | 重点深入细节 |
|---|---|---|---|---|
| 业务身份与执行身份分层 | 受理至终结 | 一笔付款可以有多个交易哈希 | 哈希变了就再付一次，或取消成功被误认付款成功 | requestKey、W1、nonce_slot、draft、attempt、观察、结算键 |
| nonce 持久分配与低序号推进 | 调度、恢复 | 同钱包执行顺序依赖 nonce | 多实例撞号、产生缺口、未知交易被复用 | 钱包行锁、唯一槽、局部 pending 视图、不可随意回收 |
| 签名前授权、签后耐久记录 | 构造到广播 | 签名产生可独立传播的执行能力 | 数据库丢记录但付款仍可发生 | 字段核验、签名审计、签后未知、复制边界与旧 raw |
| 同字节重播与 UNKNOWN | 广播 | 网络超时不能否定远端执行 | 重复付款、错误退回用户冻结 | 先算 hash、持久 raw、错误分类、禁止新 nonce 补发 |
| 同 nonce 替换的竞争规则 | 加速与取消 | 本地“选中”不决定网络最终获胜者 | 丢失旧 hash、取消后释放再出现付款 | 全 attempt 追踪、预算按槽最大、最终占用证据 |
| 执行结果与业务结果分离 | 回执 | status 只表达交易级执行状态 | 转错合约、事件不符仍记成功 | 交易载荷、可信 T 的日志、取消类型、失败 Gas |
| 规范链身份与最终性 | 确认 | 入块可以被重组撤销 | 跨分叉重复结算或固定确认数冒充最终性 | blockHash、祖先验证、finalized 水位、临时观察回退 |
| 本地结算原子性与外部证据 | 终结、回报 | 链与数据库没有共同事务 | 冻结先释放、账本漏记、回报重复导致外部二次处理 | 结算唯一键、Inbox／Outbox、余额与义务的同水位核销 |
| 恢复与权限围栏 | 重启、切主 | 日志耐久与防旧主是两种保证 | 双主签名、丢失已承诺交易、恢复时再次付款 | 任期、签名出口校验、已签 raw 局限、RPO 与冻结策略 |
| Go 有界并发与可补扫追踪 | 运行时 | 钱包有序、RPC 多变且订阅可丢 | goroutine 无界、低 nonce 饿死、断线漏最终结果 | actor 边界、worker 池、context、重试退避、游标与指标 |

“20%”是正确性杠杆，不是机械限制题数。Solidity 语法、节点搭建、完整密钥系统、完整账户总账与索引平台不另开长篇；但它们与本专题相关的执行证据、授权和预留契约必须讲清。

## 第四部分：设计与规则

### 4.1 不变量与不能互换的身份

1. `requestKey` 在用户与业务作用域内唯一，并永久绑定规范化载荷摘要；相同键不同地址或金额不是重试。
2. `intentId=W1` 表达“向 B 付 100 T”。`nonce_slot=(chainId,H,42)` 表达一次钱包序号竞争。`attemptId` 与 `txHash` 表达具体签名交易；X1、X2、Xc 不等于三个付款义务。
3. 同一规范链里，普通 EOA 同一 nonce 最多有一个交易被执行；这不是全网 mempool 全局去重，也不意味着不同分叉不能各有候选。
4. 普通 ERC-20 `transfer` 不认识 W1。给 W1 自动换到 nonce 43 并不具备业务去重，可能在 42 与 43 连续付款。
5. 本地可用资金不得为负，用户冻结必须覆盖未终结提现。钱包资金准入同时检查 T 和 ETH；不同槽位的有效承诺求和，同槽位相互排斥候选按最坏需求计，不能把加速交易金额重复相加，也不能不补费用预算。
6. 仅凭超时、单节点查无交易、pending nonce 变化或本地 TTL，不得释放未知付款的用户冻结。未签名撤销要先关闭签名授权和所有在途请求；签后通常须等待同槽位最终结果。
7. 每个最终结算键至多落一组账务结果。最终成功消耗冻结；最终未付款才释放冻结。账本幂等不能阻止已经另发新 nonce 的链上重复转账。
8. 普通 type-2 交易没有本地 TTL 自动过期机制；本地停止广播不会撤销已传播 raw。提高 base fee 使当前费率不可打包，也不等于永久失效。
9. 任何“最终”都以已核验网络和可信链视图为前提；不把多个 RPC 回答一致说成重新执行了链共识。

### 4.2 架构、权威与持久边界

```text
账户域／提现 API
    └─ 受理事务：请求身份 + W1 + 用户冻结
                ↓
钱包调度器〔按 chainId + H 串行决策，可跨钱包并行〕
    └─ 钱包锁 + nonce_slot + T／ETH 预算 + 授权 draft
                ↓
受控签名服务〔密钥不出签名边界，独立审计与幂等查询〕
    └─ 返回签名 → 核验字段 → attempt(raw,hash) + broadcast_task 同事务
                                              ↓
                                     广播 worker → RPC A／B
                                              ↓
链追踪器〔区块补扫 + receipt 查询 + finalized 验证〕
    └─ inclusion_observation + 槽位候选结果 + 扫描游标
                ↓
最终结算器
    └─ intent 版本检查 + 账本分录 + 预算核销 + 结算键 + Outbox 同事务
                ↓
                              查询投影／通知消费者
```

- 数据库决定本地业务资格与资金记录，链决定执行与最终性。不能让“本地已广播”覆盖链上执行事实。
- 签名调用与数据库事务不是同一原子操作。必须预先落授权请求、签名服务保留可查询的幂等结果；签名完成但客户端未拿到响应时，恢复原请求，而不是创建新付款。
- raw/hash 与广播任务同事务落盘，广播只消费已提交任务。其复制耐久条件必须覆盖故障后继续承担的义务；只存在旧主内存或会丢失的异步副本不够。
- 数据库 epoch／租约只约束配合协议的本地写者。签名出口还需核验任期与授权；旧 raw 一旦离开系统，应用围栏不能撤销它。

### 4.3 核心对象与交互

| 对象 | 必要字段 | 关键约束 |
|---|---|---|
| `withdraw_intent` | W1、用户、requestKey、payloadDigest、T、B、整数金额、业务状态、version | 请求唯一；业务成功不能由 RPC 发送返回值驱动 |
| `fund_reservation` | intentId、用户冻结、钱包代币与费用预算、记账／观察水位 | 用户预留和钱包容量不是同一个余额；同水位避免双扣或提前释放 |
| `wallet_state` | chainId、H、nextNonce、epoch、恢复水位、健康状态 | 钱包行锁；初始化与恢复先对齐，不靠定时重设 pending nonce |
| `nonce_slot` | chainId、H、nonce、intentId、槽位状态 | 三元组唯一，关联整个候选集合；不把某次发送失败当作空槽 |
| `sign_draft` | draftId、operationKind、完整载荷、审批版本、费用上限、签名请求身份 | 业务载荷冻结；付款与取消独立授权 |
| `tx_attempt` | attemptId、slotId、draftId、hash、raw、签名核验结果、费用、传播进度 | raw 属于敏感执行能力；先耐久后外发；不覆盖旧 attempt |
| `inclusion_observation` | chainId、txHash、blockHash、blockNumber、txIndex、receipt、业务判定、规范性、finality | 同 hash 可在重组后有不同区块观察；不能仅按高度去重 |
| `settlement`／`outbox` | 唯一业务结算键、intent 版本、结果、账本引用、事件 ID | 本地原子提交；重复发送与消费均不再结算 |

命令包括“受理 W1”“批准 draft”“请求签名”“广播指定 raw”“申请同槽加速”“申请取消”；事实包括“签名结果已保存”“节点接收证据”“某块观察到 receipt”“该观察被重组撤销”“最终结果已结算”。命令期望不等于事实已经发生。

### 4.4 分开维护状态，而非塞进一个 status

```text
业务意图：RESERVED → EXECUTING → SUCCEEDED_FINAL
                            ├→ FAILED_FINAL
                            └→ CANCELLED_FINAL
             任意异常可加人工隔离标志，但 UNKNOWN 不是资金释放终态

单个 attempt：DRAFT → SIGN_REQUESTED → SIGNED_DURABLE → BROADCAST_ATTEMPTED
                                                     ├→ SEEN_BY_PROVIDER
                                                     └→ SEND_UNKNOWN
             随后可能有 INCLUDED 观察；旧 attempt 不因创建 X2 而删除

链观察：INCLUDED_PROVISIONAL → SAFE〔可选〕→ FINALIZED
                └→ ORPHANED → 重新检查该槽位全部候选
```

`FAILED_FINAL` 表示有最终未付款依据后结束本次提现，并不表示钱包私钥失效或代币永远不能转账。是否重新发起付款属于新的受控业务决策，不在 UNKNOWN 分支自动执行。

### 4.5 费用与资产核销口径

普通 type-2 交易在适用区块中需满足费用有效性与执行条件。主例：

```text
effectiveGasPrice = min(maxFeePerGas, baseFeePerGas + maxPriorityFeePerGas)
                  = min(40, 30 + 2) = 32 gwei

最坏费用预算 = gasLimit × maxFeePerGas = 0.0026 ETH
实际 Gas 费用 = gasUsed × effectiveGasPrice = 0.0016 ETH
```

Gas limit、费用 cap、用户转账金额分别约束不同东西。节点替换准入是实现与配置策略，不存在 EIP-1559 统一规定“提高固定百分比必然替换”。费用超预算时停留在等待或重新审批，不靠无限自动加价保证成功。

钱包余额镜像更新与槽位义务核销必须对齐观察水位。若链上 T 已从 10,000 变为 9,900，而本地仍保守扣着 100 T，可以暂时少报可用；不能在旧余额 10,000 上先去掉 100 T 义务，短暂恢复成可再支配 10,000。Gas 同理。最终对账是检测机制，不替代事前准入。

## 第七部分：工程实践——一个简洁 MVP

### 7.1 目标与范围

只手工验证一个闭环：**同 nonce 的付款／加速／取消候选，遇到广播未知或临时入块时保留冻结，只有位于最终链前缀的明确结果才能结算一次。**

不实现真实签名、RPC、存储事务、并发恢复、完整扫描器或密钥服务。下面使用预先核验的交易／回执输入，不能据此声称完成生产系统或工程测试。

### 7.2 核心伪代码

输入前提：候选都已验证签名与 slot；付款候选的 T、B、金额与 W1 一致，取消候选为批准的 H 自转。区块输入为经可信链视图核验的连续父链片段，`finalizedHash` 是该视图的最终块；回执输入已验证确实来自对应区块，付款事件匹配标志来自可信 T 的日志与准确载荷核验。MVP 不伪造这些外部证据的产生过程。

```text
state = {available: 900, frozen: 100, final: NONE, observations: {}}
attempts = {X1: PAY, X2: PAY, Xc: CANCEL}    # 三者都属于 nonce 42

onSendResult(attempt, result):
    appendSendEvidence(attempt, result)     # 演示只记录，不终结资金
    return state                           # 超时／接收均不改冻结

onObservation(attempt, receipt):
    state.observations[(attempt, receipt.blockHash)] = {attempt, ...receipt}

onChainView(blocksByHash, finalizedHash):
    finalPrefix = set()
    h = finalizedHash
    while h != agreedAnchor and h exists in blocksByHash:
        finalPrefix.add(h)
        h = blocksByHash[h].parentHash
    if h is not agreedAnchor: return NEED_MORE_HEADERS
    winners = values(state.observations) whose blockHash is in finalPrefix
    if count(winners) > 1: return FREEZE_INCONSISTENT_INPUT
    if state.final != NONE:
        if state.settledBlockHash not in finalPrefix: return FREEZE_FINALITY_CONFLICT
        return state                      # 重复输入不重复结算，不自动回滚终态
    if count(winners) == 0: return WAIT     # 不用查无回执证明失败
    r = winners[0]
    if r.status == 0: outcome = FAILED_FINAL
    else if attempts[r.attempt] == CANCEL: outcome = CANCELLED_FINAL
    else if r.transferMatches: outcome = SUCCEEDED_FINAL
    else: return FREEZE_BUSINESS_MISMATCH
    # 以下块在MVP中按一次不可分割状态更新手工推演；不是已实现的DB事务
    if outcome != SUCCEEDED_FINAL: state.available += state.frozen
    state.frozen = 0
    state.final = outcome
    state.settledBlockHash = r.blockHash
    state.gasExpense = r.gasUsed * r.effectiveGasPrice
    return state
```

这里共同锚点选在该 nonce 尚未被消费的已核验初始状态，最终链片段必须从该锚点之后连续覆盖执行范围；缺段就等待，不能因为最终块高度很大而跳过祖先核验。正常重组后重新输入新链视图，旧分叉回执仍可留作审计，但不在最终前缀就不能结算。生产版还须持久结算键、账本、预算核销与 Outbox，同事务提交；伪代码没有实现这些能力。

### 7.3 输入与手工预期结果

| 输入序列 | 预期结果 | 检验的边界 |
|---|---|---|
| X1 广播超时，随后节点返回 already known，没有最终回执 | 可用 900、冻结 100，继续等待 | 发送结果不决定付款或失败 |
| X1 在块 A 入块；A 被重组；最终链片段不含 A | 保留 100 T 冻结；旧观察不能触发终结 | 入块不等于最终付款 |
| 新最终链前缀含 X2；status=1 且付款证据吻合；重复交付同输入 | 一次成功终结，可用 900、冻结 0；主例 Gas 0.0016 ETH | 多 hash 仍为一笔付款，重复结果不重复扣款 |
| 独立变体：最终前缀含 Xc；status=1；X1 仍被节点报告 pending | 取消终结，可用 1,000、冻结 0；按 Xc 的实际 Gas 计费 | 最终占用 nonce 排除旧付款，本地 pending 不是反证 |
| 独立变体：最终前缀含 X1；status=0 | 失败终结、释放 100 T，按该失败回执计 Gas | 失败仍耗 Gas 与 nonce |
| status=1 但 T／收款人／金额不符，或链片段缺父块 | 隔离或继续补证，不释放、不新发 | 证据不足不能强行二选一 |

以上均为手工预期结果，不是工程测试报告。
