# 撮合交易与核心链路：大白话导读任务清单

## 目标与范围

面向懂一些后端开发、但尚不熟悉撮合、订单、清算、账本、持仓和充值提现业务的读者，为本目录下全部 **80 个现有 Markdown 文件（74 篇正文 + 6 篇专题 README）** 添加前置导读。本文是执行清单，不属于待添加导读的业务文章。

每个文件在原有一级标题之后、原正文之前增加：

1. **先看懂：关键词大白话解释**：用表格解释本文的交易名词、英文缩写、公式符号及关键工程概念，说明在本文中的具体含义。
2. **把整篇文章压缩成一个故事**：沿一个具体人物或系统事件串起起因、处理过程、结果和不能理解错的边界。

## 编写与验收标准

- 保留原有标题、正文、链接、公式和问答，不借导读修改原文规则；用 `<!-- 大白话导读开始 -->` 与 `<!-- 大白话导读结束 -->` 明确新增区块。
- 各篇导读独立可读，不用“同上”代替解释；词表按本文内容选择，不机械复制通用名词。
- 采用“费曼式解释 + 单一具体案例 + 不变量与边界反例”：先说真实业务，再解释后端如何保证业务成立，不用比喻掩盖提交边界。
- 区分下单意图、资产预留、可靠受理、撮合接纳、成交确定、账务完成和查询可见；不把一个 `SUCCESS` 当成全链路已完成。
- 区分限价与实际成交价、订单类型与有效期规则、同价权威接纳顺序与客户端时间；IOC、FOK、市价及改单等扩展不能混作基线能力。
- 区分累计成交量、剩余量、取消量；撤单只能取消实际剩余，不能撤回已成立成交；终态不等于所有预留都能立刻释放。
- 区分可用、预留、余额、清算义务和正式分录；按资产分别守恒，不把 BTC 与 USDT 的数量直接相加，不把复式平衡当成经济正确性的充分证明。
- 区分请求幂等、结果交付幂等和账务幂等；超时、查询未找到及消息未确认都不等于确定失败，不因此换编号重做或提前退款。
- 区分逻辑命令序号、结果提交进度、账务消费水位和查询投影版本；单写者不等于持久化原子性，本地事务不等于跨分片全局事务。
- 持仓专题沿用各篇产品、合约乘数和成本口径；区分现货与衍生品、已实现与未实现盈亏、毛收益与费用，不把估值变化当成重复现金结转。
- 充提专题区分平台内部账与链上资产、识别与确认、交易哈希与业务身份、广播未知与最终失败；重组、Nonce 替换及安全释放按原文信任边界解释。
- 教学金额、零手续费、定点单位、舍入、确认阈值、性能目标和恢复策略仅在各篇约定内成立，不泛化为所有平台规则。
- 用修改前工作区快照验证原文逐字保留；结构检查验证每份已完成文件均有且只有一套前置导读。
- 检查新增 Markdown 表格、相对链接和故事关键算式，按实际结果更新清单及复利记录。不创建 Go 工程，不声称运行生产故障、链上实测或性能测试。
